## 确认 Bug

### 1. riscv-hart-trace-interface / PR #59 / xiangshan — info_leak
**描述**: 香山处理器的 hart 到 trace encoder 接口在 interrupt retirement (itype=2) 时无条件将 mtval/stval CSR 值作为有效 tval 输出。按 spec 修订，tval 仅对 exception (itype=1) 有效，interrupt 时输出会泄露前一次 exception 的 CSR 残留值或未初始化微架构状态到片外 trace encoder。`CtrlBlock.scala:309-310` 的 `io.traceCoreInterface.toEncoder.trap.tval := io.fromCSR.traceCSR.tval` 缺少 `Mux(itype === Itype.Exception, ...)` 门控。

### 2. riscv-iommu / PR #694 / qemu — data_corruption
**描述**: QEMU 的 IOMMU 模拟在 `validate_device_ctx()` 中使用 `RISCV_IOMMU_CAP_SV32`（值为 256）与 `fsc_mode` 做相等比较，而非使用正确的 `RISCV_IOMMU_DC_FSC_IOSATP_MODE_SV32`（值为 8），导致 SXL=1 时的 first-stage SV32 能力检查永远为 false（死代码）。同时 G-stage (IOHGATP) 模式未在 validate 阶段做能力校验，恶意的 guest 可安装不支持的 G-stage 模式，导致 DMA 翻译时 SPA 计算错误。

### 3. riscv-iommu / PR #714 / qemu — info_leak
**描述**: QEMU IOMMU 的 `riscv_iommu_spa_fetch()` 从未向 PTE 写回 A/D 位。当 GADE/SADE=1 时仅跳过 A/D 检查而不执行硬件更新，导致 writable page (W=1, D=0) 上的 ATS implicit write 静默通过而 D 位保持为 0。如果 guest OS 后续切换到 GADE/SADE=0 或期望 A/D 已被设置，将导致翻译行为错误。与 `target/riscv/cpu_helper.c:1594-1639` 中 Svadu ADUE=1 的原子 cmpxchg write-back 形成对比。

### 4. riscv-iopmp / PR #169 / xiangshan — privilege_escape
**描述**: 香山 IOPMP RTL 实现的是 PR 之前的 spec（指令 fetch 权限检查被 chk_x 位门控），且 `IopmpParams.chk_x = 0` 硬连线。PR 删除了 chk_x 并将 instruction fetch 权限检查升为 baseline，但 RTL 的 `ReqBundle` 无 fetch 事务类型编码（仅 `rw: Bool`）、`RspBundle` 无 cf_x 响应通道、Ctrl FSM 从不检查 `entry_attribute.x`、ttype 只编码 0x1(read)/0x2(write)。所有 instruction fetch 事务未经检查通过，构成完整的指令访问绕过链。

### 5. riscv-iopmp / PR #183 / xiangshan — privilege_escape
**描述**: 香山 IOPMP 的 MDCFG 写入路径无单调性检查，非单调的 MDCFG(m).t 设置被无条件接受至 SRAM。Ctrl FSM 在 sPriority 状态使用基于 `j_indx === md_t` 的等值退出条件，但非单调 MDCFG 下 j_indx 从 md_t_pre 出发增量递增，可能跨越多个 MD 边界扫描条目。MDCFGLCK、MDLCK、MDLCKH、ENTRYLCK 保护寄存器全部被注释掉为 "not implemented"，配置完整性无硬件保障。

### 6. riscv-iopmp / PR #185 / xiangshan — privilege_escape
**描述**: `RegHwcfg2` 的 bit layout 为过时 v0.8 版（仅 prio_entry[15:0] + rrid_transl[31:16]），缺少 msi_en(bit 26) 等 8 个扩展能力字段。`RegErrcfg` 字段名仍为 `msi_en` 而未按 spec 重命名为 `msi_sel`，与 HWCFG2.msi_en 名称冲突。ERR_MSIADDR/ERR_MSIADDRH 寄存器未实现（仅 offset 常量存在）。Ctrl 中断生成逻辑始终使用 wired interrupt 而不检查 msi_sel。软件读 HWCFG2 固定看到 bit26=0，误判 MSI 不可用。

### 7. riscv-iopmp / PR #193 / xiangshan — denial_of_service
**描述**: ERR_CFG.stall_violation_en 字段无条件接受写入（仅 lock 位门控），未按 spec 要求 gating 在 `hwcfg2.stall_en=1` 上。参考模型 `iopmp_reg.c:712-713` 明确包含 `if (iopmp->reg_file.hwcfg2.stall_en)` 保护。虽然 stall_en 硬连线为 0 且 Ctrl FSM 不产生 etype=0x07（stalled transaction error），使该 bug 实际效果受限，但软件可写入 stall_violation_en=1 后读出该值，产生误导性配置预期。ERR_CFG.msi_en 和 msidata 同样缺少 `hwcfg.msi_en` gate。

### 8. riscv-isa-manual / PR #1434 / linux — data_corruption
**描述**: Linux 内核在 RV32 上模拟 FSD/C.FSD/C.FSDSP 等 8 字节宽浮点存储时，通过 `copy_to_user()` 一次写入全部字节，而 `copy_to_user()` 在 XLEN=32 环境下分解为两个 32-bit 写。如果地址跨越 PMP/page 边界导致第二个 32-bit 写 fault，第一个 32-bit 写已提交到受保护区域。RISC-V spec (machine.adoc:3567-3574, supervisor.adoc:1724-1730) 明确声明 PMP/page fault 不保证原子性。Kernel mode 下的 `memcpy()` fallback 路径同样受影响。

### 9. riscv-isa-manual / PR #1434 / qemu — privilege_escape
**描述**: QEMU 的 `helper_cbo_zero()` 通过 `probe_write(env, address, cbozlen, ...)` 在 cache block 粒度上执行单次整体 PMP 检查，而非按分解后的子内存操作独立检查。spec (machine.adoc:3567-3570, cmo.adoc:336-345) 明确要求 PMP 检查应用于每个内存操作独立进行：一个 64 字节的 cbo.zero 跨越两个 32 字节 PMP 区域时，若两个区域权限相同应成功（分解后），但 QEMU 的单次整体检查因 "partially inside" 而 fault。`check_zicbom_access()` 同样受影响。

### 10. riscv-isa-manual / PR #1879 / qemu — privilege_escape
**描述**: QEMU 的 mseccfg CSR 在 VM 迁移状态 (`vmstate_riscv_cpu`) 中未被保存/恢复。若 Smepmp 已配置（MML=1, MMWP=1），热迁移目标 VM 以 mseccfg=0 启动，导致 Smepmp sticky 位被静默丢弃，guest 内存保护 revert 到非 Smepmp 语义。mseccfg sticky-bit 写入逻辑（`mseccfg_csr_write`）、RLB 写门控（`pmp_is_locked`）和 reset 清零均正确实现。

### 11. riscv-isa-manual / PR #2366 / linux — denial_of_service
**描述**: Linux 内核仅通过 ISA string 探测 Sstc 扩展（`riscv_isa_extension_available(SSTC)`），但未检查 `menvcfg.STCE` 是否已被 firmware 置 1。当 STCE=0 时，从 S 模式访问 stimecmp CSR 会触发 illegal-instruction 异常。影响点：`timer-riscv.c` 的 `riscv_clock_next_event()` 和 `riscv_clock_event_stop()`、`suspend.c` 的 save/restore 路径、KVM `vcpu_timer.c` 的 vstimecmp 路径。KVM 还额外在 guest ISA string 和 henvcfg 状态之间产生不一致（guest ISA 广告 Sstc 但 henvcfg.STCE=0）。

### 12. riscv-isa-manual / PR #2432 / linux — function_loss
**描述**: KVM 无条件为 guest VM 设置 `henvcfg.CBIE = INV`（cbo.inval 执行真 invalidate），而 host userspace 故意受限为仅 CBCFE（clean/flush）。RISC-V spec (cmo.adoc:584-597) 明确警告"granting lower-privilege true invalidate capability may result in a security hole"。建议将 KVM guest 的 CBIE 设为 FLUSH (01b)。同时 Andes errata 将 `riscv_cbom_block_size` 设为 1 仅为"让 core CBO 代码高兴"，每字节发出一个完整 CBO 指令而实际硬件 block size 可能为 64 字节。

### 13. riscv-isa-manual / PR #2472 / qemu — privilege_escape
**描述**: QEMU RV32 的 `pmp_update_rule_addr()` 中 `sa = prev_addr << 2` 在 32-bit 算术下求值后赋值给 64-bit hwaddr。对表示物理地址 ≥ 4 GiB 的 pmpaddr 值（`pmpaddr >= 0x40000000`，即 pa[33:32] != 00），`<< 2` 溢出 32 位截断高位。TOR PMP 区域别名到低 4 GiB 空间，违反 spec 要求 RV32 PMP 支持 34 位物理地址的规定 (machine.adoc:3390-3392)。NA4 路径 `this_addr << 2` 同样受影响。NAPOT 路径因参数升格为 hwaddr 而安全。

### 14. riscv-isa-manual / PR #2482 / freebsd-src — privilege_escape
**描述**: FreeBSD bhyve VMM 在 VM entry 时通过 `csr_write(henvcfg, HENVCFG_STCE)` 写入 henvcfg，将 CBZE(bit7)、CBCFE(bit6)、CBIE(bits4-5) 全部清零。这禁用了 guest VS/VU 模式的所有 CBO 指令执行（应产生 virtual-instruction exception），但 VMM 的 `SCAUSE_VIRTUAL_INSTRUCTION` handler 仅解码 WFI，CBO 触发的 virtual-instruction exit 落入 `VM_EXITCODE_BOGUS`。`struct hypcsr` 缺少 `henvcfg` 字段，vCPU save/restore 不保存 henvcfg。CBO 指令仿真框架 (`vmm_emulate_instruction`) 无 CBO opcode 支持。

### 15. riscv-isa-manual / PR #2482 / qemu — info_leak
**描述**: QEMU 的 `check_zicbom_access()` 先用 `MMU_DATA_LOAD` (read permission) 探测，失败后 fallback 到 `probe_write()` (write permission)。但更新后的 ISA spec (machine.adoc:3421-3426, supervisor.adoc:1566-1571) 明确将 cache-block management 指令与 load 并列，要求无读权限时 raise load access-fault/load page-fault。QEMU 的 write fallback 既产生错误异常类型（store 而非 load fault），又在 write-only 区域可能不当放行。注意 cmo.adoc:352-361 仍描述为需要 store 类型 exception，与 ISA manual 冲突。

### 16. riscv-isa-manual / PR #2493 / xiangshan — privilege_escape
**描述**: 香山 RTL 的 mseccfg.MML(bit 0) 和 MMWP(bit 1) 被声明为 `RO(0)`（`ROType.wfn = wNoEffect`），所有 CSR 写入被静默丢弃。Spec 要求这些位是 WARL sticky bit：写 1 必须生效，写 0 必须被忽略直到 PMP reset。PMP checker 的 `passThrough = (mode > 1.U)` 无条件对 M-mode 放行 r/w/x，`PMPCheckerEnv` 无 MML/MMWP/RLB 字段，仅 `PMM` 被连线到 TLB（`io.tlb.pmm.mseccfg` 宽度仅 2 位）。Smepmp 扩展在硬件中完全未实现。

## 潜在风险

### 1. riscv-isa-manual / PR #1434 / opensbi — privilege_escape
**描述**: OpenSBI 在 `sbi_hart_smepmp_map_range()` 和 `unmap_range()` 后未执行 SFENCE.VMA 以同步 speculative PMP cache。Domain context switch 在 PMP unconfigure→configure 之间无 fence 保护。Eswin 平台的 `pmp_unconfigure()` 同样缺少 fence。PMP 区域边界对齐也未验证——相邻 PMP 区域的不同权限边界可能被分解后的 CBO 或 wide store（FSD on RV32）跨越，导致部分写成功 bypass 写保护。`sbi_hart_pmp_fence()` 本身正确检查 misa_extension('S') 后发出 SFENCE.VMA。

### 2. riscv-isa-manual / PR #1434 / xiangshan — privilege_escape
**描述**: 香山 RTL 的 PMP 检查接口 `PMPReqBundle` 编码单一 (addr, size, cmd) 三元组，天然假设每次 PMP 检查对应一个连续地址范围。Spec 要求 CMO 分解为多个子操作后各自 PMP 检查，需扩展该接口支持多 (addr, size) 对。PMP checker 本身按照传入的 (addr, size) 正确实现 first-match 语义（`pmp_match_res`、`pmp_check` 均正确），漏洞在上游尚未分解 CMO 访问——当前为架构层合规性缺口，不构成 runtime exploit。

### 3. riscv-isa-manual / PR #2397 / linux — denial_of_service
**描述**: Linux 内核的 spinwait secondary boot 路径不配置 PMP。虽然 PMP 条目复位为 OFF 时 M-mode 访问全部放行，但如果 firmware 或更早启动阶段遗留下有部分覆盖的 PMP 条目，M-mode 访问跨越 PMP 边界的操作会 fault（即便匹配条目 L=0，因 all-bytes-must-match 规则无条件优先）。内核在配置 PMP0 (NAPOT full address) 后无 CSR 读回校验，若硬件 WARL 静默忽略写入而无任何告警。

### 4. riscv-isa-manual / PR #2400 / freebsd-src — data_corruption
**描述**: FreeBSD bhyve 的 `vmmops_run()` 写入 henvcfg 后无 `HFENCE.VVMA`，且 vsatp 恢复顺序不符合 spec 推荐的"zero vsatp → 写 henvcfg.ADUE → 写新 vsatp"模式。目前 ADUE=0 无害，但若未来启用 Svadu，stale VS-stage TLB entries 会在旧 ADUE 设置下解释 PTE A/D 位。代码库缺少 `hfence_vvma()` 包装函数、`HENVCFG_ADUE` 宏未定义、henvcfg 未在 world-switch 中保存/恢复。G-stage 同步（HFENCE.GVMA）已正确处理。

### 5. riscv-isa-manual / PR #2440 / freebsd-src — info_leak
**描述**: FreeBSD 的 `page_fault_handler` 直接读取 `tf_stval`，无 pointer masking 感知。若 Ssnpm 被启用，硬件写入 stval 的是 masked（变换后）地址，而 kernel 将其作为原始地址用于 `VIRT_IS_VALID()`（可能错误拒绝有效 tagged 地址）、`call_trapsignal` si_addr 传递和 `vm_fault_trap` 查找。指令 fetch fault 与数据 fault 在 stval 的 masking 处理上不同（spec 只对数据访问应用 PM），handler 未按 scause 区分。FreeBSD 当前无任何 Ssnpm/Supm 配置代码。

### 6. riscv-isa-manual / PR #2442 / freebsd-src — info_leak
**描述**: 与 PR #2440 类似，侧重信号传递路径的 tagged address 丢失。FreeBSD trap handler 将 masked stval 通过 `call_trapsignal → ksiginfo_init_trap → sendsig` 链路传递给 userspace 信号 handler 的 `siginfo_t.si_addr`，原始 tagged 地址的 tag bits（通过 PM ignore transformation 清零或符号扩展）被永久丢失。对 HWASAN 风格依赖 tagged pointer 诊断的 userspace 程序影响显著。`save_registers` 宏在 exception.S 中无条件通过 `csrr t0, stval` 捕获。

### 7. riscv-isa-manual / PR #2482 / linux — privilege_escape
**描述**: Linux kernel 在 `riscv_user_isa_enable()` 中无条件为所有 userspace 进程开启 `ENVCFG_CBZE` 和 `ENVCFG_CBCFE`，未做 per-process opt-in。虽然新 spec 要求硬件在 PTE 权限不足时 raise page-fault，但若运行在不完整 CBO 权限检查的旧硬件上，userspace 可在 read-only 映射上执行 cbo.zero 或在不可访问页面上执行 cbo.clean/cbo.flush。`cbo.inval` 正确未启用（ENVCFG_CBIE=0）。Kernel 自己的 CBO 使用点（DMA `phys_to_virt`、PMEM kernel VA、clear_page buddy pages）均操作 kernel-owned pages，安全。

## 跨 Spec 模式

### PMP 完整性与分解语义 (PR #1434, #2397, #2472, #2493)
多个 spec 修订从不同角度加强对 PMP 的约束：PR #1434 要求 **内存操作粒度 PMP 检查**（CMO/wide store/misaligned 的分解）；PR #2397 明确 **M-mode L=0 不再 bypass all-bytes-must-match 规则**；PR #2472 暴露 **RV32 TOR 地址计算溢出**；PR #2493 规范 **Smepmp sticky-bit 行为**。影响 Linux (data_corruption)、OpenSBI (privilege_escape)、QEMU (privilege_escape)、XiangShan (privilege_escape) 四个 target。建议设计统一的 PMP 合规性测试套件，覆盖分解语义、RV32 大地址、Smepmp 三者交叉场景。

### CBO 权限模型收敛 (PR #2482, #2432)
PR #2482 将 CBO 指令的权限模型从规范层面收敛：cache-block management (clean/flush/inval) 被明确归类为需要 **read permission**（此前 spec 文本与 ISA manual 有 store-fault 模糊性），cbo.zero 需要 **write permission**。影响 FreeBSD (privilege_escape via bhyve VMM hole——CBO 指令无仿真且虚拟异常未注入)、QEMU (info_leak via wrong fault type——write fallback 产生 store fault 而非 load fault)、Linux (privilege_escape via unconditional U-mode enable——无 per-process 策略)。PR #2432 补充了 `henvcfg.CBIE` 的安全考量——KVM 不应无条件授予 guest 真 invalidate 能力。

### Smepmp / mseccfg 实施一致性 (PR #1879, #2493)
两个 PR 都围绕 mseccfg 的正确实施：PR #1879 处理 QEMU 的 mseccfg **迁移状态缺失**（migration hole），PR #2493 暴露 XiangShan RTL 将 MML/MMWP **硬编码为 RO(0)** 导致 Smepmp 完全不可用。核心问题是 mseccfg sticky-bit 语义在不同实现层（模拟器/硬件/固件）的不一致——每个需要 reset、write-gating、state save/restore 的组件都可能独立出错。QEMU 的 sticky-bit 写入逻辑正确但迁移缺失；XiangShan 的写入路径完全不接受 sticky-bit 写入。

### Pointer Masking 内核适配 (PR #2440, #2442)
PR #2440 和 #2442 均涉及 FreeBSD 在 Ssnpm 启用时对 stval 的处理不完善：page fault handler、信号传递、`VIRT_IS_VALID` 均无 PM（pointer masking）感知。虽然 FreeBSD 当前未启用 Ssnpm 是安全的默认，但这表明 Zjpm 扩展的软件适配在操作系统层面存在同质化缺口——stval 的 hardware-masked vs raw 语义分离需要内核在 scause 级别区分。Linux 是否有相同 pattern 值得后续扫描关注。

### IO 保护配置门控一致性 (riscv-iommu PR #694/#714, riscv-iopmp PR #183/#185/#193)
多个 IOPMP 和 IOMMU PR 共享同一安全模式：硬件/模拟器接受 CSR 配置写入时缺少 spec 要求的 **WARL capability-gated write**。IOMMU 的 G-stage 模式校验缺失和 A/D bit 更新未实现，IOPMP 的 stall_violation_en、msi_sel/msidata 无条件接受写入但对应的 capability bit (hwcfg2.stall_en, hwcfg2.msi_en) 为 0。这表明 RISCV IO 保护外设的 CSR 写门控模式是系统性问题，建议建立通用的 WARL capability-gated 写门控参考实现。
