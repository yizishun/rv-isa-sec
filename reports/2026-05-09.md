## 确认 Bug (19)

### 1. riscv-cheri / PR #1006 / linux
- **后果**: data_corruption
- **描述**: Linux 内核在 CHERI hart 上使用 vector 指令 (vle8.v/vse8.v) 实现 copy_to_user/copy_from_user 和 memcpy 类操作。CHERI spec 明确规定 "vector stores will always clear ctags in memory"，导致被拷贝内存中的 capability tag 被静默清零，破坏用户态和内核态的 capability 隔离。同时上下文切换的 vector state save/restore 路径也使用了 vse8.v，会在每次调度时清理 datap buffer 中的 ctags。

### 2. riscv-cheri / PR #1006 / opensbi
- **后果**: denial_of_service
- **描述**: OpenSBI 的 sbi_trap_handler 和 riscv_encoding.h 缺少 CHERI capability exception cause codes (32-36) 的定义和分发逻辑。当 spec 移除了 "zero active elements 不产生 CHERI 异常" 的保证后，vl=0 或全 masked 的 vector 指令引起的 CHERI 异常会落入 default 分支，触发 sbi_trap_redirect 写回原始 sepc——导致 M-mode 与 S-mode 之间的无限 trap 循环。

### 3. riscv-debug-spec / PR #1197 / xiangshan
- **后果**: function_loss
- **描述**: XiangShan RTL 将 hgDebugInt（halt-group 触发）和 hrDebugInt（直接 halt-request）OR 成单一 debug interrupt 线。TrapEntryDEvent 对所有 debug interrupt 无条件写 dcsr.cause=3 (Haltreq)。DcsrCause.Group (6) 虽已定义但从未被引用，硬件无法区分 halt-group 中断和直接 halt request，无法满足 spec 要求的 cause=6 上报。

### 4. riscv-elf-psabi-doc / PR #299 / linux
- **后果**: info_leak
- **描述**: 内核 elf_check_arch() 完全不检查 e_flags 中的 EF_RISCV_RVE 标志。LP64E (RV64E) ELF 二进制被加载时使用完整的 31-GPR 寄存器语义：x16-x31（按 RV64E spec 为 reserved、不应存在）通过 ptrace (user_regs_struct)、signal frame (setup_sigcontext)、core dump (ELF_CORE_COPY_REGS) 和 context switch (save_from_x6_to_x31) 暴露给用户态，构成跨安全边界的信息泄露。

### 5. riscv-elf-psabi-doc / PR #498 / linux
- **后果**: data_corruption
- **描述**: RISC-V 内核完全无 e_flags 校验，EF_RISCV_RVY (CHERI purecap ABI) 的 ELF 二进制会通过 elf_check_arch 静默加载到非 CHERI 内核上。同时 arch/riscv 未实现 arch_check_elf() 钩子（fallback 到无条件 return 0），且未 select ARCH_BINFMT_ELF_STATE。CHERI capability-aware 代码会被当作 bare-pointer 代码执行，导致未定义的指针损坏。

### 6. riscv-fast-interrupt / PR #609 / opensbi
- **后果**: denial_of_service
- **描述**: OpenSBI 缺少 ACLIC mstateen0 bit 53 (SMSTATEEN0_ACLIC) 的定义和配置，同时 sbi_hart_extensions 无 SBI_HART_EXT_SMACLIC 枚举值。S-mode 访问 ACLIC CSRs (acliciprio, aclicsourcecfg, topi, claimi) 时触发 illegal instruction exception，导致外部中断完全不可用。hart_detect_features() 仅探测 CSR_MTOPI 检测 SBI_HART_EXT_SMAIA，在 ACLIC-only 系统上无法识别。

### 7. riscv-fast-interrupt / PR #653 / freebsd-src
- **后果**: data_corruption
- **描述**: FreeBSD 的 save_registers 宏无条件执行 addi sp, sp, -(TF_SIZE)，但 Smip 硬件在中断入口已自动保存 x10-x15 并调整 sp。叠加的 sp 调整导致硬件保存的上下文被隔离在不可达区域，内核保存的是 handler 运行后被 clobber 的寄存器值。返回时使用 sret 而非 sipopret，硬件 sp 调整永不被撤销，x10-x15 恢复错误值，sp 永久偏移 48 字节。stvec 配置为 DIRECT 模式也与 Smip 不兼容。

### 8. riscv-fast-interrupt / PR #653 / opensbi
- **后果**: data_corruption
- **描述**: OpenSBI 的 _trap_handler 和 _trap_handler_hyp 无条件使用 mret 返回中断。Smip 要求在中断返回时使用 mipopret 以恢复硬件自动保存的 x10-x15 并销毁硬件创建的栈帧。mret 跳过这些步骤，导致寄存器损坏和栈指针偏移。此外 TRAP_SAVE_GENERAL_REGS_EXCEPT_SP_T0 无条件保存所有 GPR（包括已由硬件保存的 x10-x15），TRAP_RESTORE_MEPC_MSTATUS 覆盖 tail-chaining 时硬件保留的 mepc/mstatus。

### 9. riscv-fast-interrupt / PR #662 / linux

- **描述**: IMSIC 驱动在 ACLIC 系统上尝试写 IMSIC_EIDELIVERY=1 和 IMSIC_EITHRESHOLD=0 以启用中断传递，但 ACLIC spec 明确将 eidelivery/eithreshold 排除在 Smidctrl/Ssidctrl 范围之外。这些 indirect CSR 访问被静默忽略，中断传递从未实际启用。同时 ACLIC 的 single-hart APLIC domain 模式与 IMSIC 的多 hart interrupt file 模型根本冲突。

### 10. riscv-fast-interrupt / PR #662 / opensbi

### 11. riscv-fast-interrupt / PR #668 / freebsd-src

### 12. riscv-fast-interrupt / PR #668 / linux

### 13. riscv-fast-interrupt / PR #669 / xiangshan

## 潜在风险 (24)

### 1. integrated-matrix-extension / PR #28 / xiangshan
- **后果**: data_corruption
- **描述**: XiangShan 的 VtypeStruct、VType、VsetVType 均无 G (matrix group size) 字段。VLMAX 公式缺少 ×G 因子（当前为 VLEN×LMUL/SEW，应为 VLEN×G×LMUL/SEW）。vtypeIllegal 使用 reserved.orR 会将任何非零 G 值判为 illegal。LmultoRegNum 和寄存器重叠检测均低估 G 倍，可能遗漏矩阵操作间的 RAW/WAW 冒险。

### 2. integrated-matrix-extension / PR #3 / qemu

### 3. integrated-matrix-extension / PR #30 / linux
- **后果**: denial_of_service
- **描述**: sigreturn 从用户态恢复 vtype 和 vl 时零校验，不检查 vl 是否为 λ×LMUL 的倍数。KVM ONE_REG 接口允许 VMM 独立写入 vl 和 vtype，产生不一致的中间状态。ptrace 路径 (riscv_vr_set) 有较好的 vtype 验证但未考虑 λ 字段。当 integrated-matrix 的 λ 字段加入 vtype 后，缺失的 vl-divisibility 校验会导致 GEMM 指令触发 illegal instruction (DoS)。

### 22. riscv-fast-interrupt / PR #775 / freebsd-src
- **后果**: denial_of_service
- **描述**: FreeBSD APLIC driver 的 aplic_map_intr 验证 daf->cells[0] > sc->ndev 但不检查 cells[0]==0。若 malformed device tree 映射 IRQ #0，后续 APLIC_SRC_CFG(0)/APLIC_TARGET(0) 会通过 (idx-1)*4 公式访问 domain config 和 MSI generation 寄存器，损坏中断控制器配置。ACLIC spec 规定 aclicsourcecfg[0][15:0] 和 target[0].iprio 均为 hardwired ROZ。

### 23. riscv-fast-interrupt / PR #781 / linux
- **后果**: denial_of_service
- **描述**: KVM VCPU 加载路径直接写入 CSR_VSTVEC 而不验证 guest vstvec 值（如 MODE=11 IVT 模式）。NACL path 同样传播。内核缺少 CSR_SIVT (0x107) 和 CSR_SEIVT (0x108) 定义，对 CLIC 共享向量表权限状态完全盲视。若 M-mode firmware 共享 CLIC 向量表但 PMP 未授予 S-mode X 权限，stvec 目标页缺失 execute permission 会导致 trap-loop DoS。

### 24. riscv-fast-interrupt / PR #781 / opensbi
- **后果**: privilege_escape
- **描述**: OpenSBI 的 domain init 创建全地址空间 catch-all 区域授予 S/U-mode 完整 R/W/X。SiFive 平台 port 将 2GiB 外设端口和 512GiB 系统端口注册为 SURW_MRW（shared R/W）。任何 CLIC 向量表 (mivt/meivt) 位于这些区域时，S-mode 可读取/修改 M-mode 的 interrupt handler pointer。SUX_MRX (execute-only shared) 编码已定义但从未被使用。缺少 CSR_MIVT/MEIVT/SIVT/SEIVT 定义和 SMSTATEEN0_ACLIC。T-Head C9xx 的 vendor-specific NT_MTVT CSR 同样未受保护。

### 1. CLIC/ACLIC/Smip 快速中断 — 系统性 spec-实现落差
涉及 **riscv-fast-interrupt** 下的大量 PR (#609, #653, #662, #668, #669, #691, #695, #699, #702, #703, #706, #714, #718, #729, #761, #775, #781)，覆盖 linux、opensbi、freebsd-src、qemu、xiangshan 全部 targets。
