## 确认 Bug

### PR-2504 / opensbi → denial_of_service
- **根因**: `sbi_timer_exit()` 无条件写 `csr_clear(CSR_MIP, MIP_STIP)` 未检查 Sstc 是否使能。当 `menvcfg.STCE=1` 时 STIP 在 mip 中为只读，写入被静默忽略，导致定时器中断无法被清除。
- HSM suspend 恢复路径同样存在 `MENVCFG` 先于 `MIP_STIP` 写入的时序问题，STIP 注入被静默丢弃。

### PR-2561 / qemu → function_loss
- **根因**: `have_mseccfg()` 仅检查 `ext_smepmp/ext_zkr/ext_smmpm` 三个扩展，未包含 `ext_zicfilp`（Zicfilp 扩展向 mseccfg 添加了 MLPE 字段 bit10）。当仅使能 Zicfilp 但关闭其他扩展时，mseccfg CSR 对 guest 不可见，MLPE 字段无法访问。

### PR-2570 / opensbi → data_corruption
- **根因**: Smmpm 使能时，硬件已将 PM（pointer masking）变换后的地址写入 mtval。M-mode trap handler 在 misaligned load/store 仿真和 access fault 仿真中直接使用该值做显式访存，而 `sbi_load_u8/sbi_store_u8` 设置 MPRV 导致硬件再次施加 PM 变换——双重 mask 产生错误的物理地址。
- 影响所有 4 个仿真入口（misaligned load/store、access fault load/store），数据损坏确定发生。

### PR-2577 / opensbi → data_corruption
- **根因**: HSM non-retentive suspend 保存路径未保存 `mcountinhibit`；恢复时 `mstatus_init()` 无条件写入 `0xFFFFFFF8`（CY=0）。当 mcycle 跨 hart 共享时，mcountinhibit.CY 也为共享——一个 hart 的 resume 操作会覆写兄弟 hart 的 CY 抑制状态，破坏性能计数器配置。

### PR-2601 / qemu → privilege_escape
- **根因**: `write_menvcfg()` 在第 3182 行无条件将 `MENVCFG_CDE` 纳入写掩码，随后 RV64 分支 `mask |= (cfg->ext_smcdeleg ? MENVCFG_CDE : 0)` 只做 OR 无法清除已存在的 CDE 位。结果：Smcdeleg 未实现时 CDE 仍然可写（违反 `norm:menvcfg_cde_rdonly0`），S-mode 可绕过 gating 访问 scountinhibit。

### PR-2609 / linux → denial_of_service
- **根因**: Zicfiss shadow stack 区域（PTE 编码 R=0,W=1）只允许 `ssamoswap/sspush` 指令写入。信号帧交付路径（`setup_rt_frame`→`__copy_to_user/__put_user`）使用普通 store 指令写入 shadow stack 区域时，硬件引发 `EXC_STORE_ACCESS`（cause=7），`do_trap_store_fault` 直接发送 SIGSEGV 而不检查 uaccess fixup 表，导致信号交付失败。
- PTrace/`/proc/pid/mem` 路径通过 `FOLL_FORCE` 绕过 `VM_SHADOW_STACK` 检查，可经 kmap+memcpy 旁路硬件 PTE 强制写入 shadow stack。

### PR-2635 / qemu → denial_of_service
- **根因**: `ZVKNHB_IMPLIED` 规则未包含 Zvknha——规约规定 `Zvknhb` 隐含 `Zvknha`（SHA-256 SEW=32 支持）。用户可配置 `zvknhb=true,zvknha=false`，guest 软件检查不到 Zvknha 时可能 fallback 到软件路径或 trap。

### PR-2697 / qemu → function_loss
- **根因**: CSR `tcontrol` (0x7A5) 完全缺失：`cpu_bits.h` 未定义宏，`debug.c` 无读写处理函数，`csr_ops` 调度表中无注册。guest 访问该 CSR 返回 illegal-instruction exception，调试工具依赖 tcontrol 的功能完全失效。

### PR-2755 / freebsd-src → denial_of_service
- **根因**: FreeBSD 仅从 ISA string 解析 `has_sstc`，未验证 `menvcfg.STCE` 是否被 M-mode 固件置位。当 ISA string 声称 Sstc 但 STCE=0 时，`csr_write(stimecmp, …)` 引发 illegal-instruction exception，kernel panic。影响 `set_timecmp()` 和 `riscv_timer_intr()` 两处。

## 潜在风险

### PR-2503 / opensbi → denial_of_service
- **风险**: 当 OpenSBI 正确设置 `SSEED=1` 时无实际影响；但若未来因平台 quirk 导致 SSEED=0，M-mode illegal-instruction handler 无法区分 seed CSR 访问与其他非法指令，S-mode 将陷入不可恢复的异常循环而非收到明确错误。

### PR-2504 / freebsd-src → denial_of_service
- **风险**: 与 PR-2755 同模式但应用于 FreeBSD——`has_sstc` 仅从 ISA string 推导，`set_timecmp()` 和中断处理函数直接写 stimecmp 无 STCE 验证。

### PR-2568 / opensbi → denial_of_service
- **风险**: 规约规定 critical-error 状态下 counter/timer 更新是 UNSPECIFIED 的。OpenSBI trap handler 在 `sbi_trap_handler()` 入口和 `sbi_emulate_csr_read()` 中读取 mcycle/time/minstret 等计数器值，但未考虑这些值在 critical-error 状态下可能停滞或无效。FW PMU 计数器在 handler 返回值检查之前增计数也存在计数正当性问题。

### PR-2568 / xiangshan → function_loss
- **风险**: XiangShan RTL 中 mcycle 无条件递增（仅由 COUNTINHIBIT.CY 门控），无 criticalErrorState 输入。minstret 因 ROB commit 被 criticalErrorState 阻断而隐式停止，但 mcycle 和 mtime（独立时钟域）继续走。不一致的 counter 行为可通过 mcycle/minstret 比值泄露 critical-error 状态，形成时序侧信道。

### PR-2606 / linux → info_leak
- **风险**: Sscsrind 定义的 `siselect`（0x150）和 `sireg*`（0x151-0x157）未在 context switch 中保存/恢复。`thread_struct` 无对应字段，`__switch_to` 和 `handle_exception` 未触及这些 CSR。进程 A 设置的 siselect 窗口值可能被进程 B 通过 sireg 读取，泄露跨进程的间接寄存器状态。

### PR-2686 / linux → data_corruption
- **风险**: `L1_CACHE_BYTES` 硬编码为 64，在非 Zic64b 平台上若实际 cache block size > 64，ARCH_DMA_MINALIGN 不足以保证 CBO 操作的对齐。T-Head C9xx errata 同样硬编码 block_size=64。内核会发出 WARN_TAINT 但继续执行。

### PR-2729 / linux → info_leak
- **风险**: Zvvm IME 扩展在 vtype CSR 中定义了 lambda[2:0]、altfmt_A/B、bs 等新字段（占用 vtype[XLEN-2:8] 区域），但内核 context-switch 恢复路径使用 `vsetvl` 指令写入 vtype——vsetvl 架构上会清零 vtype[XLEN-2:8]，导致 IME tile 配置在 context switch 后被静默丢弃。影响 context switch、signal 恢复、KVM VCPU 切换等所有恢复路径。

### PR-2737 / opensbi → function_loss
- **风险**: PMP 相关的潜在风险分布在不同平台代码中：Boston 平台硬编码写 PMPADDR14/15 假设 ≥16 个条目，无读回验证；ESWIN EIC770X 硬编码 8 条目布局无运行时验证。若运行在 PMP 条目数不足的硬件变体上，WARL 静默忽略写入导致内存保护不完整。

### PR-2790 / opensbi → denial_of_service
- **风险**: 多处 MIE 写入后无读回验证（`sbi_hsm_hart_wait`、HSM non-retentive suspend restore、SiFive TMC0/Andes HSM stop 路径）。MIE 为 WARL——若硬件不支持的中断位被写入，值被静默强制为零，而固件假设写入完全生效，可能导致中断丢失（wake-up 失败）或中断状态错配。

## 跨 Spec 模式

### 模式一：CSR 访问控制的 M-mode 使能位 Gate
涉及 PR：**PR-2503 (SSEED)**、**PR-2504/opensbi (STCE/STIP)**、**PR-2504/freebsd + PR-2755 (STCE gate)**、**PR-2601 (CDE gate)**、**PR-2697 (缺失 tcontrol)**、**PR-2606 (siselect/sireg 上下文)**。

共同特征：RISC-V 规约通过 menvcfg/mseccfg 中的使能位（SSEED / STCE / CDE）控制 S-mode 对特定 CSR（seed / stimecmp / scountinhibit）的访问权限。当 M-mode 固件未正确设置这些使能位时，S-mode 访问会触发 illegal-instruction exception。核心安全问题是 **M-mode 固件与 S-mode 内核之间的契约缺口**——内核仅能通过 ISA string 或探测间接推断使能状态，缺乏直接的硬件验证机制。

此外，PR-2697 属于反向模式：CSR 地址已分配但实现方未注册，导致合法访问被当作非法指令拒绝。

### 模式二：定时器与计数器在异常状态下的正确性
涉及 PR：**PR-2504 (STIP read-only 语义)**、**PR-2568 (critical-error 中 counter/timer UNSPECIFIED)**、**PR-2577 (mcountinhibit cross-hart 竞争)**、**PR-2686 (CBO block size 硬编码)**。

共同特征：RISC-V 的平台级定时器（mtime/stimecmp）和性能计数器（mcycle/minstret/mhpmevent）在跨 hart 共享、电源管理（HSM suspend/resume）、和 critical-error 场景下存在多个 UNSPECIFIED 或共享状态竞争点。从纯硬件规约到固件实现之间存在语义传递损失。

### 模式三：规约隐含依赖未在实现中体现
涉及 PR：**PR-2561 (mseccfg 扩展检查不全)**、**PR-2601 (CDE 写掩码逻辑缺陷)**、**PR-2635 (Zvknhb 未 imply Zvknha)**。

共同特征：规约定义了扩展之间的隐含关系（extension A 的存在要求 extension B 的 CSR 也可见）或字段分配规则（扩展 X 向 CSR Y 添加字段 Z），但实现（QEMU）的初始化/验证逻辑未枚举所有关联扩展，导致 CSR 可见性或 ISA string 传播不正确。这种缺陷是**系统性的**——每个新增规约字段都可能在现有实现中遗漏。

### 模式四：Context Switch 中新架构状态的保存/恢复缺失
涉及 PR：**PR-2606 (siselect/sireg)**、**PR-2729 (vtype Zvvm fields)**、**PR-2577 (mcountinhibit)**。

共同特征：新扩展引入的 CSR 状态（间接寄存器窗口选择器、vtype 高位字段、共享计数器抑制位）未纳入 context switch 的保存/恢复路径。故障模式包括跨进程信息泄露（info_leak）、状态静默丢弃（data_corruption）、和跨 hart 竞态（data_corruption）。
