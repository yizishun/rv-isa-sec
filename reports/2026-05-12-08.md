## 确认 Bug

### PR-1153 / freebsd-src — denial_of_service
FreeBSD S-mode 内核对 Smepmp（PMP Enhancements for M-mode）完全无感知：没有 mseccfg CSR 定义，PMP CSR 虽声明但从未使用。若 M-mode 固件（OpenSBI）启用 MML=1 和 MMWP=1 且 PMP 条目未覆盖 FreeBSD 的全部物理内存，内核将在 `trap.c:338` 触发 `Memory access exception` panic。此外 `efi_exclude_sbi_pmp_cb()` 启发式假定只有一个 PMP 条目保护固件，Smepmp 可能使用多个条目导致 physmem 排除逻辑错误。

### PR-1153 / linux — denial_of_service
`CONFIG_RISCV_M_MODE` 下内核在 `head.S:240` 写入 `PMPCFG0`（L=0, RWX=111, NAPOT 全允许），假定 legacy PMP 语义。若固件在交接前设置 `mseccfg.MML=1`（Smepmp 预期启动流程），该规则按 Smepmp 真值表变成 S/U-mode-only，拒绝 M-mode 访问全部内存。若 `mseccfg.MMWP` 同时置位，M-mode 无回退白名单，立即触发指令取指 fault，内核变砖。`csr.h` 仅定义 MSECCFG_PMM 位字段，缺失 MML/MMWP/RLB 定义。

### PR-1172 / freebsd-src — info_leak
FreeBSD 内核启用 Smctr（sctrctl CSR at 0x14E）但未在 `cpu_switch.S` 或 `pcb` 中添加 sctrctl 保存/恢复。进程 A 的 CTR recording 配置（包括 privilege-mode 使能位、transfer-type 过滤位）在上下文切换时泄露到进程 B。`exec_setregs` 不清零 sctrctl，新进程继承旧进程的 CTR 配置。bhyve VM 进入/退出路径（`vmm_switch`）未保存/恢复 sctrctl/vsctrctl，恶意 Guest 可在 VM exit 前启用 CTR recording 记录 Host 内核控制流。`struct pcb`、`struct trapframe`、`struct hypcsr` 均无 sctrctl 字段，`genassym.c` 无对应 ASSYM 偏移。

### PR-1297 / xiangshan — privilege_escape
XiangShan RTL 中 mseccfg CSR（0x747）无条件实例化并加入 `machineLevelCSRMods`/`csrRwMap`，无论配置哪些扩展。按 spec `norm:mseccfg_presence`，mseccfg 仅在实现 Zkr/Smmpm/Zicfilp/Smepmp 之一时存在，否则为 reserved。当 hart 仅支持 Sm 但未启用上述任何扩展时，对 0x747 的 CSR 访问返回零而非触发 illegal instruction exception，M-mode 软件可通过 trap 行为错误推断 mseccfg 能力。

### PR-1302 / qemu — info_leak
QEMU 中 `have_mseccfg()` 省略 `ext_zicfilp` 检查，而 `mseccfg_needed()` 包含它。当 VM 仅配置 Zicfilp（无 Smepmp/Zkr/Smmpm）时，CSR_MSECCFG 以 illegal instruction 陷入，MLPE 位不可访问，但 mseccfg 状态仍通过 `mseccfg_needed()` 包含在迁移流中。造成 guest-observable 不一致：迁移恢复后的 mseccfg 状态存在但 guest 无法读写。同时 `riscv_cpu_reset_hold` 仅在 `ext_smepmp` 时清零 `env->mseccfg`。

## 潜在风险

### PR-1153 / opensbi — function_loss
OpenSBI 的 HSM non-retentive suspend 流程中，`__sbi_hsm_suspend_non_ret_save()` 保存 MIE/MIP/MEDELEG/MIDELEG/MENVCFG 但遗漏 MSECCFG。Resume 后 MSECCFG 重置为硬件默认值（MML=0, MMWP=0, RLB=0, USEED=0, SSEED=0）。虽然标准 warm-boot 路径通过 `sbi_hart_smepmp_configure` 重建 MML/RLB，但 USEED/SSEED 位（Zkr）仅通过 `mstatus_init` 间接重建而非显式保存/恢复。`struct sbi_hsm_data` 无 `saved_mseccfg` 字段。

### PR-1153 / qemu — privilege_escape
mseccfg sticky-bit（MML/MMWP/RLB）变更时 QEMU 必须在 `mseccfg_csr_write` 中执行 TLB flush 以重验证所有缓存的 PMP 访问决策。当前 sticky-bit 和 TLB flush 路径基本合规，但 `riscv_cpu_post_load` 迁移恢复后不执行 TLB flush（若未来优化添加"有效 PMP policy"缓存可能产生问题）。MLPE 位处理 `val |= (val & MSECCFG_MLPE)` 是 no-op（疑似 sticky-bit 实现错误）。mseccfg 重置仅在 `ext_smepmp` 时执行。

### PR-1236 / freebsd-src — denial_of_service
FreeBSD 在 `mp_machdep.c`、`intc.c`、`timer.c` 中写入 sie（SSIE/STIE/SEIE）假设 sie 位独立控制中断使能状态。按更新版 spec，sie 位是 mie 位的别名，非独立状态。若 M-mode 固件未通过 mideleg 委派对应中断，sie 写入静默忽略（位保持只读零），内核误认为中断已使能/禁用。反之若 mideleg 已设，写入 sie 实际写入 mie，M-mode 固件可通过 mie 读/写随时观察或覆盖 S-mode 中断使能状态。

### PR-1236 / linux — denial_of_service
内核 `riscv_intc_irq_unmask()` 通过 `csr_set(CSR_IE, BIT(d->hwirq))` 使能中断，无读回验证。若 M-mode 固件清除对应 mideleg 委派位，sie 位变为只读零，`csr_set` 静默失败——内核认为中断已使能但 hart 永不投递。`suspend_restore_csrs` 恢复保存的 sie 值但亦无读回验证。KVM 代码显式处理了 HS/VS 上下文中的类似问题，但 S-mode 路径缺少同等防护。

### PR-1245 / xiangshan — info_leak
若向量 LSU 在触发 memory access exception（如 page fault、PMP violation）的元素索引之后继续将 load 数据写入目标向量寄存器组元素，硬件将覆写精确 trap 边界之后的架构状态。这需要 LSU 写回路径按每元素索引受 trap-valid 信号门控，且 LSU 写回队列在异常检测时被排空。当前主要关注 VLMAX/SEW 计算依赖无符号整数溢出模拟有符号 LMUL 值（3-bit 无符号算术），功能上正确但脆弱——修改操作数位宽可能静默破坏 VLMAX 计算。

### PR-1276 / freebsd-src — denial_of_service
FreeBSD 内核 FPU 管理完全依赖 `mstatus.FS` 门控 FP 访问，忽略了 state-enable CSR 链（mstateen0/sstateen0/hstateen0）。在 Zfinx+Smstateen 系统上，`mstatus.FS` 硬连线为 0，实际门控是 `sstateen0.FCSR`（bit 1）。FreeBSD 整个 `sys/riscv/` 中无 `mstateen0`/`sstateen0` 引用。`fpe_init` → `fpe_enable`（设置 sstatus.FS=Initial → Zfinx 上为 no-op）→ `fpe_store`（执行 frcsr）→ 在 stateen0.FCSR=0 时立即触发 illegal instruction exception，在内核启动阶段 `SI_SUB_CPU` 就 panic。

### PR-1302 / xiangshan — info_leak
与 PR-1297 类似：mseccfg 无条件实例化在 `csrRwMap` 中。当前默认配置包含 smmpm（mseccfg 合法存在），但若配置移除 smmpm 且不加 zkr/smepmp/zicfilp，mseccfg 仍存在并可访问，违反 spec "otherwise reserved" 规则。各字段位宽和位位置正确：smmpm PMM(WARL bit[33:32])、Smepmp 字段(RO零)、Zkr 字段(RO零)、Zicfilp 字段(RO零)。mseccfgh(0x757) 在 RV64 下正确不存在。

## 跨 Spec 模式

### mseccfg CSR 存在性与访问控制
PR-1153、PR-1297、PR-1302 均围绕 mseccfg CSR 的规范合规性：FreeBSD/Linux 缺乏 mseccfg 意识导致 Smepmp 下功能故障；XiangShan RTL 无条件实例化 mseccfg 违反 `norm:mseccfg_presence`；QEMU 的 `have_mseccfg` 与 `mseccfg_needed` 扩展检查不一致。建议跨 target 统一审计 mseccfg 的 CSR 存在门控和字段可读写性语义。

### sie/mie 别名与 mideleg 依赖
PR-1236 同时影响 FreeBSD 和 Linux：两个内核都将 sie 视为独立中断使能寄存器，但 spec 明确 sie 是 mie 的子集/别名。写入效果取决于 mideleg 委派状态——未委派时静默忽略，委派时直通 mie。两者均缺乏写入后读回验证，需跨内核统一修复。

### Smctr CTR recording 上下文切换
PR-1172 揭示 Smctr 在 FreeBSD 上缺乏完整的上下文切换（含 trapframe、PCB、VMM 路径）。qemu/linux/opensbi 尚未报告同类问题，值得后续扫描关注。

### State-enable CSR 链（Smstateen/Ssstateen）
PR-1276 暴露 FreeBSD 对 state-enable CSR 链的总体性缺乏——整个 `sys/riscv/` 无 mstateen0/sstateen0 引用。影响 Zfinx+Smstateen 系统上所有 FPU 操作。建议将 stateen CSR 链列为跨 target 审计主题。
