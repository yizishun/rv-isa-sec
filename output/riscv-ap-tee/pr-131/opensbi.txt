PR #131  target=opensbi  overall=compliant
Spec: Domain context switch in sbi_domain_context.c omits medeleg/mideleg from saved/restored CSRs, allowing S-mode-delegated exceptions during TVM execution to be intercepted by the host OS/VMM instead of trapped to M-mode TSM
Violation: When OpenSBI (acting as M-mode TSM) performs a domain context switch via switch_to_next_domain_context() from the host domain to a confidential TVM domain, the hart_context structure saves/restores only S-mode CSRs (sstatus, sie, stvec, sscratch, sepc, scause, stval, sip, satp, scounteren, senvcfg, srmcfg) but does NOT save/restore medeleg or mideleg. If the host domain's medeleg delegates ECALLs to S-mode (as is normal for non-confidential execution), those delegation bits remain set during TVM execution, causing the TVM's SBI ECALLs to trap into the OS/VMM's S-mode handler instead of the TSM's M-mode handler.
Consequence: privilege_escape
Pattern: context switch CSR save/restore loop that omits medeleg/mideleg while switching between domains with different confidentiality requirements; check for hart_context struct member list and csr_swap sequences in domain context switch functions
