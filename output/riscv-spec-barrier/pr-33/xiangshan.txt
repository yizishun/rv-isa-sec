PR #33  target=xiangshan  overall=compliant
Spec: Zisb barrier semantics narrowed to in-domain only; cross-domain speculative attacks (e.g., Spectre-V2 across privilege/VM boundaries) require predictor domain-tagging that is orthogonal to barrier instruction execution — XiangShan must verify predictor structures are partitioned by privilege/VMID or cross-domain leaks remain unmitigated
Violation:
  XiangShan RTL implements Zisb barrier instructions (TEB/MDB/DPB) with
  correct stall/pipeline semantics, but branch predictor (FTQ/TAGE in
  Frontend.scala), load-store disambiguator (LoadQueueRAR.scala), and/or data-
  value predictors are NOT tagged with domain identifiers (privilege mode,
  VMID, ASID, hart ID). The revised spec explicitly scopes Zisb barriers to
  in-domain attacks only and requires cross-domain mitigation via predictor
  domain-tagging. Without domain-tagged predictors, a lower-privilege domain
  (e.g., U-mode or a different VM) can poison predictor state that influences
  speculation in a higher-privilege domain (e.g., S-mode or a different VM),
  and Zisb barriers provide no defense because they do not flush or partition
  predictor state.
Consequence: info_leak
Pattern:
  (branch_predictor|tage|ftq|predict|BTB|RAS|PHT|disambiguator|store_bypass|lo
  ad_queue|LSU).*(domain|tag|VMID|ASID|priv|part|isolat|label) NOT implemented
