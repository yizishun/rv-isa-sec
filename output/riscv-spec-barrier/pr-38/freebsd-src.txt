PR #38  target=freebsd-src  overall=potential_risk
Spec: ASID/VMID reuse without fence.hpd on RISC-V enables transient-execution predictors to leak secrets across FreeBSD process boundaries or bhyve guest VMs
Violation:
  When the FreeBSD kernel reuses an ASID (satp.ASID) during context switch or
  ASID space wrap-around without executing fence.hpd, or when bhyve reuses a
  VMID (hgatp.VMID) without executing fence.hpd, predictions learned in the
  previous protection domain (process or VM) can be used speculatively in the
  new domain, enabling cross-domain transient execution attacks.
Consequence: info_leak
Pattern:
  ASID allocation or recycling code (pmap_activate, pmap_invalidate_all, ASID
  wrap handling in sys/riscv/riscv/pmap.c) that issues sfence.vma but does not
  issue fence.hpd before reusing a previously-allocated ASID; bhyve VMID
  allocation/reuse paths (hgatp.VMID management) without fence.hpd; any satp
  write that assigns a recycled ASID without a preceding fence.hpd.
------------------------------------------------------------

[potential_risk] sys/riscv/vmm/vmm_riscv.c:620-630  vmmops_run
  hfence_gvma() at line 628 is issued before csr_write(hgatp, ...) at line
  630, which switches the G-stage (stage-2) page-table root when entering a
  different VM. The comment at lines 620-627 correctly cites the RISC-V spec
  requirement for hfence.gvma before/after hgatp writes. However, hfence.gvma
  only orders prior stores before G-stage implicit address-translation reads
  (TLB invalidation). It does NOT cover hardware page-table-walker prediction
  structures. When switching between VMs, predictions learned from VM A's page
  tables can be used speculatively for VM B's address translations before the
  TLB miss triggers an actual walk. This is a cross-VM transient execution
  info-leak path on hardware with speculative page table walks.

[potential_risk] sys/riscv/vmm/vmm_riscv.c:228-229  vmmops_vcpu_init
  hstatus is initialized as HSTATUS_SPV | HSTATUS_VTW | HSTATUS_SPVP.
  HSTATUS_VTSR (bit 22, defined at riscvreg.h:134 but unused) is NOT set. When
  VTSR=1, SRET from VS-mode traps to HS-mode, giving the hypervisor an
  intervention point to issue fence.hpd before the guest resumes execution.
  Without VTSR, SRET in VS-mode executes directly, and the hypervisor cannot
  insert fence.hpd on guest ASID switches performed via SRET+satp-write
  sequences. This is a defense-in-depth gap.
  | hypctx->guest_regs.hyp_hstatus = HSTATUS_SPV | HSTATUS_VTW;
  | hypctx->guest_regs.hyp_hstatus |= HSTATUS_SPVP;
