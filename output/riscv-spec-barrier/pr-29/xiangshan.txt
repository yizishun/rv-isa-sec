PR #29  target=xiangshan  overall=compliant
Spec: Tightened MDB spec from 'an instruction that stores' to 'the last instruction that stores' — LSQ forwarding must guarantee youngest-match selection; any bug selecting a non-last matching store lets post-MDB loads observe stale data, breaking the barrier and enabling Spectre-style data leaks past the speculation fence.
Violation:
  In XiangShan's Load-Store Queue (LSQ), when store-to-load forwarding
  searches matching stores for a load after MDB, if the age-based CAM/tag
  match logic incorrectly forwards from a non-youngest matching store (e.g.,
  due to CAM returning first hit instead of youngest hit, or due to a partial
  address match on a store that is not the last one in program order), the
  load obtains data from a store older than the 'last' store to the same
  physical address, violating the tightened MDB semantics that require
  forwarding from precisely the last preceding store.
Consequence: privilege_escape
Pattern:
  store-to-load forwarding CAM search that does not prioritize youngest/last
  matching store by program order; LSQ age comparison using stale/incomplete
  store-mask bits; load-forwarding path that selects first CAM match instead
  of walking all matches to find the most recent
