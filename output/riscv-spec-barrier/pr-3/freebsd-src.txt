PR #3  target=freebsd-src  overall=potential_risk
Spec: FreeBSD RISC-V kernel lacks Zisb speculation barriers (TEB/MDB/DPB) after all bounds checks in copyinout.S and during signal frame/trapframe manipulation in exec_machdep.c and swtch.S, enabling Spectre-v1 bounds-check-bypass and Spectre-v2 BTB-style info leaks via mispredicted branches on user-controlled inputs
Violation:
  In the FreeBSD RISC-V kernel, copyin/copyout (sys/riscv/riscv/copyinout.S)
  performs a bounds check (bgeu against VM_MAXUSER_ADDRESS) followed by user
  memory access under SSTATUS_SUM without any speculation barrier (TEB). When
  the bounds-check branch is mispredicted, the CPU can speculatively execute
  the subsequent load/store with an out-of-bounds user address or a kernel
  address, leaking kernel memory through microarchitectural side channels
  (cache timing). Additionally, sendsig() in exec_machdep.c writes user-
  controlled signal handler addresses to tf_sepc and tf_sp without MDB/DPB
  barriers, and sys_sigreturn() restores user-provided register state
  including sstatus bits without barriers, allowing speculative execution with
  attacker-influenced architectural state.
Consequence: info_leak
Pattern:
  bgeu.*VM_MAXUSER_ADDRESS|bgeu.*copyio_fault|bounds[_-
  ]?check.*\.S|sendsig.*tf_sepc|copyin.*fault.*nopcb|sigreturn|ENTER_USER_ACCE
  SS without preceding speculation barrier
------------------------------------------------------------

  The sret-based return path restores sstatus (including SUM=0) at line 131
  within load_registers before sret at line 234. The sstatus write via csrw at
  line 131 ensures SUM is cleared before the sret instruction commits, so any
  return to userspace will not retain supervisor SUM privileges. No
  speculation barrier is required at this point because SUM is architecturally
  cleared before sret; speculative execution after sret runs in user mode.
  This is architecturally correct.
