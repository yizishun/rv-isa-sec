PR #177  target=qemu  overall=not_implemented
Spec: Signed averaging subtract instructions require arithmetic (sign-extending) right shift on the full-precision intermediate difference; using logical shift or C truncating-division corrupts results for negative odd differences, causing guest-visible data corruption indistinguishable from incorrect ISA emulation
Violation:
  QEMU TCG generates a logical right shift (shri) or C division (/) instead of
  arithmetic right shift (sari) for the full-precision intermediate difference
  in signed averaging subtract instructions (PASUB.B/H/W, ASUB,
  PASUB.DB/DH/DW). The spec requires diff >> 1 with arithmetic shift toward
  negative infinity (floor rounding). A logical shift or truncating-division
  produces bit-incorrect results when the intermediate difference is negative
  and odd, because logical shift zero-fills the MSB of the intermediate
  precision width while arithmetic shift sign-extends it, and C division
  truncates toward zero instead of floor.
Consequence: data_corruption
Pattern:
  tcg_gen_shri_i64|tcg_gen_shri_i32.*pasub|gen_helper.*pasub[^u].*shr|sari.*sh
  ri.*averaging|>> 1.*signed.*packed|/ 2.*averaging
------------------------------------------------------------
[not_implemented] target/riscv/:0-0  N/A
  The P-ext packed SIMD averaging subtract instructions (PASUB.B, PASUB.H,
  PASUB.W, ASUB, PASUB.DB, PASUB.DH, PASUB.DW) are not implemented in this
  QEMU codebase. The codebase only contains RVV vector averaging subtract
  (vasub.vv/vx). No TCG translation, decode entries, or helper functions exist
  for the P-ext averaging subtract instructions, so the vulnerability
  condition (logical right shift vs arithmetic right shift in P-ext packed
  averaging subtract) cannot be assessed as present.
