PR #187  target=opensbi  overall=compliant
Spec: Saturating shift instructions set vxsat as a side effect; if M-mode OpenSBI uses them and returns to S/U mode without clearing vxsat, lower privilege modes can observe whether saturation occurred during M-mode execution, leaking information about M-mode internal data values
Violation:
  OpenSBI M-mode trap handlers or SBI call handlers use P-extension saturating
  shift instructions (PSSLAI, SSLAI, SRARI, PSSHA, PSSHAR variants) without
  saving/restoring or clearing the vxsat CSR before returning to S/U mode via
  MRET/SRET, leaking M-mode internal computation state to lower privilege
  levels
Consequence: info_leak
Pattern:
  P-extension saturating shift instruction followed by MRET/SRET without
  intervening vxsat save/restore or clear
