PR #187  target=qemu  overall=not_implemented
Spec: Saturating left-shift intermediate must be computed at >=2x element width to preserve overflow bits for correct saturation detection; native-width TCG shifts silently wrap before saturation bounds check fires
Violation:
  In QEMU TCG, when a saturating shift-left instruction (PSSLAI.H, PSSLAI.W,
  SSLAI, PSSHA.DHS, PSSHA.DWS, PSSHAR.DHS, PSSHAR.DWS, PSSLAI.DH, PSSLAI.DW)
  computes 'a << shamt' in the native element width (e.g., int16_t for
  halfword, int32_t for word) without widening the intermediate result to at
  least 2x the element width, causing silent integer overflow before the
  saturation bounds check executes. The spec requires the comparison 'result <
  -2^15' and 'result > 2^15-1' to operate on a mathematically-precise shifted
  value, but a naive TCG implementation using C-level shifts wraps around
  modulo 2^N, making overflowed values appear non-overflowing and bypassing
  saturation to produce arbitrary wraparound results. This also applies to the
  double-wide register-pair variants where the same per-element shift-saturate
  logic runs on even/odd register pairs — a single-element TCG overflow bug
  propagates to both halves.
Consequence: data_corruption
Pattern:
  tcg_gen_shl_i{32,64} or tcg_gen_sari_i{32,64} on packed element without
  prior sign extension to double-width temporary, followed by signed
  comparison against saturation bounds — the shift intermediate must be
  computed at 2× element width before truncation and saturation clamping
