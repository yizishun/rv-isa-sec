PR #249  target=qemu  overall=compliant
Spec: Spec pseudocode had copy/paste errors using signed comparisons (>_s, <_s) for unsigned saturation bounds; QEMU helpers implementing the old pseudocode would produce incorrect saturation results for values with MSB=1, corrupting guest packed SIMD computation
Violation: QEMU TCG helper for P-extension saturating shift instructions (PSSHL.HS, PSSHL.WS, PSSHLR.HS, PSSHLR.WS, SSHL) uses signed comparison (>_s / <_s) for unsigned saturation checks on the shifted result, causing values with the MSB set (e.g., 0x80000000) to be treated as negative and incorrectly saturate to signed min/max bounds instead of the unsigned max bound (0xFF...FF), or fail to saturate when the unsigned magnitude exceeds the unsigned max but the signed magnitude is within signed range
Consequence: data_corruption
Pattern: signed integer comparison against 0x7FFF... or 0x8000... in TCG helper for saturating packed shift, where the saturation target is an unsigned range; look for `>_s` or `<_s` semantics (C: `(int64_t)val > INT32_MAX` or `(int64_t)val < INT32_MIN`, or Rust-like `as i64` wrapping) where `>_u` / unsigned comparison against 0xFFFF...FFFF is required per corrected pseudocode
