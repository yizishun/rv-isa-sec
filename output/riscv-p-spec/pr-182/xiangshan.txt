PR #182  target=xiangshan  overall=compliant
Spec: 24 Min/Max packed SIMD instructions share funct3=0x6 under OP-32 (0x3b, single-register) or OP-IMM-32 (0x1b, register-pair), with funct4[0] as the sole signed/unsigned comparator select bit — a single wire inversion in the ALU control path silently corrupts all signed/unsigned distinction across byte/halfword/word element widths, and register-pair variants lack explicit even-register enforcement in hardware, risking silent register aliasing
Violation: In XiangShan RTL, when the packed SIMD ALU in the integer execution unit uses a single comparator datapath for both signed (PMIN/MAX) and unsigned (PMINU/MAXU) variants differentiated only by the funct4 field (0xc/0xe vs 0xd/0xf), if the decoder-to-ALU control signal mapping is swapped or if the comparator sign-extension logic is incorrectly gated (e.g., funct4[1] used as signed/unsigned select but wired inverted), the hardware performs the wrong comparison on elements where the MSB differs. Specifically: funct2 selects element width (0x2=B, 0x0=H, 0x1=W), funct4 selects operation (0xc=PMIN, 0xd=PMINU, 0xe=PMAX, 0xf=PMAXU), and funct4[0] controls signed-vs-unsigned comparator muxing — a single-bit decode error silently inverts the semantic for all 24 instructions. Additionally, the .DB/.DH/.DW register-pair variants use OP-IMM-32 (0x1b) with 4-bit register-pair fields `rd_p`, `rs1_p`, `rs2_p` that must address even registers only; if the hardware computes `rd_p * 2` without checking `rd_p[0] == 0`, an odd pair index silently aliases to wrong register numbers, causing operand substitution. On RV64 configs, PMIN.W/MAX.W are encoded in OP-32 but must trap as illegal on RV32; if XLEN is configurable at elaboration time and the decoder omits the RV64-only gating, these encodings execute on RV32 with undefined 64-bit slicing behavior.
Consequence: data_corruption
