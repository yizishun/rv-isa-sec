PR #239  target=qemu  overall=not_implemented
Spec: Missing SRL < RCIDLEN (strict) constraint when SSRM=1 in msdcfg WARL logic: writing SRL >= RCIDLEN causes RCID upper-bound underflow, letting supervisor access M-mode-private resource controller IDs
Violation:
  QEMU's msdcfg CSR write handler accepts SSRM=1 with SRL >= RCIDLEN (or
  SSMM=1 with SML >= MCIDLEN) without coercing to SRL < RCIDLEN, causing the
  srmcfg.RCID upper bound 2^RCIDLEN - 2^SRL - 1 to underflow to a large
  positive value in unsigned arithmetic, thereby allowing supervisor writes of
  RCID values that should be architecturally inaccessible
Consequence: privilege_escape
Pattern:
  WARL write handler for msdcfg SRL/SML does not check SSRM/SSMM-dependent
  strict-inequality bound (SRL < RCIDLEN, not SRL <= RCIDLEN) before computing
  srmcfg.RCID/MCID legal range; integer underflow risk in unsigned 2^N - 2^K -
  1 when K >= N
------------------------------------------------------------
[not_implemented] target/riscv/:0-0  N/A
  QEMU does not implement the msdcfg CSR, SSRM/SSMM fields, SRL/SML WARL
  constraints, or any supervisor domain configuration machinery. The
  vulnerability pattern — WARL write handler for msdcfg SRL/SML not checking
  SSRM/SSMM-dependent strict-inequality bound (SRL < RCIDLEN) — cannot exist
  in code that is entirely absent from the target/riscv/ directory. The srmcfg
  CSR from the related Ssqosid extension is also not implemented.
