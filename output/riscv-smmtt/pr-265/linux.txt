PR #265  target=linux  overall=compliant
Spec: Removal of invalid-SIDN behavioral guarantees (was: SEIP=0, siselect/stopei→illegal-instruction, hgeip/hgeie=0, VGEIN read-only zero) means kernel must validate msdcfg.SIDN before any domain-dependent CSR access, or risk undefined trap/state behavior
Violation:
  Kernel (HS-mode or M-mode firmware) accesses siselect, sireg, stopei, hgeip,
  hgeie, hstatus.VGEIN, or relies on mip.SEIP/m sideip behavior when
  msdcfg.SIDN may reference an unimplemented supervisor interrupt domain,
  without first validating SIDN against the implemented domain count — the
  spec no longer defines behavior for this case (previously guaranteed SEIP=0,
  illegal-instruction on access, hgeip/hgeie=0, VGEIN read-only zero).
Consequence: denial_of_service
Pattern:
  csr_(read|write)\(.*(siselect|sireg|stopei|hgeip|hgeie|msideip).*\)|msdcfg|S
  IDN
