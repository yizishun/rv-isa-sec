PR #265  target=opensbi  overall=not_implemented
Spec: PR removes explicit trapping/zeroing guarantees when msdcfg.SIDN is invalid, so unvalidated SIDN writes followed by CSR reads in OpenSBI M-mode may leak stale interrupt-domain state from other domains
Violation:
  OpenSBI writes an invalid (unimplemented) SIDN to msdcfg, then reads
  mip.SEIP, sireg, stopei, hgeip, hgeie, or hstatus.VGEIN, relying on the now-
  removed guarantee that these return 0 or trap — hardware behavior is
  UNSPECIFIED after this change
Consequence: info_leak
Pattern:
  csr_write.*msdcfg.*\n.*csr_read.*(mip|sireg|stopei|hgeip|hgeie|hstatus)
------------------------------------------------------------
[not_implemented] N/A:0-0  N/A
  OpenSBI does not implement MSDCFG/SIDN CSR handling. No csr_write to msdcfg
  exists in the codebase, and none of the dependent CSRs (sireg, stopei,
  hgeip, hgeie, hstatus) are read after any msdcfg write. The MSDCFG CSR is
  not even defined in include/sbi/riscv_encoding.h. The vulnerability pattern
  (write invalid SIDN to msdcfg, then read affected CSRs relying on the
  removed zero/trap guarantee) cannot occur.
  | // No MSDCFG/SIDN-related code found in the OpenSBI source tree
