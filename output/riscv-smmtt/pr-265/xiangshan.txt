PR #265  target=xiangshan  overall=bug_confirmed
Spec: PR removes mandatory trap-and-zero behavior for invalid msdcfg.SIDN, making hardware-level SIDN bounds-checking critical: missing comparators allow out-of-bounds array indexing into per-domain hgeip/hgeie/IMSIC register state, leaking stale internal state or corrupting adjacent memory
Violation:
  When msdcfg.SIDN holds a value that does not correspond to an implemented
  supervisor interrupt domain, the XiangShan RTL accesses internal per-domain
  register arrays (hgeip/hgeie array, IMSIC interrupt file register file)
  using SIDN as an unchecked index. The PR removes the previously mandatory
  trap-on-invalid-SIDN behavior (illegal instruction on siselect/sireg/stopei
  access, read-only zero on hgeip/hgeie/hstatus.vgein, SEIP=0), making the
  invalid-SIDN behavior UNSPECIFIED. If the hardware does not implement
  bounds-checking comparators on SIDN before using it to index internal state
  arrays, out-of-bounds reads return uninitialized or stale register state,
  and out-of-bounds writes corrupt memory adjacent to the array.
Consequence: info_leak
Pattern:
  msdcfg.SIDN used as array index without bounds check; SIDN >=
  NUM_SUPERVISOR_DOMAINS not gated before hgeip/hgeie internal array access;
  siselect/sireg CSR access path missing SIDN validity check; stopei CSR read
  path missing SIDN validity gate; IMSIC interrupt file address computation
  using SIDN without saturation/clamping
