PR #265  target=freebsd-src  overall=potential_risk
Spec: Spec removes well-defined fail-safe behavior for invalid msdcfg.SIDN—SEIP suppression and IMSIC-access traps are no longer guaranteed, shifting all SIDN-validation burden onto software and creating info-leak/undefined-behavior risk during context switch on implementations where invalid SIDN does not trap
Violation:
  FreeBSD kernel (or bhyve) writes an unimplemented supervisor interrupt
  domain number into msdcfg.SIDN during context switch or domain selection.
  Under the old spec text, this invalid SIDN guaranteed well-defined fail-safe
  behavior (mip.SEIP=0, siselect/sireg raise illegal-instruction exceptions,
  stopei raises illegal-instruction exception, hgeip/hgeie read-only 0,
  msideip still visible for monitoring). Under the updated spec, these rules
  are deleted, making behavior UNSPECIFIED: hardware may spuriously assert
  SEIP, leak stale interrupt-pending state through siselect, or expose guest
  interrupt file state rather than trapping.
Consequence: info_leak
Pattern:
  write to msdcfg CSR without prior validation that SIDN field value ≤ maximum
  implemented supervisor interrupt domain number; context-switch save/restore
  of msdcfg that does not sanitize SIDN on restore path; RDSM/hypervisor
  emulation code relying on deleted illegal-instruction-trap guarantee for
  invalid-SIDN siselect/sireg/stopei access to intercept and emulate
------------------------------------------------------------
