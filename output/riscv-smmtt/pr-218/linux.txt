PR #218  target=linux  overall=not_implemented
Spec: RDSM failure to context-switch msdcfg.SEDA/SETA causes cross-domain info leak via inherited external debug/trace permissions; kernel has no visibility into msdcfg and implicitly trusts RDSM correctness
Violation:
  The Linux kernel (running as a supervisor domain) implicitly trusts that the
  RDSM correctly saves and restores msdcfg.SEDA/SETA across domain context
  switches. If the RDSM violates the normative requirement to 'preserve and
  restore this configuration state across context switches using secure
  memory,' one supervisor domain inherits another domain's SEDA/SETA
  permissions. The kernel has no mechanism to detect or mitigate this—it
  cannot read back msdcfg to verify, and external debug/trace is transparent
  to software.
Consequence: info_leak
Pattern:
  msdcfg|SEDA|SETA|smsdedbga|smsdetrca|external.debug|external.trace
