PR #219  target=linux  overall=not_implemented
Spec: MPT permission checks ignore mstatus.MXR and HLVX overrides; kernel MXR-based uaccess paths will fault on execute-only MPT entries where they would succeed under standard page-table MXR semantics, and KVM HLVX instruction emulation cannot bypass MPT execute-only restrictions.
Violation:
  Linux kernel sets mstatus.MXR to make execute-only pages readable for user-
  memory access (copy_from_user/copy_to_user), but the MPT entry grants only X
  permission without R; the access faults unexpectedly because MXR does not
  override MPT permission interpretation — only the raw XWR bits in the leaf
  MPTE determine access, and MXR is explicitly excluded from MPT permission
  checks per step 7 sub-bullet.
Consequence: denial_of_service
Pattern:
  mstatus.*MXR|MXR.*mstatus|__enable_mxr|set_mxr|csr_set.*MXR|STATUS_MXR
------------------------------------------------------------
[not_implemented] arch/riscv/include/asm/csr.h:13-65  N/A (header definitions)
  Linux RISC-V does not define SR_MXR (bit 19, 0x00080000) anywhere in its CSR
  header. The only related bit defined is SR_SUM (bit 18, 0x00040000), which
  is used instead for supervisor user-memory access. No __enable_mxr(),
  set_mxr(), or any MXR manipulation code exists in arch/riscv/. The claimed
  vulnerability pattern — Linux setting mstatus.MXR for
  copy_from_user/copy_to_user — does not exist in this kernel.

[compliant] arch/riscv/lib/uaccess.S:30-38  N/A (user access assembly)
  Linux RISC-V uses SR_SUM (bit 18), not MXR (bit 19), to enable supervisor
  access to user pages during copy_from_user/copy_to_user. The SUM mechanism
  is the correct RISC-V mechanism for this purpose. SUM allows S-mode to
  access U-mode pages; MXR is a different mechanism that makes execute-only
  pages readable. The two bits serve different purposes and Linux correctly
  uses SUM, not MXR, for user-memory access.

  | csrs CSR_STATUS, t6
