PR #863  target=linux  overall=compliant
Spec: Svucrg redefines three independent PTE bits (CRW/CRG/CD) into a single 3-bit encoded CRW field with inverted CD polarity at CRW[1]; kernel code using pre-existing per-bit macros will silently corrupt capability dirty/generation state, breaking user-mode capability revocation and enabling tagged capability stores to pages the kernel believes are clean
Violation: Linux kernel PTE manipulation code treats bits [58:56] as three independent fields (CRW, CRG, CD) instead of a single 3-bit encoded CRW field whose logical CD/CRG are derived from the encoding. Specifically, old code that reads bit 57 (old CD position) directly as the Capability Dirty indicator will observe an INVERTED value under the new encoding — 0b100 means CD=1 but bit 57 is 0, while 0b110 means CD=0 but bit 57 is 1 — causing the kernel to incorrectly skip or trigger revocation sweeps, mis-handle COW break, or corrupt PTE state during context switch / migration / KVM stage-2 translation.
Consequence: data_corruption
Pattern: PTE bitwise mask/shift on bits 56, 57, or 58 treating them as separate _PAGE_CRW, _PAGE_CRG, _PAGE_CD macros rather than a combined _PAGE_CRW_FIELD[2:0] with encoding-table lookup
