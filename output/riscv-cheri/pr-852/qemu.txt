PR #852  target=qemu  overall=compliant
Spec: If QEMU exposes capability encoding CSRs (uycfg/sycfg/vsycfg/mycfg) unconditionally as part of base CHERI rather than gating them behind cheri_xycfg_csr, guest software can discover implementation-specific CHERI encoding details that the spec now defers to a future discovery mechanism — leaking microarchitectural capability format information.
Violation: QEMU unconditionally instantiates and exposes uycfg/sycfg/vsycfg/mycfg CSRs as part of base CHERI emulation without the cheri_xycfg_csr extension flag. Guest CSR reads to these addresses return capability encoding version/format data, and guest CSR writes succeed (or return WARL values), when the updated spec gates these CSRs behind an undefined conditional whose discovery mechanism is explicitly postponed — meaning these CSRs should generate illegal instruction traps on access in a base CHERI implementation.
Consequence: info_leak
Pattern: cheri_xycfg_csr|Xycfg|uycfg|sycfg|vsycfg|mycfg|CHERI_CAP_ENCODING
