PR #860  target=linux  overall=potential_risk
Spec: CHERI v1 ratification now includes V extension with the invariant that vector memory accesses using x0 as base are reserved/illegal, because the nulla capability cannot authoritatively cover all of addressable memory; the kernel must trap these encodings as illegal instructions rather than executing or emulating them, or user space bypasses capability-based memory access control
Violation: Under CHERI-capable RISC-V, the kernel allows execution (or emulates) vector load/store instructions whose base register is x0, when the spec reserves those encodings as illegal
Consequence: privilege_escape
Pattern: vector.*x0.*base|base.*x0.*vector|cheri.*vector.*reserved|vsetvli|vle|vse|vlse|vsse|lut4o16i4.*cheri
