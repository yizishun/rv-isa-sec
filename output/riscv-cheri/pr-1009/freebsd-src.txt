PR #1009  target=freebsd-src  overall=compliant
Spec: FreeBSD's context-switch and signal-delivery paths perform capability loads through kernel-internal authorizing capabilities; if any such authorizing capability lacks LM permission, restored user capabilities silently lose write permission, enabling privilege downgrade attacks where a process wakes up with unexpectedly read-only data capabilities after a context switch or signal return.
Violation: In the FreeBSD kernel, a capability load instruction (e.g., CLC) executes with an authorizing capability that grants R and C permissions but lacks LM permission, and the loaded value is a valid tagged unsealed capability — the hardware will clear W and LM permissions in the destination register. This occurs during context-switch restore (loading saved user capabilities from the PCB via a kernel-internal authorizing capability), signal frame construction (copying capability arguments to the user stack through a restricted DDC), or copyin/copyout paths where the kernel source capability for a user buffer inadvertently lacks LM permission.
Consequence: privilege_escape
Pattern: cheri_cap_load.*(lm_perm|LM_PERM|LoadMutable|CHERI_PERM_LOAD_MUTABLE).*|CL[CWSD].*authorizing.*(without|missing|lacking).*(lm|w_perm)|capability.*restore.*(w_perm|write.*perm).*stripped|context.*switch.*cap.*load.*permission.*clear
