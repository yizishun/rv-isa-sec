PR #1009  target=qemu  overall=compliant
Spec: Capability load LM/W permission stripping must gate on the written-back (post-authorization) tag, not the memory tag; using the pre-authorization tag can cause permission stripping on already-invalidated capabilities, diverging from hardware behavior
Violation: In QEMU TCG, when emulating a CHERI capability load (e.g., CLC) through an authorizing capability that grants R and C but lacks LM, the emulator checks the capability tag read FROM MEMORY (or the pre-authorization tag) to decide whether to strip W and LM, rather than checking the tag of the finalized capability being WRITTEN INTO THE DESTINATION REGISTER after bounds/authority checks have completed. If authorization clears the tag (e.g., bounds violation, representability failure), a QEMU implementation checking the memory tag would strip W/LM from a now-untagged value, whereas hardware would skip stripping because the written-back tag is 0.
Consequence: data_corruption
Pattern: tag check on source/memory tag instead of destination/writeback tag before LM/W permission stripping in capability load emulation (e.g., if (mem_ctag) vs if (result_ctag) before clearing CAP_PERM_WRITE | CAP_PERM_LOAD_MUTABLE)
