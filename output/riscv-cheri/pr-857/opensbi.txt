PR #857  target=opensbi  overall=compliant
Spec: Multi-encoding-format CHERI capability spec requires OpenSBI to query uycfg and adapt save/restore/validation to the active encoding format; hardcoding field offsets from any single encoding silently corrupts capability tags, bounds, and permissions across privilege boundaries.
Violation: OpenSBI saves/restores or inspects CHERI capability state (during context switch, HSM suspend/resume, or SBI call handler) using hardcoded field positions from the old default encoding instead of first reading uycfg CSR to determine the active capability encoding format and applying format-specific decode/validate/encode logic, causing capability metadata corruption when the hardware uses an encoding format other than the one OpenSBI assumes.
Consequence: privilege_escape
Pattern: uycfg|capability encoding format|save.*cap|restore.*cap|context.*switch.*cap|capability.*metadata|cap.*bounds|cap.*permissions|malformed.*cap|cap.*integrity
