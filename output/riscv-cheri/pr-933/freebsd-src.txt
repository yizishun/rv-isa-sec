PR #933  target=freebsd-src  overall=potential_risk
Spec: PR #933 replaces single-bit pte.crw with a 4-bit pte.rvy field and renames sstatus.CRGE/UCRG to sstatus.RGE/SRG/URG, adding a supervisor read-generation bit; any FreeBSD RISC-V CHERI port must context-switch the new 3-bit sstatus sub-fields correctly and construct the 4-bit PTE field per the default (Y=bit58 only, bits 57:55 reserved) versus Svyrg-enabled (full 4-bit) semantics to avoid cross-process capability generation state leaks and spurious page faults.
Violation: On a hypothetical CHERI-RISC-V FreeBSD port, if the kernel context-switch path (cpu_switch/cpu_throw in sys/riscv/riscv/swtch.S or the trap handler in exception.S) saves and restores only the existing sstatus fields without awareness of the new 3-bit sstatus sub-fields (RGE, SRG, URG) mandated by Svyrg, then one process's supervisor/user capability read generation and enable state could leak into another process's execution context. Additionally, if the pmap layer constructs PTEs with bits 58:55 set without the Svyrg enable bit (sstatus.RGE) being active, or sets bits 58:56 to non-zero values when only bit 58 (Y) is defined by the base RVY PTE format, a page-fault will be raised where normal capability access was intended.
Consequence: info_leak
