PR #870  target=linux  overall=compliant
Spec: SCBNDSRD provides a round-down bound-setting primitive critical for safe cross-domain capability delegation; the kernel must ensure that when it constructs capabilities on behalf of or for delivery to user space, it does not inadvertently use round-up semantics that could grant access to memory beyond the intended authorization scope.
Violation: In the Linux kernel, when kernel code (e.g., signal frame setup, ptrace capability writes, or KVM capability emulation) constructs or modifies a user-visible capability bound using SCBNDSR (round-up) semantics instead of SCBNDSRD (round-down) semantics for cross-trust-domain buffer sharing, the representability rounding may silently extend the effective bounds beyond the kernel-intended authorization boundary, granting the recipient access to memory the kernel did not intend to expose.
Consequence: info_leak
Pattern: kernel capability bound construction that does not verify representability rounding direction (round-up vs round-down) before exposing a capability to a less-privileged subject; grep for CHERI capability bound-setting in signal delivery (sigframe capability setup), ptrace capability write paths, and KVM capability register emulation; any manual bound computation that mimics SCBNDS/SCBNDSR without considering the safer SCBNDSRD round-down alternative when the capability crosses a trust boundary.
