PR #996  target=freebsd-src  overall=potential_risk
Spec: PR #996 removes the sstatus enable bit that previously gated the PTE Y-field capability-flow-control behavior, making Svyrg semantics the architectural default — FreeBSD's pmap layer must unconditionally preserve and manage the 4-bit Y-field (yr/yw/yd/ys) in all RV64 PTE formats, and the kernel's exception handlers must always recognize capability-load-fault and capability-dirty-store-fault cause values regardless of sstatus configuration, or else capability revocation tracking state will be silently corrupted on context switch and page table updates.
Violation: In the FreeBSD kernel, if pmap code (e.g., pmap_enter, pmap_remove, pmap_protect in sys/riscv/riscv/pmap.c) clears, ignores, or unconditionally overwrites the PTE Y-field bits (yr, yw, yd, ys) during page table manipulation — for example, when recycling PTEs, constructing new mappings, or performing demotion/promotion of superpages — without preserving or explicitly initializing these 4 capability-flow-control bits, the kernel silently destroys the hardware-managed capability dirty/read tracking state required by Svyrg semantics.
Consequence: privilege_escape
Pattern: PTE_SET\b|PTE_CLEAR\b|pte_store|pmap_store_pte|pmap_clear_pte|pmap_invalidate_page|pmap_kremove|pmap_qremove|\byr\b|\byw\b|\byd\b|\bys\b|PTE_Y_MASK|Y_FIELD|capability.*PTE|PTE.*capability
