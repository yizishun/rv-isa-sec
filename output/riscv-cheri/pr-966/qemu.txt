PR #966  target=qemu  overall=compliant
Spec: CHERI ASR permission scope clarified: MRET/SRET/DRET and all privileged/debug CSR access now require ASR in PCC — missing checks in QEMU TCG translate/helper code allows capability-sandboxed guest to escalate privilege or corrupt privileged state
Violation: QEMU emulates CHERI but fails to check ASR permission in PCC before executing MRET/SRET/DRET or allowing access to privileged/debug CSRs. The spec now explicitly requires ASR in PCC for: (a) MRET_CHERI, SRET_CHERI, DRET_CHERI execution, (b) all privileged CSR read/write access, (c) debug CSR access, (d) CBO_INVAL_CHERI execution. Omitting any of these checks means capability-restricted (sandboxed) guest code can escape its authority boundary by manipulating privileged state or executing xRET to escalate to a higher privilege level.
Consequence: privilege_escape
Pattern: MRET|SRET|DRET CSR_RW check_asr_pcc|ASR_PERM privileged_csr_access debug_csr_access helper_mret helper_sret csrrw csrrs csrrc riscv_csrrw
