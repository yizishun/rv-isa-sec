PR #902  target=linux  overall=compliant
Spec: Jumps in CHERI hybrid mode are no longer PCC-authorized — kernel CFI assumptions that jumps will fault on PCC violation are now invalid, creating a control-flow integrity gap where out-of-bounds jumps silently succeed.
Violation: Kernel code running in CHERI hybrid mode relies on PCC bounds/permissions to trap on out-of-bounds or unauthorized jump targets (e.g., expecting a CHERI fault on JALR to an address outside PCC bounds), but jumps no longer fault per the updated spec.
Consequence: privilege_escape
Pattern: assumes PCC-authorised jumps in hybrid mode|relies on jump CHERI fault in hybrid|PCC bounds check on JALR hybrid
------------------------------------------------------------
[compliant] arch/riscv/:0-0  N/A
  The arch/riscv/ directory contains zero CHERI ISA support code. No CHERI hybrid mode, no PCC (Program Counter Capability) references, no purecap mode, no capability-based jump authorization, and no CHERI-specific Kconfig options exist anywhere in the RISC-V architecture code. The vulnerability pattern ('assumes PCC-authorised jumps in hybrid mode', 'relies on jump CHERI fault in hybrid', 'PCC bounds check on JALR hybrid') has no target code to exploit. CHERI exists only in arch/arm64/ as Morello support (Documentation/devicetree/bindings/arm/arm,morello.yaml, arch/arm64/boot/dts/arm/morello-*.dts), which is a different architecture. The spec at riscv-cheri/src/cheri/riscv-hybrid-integration.adoc:16-17 and riscv-cheri/src/cheri/insns/jalr_32bit.adoc:24-35 documents PCC-based JALR authorization in hybrid mode, but the Linux RISC-V port has not yet implemented CHERI support to be affected by the spec change removing PCC bounds checks on jumps.
