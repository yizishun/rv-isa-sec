PR #998  target=qemu  overall=compliant
Spec: GCTOP promoted from optional Zytopr extension into base CHERI: QEMU must decode GCTOP whenever CHERI base is enabled, else guests that rely on the always-available GCTOP (with no spec-defined software fallback) will trap and crash
Violation: QEMU's TCG decoder or CHERI capability emulation gates GCTOP instruction availability on a Zytopr extension flag, when the spec now promotes GCTOP into the base CHERI extension — meaning it must be unconditionally available whenever CHERI is enabled. If QEMU raises an illegal instruction exception for GCTOP on a CHERI machine that lacks the Zytopr flag in misa/isa string, the emulation violates the spec.
Consequence: denial_of_service
Pattern: GCTOP decode guarded by Zytopr extension check instead of base CHERI capability check; trans_gctop or gen_helper_gctop wrapped in #ifdef TARGET_CHERI_ZYTOPR rather than TARGET_CHERI; isa_ext_cheri_zytopr flag used as decode gate for GCTOP in decode_opcode or cheri.decode; CHERI CSR or capability meta-operations referencing gctop_valid or has_zytopr boolean
