Spec: GCTOP promoted from optional Zytopr to mandatory base; any kernel fallback computing top = base + len may produce a different bound than the architectural GCTOP, enabling capability-bounds bypass where the software-enforced window is wider than the hardware capability's true top
Violation: Linux kernel CHERI capability bounds-enforcement code computes the top bound via software (saturating_add(GCBASE(c), GCLEN(c))) as the old fallback path for implementations without Zytopr, and that software-computed top differs from the architectural GCTOP(c) result now guaranteed by the base ISA. This causes the kernel to enforce a bounds window that does not match the hardware capability's true architectural top.
Consequence: privilege_escape
Pattern: saturating.*add.*(GCBASE|gcbase|GCLEN|gclen)|base.*\+.*len.*top|top.*=.*base.*\+.*len|if.*!.*Zytopr|if.*!.*has_cap.*GCTOP
