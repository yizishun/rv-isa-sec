PR #868  target=qemu  overall=compliant
Spec: Stored capability `top` field desynchronization: if capability-mutating operations update `base`/`length` without correctly updating the precomputed `top`, YTOPR returns a stale top value inconsistent with the saturating base+length used elsewhere, breaking guest memory-safety invariants
Violation: QEMU's capability representation stores `top` as a precomputed field that can diverge from `base + length` (saturating). When a capability modification operation (e.g., CSetBounds, CSetAddr) updates `base` and/or `length` but fails to recompute or incorrectly recomputes the stored `top` field, the YTOPR instruction returns a different value than the architecturally-equivalent saturating-add sequence of GCBASE + GCLEN. This violates the normative equivalence stated in the spec.
Consequence: data_corruption
Pattern: static inline target_ulong get_cap_top\b|helper_.*ytopr|case 0xXXXX:.*YTOPR|decode.*funct5.*00100|funct7.*0001000|top = base \+ len|cap_top_update
