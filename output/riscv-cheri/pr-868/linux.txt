PR #868  target=linux  overall=compliant
Spec: Kernel that computes capability top as base+len (instead of using GCTOP) may enforce incorrect bounds if the hardware's decoded top diverges from the software computation, allowing userspace to bypass CHERI capability bounds checks.
Violation: Kernel code computes a capability's top bound as saturating_add(GCBASE(cap), GCLEN(cap)) for access-control or bounds-enforcement decisions instead of using the GCTOP instruction, and the hardware's actual decoded top diverges from that software computation due to representable-format edge cases, saturation semantics mismatch, or future capability encoding changes.
Consequence: privilege_escape
Pattern: saturating.*add.*(GCBASE|CGetBase|YBASER).*(GCLEN|CGetLen|YLENER)|top\s*=\s*(base|GCBASE|csr_base).*\+.*(len|GCLEN|csr_len)|(((base)|(csr_base))\s*\+\s*((len)|(csr_len)))
