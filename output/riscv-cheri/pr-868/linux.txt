PR #868  target=linux  overall=compliant
Spec: GCTOP replaces the saturating-add top computation; kernel must use exactly one method per capability instance or risk divergent bounds that let a sandboxed compartment access memory beyond its intended top.
Violation: Linux kernel capability-bounds validation code computes the top bound via saturating GCBASE+GCLEN addition on hardware that implements Zytopr, or vice versa uses GCTOP on hardware lacking Zytopr, causing two code paths to derive inconsistent top values for the same capability when the capability's architectural length exceeds XLEN bits (GCLEN saturates to XLEN, so the software-calculated top underflows).
Consequence: privilege_escape
Pattern: saturating.*GCBASE.*GCLEN|GCBASE.*\+.*GCLEN|top.*=.*base.*\+.*len|ytopr|GCTOP|alternative.*Zytopr|riscv_has_extension.*Zytopr
