PR #943  target=qemu  overall=compliant
Spec: CHERI integrity checks must apply to both valid and invalid capabilities with tag set; skipping checks on invalid capabilities allows subtly corrupted capability metadata (e.g., illegally encoded permissions from CLRPERM on an invalid cap) to go undetected, which instructions like ybld/ymoder/ymodew would then operate on, undermining the security invariant that any tagged capability failing integrity represents host-detected state corruption or faulty CHERI IP.
Violation: QEMU gates capability integrity checks (e.g., reserved field validation, legal permission encoding asserts) on the capability being valid, thereby skipping integrity checks for invalid-but-tagged capabilities. This violates the clarified spec because instructions such as ybld, ymoder, and ymodew rely on integrity checks of *invalid* capabilities with ctag set. In QEMU TCG, this would manifest as a translator helper or cap_check() routine that returns early or short-circuits when cap_is_valid(cap) returns false, without also verifying that reserved metadata bits/fields contain no illegal encodings.
Consequence: privilege_escape
Pattern: if (cap_tag && !integrity_check_on_invalid_cap)
