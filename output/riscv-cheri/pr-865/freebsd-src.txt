PR #865  target=freebsd-src  overall=compliant
Spec: FreeBSD pmap must correctly program PTE tag-clearing bits for shared pages and user-kernel boundary mappings; this PR makes platform-defined load-tag-clearing explicitly normative, so any kernel assumption that loaded tags always equal stored tags is a security violation at every cross-domain capability transfer point
Violation: FreeBSD kernel code loads a capability through an MMU mapping or PMA region where platform-defined tag-clearing is active (e.g., a PTE configured to strip tags for cross-address-space data sharing, an MMIO PMA that cannot store tags, or a CHERIoT-style load filter), but the kernel does not account for the cleared tag and either dereferences the now-untagged capability without checking, or relies on its authority to enforce a security boundary. Concretely: (1) pmap enters a PTE with tag-clearing semantics intended to deanthropomorphize capabilities on shared pages between VMs, but the PTE bits are misprogrammed, allowing full tagged capabilities to transit; (2) copyin/copyout paths depend on tag-clearing mappings to strip authority from user capabilities entering kernel space, but the underlying pmap entry incorrectly preserves tags; (3) sigreturn restores capability register frames from user-controlled memory through a mapping that unexpectedly preserves tags, giving userspace the ability to inject tagged capabilities into the kernel or a different privilege context; (4) bhyve capability load/store emulation virtualizes tag-clearing behavior inconsistently with hardware, causing guest kernels to load tagged capabilities they should not possess.
Consequence: privilege_escape
Pattern: LOAD_CAP or capability load through PTE where HW tag-clearing is assumed by kernel security policy but not enforced in page table entry or PMA configuration
