PR #865  target=linux  overall=compliant
Spec: Tag-preservation-on-load is no longer guaranteed: platform PMAs, MMU PTE tag-clear bits, and load filters can silently strip capability tags during load, so kernel code paths (context switch, KVM, ptrace, signal delivery) that store-then-reload capabilities across VM boundaries or after PTE changes must explicitly re-derive or re-validate tags rather than assuming round-trip fidelity
Violation: Linux kernel code loads a capability from memory and uses its tag for authorization or control flow without first re-validating the tag, when the load source may be subject to platform tag-clearing (non-CHERI PMA regions, MMU mappings configured to strip tags, or capability load filters). Additionally, any kernel code that saves a tagged capability to memory and later reloads it under a different virtual mapping or after PTE modification, implicitly assuming tag preservation, violates this spec.
Consequence: privilege_escape
Pattern: CL[BHWD]\s+(c|ca|cd)\d+.*\n.*(?:beqz|beq.*x0|CAnd|cand)\s+\1.*tag|ld\s+c[ad]\d+.*(?:jal|call|jr|jalr).*\1|sc\.[bwd].*c[ad]\d+.*\n.*ld\.[bwd].*\1.*\n.*(?:jalr|jr)\s+\1
