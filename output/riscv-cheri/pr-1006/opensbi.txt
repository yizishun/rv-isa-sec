PR #1006  target=opensbi  overall=compliant
Spec: If OpenSBI trap handlers access mepc as XLEN instead of YLEN on CHERI hardware, the P-bit in mepc_y is corrupted, causing MRET to resume S-mode in wrong CHERI Execution Mode—bypassing capability bounds enforcement
Violation: OpenSBI saves/restores mepc_y during trap handling using XLEN-width CSR instructions (standard CSRRW/CSRRS/CSRRC) while the hart is in CHERI Capability Mode, causing the P-bit and capability metadata (tag, bounds, permissions) in the upper YLEN-XLEN bits to be silently lost or zeroed when the CSR is written back via SCADDR address reconstruction semantics.
Consequence: privilege_escape
Pattern: csr[rw|rs|rc].*mepc|SBI_SAVE_CSR.*mepc|SBI_RESTORE_CSR.*mepc|CSRW.*MEPC|CSRS.*MEPC|CSRC.*MEPC
