Spec: Variable-length ide_stream_desc with Num_Addr_Assoc count field read from S-mode shared memory: M-mode firmware must validate against HW capability register before iterating, or risk out-of-bounds read leaking cross-domain data
Violation: OpenSBI's CoVE-IO ecall handler for sbi_covh_connect_device(FID #1024) or sbi_covt_program_rp_ide_stream(FID #1029) reads the Num_Addr_Assoc field from the S-mode-provided ide_stream_desc shared-memory buffer, then iterates over Num_Addr_Assoc * 12 bytes of address-association blocks without first: (1) validating Num_Addr_Assoc against the device's PCIe Selective IDE Stream Capability Register, and (2) bounding the total structure size against the shared-memory region the buffer resides in.
Consequence: info_leak
Pattern: M-mode firmware reads length/count field from untrusted S-mode shared buffer and uses it as loop bound for subsequent loads from the same buffer without hardware-backed upper-bound validation
