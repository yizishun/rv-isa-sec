PR #181  target=opensbi  overall=compliant
Spec: Missing _hi == 0 validation on RV64 in CoVE-IO SBI handlers lets S-mode forge physical addresses outside the valid address space, bypassing PMP/ePMP and allowing read/write of M-mode firmware memory
Violation: OpenSBI M-mode SBI handler for any CoVE-IO function receives a call where _hi is non-zero on RV64 but fails to reject with SBI_ERR_INVALID_PARAM before reconstructing the full physical address from (_hi << 64 | _lo). An S-mode attacker sets _hi to a small value targeting M-mode memory (e.g., 0x8 pointing past the PMP-protected DRAM region into OpenSBI's own code/data). The reconstructed address escapes PMP/ePMP checks that only operate on the lower XLEN bits.
Consequence: privilege_escape
Pattern: if.*!sbi_cov[ght]_.*_hi.*\breturn SBI_ERR_INVALID_PARAM\b
------------------------------------------------------------
[compliant] N/A:0-0  N/A
  No CoVE-IO ecall handler exists in this version of OpenSBI. The vulnerability pattern (non-zero _hi on RV64 not rejected before address reconstruction) cannot manifest because there is no CoVE-IO handler to receive such a call. The _hi/_lo splitting pattern in the codebase is used exclusively by unrelated SBI extensions (MPXY, DBTR, PMU, SSE) that have their own independent validation.
  | No CoVE-IO code present in the repository.
