[potential_risk] lib/sbi/sbi_domain_context.c:116-128  switch_to_next_domain_context
  Domain context switch performs PMP reconfiguration (lines 127-128: unconfigure then configure) after updating domain assignment hartmasks but before swapping S-mode CSRs. The PMP unconfigure/configure window is brief and runs entirely in M-mode on the same hart, so no concurrent M-mode access from other harts can exploit it. However, if the platform's PMP unconfigure step leaves entries in a permissive state before the configure step programs the new domain's entries, there is a transient window where PMP restrictions are relaxed. This is mitigated by the fact that the hart is in M-mode (not S/U) during this window, so no lower-privilege code can execute. Risk is low but inherent to the two-step PMP switch design.
  | /* Reconfigure PMP settings for the new domain */
  |         sbi_hart_protection_unconfigure(scratch);
  |         sbi_hart_protection_configure(scratch);
