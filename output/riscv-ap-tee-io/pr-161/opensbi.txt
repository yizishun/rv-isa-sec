PR #161  target=opensbi  overall=compliant
Spec: PR renames SBI parameters to clarify they are shared-memory addresses (e.g., key_desc → key_desc_addr); M-mode OpenSBI must copy-and-validate these structures before use to prevent S-mode from TOCTOU-modifying security-critical fields after validation
Violation: OpenSBI M-mode SBI handler dereferences a pointer parameter (e.g., key_desc_addr, ide_stream_desc_addr, data_out_addr) received from S-mode without: (a) validating the address is 4KB-aligned per spec, (b) verifying the memory range falls within a permitted shared-memory region, and (c) copying the structure into a private M-mode buffer before validating its contents to prevent TOCTOU races with S-mode concurrently modifying the data between check and use.
Consequence: privilege_escape
Pattern: SBI handler reads unsigned long argument as a pointer and dereferences it directly into M-mode CSR writes or PMP/ePMP configuration decisions without first copying and validating the structure in a private M-mode buffer
