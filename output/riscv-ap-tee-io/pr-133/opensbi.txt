PR #133  target=opensbi  overall=compliant
Spec: Missing fence between M-mode writes to host-shared transcript buffer and mret to S-mode allows host to observe stale/incomplete SPDM connection data, breaking TVM device trust verification
Violation: In OpenSBI's implementation of sbi_covh_connect_device(), the TSM writes the device connection transcript (containing SPDM certificate chains and measurements) to a host-provided shared memory buffer at connection_data_addr_out, then returns to S-mode via mret without first executing a fence (e.g., fence w,w or fence ow,ow) to ensure the memory writes are globally visible before the untrusted host reads them. Similarly, in sbi_covh_get_device_connection_transcript(), the TSM reads host-provided transcript data from shared memory and computes a digest for integrity verification against an internal map without a fence r,r after the read, potentially comparing against stale cached data.
Consequence: data_corruption
Pattern: SBI handler writes to or reads from caller-provided shared memory (addr_out/addr_in parameter from S-mode) followed by mret or digest comparison without an intervening fence instruction; specifically, sbi_covh_connect_device or sbi_covh_get_device_connection_transcript handlers that dereference unsigned long address parameters from the untrusted host without fence + PMP bounds check
