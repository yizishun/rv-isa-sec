Spec: ABI break: IOMMU registration and MSI notification SBI calls removed with FID renumbering — kernel using stale FIDs against updated TSM silently invokes wrong functions, enabling untrusted host to corrupt PCIe root-port or device-binding state
Violation: Linux kernel SBI CoVE-IO host driver calls the removed FID 1024 (was sbi_covh_register_iommu) or FID 1025 (was sbi_covh_notify_iommu_msi) against a TSM implementing the updated spec, where those FIDs now map to register_rp and connect_device respectively — causing the kernel to invoke a semantically different SBI function with misaligned parameter semantics (e.g., IOMMU MSI config array reinterpreted as PCIe root port parameters).
Consequence: privilege_escape
Pattern: SBI_EXT_COVH.*(1024|1025)|sbi_covh_register_iommu|sbi_covh_notify_iommu_msi|EID.*0x434F5648.*FID.*102[45]
