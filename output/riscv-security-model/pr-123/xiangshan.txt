PR #123  target=xiangshan  overall=compliant
Spec: SR_WOR_004 mandates mwid CSR lock at earliest boot stage with hardware-enforced immutability; failure to gate CSR writes after lock assertion enables post-boot world ID mutation, breaking all downstream world-ID-based isolation (IOPMP integration SR_WOR_003) and privilege-boundary enforcement (SR_WOR_005/006/007), resulting in privilege escape via spoofed bus transaction World ID
Violation:
  In XiangShan RTL, the mwid CSR (Machine World ID) lock bit is implemented as
  a W1S (write-1-to-set) register field. If the hardware allows any subsequent
  write to clear or modify the mwid value after the lock bit is set — through
  omission of lock-gating in the CSR write datapath, failure to suppress
  writes when mwid_lock is asserted, or a speculative CSR write bypassing the
  lock check during pipeline replay — then the mwid value becomes mutable
  post-boot, directly violating SR_WOR_004's requirement that mwid be locked
  at the earliest boot stage and remain immutable thereafter. Additionally, in
  the XiangShan system bus interface (e.g., L2Cache/L3 cache TileLink
  channels), if the World ID field in outgoing bus transactions (TileLink
  `uuid` or equivalent user-defined channel) is sourced from a CSR read
  datapath that is not synchronized/flushed after mwid write before the lock
  takes effect, a transient incorrect World ID may propagate onto the fabric,
  allowing bus transactions to carry a stale or attacker-controlled World ID
  and bypass IOPMP or Worlds-compatible checker access control (SR_WOR_003).
Consequence: privilege_escape
