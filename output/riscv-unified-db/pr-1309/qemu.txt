PR #1309  target=qemu  overall=compliant
Spec: Vector instruction emulation must iterate exactly CSR[vl] elements (not vlmax) and apply CSR[vstart] offset to source/dest bit positions, otherwise QEMU corrupts tail elements the guest kernel's undisturbed policy protects, breaking vector register isolation between guest processes
Violation:
  QEMU TCG or helper iterates vector element operations (vadd.vv, vle8.v,
  vse8.v) up to vlmax (VLEN/SEW/LMUL) instead of CSR vl actual value, causing
  writes to destination vector register elements beyond the configured vector
  length that the guest expects to remain undisturbed per tail-agnostic/tail-
  undisturbed policy
Consequence: data_corruption
Pattern:
  vector loop bound uses vlmax or VLEN/SEW-derived maximum instead of env->vl
  or CSR vl; missing vl-based early termination in vext_ldst_us,
  vext_ldst_stride, or vector arith helpers; vstart not added to element index
  in memory address calculation for unit-stride loads/stores
