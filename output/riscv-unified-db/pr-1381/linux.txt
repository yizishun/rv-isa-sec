PR #1381  target=linux  overall=bug_confirmed
Spec: KVM trap redirection writes raw VSTVEC (including MODE bits) to guest SEPC, crashing guests that use Vectored stvec mode on trap injection
Violation:
  In arch/riscv/kvm/vcpu_exit.c:kvm_riscv_vcpu_trap_redirect(), the guest
  VSTVEC CSR is read via ncsr_read(CSR_VSTVEC) and written directly to guest
  SEPC as the trap injection target without masking the low 2 MODE bits. If
  the guest has configured stvec.MODE=Vectored (MODE=1), the SEPC receives a
  misaligned address (BASE | 0x01). Since the injected traps are always
  synchronous exceptions, the spec requires using only the BASE address
  regardless of MODE, making this a direct spec violation that causes the
  guest to take an instruction-address-misaligned fault instead of the
  intended injected trap.
Consequence: denial_of_service
Pattern:
  ncsr_read(CSR_VSTVEC) used as sep= target without & ~0x3 mask
------------------------------------------------------------
[bug_confirmed] arch/riscv/kvm/vcpu_exit.c:166-166  kvm_riscv_vcpu_trap_redirect
  ncsr_read(CSR_VSTVEC) reads the raw vstvec CSR value including the low 2
  MODE bits, and assigns it directly to guest_context.sepc as the trap
  injection target. When the guest has configured vstvec.MODE=Vectored
  (MODE=1), sepc receives BASE|0x01 — a misaligned address. Per the RISC-V
  spec, all synchronous exceptions (which is what trap_redirect injects) must
  use only the BASE field regardless of MODE. The injected trap causes an
  instruction-address-misaligned fault instead of the intended handler,
  resulting in guest DoS.
  | vcpu->arch.guest_context.sepc = ncsr_read(CSR_VSTVEC);
