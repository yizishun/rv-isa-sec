PR #1381  target=freebsd-src  overall=potential_risk
Spec: FreeBSD never checks stvec.MODE and has no vectored-dispatch infrastructure — any accidental write of MODE=Vectored (e.g., via corrupted bhyve hypctx->host_stvec on VM exit) causes interrupts to jump to garbage BASE+4*cause offsets, crashing the hart
Violation:
  FreeBSD writes stvec via csrw/csrrw with an address whose bits[1:0] ≠ 00
  (i.e., MODE ≠ Direct). The kernel unconditionally assumes Direct mode
  dispatch through cpu_exception_handler and has no vector table
  infrastructure to handle MODE=Vectored. If a corrupted write sets
  MODE=Vectored (e.g., bhyve hypctx->host_stvec memory corruption during VM
  exit restore in vmm_switch.S:165), interrupts then jump to BASE + 4*cause —
  scattering each IRQ source to an uninitialized or attacker-controlled code
  pointer rather than the unified trap entry, with no kernel recovery path.
Consequence: denial_of_service
Pattern:
  csrw stvec.*[^0c]0$|csr_write\(stvec|csr_swap\(stvec|csrrw.*stvec|host_stvec
  |vstvec

[compliant] sys/riscv/riscv/exception.S:208-217  cpu_exception_handler
  The unified trap entry point dispatches all exceptions and interrupts
  through a single handler, relying on software to check scause and branch
  accordingly. This design implicitly assumes MODE=Direct: all traps arrive at
  this single entry point. Under MODE=Vectored, interrupts would bypass this
  handler entirely, jumping to BASE+4×cause instead.
  | ENTRY(cpu_exception_handler)
  |     csrrw sp, sscratch, sp
  |     beqz sp, 1f
  |     j cpu_exception_handler_user
  References:
    - riscv-isa-manual/src/priv/supervisor.adoc:348-352
      "Direct: All exceptions set pc to BASE. Vectored: Asynchronous
      interrupts set pc to BASE+4×cause."
