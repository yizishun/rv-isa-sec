PR #1381  target=xiangshan  overall=compliant
Spec: stvec.MODE Vectored mode (MODE=1) drives trap-entry PC = BASE + 4*cause for interrupts; incorrect WARL masking on BASE/MODE fields or wrong adder triggering on sync exceptions causes traps to vector to wrong handler addresses, enabling privilege-boundary bypass
Violation:
  In XiangShan RTL, when stvec.MODE=1 (Vectored) and an interrupt arrives, the
  trap-entry PC is computed as stvec.BASE + (cause << 2). If the CSR module's
  WARL mask for stvec.BASE truncates lower bits that are required for the
  vectored offset (e.g., forcing BASE[1:0] = 0 when there are more than 4
  interrupt causes), OR if the vectored-address adder incorrectly applies to
  synchronous exceptions (which must always use stvec.BASE), OR if the MODE
  field WARL encoding does not accept the value 1, the hardware violates this
  spec.
Consequence: privilege_escape
Pattern:
  stvec.*MODE.*Vectored|stvec.*BASE.*cause.*<<.*2|trap_entry_pc.*stvec|vectore
  d.*interrupt.*pc|WARL.*stvec.*MODE|CSR_STVEC.*wmask
