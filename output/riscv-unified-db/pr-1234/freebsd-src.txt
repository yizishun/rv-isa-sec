PR #1234  target=freebsd-src  overall=not_implemented
Spec: Zcmt introduces jvt CSR holding a jump-table base pointer; FreeBSD must save/restore jvt on context switch, validate jvt.BASE alignment (64-byte), enforce jvt.MODE=0, and in bhyve correctly trap or proxy guest jvt access via hstateen0.JVT — omission allows cross-process control-flow hijacking via stale jump-table pointer
Violation:
  FreeBSD kernel context-switches between processes without saving/restoring
  the jvt CSR. A malicious process sets jvt.BASE to point to attacker-
  controlled memory, then yields the CPU. When the victim process executes
  cm.jalt or cm.jt, the hardware reads the jump target from the attacker's
  table via the stale jvt.BASE, redirecting the victim's control flow to an
  attacker-chosen address.
Consequence: privilege_escape
Pattern:
  cpu_switch|savectx|restorectx|set_regs|fill_regs.*jvt|CSR_JVT|jvt.*context|Z
  cmt.*switch

[not_implemented] sys/riscv/riscv/swtch.S:258-358  cpu_switch
  cpu_switch() does not save/restore the jvt CSR. The context switch saves
  only ra, sp, s[0-11], and conditionally the FPU state. On hardware
  implementing Zcmt, leaving jvt un-switched allows a malicious process to set
  jvt.BASE to attacker-controlled memory; when the victim executes
  cm.jalt/cm.jt, the hardware fetches the jump target from the attacker's
  table via the stale jvt.BASE, redirecting victim control flow.
  | ENTRY(cpu_switch)
  |     sd a1, PC_CURTHREAD(tp)
  |     ...
  |     sd ra, (PCB_RA)(x13)
  |     sd sp, (PCB_SP)(x13)
  |     sd s0, (PCB_S + 0 * 8)(x13)
  |     ...
  |     /* no jvt CSR save/restore anywhere */
