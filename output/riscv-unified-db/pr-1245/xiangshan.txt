PR #1245  target=xiangshan  overall=potential_risk
Spec: Unchecked vector register writeback past trap element index leaks data from protected memory into architected state visible to exception handlers, bypassing PMP/page-table access controls at hardware level
Violation:
  In XiangShan RTL, if the vector LSU (Load/Store Unit) continues to write
  load data into destination vector register group elements with indices
  greater than the element that triggered a memory access exception (e.g.,
  page fault, PMP violation, or access fault), the hardware overwrites
  architectural state past the precise trap boundary. This occurs when
  VECTOR_LOAD_PAST_TRAP is either explicitly enabled (parameter=true) or
  inadvertently implemented due to the LSU processing multiple elements in
  parallel across beats without aborting in-flight element writes upon trap
  detection on an earlier element index. The violation manifests when: (1) the
  trap is reported at element index i, (2) the trap handler inspects vstart
  (pointing to i) or vl, but (3) destination register elements at indices > i
  already contain data loaded from potentially protected/privileged memory
  addresses before the LSU pipeline was flushed. In Chisel/Verilog, this
  corresponds to the vector register writeback path not being gated by the
  trap-valid signal on a per-element-index basis, or the LSU writeback queue
  not being drained/cancelled upon exception detection.
Consequence: info_leak
Pattern:
  (vector.*load.*past.*trap|vecLsu.*writeback.*exception|vreg.*writeEn.*trap|l
  su.*beat.*fault.*write|vectorLoadUnit.*cancel.*beat|vlWritebackQueue.*flush)
