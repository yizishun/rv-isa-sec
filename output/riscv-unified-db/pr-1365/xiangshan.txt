PR #1365  target=xiangshan  overall=compliant
Spec: sstatus.UBE applied without privilege-mode gating corrupts S/M-mode data accesses or instruction fetches, breaking hardware privilege isolation
Violation:
  XiangShan LSU (Load-Store Unit) applies sstatus.UBE-based byte reordering to
  data accesses using only the UBE bit value without qualifying by current
  privilege mode (priv_mode != U-mode), causing S-mode or M-mode data accesses
  (including page table walks, kernel memory operations, and I/O) to be byte-
  swapped when sstatus.UBE=1. Conversely, if instruction fetch endianness
  logic checks UBE, instruction bytes in U-mode would be incorrectly swapped,
  violating the spec mandate that instructions are always little-endian.
Consequence: privilege_escape
Pattern:
  endian_swap.*priv_mode|byte_reorder.*(U|S|M)_mode|UBE.*access_type|load_alig
  n.*UBE|store_align.*UBE|mem_endian.*sstatus|ifetch.*endian|LSU.*byte.*swap.*
  !(U|priv)
