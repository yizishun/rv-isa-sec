PR #1190  target=qemu  overall=compliant
Spec: ISA-spec VLMAX formula used SEW bit-value (8/16/32/64) where the VSEW field (0-3) was intended; QEMU must ensure every VLMAX path uses the 3-bit VSEW encoding — not the decoded SEW bit-count — in the shift arithmetic, or vector operations will overrun register groups
Violation:
  Any VLMAX computation path in QEMU that uses the SEW byte-count value (e.g.
  8, 16, 32, or 64 bits) where the VSEW field encoding (0-3) is expected in
  the shift expression `(vlen >> (sew + 3 - lmul))` produces a wildly
  incorrect element count — for fractional LMUL the error is multiplicative
  (e.g. SEW=8 yields `3+8=11` instead of `3+0=3`, shifting VLEN by 11 bits
  instead of 3), and every subsequent vector instruction then iterates past
  the architectural register-group boundary, reading or corrupting adjacent
  vector register state.
Consequence: data_corruption
Pattern:
  VLMAX or max_elems computed with `sew_value_in_bits` (derived as `8 <<
  vsew`) instead of the raw `vsew` encoding, or any expression matching `>> (3
  + sew_value)` or `>> (sew_value + 3 - lmul)` where the first operand of `+`
  is a byte-count or bit-count rather than the 3-bit VSEW field
