PR #1685  target=freebsd-src  overall=compliant
Spec: Buggy cbo.zero access-check pseudocode allowed VS-mode FreeBSD guest to bypass hypervisor henvcfg.CBZE denial and VU-mode to execute with only one envcfg bit set, violating the two-key RISC-V CBO gating model
Violation:
  In FreeBSD RISC-V, when running as a guest OS (VS-mode) under a hypervisor
  that sets henvcfg.CBZE=0 to deny cbo.zero access, or when running as VU-mode
  userspace with only one of senvcfg.CBZE/henvcfg.CBZE set: the old (pre-fix)
  spec's operation() pseudocode had three bugs — (1) S/VS-mode was never
  checked against menvcfg/henvcfg.CBZE, so VS-mode FreeBSD could execute
  cbo.zero despite henvcfg.CBZE=0; (2) VU-mode used OR semantics
  ((henvcfg.CBZE | senvcfg.CBZE) == 0) instead of requiring both bits; (3)
  M-mode incorrectly trapped when menvcfg.CBZE=0. An implementation following
  the buggy spec would allow cbo.zero to execute across privilege boundaries
  where it should trap with IllegalInstruction or VirtualInstruction.
Consequence: privilege_escape
Pattern:
  cbo.zero operation() access check missing S/VS-mode guard against
  menvcfg/henvcfg CBZE; VU-mode OR semantics instead of AND for dual-envcfg
  check
