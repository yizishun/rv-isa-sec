PR #1685  target=qemu  overall=bug_confirmed
Spec: check_zicbo_envcfg raises IllegalInstruction for VS/VU modes when menvcfg enable bit is 0, but spec requires VirtualInstruction so HS-mode hypervisor can trap-and-emulate CBO instructions
Violation:
  In check_zicbo_envcfg() at target/riscv/op_helper.c:148, when env->priv <
  PRV_M and the menvcfg enable bit (CBZE/CBCFE/CBIE) is 0, QEMU raises
  RISCV_EXCP_ILLEGAL_INST for all non-M modes without inspecting
  env->virt_enabled. The corrected spec requires VS/VU modes to raise
  VirtualInstruction (RISCV_EXCP_VIRT_INSTRUCTION_FAULT) instead, so the HS-
  mode hypervisor can trap-and-emulate. QEMU's flat menvcfg check at line 148
  fires before the virt_enabled path at line 152 is reached, causing the
  exception to route to M-mode with the wrong exception code, bypassing the
  hypervisor delegation path (medeleg[22]).
Consequence: function_loss
Pattern:
  env->priv <
  PRV_M.*get_field.*menvcfg.*(CBZE|CBCFE|CBIE).*ILLEGAL_INST(?!.*virt_enabled)
