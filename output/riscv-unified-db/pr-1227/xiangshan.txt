PR #1227  target=xiangshan  overall=compliant
Spec: Svade/Svadu reclassified from unprivileged to privileged: A/D-bit update control (menvcfg/henvcfg.ADUE) must remain M/HS-mode-only; exposing it at S/U-mode would let unprivileged software probe OS page-table state via page-fault timing.
Violation:
  If an RTL implementation incorrectly classifies Svade/Svadu as unprivileged
  extensions, the A/D-bit update control field (menvcfg.ADUE / henvcfg.ADUE,
  bit 61) could be exposed at supervisor or user privilege levels via senvcfg
  or a user-accessible CSR instead of being restricted to M/HS-mode. In
  XiangShan, menvcfg.ADUE (CSRBundles.scala:71) is already RO=0 and menvcfg is
  M-mode-only (addr[9:8]=11), and henvcfg.ADUE (HypervisorLevel.scala:364-374)
  is also RO=0 with HS-mode+ access. However, if a future Svadu implementation
  added ADUE to senvcfg (SupervisorLevel.scala:259) or made it RW, U-mode
  software could probe A/D-bit behavior via timed page fault patterns to leak
  OS page table state, or VS-mode could override hypervisor A/D-bit policy.
Consequence: info_leak

  mode|envcfg.*user|isPf.*adue|isGpf.*adue
