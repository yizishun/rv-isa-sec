PR #1172  target=freebsd-src  overall=bug_confirmed
Spec: Smctr CSRs (sctrctl/mctrctl/vsctrctl) add per-hart CTR recording configuration that must be context-switched; failing to save/restore sctrctl in cpu_switch and bhyve VM-entry paths leaks control-flow trace configuration between processes and VMs
Violation:
  FreeBSD kernel enables Smctr (sctrctl CSR at 0x14E) without adding
  sctrctl/mctrctl save/restore to the context-switch path in cpu_switch.S or
  the pcb, causing one process's CTR recording configuration (and potentially
  the recorded transfer buffer entries written in U/S mode) to persist across
  thread switches into another process
Consequence: info_leak
Pattern:
  Smctr|sctrctl|mctrctl|vsctrctl|CTR_CTL|0x14E|0x34E|0x24E
------------------------------------------------------------

  conditionally FP state. No sctrctl (0x14E) save/restore exists. On hardware
  implementing Smctr, the new thread inherits the old thread's raw sctrctl
  hardware configuration — including privilege-mode enable bits (U/S),
  transfer-type filter bits, and recording-enable state. This causes one
  process's CTR recording configuration to persist across context switches
  into another process, enabling cross-process info leak via covert control-
  flow recording.

  |         sd      x13, PC_CURPCB(tp)

  |         /* Save the old context. */
  |         ld      x13, TD_PCB(a0)
  | 
  |         /* Store ra, sp and the callee-saved registers */

  guest GP registers, sstatus, hstatus, scounteren, stvec, sscratch, sepc.
