PR #1153  target=opensbi  overall=potential_risk
Spec: MSECCFG is not saved/restored across HSM non-retentive suspend/resume; USEED/SSEED bits are lost and platform-specific resume paths may leave Smepmp disabled
Violation:
  In OpenSBI's HSM non-retentive suspend flow,
  __sbi_hsm_suspend_non_ret_save() saves MIE, MIP, MEDELEG, MIDELEG, and
  MENVCFG but omits MSECCFG. On resume, __sbi_hsm_suspend_non_ret_restore()
  restores those CSRs but does not restore MSECCFG. After the hart loses power
  during non-retentive suspend, MSECCFG resets to its hardware default (MML=0,
  MMWP=0, RLB=0, USEED/SSEED=0). While the standard warm-boot resume path
  (init_warm_resume → sbi_hart_protection_configure →
  sbi_hart_smepmp_configure) re-programs MML and RLB as a side effect, non-
  MSECCFG bits (USEED, SSEED for Zkr) are never re-established since
  sbi_hart_reinit() does not touch MSECCFG and the Zkr seed CSR configuration
  is only done during cold boot (sbi_hart.c:177-179). Additionally, any
  platform-specific resume path that bypasses sbi_hart_protection_configure()
  would leave MSECCFG at hardware reset value, defeating Smepmp MML/MMWP
  enforcement entirely.
Consequence: function_loss
Pattern:
  saved_menvcfg without corresponding saved_mseccfg in suspend save/restore;
  sbi_hart_reinit omitting MSECCFG reconfiguration; warm-boot resume not
  restoring USEED/SSEED bits

  sbi_hart_protection_configure() before sbi_hsm_hart_resume_finish(). This
  ordering ensures mstatus_init() re-establishes MSECCFG.SSEED/USEED before
  sbi_hart_smepmp_configure() sets MML/RLB. However, the MSECCFG
  reconfiguration relies on this exact call sequence being maintained; there
  is no architectural guarantee that MSECCFG state is preserved if the
  sequence is modified.

[potential_risk] lib/sbi/sbi_hsm.c:479-479  sbi_hsm_hart_resume_finish
  __sbi_hsm_suspend_non_ret_restore() runs AFTER sbi_hart_reinit() and
  sbi_hart_protection_configure() have already re-initialized MSECCFG from
  scratch. This means any MSECCFG bits set by those functions (SSEED/USEED
  from mstatus_init, MML/RLB from smepmp_configure) are correctly applied.
  However, the MENVCFG write in __sbi_hsm_suspend_non_ret_restore() (line 441)
  OVERWRITES the MENVCFG value that mstatus_init() computed at line 174. This
  is by design — the saved pre-suspend MENVCFG is restored instead of the
  reconstructed one — but the inconsistency between how MENVCFG and MSECCFG
  are handled (saved/restored vs re-initialized) is architecturally fragile.
