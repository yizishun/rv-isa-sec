PR #1153  target=xiangshan  overall=compliant
Spec: Smepmp introduces MML-dependent PMP truth table inversion and RLB-gated rule locking; incorrect hardware implementation of the MML-gated pmpcfg.L semantics, shared-region encoding (RW=01), or RLB lockout mechanism directly enables M-mode↔S/U-mode privilege escape via PMP bypass
Violation:
  When mseccfg.MML=1, the PMP checker in XiangShan RTL does not correctly
  apply the MML-dependent truth table for PMP permission evaluation.
  Specifically: (1) pmpcfg.L semantics are not inverted based on MML — L=0
  should deny M-mode access and L=1 should deny S/U-mode access per the Smepmp
  truth table, but if the checker continues using pre-Smepmp L-bit semantics
  (L=1 means 'locked and enforced on all modes'), M-mode retains access to
  S/U-mode-only regions (L=0 rules), creating a privilege escalation path. (2)
  The formerly reserved encoding pmpcfg.RW=01 is decoded as 'reserved' or
  'invalid' instead of 'Shared-Region' when MML=1, causing access faults on
  legitimate shared memory. (3) Writes to pmpcfg that attempt to create
  executable M-mode-only rules (L=1, X=1) or locked Shared-Region rules when
  RLB=0 are not silently ignored but instead take effect, allowing M-mode to
  execute from arbitrary regions in violation of the 'no executable M-mode-
  only rule creation without RLB' restriction. (4) The RLB lockout mechanism —
  where RLB must remain 0 and ignore further writes when RLB=0 and any
  pmpcfg.L=1 — is not enforced atomically across all PMP entries, creating a
  TOCTOU window where RLB can be set between PMP entry checks.
Consequence: privilege_escape
Pattern:
  MML.*pmpcfg|pmpCheck.*mseccfg|PMPChecker.*MML|pmp.*L.*MML|mseccfg.*RLB.*pmpc
  fg|pmpcfg.*write.*ignore.*MML|RW.*01.*shared.*region|sticky.*MML.*clear|RLB.
  *lockout|pmpcfg.*L.*RLB.*remain
