PR #1153  target=qemu  overall=potential_risk
Spec: QEMU must re-validate all cached PMP access decisions (TLB flush) on any mseccfg sticky-bit change (MML/MMWP/RLB) and must correctly implement the 32-entry Smepmp truth table in pmp_hart_has_privs, including the MML-mode-specific redefinition of pmpcfg.L semantics and RLB-gated lock bypass
Violation:
  When QEMU TCG emulates mseccfg.MML bit 0→1 transition but does not re-
  evaluate all TLB-cached PMP access decisions (e.g., cached code-translation
  blocks or cached page protections), guest M-mode code could execute from
  regions previously allowed but now denied under the Smepmp MML truth table
  (case c of MML spec: M-mode execution requires explicit M-mode-only or
  locked-shared-region rule). Similarly, if mseccfg.MMWP transitions 0→1
  without flushing cached PMP bypass for M-mode, cached TLB entries could
  grant M-mode access to regions that should now be denied. Conversely, RLB
  transitions that unlock locked PMP entries without TLB flush could leave
  stale denial caches.
Consequence: privilege_escape
Pattern:
  mseccfg write handler does not tlb_flush on every sticky-bit change that
  alters PMP access semantics; OR pmp_hart_has_privs truth table incorrectly
  maps smepmp_operation codes to allowed_privs for M-mode vs S/U-mode; OR
  mseccfg_csr_write fails to enforce RLB lock-out when any pmpcfg.L is set in
  disabled (OFF) entries; OR pmpcfg_csr_write allows executable M-mode-only or
  locked-shared-region configurations when MML=1 and RLB=0 (spec clause 4b);
  OR mseccfg.MML/MMWP re-enabled after migration resume without TLB
  invalidation
