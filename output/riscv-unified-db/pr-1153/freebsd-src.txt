PR #1153  target=freebsd-src  overall=bug_confirmed
Spec: FreeBSD S-mode kernel has zero Smepmp (PMP Enhancements for M-mode) awareness — if firmware activates this ratified spec's M-mode lockdown/allowlist, the kernel's implicit pre-Smepmp PMP assumptions cause boot-time panics or incorrect physmem reservations
Violation:
  FreeBSD runs as S-mode without any Smepmp awareness: it cannot read mseccfg
  (sticky fields prevent polling), cannot write PMP CSRs, and implicitly
  assumes pre-Smepmp PMP semantics where M-mode has unrestricted access to all
  non-locked regions. If M-mode firmware (OpenSBI) enables MML=1 and MMWP=1
  with PMP entries that do not cover all of FreeBSD's physical memory as
  S/U-mode-accessible or Shared-Region, the kernel will trigger access faults
  (panic at trap.c:338) when touching unprotected regions. Additionally, the
  efi_exclude_sbi_pmp_cb() heuristic at machdep.c:541 assumes exactly one PMP
  entry protects firmware — Smepmp may use multiple entries, causing false-
  positive/false-negative physmem exclusion.
Consequence: denial_of_service
Pattern:
  physmem_exclude_region|efi_exclude_sbi_pmp_cb|panic.*Memory access
  exception|sbi_init|SCAUSE_LOAD_ACCESS_FAULT|SCAUSE_STORE_ACCESS_FAULT
------------------------------------------------------------
