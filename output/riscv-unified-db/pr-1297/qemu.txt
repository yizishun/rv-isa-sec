PR #1297  target=qemu  overall=compliant
Spec: have_mseccfg() predicate omits Zicfilp from mseccfg existence check, denying guest access to MSECCFG_MLPE forward-CFI control when Zicfilp is the only implemented field-bearing extension
Violation:
  QEMU's have_mseccfg() CSR existence predicate at target/riscv/csr.c:775
  gates mseccfg access on ext_smepmp, ext_zkr, or ext_smmpm, but omits
  ext_zicfilp. The spec (Sm >= 1.12 AND anyOf{Zkr, Smmpm, Zicfilp}) requires
  mseccfg to exist when Zicfilp is the sole qualifying extension. A VM
  configured with only Zicfilp (and Sm >= 1.12) will receive
  RISCV_EXCP_ILLEGAL_INST on mseccfg access, blocking guest software from
  reading/writing the MSECCFG_MLPE forward-CFI control bit, yet QEMU's
  mseccfg_csr_write already contains a branch handling ext_zicfilp for MLPE —
  confirming the CSR was intended to be reachable.
Consequence: function_loss
Pattern:
  have_mseccfg(.*ext_zicfilp|ext_sm.*allOf.*anyOf)|CSR_MSECCFG.*predicate
  misses extension
