PR #1677  target=qemu  overall=compliant
Spec: Spec fixes bit-slice boundary guards in vmv.v.i reference model; QEMU avoids the exact concat-range bug by using per-element typed stores, but the same vector-element placement correctness must be verified across GEN_VEXT_VMV_VX helpers and their H() indexing macros
Violation:
  QEMU's vmv.v.i implementation (both the tcg_gen_gvec_dup_imm fast path at
  trans_rvv.c.inc:2217 and the vmv_v_x helper slow path at
  vector_helper.c:2131) writes SEW-width typed elements directly at computed
  offsets rather than using register-level bit-slice concatenation, so the
  boundary bug in the spec reference model does not apply. However, if the
  helper's element-index macro H(i) miscomputes the byte offset within the
  vector register (e.g., off-by-one in H1/H2/H4/H8 in vector_internals.h),
  individual SEW-bit element writes could corrupt adjacent elements' bits that
  should remain untouched, matching the same class of defect as the spec fix
  guards against—failing to preserve bits outside the target element's bit-
  slice.
Consequence: data_corruption
Pattern:
  vector element write that computes byte offset from per-element index
  without validating SEW-aligned boundaries within the VLEN-wide register;
  specifically, any vector helper using (ETYPE *)vd + H(i) where H() is
  misdefined for the SEW/register-width ratio, or any gvec_dup_imm fast path
  whose vl_eq_vlmax guard incorrectly skips tail-element preservation

  On little-endian hosts (all common QEMU targets), all H macros are identity
  functions: H1(x)=x, H2(x)=x, H4(x)=x, H8(x)=x. On big-endian hosts, they
  correctly byte-reverse within 64-bit chunks to handle the host-endian
  storage layout of vector registers (stored as uint64_t[32*RV_VLEN_MAX/64]).
  No off-by-one or miscomputation exists. The element-index-to-byte-offset
  mapping is correct for all SEW values.

  | ...
  | #else
  | #define H1(x)   (x)
  | #define H2(x)   (x)
  | #define H4(x)   (x)
  | #define H8(x)   (x)
  | #endif

  The tail-element fill function correctly implements the tail-agnostic
  policy. On little-endian hosts, it simply does memset(base + cnt, -1, tot -
