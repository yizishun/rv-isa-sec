PR #1164  target=xiangshan  overall=not_implemented
Spec: SCTRCLR clear sequence must be atomic with respect to control transfer recording: a transfer arriving mid-clear produces CCV=1 violating the spec-mandated CCV=0 for the first post-clear record, leaking cycle-counter timing information
Violation:
  In XiangShan RTL, SCTRCLR executes as a multi-cycle operation iterating over
  DEPTH entries via the indirect CSR interface (siselect/sireg* writes). If a
  qualified control transfer (jump, branch, trap, or trap return) occurs
  during this clear window—after some entries are zeroed but before
  CTR_CYCLE_COUNTER and CCV_HW are reset—the hardware records a new transfer
  with CCV=1 and a non-zero CC field, violating the spec guarantee that 'the
  first recorded transfer following SCTRCLR will have ctrdata.CCV=0' and that
  'any read of ctrsource/ctrtarget/ctrdata following SCTRCLR returns 0.'
Consequence: info_leak
Pattern:
  SCTRCLR pipeline implementation lacks serialization/fence semantics
  preventing concurrent CTR buffer writes during the clear sequence;
  CTR_CYCLE_COUNTER reset not ordered-before entry zeroing; CCV_HW clear not
  atomic with respect to control transfer recording
