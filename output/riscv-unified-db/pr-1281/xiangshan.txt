PR #1281  target=xiangshan  overall=compliant
Spec: vsetvli vl assignment uses strict < instead of <= at boundary condition avl==vlmax, causing vl undercount and truncating vector operations; reserved vsew must additionally zero vl to prevent stale-element execution
Violation:
  In XiangShan RTL, the vsetvli instruction decoder/compute unit uses a
  strict-less-than comparator (avl < vlmax) instead of less-than-or-equal (avl
  <= vlmax) to determine the vl assignment path. When avl equals vlmax
  exactly, the hardware incorrectly enters the avl < 2*vlmax branch instead of
  the avl <= vlmax branch, causing vl to be set to ceil(AVL/2) (or another
  intermediate value) rather than the correct full AVL value. Additionally,
  when a reserved vsew encoding (vtype[5]==1) is supplied, the RTL must zero
  out CSR[vl].VALUE alongside setting VILL; failure to zero vl leaves stale
  state that subsequent vector instructions may interpret as a valid element
  count.
Consequence: data_corruption
Pattern:
  vsetvli.*vl.*comparator|avl.*<=.*vlmax|avl.*<.*vlmax|vl_calc|VSetVli|vsetype
  .*vl|VILL.*vl.*zero|reserved.*vsew.*vl
