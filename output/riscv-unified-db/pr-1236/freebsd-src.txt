PR #1236  target=freebsd-src  overall=potential_risk
Spec: sie bits are aliases of mie bits, not independent state — FreeBSD writes to sie for IPI/timer/external interrupt control silently fail if mideleg is not configured, and M-mode can always observe/override sie state via mie
Violation:
  FreeBSD writes to sie (CSR 0x104) in mp_machdep.c, intc.c, and timer.c
  assuming sie bits independently control interrupt enable state. The spec now
  clarifies that sie.SSIE/STIE/SEIE/LCOFIE are aliases of the corresponding
  mie bits, not independent state. If M-mode firmware (OpenSBI/BBL) has not
  delegated the corresponding interrupt via mideleg, the write to sie is
  silently ignored (bit remains read-only 0), and FreeBSD incorrectly assumes
  the interrupt is enabled/disabled. Conversely, if mideleg IS set, writing to
  sie actually writes through to mie, which means the interrupt-enable is
  truly controlled at M-level — a malicious or buggy M-mode firmware can
  observe or override sie state at any time via mie reads/writes.
Consequence: denial_of_service
Pattern:
  csr_write\(sie|csr_set\(sie|csr_clear\(sie
------------------------------------------------------------
[potential_risk] sys/riscv/riscv/mp_machdep.c:166-168  init_secondary
  AP boot path writes csr_set(sie, SIE_SSIE) to ensure WFI doesn't halt the
  hart, but never verifies that SSI is delegated via mideleg[1]. If M-mode
  firmware has not set mideleg[1], the write is silently ignored (sie.SSIE is
  read-only zero per norm:sie_acc), and the WFI may hang the AP indefinitely.
  Conversely, if delegation IS active, the write actually targets mie.MSIE at
  M-level, meaning M-mode firmware can observe/override the interrupt-enable
  state that FreeBSD treats as S-mode-private.

[potential_risk] sys/riscv/riscv/intc.c:193-197  intc_disable_intr
  intc_disable_intr() writes csr_clear(sie, 1ul << irq) for any IRQ 0-15
  without checking mideleg. For interrupts not delegated to S-mode (e.g., if
  firmware doesn't set mideleg[9] for external interrupts, or mideleg[5] for
  timer), the sie bit is read-only zero and the clear is silently ignored —
  FreeBSD believes it disabled the interrupt but it remains enabled at
  M-level. For delegated interrupts, csr_clear(sie, ...) actually clears the
  mie bit, so M-mode firmware can observe the disable state change and can re-
  enable it via mie writes, breaking the S-mode security invariant.
  | irq = ((struct intc_irqsrc *)isrc)->irq;
  | if (irq >= INTC_NIRQS)
  |   panic("%s: Unsupported IRQ %u", __func__, irq);
  | 
  | csr_clear(sie, 1ul << irq);

  riscv_timer_et_stop() writes csr_clear(sie, SIE_STIE) to disable timer
  interrupts without checking mideleg[5]. If the timer interrupt is not
