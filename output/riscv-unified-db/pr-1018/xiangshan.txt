PR #1018  target=xiangshan  overall=compliant
Spec: mvip writability must be dynamically gated by mvien's current register value per spec WARL coupling; implementing mvip's writable mask from the static configuration parameter alone breaks the mvien→mvip dependency and allows virtual interrupt injection with mvien cleared
Violation:
  In XiangShan RTL, the CSR write datapath for mvip (0x309) independently
  computes its writable-bit mask using the MACHINE_VIRTUAL_INTERRUPTS
  parameter rather than deriving it from the current value of mvien. The spec
  requires that a mvip bit is writable only when the corresponding mvien bit
  is both writable AND currently set to 1 (i.e., mvip writability is gated by
  mvien's live register value, not just the configuration parameter). If
  mvien[i] is programmed to 0 (interrupt disabled), a subsequent write to
  mvip[i]=1 must be ignored by hardware. Implementing mvip's WARL mask from
  the static parameter alone bypasses this dynamic coupling, allowing software
  to assert virtual interrupt pending bits for interrupt IDs whose virtual
  enable is cleared.
Consequence: privilege_escape
Pattern:
  mvip WARL write mask derived from MACHINE_VIRTUAL_INTERRUPTS parameter
  instead of mvien register read; missing cross-CSR data dependency in CSR
  write datapath; mvip writable-bit gating not conditioned on mvien.VOTHERIE
  field value
