PR #1364  target=xiangshan  overall=not_implemented
Spec: Ztso mandates TSO memory ordering (loads = acquire, stores = release); if XiangShan advertises Ztso but the LSU/store-buffer permits younger loads to bypass older stores without forwarding checks, software relying on x86-style TSO semantics will experience data races and silent data corruption across harts.
Violation:
  XiangShan RTL advertises Ztso support (e.g., misa.T bit or ISA string
  reports 'ztso') but the load/store unit (LSU), store buffer, or memory
  subsystem does not enforce TSO ordering: specifically, a younger load can
  bypass an older store to a different address without checking the store
  buffer for forwarding, or store-to-load ordering is not maintained in the
  pipeline. This occurs when the store buffer allows loads to issue before
  older stores have drained, violating the 'all loads have implicit acquire
  semantics' guarantee that Ztso requires.
Consequence: race_condition
Pattern:
  Ztso|tso|total.store.order|store.buffer.bypass|load.speculation.*store|mem.o
  rdering.TSO|FENCE.TSO|acquire.*implicit|store_to_load.*order

[not_implemented] src/main/scala/xiangshan/mem/sbuffer/Sbuffer.scala:778-778  Sbuffer (load forwarding logic)
  The store buffer implements only RVWMO load forwarding semantics (store-to-
  load forwarding based on address match/mask). It does not enforce TSO
  ordering constraints: under Ztso, all loads must have implicit acquire-RCpc
  semantics, meaning a younger load must not bypass an older store to a
  different address without checking the store buffer for potential
  forwarding. The current design allows loads to issue before older stores
  have drained from the store buffer, which is legal under RVWMO but would
  violate Ztso if Ztso were advertised.
  | // ---------------------- Load Data Forward ---------------------
