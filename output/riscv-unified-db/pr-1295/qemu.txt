PR #1295  target=qemu  overall=compliant
Spec: Using vlmax instead of vl as vector element loop bound writes past vl into tail elements, corrupting destination register state beyond the configured element count
Violation:
  QEMU's TCG translation or helper for vadd.vv (and potentially other vector
  ALU instructions) iterates over vlmax = (VLEN>>LMUL)>>SEW elements instead
  of the CSR vl value, writing computed results into destination vector
  register elements beyond the configured vector length. This corrupts tail
  elements that the guest expects to remain either undisturbed (vtype.vta=0)
  or agnostic (all-1s), breaking the architectural contract where only vl
  elements are written.
Consequence: data_corruption
Pattern:
  Vector instruction helper or translator using max_elems or vlmax derived
  from vext_get_vlmax() as the element loop bound instead of env->vl or desc
  vlenb-derived actual vl; specifically any loop head containing 'i < vlmax'
  'i < max_elems' or equivalent where vlmax != vl, in
  target/riscv/vector_helper.c or target/riscv/insn_trans/trans_rvv.c.inc
