PR #1009  target=freebsd-src  overall=not_implemented
Spec: Zicfiss shadow stack CSR (ssp) must be saved/restored on FreeBSD context switch and populated on signal delivery, or cross-process shadow stack corruption enables ROP-based privilege escalation bypassing CFI
Violation:
  When Zicfiss is enabled (menvcfg.SSE=1) but the FreeBSD kernel context
  switch path (cpu_switch() / savectx() in sys/riscv/riscv/swtch.S) does not
  save and restore the ssp CSR (address 0x011), causing the shadow stack
  pointer to bleed between processes. Additionally, when the kernel signal
  delivery path (sendsig() in sys/riscv/riscv/machdep.c) sets up a signal
  frame without pushing the intercepted return address onto the shadow stack,
  then upon sigreturn the sspopchk instruction raises an unhandled
  SoftwareCheck (exception code 18) whose lack of a trap handler entry causes
  a kernel panic.
Consequence: privilege_escape
Pattern:
  \b(cpu_switch|savectx|pcb)\b.*|ssp(?!ush|opchk|rdp)
------------------------------------------------------------

[not_implemented] sys/riscv/riscv/swtch.S:434-457  savectx
  savectx saves ra, sp, tp, gp, s0-s11, and FPU state to PCB but does not save
  ssp. This function is used for forking and core dumps — without ssp, the
  shadow stack pointer is lost on fork, and a child process inheriting the
  parent's shadow stack pointer would corrupt the parent's shadow stack on
  first sspush.
