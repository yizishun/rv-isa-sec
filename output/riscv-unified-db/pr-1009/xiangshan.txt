PR #1009  target=xiangshan  overall=not_implemented
Spec: Zicfiss shadow stack instruction SSE gating requires mode-specific two-stage checking (illegal check per-mode then any-SSE OR for execution); implementing as a single combined OR-gate of all three SSE bits enables privilege escape where guest/hypervisor-disabled shadow stack operations execute incorrectly
Violation:
  In XiangShan RTL, when shadow stack instructions (sspush, sspopchk, ssrdp,
  ssamoswap, c.sspush, c.sspopchk) are decoded and the implementation checks
  only the OR of menvcfg.SSE, henvcfg.SSE, and senvcfg.SSE as a single
  combined enable signal (e.g., any_sse_en = menvcfg.SSE | henvcfg.SSE |
  senvcfg.SSE) instead of performing the two-stage check: (1) gate on the
  mode-specific SSE bit to raise IllegalInstruction/VirtualInstruction for the
  current privilege level, then (2) check any SSE bit for the operation body.
  Specifically, in VS/VU mode when menvcfg.SSE=1 but henvcfg.SSE=0, or in VU
  mode when senvcfg.SSE=0, or in U-mode when menvcfg.SSE=1 but senvcfg.SSE=0,
  a single-combined-check implementation would execute shadow stack operations
  that the spec requires to trap with VirtualInstruction or
  IllegalInstruction.
Consequence: privilege_escape
Pattern:
  menvcfg.SSE | henvcfg.SSE | senvcfg.SSE
