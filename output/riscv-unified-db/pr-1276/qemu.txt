PR #1276  target=qemu  overall=compliant
Spec: check_f_ok now gates FP execution on stateen CSRs for Zfinx instead of mstatus.FS; QEMU TCG translate must switch between these two gating regimes based on implemented extensions, or a guest in a mode disabled via stateen can execute FP instructions, leaking or corrupting FPR state across privilege boundaries
Violation:
  QEMU implements Zfinx but does not check mstateen0.FCSR / sstateen0.FCSR /
  hstateen0.FCSR before executing floating-point instructions, or incorrectly
  routes the F-extension path (mstatus.FS check) when Zfinx is active, because
  the old code only checked mstatus.FS and misa.F. A QEMU build where Zfinx is
  advertised via ISA string or device tree but the TCG translate path still
  uses the legacy mstatus.FS gating would execute FP instructions that the
  spec mandates must raise IllegalInstruction.
Consequence: privilege_escape
Pattern:
  check_f_ok OR helper_check_f_ok OR REQUIRE_FPU OR require_fp OR fp_ok OR
  riscv_csrrw.*mstateen OR riscv_csrrw.*sstateen OR Zfinx.*translate OR
  trans_.*fmadd OR trans_.*fadd
