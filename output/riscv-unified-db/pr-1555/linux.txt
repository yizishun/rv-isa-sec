PR #1555  target=linux  overall=compliant
Spec: Spec now allows AMO instructions to enter unpredictable state (not just trap) when misa.A=0 on implementations with TRAP_ON_UNIMPLEMENTED_INSTRUCTION=false, breaking the kernel invariant that AMOs either execute atomically or trap — KVM currently blocks misa.A writes but non-KVM hypervisors or firmware could trigger silent atomicity loss
Violation:
  In the Linux kernel, when TRAP_ON_UNIMPLEMENTED_INSTRUCTION is false in the
  hardware implementation and misa.A is cleared (e.g., by firmware or a
  hypervisor that does allow A-disabling), any subsequent kernel execution of
  Zaamo/Zabha AMO instructions (e.g., amoswap used in atomic primitives)
  enters 'unpredictable' hardware state instead of raising IllegalInstruction.
  The kernel assumes AMO instructions either execute atomically or trap — it
  has no code path to handle silent non-atomic execution.
Consequence: data_corruption
Pattern:
  misa.A.*=.*0|csr_write.*misa.*0x......(A=0)|misa &= ~(1UL <<
  0)|TRAP_ON_UNIMPLEMENTED_INSTRUCTION
