PR #1262  target=xiangshan  overall=compliant
Spec: vsetvli with rs1==x0 must force vl=vlmax per spec PR #1262; if the decode-stage RS1==x0 detection fails, X[0]=0 produces vl=0 instead of vlmax, silently disabling the entire vector unit (all subsequent vector insts execute 0 iterations)
Violation:
  In XiangShan RTL, when the DecodeUnitComp (DecodeUnitComp.scala:126-127)
  RS1==x0 detection logic fails to apply VSETOpType.setVlmax to the vsetvli
  micro-op's fuOpType — either because the RS1 field extraction from the
  instruction word is incorrect, the RS1===0 comparison is masked by an
  earlier branch (e.g., dest===0 && src1===0 at line 124 short-circuits
  without also checking isVsetvli vs isVsetvl), or the setVlmax bit (bit 0) is
  overwritten downstream — then VsetModule (Vsetu.scala:91-93) computes
  normalVL = Mux(0 > vlmax, vlmax, 0) = 0, yielding CSR[vl] = 0 instead of
  vlmax.
Consequence: denial_of_service
Pattern:
  VSETOpType\.(setVlmax|keepVl)\(.*fuOpType\)|inInstFields\.RS1\s*===\s*0\.U|i
  sSetVlmax.*vlmax|normalVL.*avl.*vlmax|uvsetvcfg_vlmax_i|uvsetvcfg_keep_v
