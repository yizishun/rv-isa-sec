PR #1554  target=qemu  overall=compliant
Spec: Zalasr instructions mandate natural alignment traps and acquire/release memory ordering; QEMU must enforce alignment in TCG before access and emit host memory fences when aq/rl bits are set, otherwise multi-hart guest synchronization code suffers silent data races
Violation:
  QEMU TCG translates and executes Zalasr load-acquire/store-release
  instructions (opcode 0x2f, funct3=0-3 for loads, funct3 encodes in upper
  bits for stores) without: (a) checking natural alignment before memory
  access and raising the appropriate misaligned exception
  (LoadAddressMisaligned/StoreAmoAddressMisaligned), or (b) inserting memory
  ordering barrier primitives (acquire after load, release before store)
  corresponding to the aq/rl bits encoded in the instruction. In multi-hart
  SMP emulation, the absence of these barriers means the TCG translator does
  not emit the necessary host memory fences, allowing cross-hart memory
  operation reordering that violates the acquire/release semantics the guest
  synchronization code depends on.
Consequence: race_condition
Pattern:
  translator decodes Zalasr opcode 0x2f with aq/rl bits set but does not call
  gen_load_acquire / gen_store_release barriers, or skips gen_alignment_check
  before gen_load/store
