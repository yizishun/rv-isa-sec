PR #1302  target=linux  overall=compliant
Spec: Smmpm/Zkr/Zicfilp now explicitly gate mseccfg existence, but the S-mode kernel cannot read mseccfg to verify M-mode firmware configured it correctly before using dependent features
Violation:
  S-mode kernel detects Zkr/Smmpm/Zicfilp via ISA string and uses their
  features (SEED CSR, pointer masking, CFI) that depend on mseccfg fields
  being present and configured, but the kernel never reads CSR_MSECCFG (M-mode
  only, inaccessible from S-mode) and has no SBI call to validate mseccfg
  state, so it blindly trusts M-mode firmware has configured mseccfg correctly
Consequence: data_corruption
Pattern:
  riscv_has_extension_likely\(RISCV_ISA_EXT_(ZKR|SMMPM|ZICFILP)\).*csr_(read|w
  rite|swap)|riscv_has_extension.*(ZKR|SMMPM|ZICFILP).*(?!.*mseccfg)
