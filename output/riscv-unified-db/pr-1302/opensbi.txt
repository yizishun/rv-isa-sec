PR #1302  target=opensbi  overall=compliant
Spec: mseccfg CSR existence is now gated on qualifying extensions (Zkr/Smmpm/Zicfilp/Smepmp) — unconditional access in M-mode firmware causes unrecoverable illegal-instruction trap and system denial-of-service if none of those extensions are implemented
Violation:
  OpenSBI accesses CSR_MSECCFG or CSR_MSECCFGH without first verifying that at
  least one of the qualifying extensions (Zkr, Smmpm, Zicfilp, Smepmp) is
  implemented on the hart. The spec now defines mseccfg as existing iff any
  extension that adds fields to it is implemented. On hardware implementing
  Sm≥1.12 but none of {Zkr,Smmpm,Zicfilp,Smepmp}, the CSR does not exist and
  accessing it causes an unrecoverable M-mode illegal-instruction trap (no
  delegation target; M-mode can't delegate synchronous exceptions to a less-
  privileged mode).
Consequence: denial_of_service
Pattern:
  csr_read|csr_write|csr_set|csr_clear\(CSR_MSECCFG\) or CSR_MSECCFGH without
  a preceding sbi_hart_has_extension check for SBI_HART_EXT_ZKR,
  SBI_HART_EXT_SMPMPM, SBI_HART_EXT_SMEPMP, or SBI_HART_EXT_ZICFILP in the
  same control-flow path
