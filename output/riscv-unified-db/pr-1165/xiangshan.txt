PR #1165  target=xiangshan  overall=compliant
Spec: Six single-precision FP instructions newly declare data_independent_timing: true; any operand-value-dependent execution latency in the XiangShan FPU pipeline (subnormal normalization, NaN fast-return, zero bypass) is a timing side-channel violation
Violation:
  The XiangShan FPU execute pipeline takes data-dependent cycle counts when
  processing fdiv.s, fmul.s, fmadd.s, fmsub.s, fnmadd.s, or fnmsub.s
  instructions. Specifically: (a) subnormal operands trigger the
  softfloat_normSubnormalF32Sig normalization path which may take extra
  microarchitectural cycles vs normal operands; (b) NaN operands (exp==0xFF
  with nonzero sig) take the softfloat_propagateNaNF32UI fast-return path,
  creating a timing differential vs normal computation; (c) zero operands take
  early-return paths with different latency; (d) the fused multiply-add
  sign/subtraction case where both operands are equal and opposite-sign zeros
  (returning +0 or -0 depending on RDN mode) is a rarely-triggered
  microarchitectural corner case with potentially unique timing. The spec
  declares data_independent_timing: true for all these instructions, meaning
  any cycle-count variation based on operand class violates the spec and
  constitutes an observable timing side channel.
Consequence: function_loss
Pattern:
  FPU_EXE.*(fdiv|fmul|fmadd|fmsub|fnmadd|fnmsub).*(io_ready|io_valid|fire|stal
  l)|when.*(isSubnormal|isNaN|isZero|isInf).*{.*delay|when.*(expA.*0xFF|expB.*
  0xFF|sigA.*0|sigB.*0).*{.*latency|io_fpu.*(fdiv_s|fmul_s|fmadd_s|fmsub_s|fnm
  add_s|fnmsub_s).*(pipe_stage|exe_cycles)
