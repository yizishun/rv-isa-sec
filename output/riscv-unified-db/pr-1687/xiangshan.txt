PR #1687  target=xiangshan  overall=bug_confirmed
Spec: MNPELP (bit 9 of mnstatus) must be sampled from the Zicfilp ELP tracking FSM on NMI entry and restored on MNRET; incorrect RW-H encoding, missing wire-up in the CSR write mask, or failure to latch the microarchitectural ELP bit at trap-entry time allows attacker-controlled ELP state manipulation and forward-edge CFI bypass via timed NMI delivery
Violation:
  In XiangShan RTL, the mnstatus CSR module either (a) omits bit 9 (MNPELP)
  entirely from the CSR decode/write mask, causing reads to return 0 and
  writes to be silently dropped; or (b) implements MNPELP as unrestricted RW
  instead of RW-H, allowing software to arbitrarily set the saved ELP state
  and bypass Zicfilp forward-edge CFI on MNRET; or (c) fails to sample the
  active ELP microarchitectural state into MNPELP on NMI trap entry, causing
  stale/incorrect previous-ELP to be restored on MNRET; or (d) resets MNPELP
  to a deterministic 0 instead of UNDEFINED_LEGAL, creating an observable side
  channel where NMI entry reveals prior ELP state via the reset path. In all
  cases, the NMI save/restore path in the CSR module or trap controller does
  not correctly preserve the Zicfilp landing-pad tracking bit across privilege
  transitions.
Consequence: privilege_escape
Pattern:
  mnstatus.*MNPELP|bit.*9.*mnstatus|NMI.*ELP|Zicfilp.*mnstatus|RW-
  H.*MNPELP|UNDEFINED_LEGAL.*mnstatus|nmi_trap_entry.*elp|mnret.*elp_restore

[bug_confirmed] src/main/scala/xiangshan/backend/fu/NewCSR/MachineLevel.scala:602-602  MnstatusBundle
  MNPELP declared as RO (read-only, writes silently dropped) but spec mandates
  RW-H (hardware-writable, software-writable with WARL conversion). RO means
  CSR write instructions (CSRRW/CSRRS/CSRRC) that target bit 9 are silently
  ignored. The spec requires writes to be accepted and WARL-converted to legal
  values (0 or 1). This also means that even if the TrapEntryMNEvent were
  later wired to update MNPELP, software writes that interleave with NMI
  events would be lost rather than arbitrated through the CSRModule's write-
  path mux.
  | val MNPELP = RO          (9).withReset(0.U).withDescription("Saved landing-pad state for resumable NMI handling.")

[potential_risk] src/main/scala/xiangshan/backend/fu/NewCSR/MachineLevel.scala:602-602  MnstatusBundle
  MNPELP resets to deterministic 0 instead of UNDEFINED_LEGAL as specified.
  Per mnstatus.yaml, MNPELP reset_value is UNDEFINED_LEGAL. While 0 is a legal
  value for a 1-bit field, the spec allows implementations to choose any legal
  value at reset. A hardwired 0 is a conforming choice, but the combination of
  RO+reset=0 means the field is permanently 0 — it can never reflect a saved
  ELP state even if Zicfilp were later implemented, since RO prevents hardware
  from writing it through the event path. The practical risk is low since
  Zicfilp is not currently implemented (not in ISA string,
  menvcfg.LPE=mseccfg.MLPE=0), but this creates a silent trap: if Zicfilp is
  later enabled, MNPELP will still read as 0 on MNRET, restoring wrong ELP
  state.
  | val MNPELP = RO          (9).withReset(0.U).withDescription("Saved landing-pad state for resumable NMI handling.")
  References:
    - riscv-unified-db/spec/std/isa/csr/Smrnmi/mnstatus.yaml:60-61
      "type: RW-H, reset_value: UNDEFINED_LEGAL"
