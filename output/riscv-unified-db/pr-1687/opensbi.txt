PR #1687  target=opensbi  overall=not_implemented
Spec: MNPELP (mnstatus bit 9, RW-H) holds the Zicfilp ELP state latched by hardware on RNMI entry; MNRET restores ELP from it. If OpenSBI's CSR save/restore zeroes or corrupts bit 9, MNRET pops a wrong ELP, and the next indirect branch triggers a spurious Zicfilp landing-pad violation trap, crashing the resumed context
Violation:
  OpenSBI blindly saves and restores the full mnstatus CSR word (e.g., during
  HSM suspend/resume or trap entry/exit) without preserving bit 9 (MNPELP),
  overwriting the RW-H hardware-written Zicfilp Expected Landing Pad state
  with a stale or zeroed value
Consequence: denial_of_service
Pattern:
  unconditional csr_write(CSR_MNSTATUS, saved_raw)|bitmask or bitfield
  insertion into mnstatus that clears bit 9|HSM suspend save array that reads
  whole mnstatus into a generic u64 slot without field-level masking for
  MNPELP|MNRET execution path after OpenSBI clobbered mnstatus without proper
  MNPELP preservation

  OpenSBI does not define CSR_MNSTATUS or any mnstatus bit fields (NMIE, MNPV,
  MNPP, MNPELP). The encoding header defines CSR_MEPC (0x341), CSR_MCAUSE
  (0x342), CSR_MSTATUS (0x300), CSR_MSCRATCH (0x340) but has no Smrnmi CSR
  definitions. Without CSR_MNSTATUS macro and MNPELP bit definition, no code
  in the codebase can reference mnstatus state, so the vulnerability pattern
  (blind save/restore of full mnstatus CSR word overwriting MNPELP) cannot
  occur.
