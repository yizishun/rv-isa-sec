PR #662  target=freebsd-src  overall=compliant
Spec: eidelivery hardwired to ACLIC mode (0x20000000) on Smidctrl/Ssidctrl harts silently ignores kernel writes and re-maps eip/eie/eithreshold to APLIC domain state, breaking any FreeBSD code that inspects eidelivery to select interrupt controller code paths
Violation: In the FreeBSD kernel, when running on a hart with Smidctrl/Ssidctrl where eidelivery is WARL-fixed to 0x20000000, any code that writes eidelivery (expecting to set direct/MSI mode) gets silently ignored; the kernel then reads back 0x20000000 which matches none of the known AIA constants (0=direct, 1=MSI, 0x40000000=PLIC/APLIC), causing a branch-miss into undefined behavior where eip/eie CSR aliases point to APLIC domain state rather than IMSIC interrupt files, and eithreshold directly controls the APLIC domain threshold instead of hart-local threshold.
Consequence: denial_of_service
Pattern: csr_write.*eidelivery|csr_read.*eidelivery|eidelivery.*==|switch.*eidelivery|SMAIA.*eidelivery|SSAIA.*eidelivery
