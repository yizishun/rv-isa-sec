PR #662  target=qemu  overall=compliant
Spec: eidelivery CSR becomes read-only fixed to 0x20000000 under Smidctrl/Ssidctrl; QEMU must reject writes or risk guest switching to non-existent IMSIC delivery and breaking interrupt routing
Violation: QEMU emulates Smidctrl/Ssidctrl (formerly Smaclic/Ssaclic) but allows software write to {eidelivery} CSR to change the delivery mode away from 0x20000000, or allows the domaincfg.DM field to be set to a value other than 0 (direct delivery mode). The new spec mandates eidelivery is fixed (read-only) to 0x20000000 and DM is fixed to 0 when ACLIC is present, whereas the old spec only specified reset values and a separate ACLIC delivery mode (DM=2).
Consequence: denial_of_service
Pattern: eidelivery.*writable|write_eidelivery|eidelivery.*reset.*0x20000000|DM.*=.*2|ACLIC.*delivery.*mode|domaincfg.*WARL|smaclic.*eidelivery|smidctrl.*eidelivery
