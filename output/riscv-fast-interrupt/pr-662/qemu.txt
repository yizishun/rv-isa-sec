PR #662  target=qemu  overall=potential_risk
Spec: eidelivery CSR hardening: spec changes from reset-initialized to read-only-fixed 0x20000000 for ACLIC; writable implementation allows guest to break interrupt delivery path
Violation: QEMU implements eidelivery CSR as writable (old spec: 'reset initializes to 0x20000000') instead of read-only fixed to 0x20000000 as required by the new spec when Smidctrl/Ssidctrl are present, allowing guest software to switch interrupt delivery mode away from ACLIC direct delivery
Consequence: denial_of_service
Pattern: eidelivery.*writ|eidelivery.*reset|0x20000000.*writable|ACLIC.*delivery.*mode.*switch
------------------------------------------------------------
[potential_risk] hw/intc/riscv_imsic.c:90-106  riscv_imsic_eidelivery_rmw
  eidelivery CSR is unconditionally writable via bit 0: the RMW function allows guest software to set or clear the delivery bit (wr_mask &= 0x1; imsic->eidelivery[page] = (old_val & ~wr_mask) | (new_val & wr_mask)). When Smidctrl/Ssidctrl are present (the ACLIC rework PR's target), the new spec requires eidelivery to be read-only fixed to 0x20000000. If this function is not gated on the absence of Smidctrl/Ssidctrl, a guest could switch interrupt delivery away from ACLIC direct delivery mode, causing denial of service.
