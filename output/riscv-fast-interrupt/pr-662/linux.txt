PR #662  target=linux  overall=bug_confirmed
Spec: eidelivery CSR hardwired to 0x20000000 on ACLIC systems (Smidctrl/Ssidctrl) breaks existing kernel AIA interrupt drivers that only handle delivery modes 0/1/0x40000000, causing unrecognized-mode fallback and loss of all external interrupt delivery
Violation: Linux kernel AIA interrupt driver (irq-riscv-imsic.c, irq-riscv-aplic.c) reads eidelivery CSR and branches on values 0 (none), 1 (IMSIC/MSI), or 0x40000000 (PLIC/APLIC direct), but encounters the hardwired value 0x20000000 on ACLIC systems — an unrecognized delivery mode. Writes to eidelivery intended to switch modes are silently ignored because the CSR is fixed. Additionally, kernel SMP code assumes per-hart IMSIC interrupt files with independent pending/enable bits, but ACLIC hart-local APLIC domains are single-hart-only with no IDC structures for multi-hart delivery, causing secondary harts to lack functional external interrupt delivery.
Consequence: denial_of_service
Pattern: eidelivery.*0x[01]|CSR_IEIDELIVERY|riscv_imsic_eidelivery|switch.*delivery.mode|imsic.*probe.*eidelivery|aplic.*probe.*eidelivery|case 0x40000000|readl.*IEIDELIVERY
