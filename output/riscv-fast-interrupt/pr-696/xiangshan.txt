PR #696  target=xiangshan  overall=compliant
Spec: ACLIC threshold comparison must use the single xtopi-derived IPRIO (highest pending-enabled priority), not per-source iprio[i]; mismatched internal logic causes incorrect interrupt masking and potential denial of service.
Violation: In XiangShan's ACLIC/PLIC interrupt controller module, the threshold masking logic still performs per-interrupt-source comparison using each source's individual configured priority (iprio[i]) against xithreshold, rather than using the globally-reported xtopi.IPRIO value (the highest priority among all pending-enabled interrupts). Specifically, if the hardware iterates over interrupt sources and masks each source when its own iprio[i] >= xithreshold & NIPPRIO_MASK, it implements the old pre-PR#696 semantics. The new spec requires the threshold to gate based on the single IPRIO value derivable from the xtopi CSR, which reflects the highest-priority pending-enabled interrupt. Additionally, if the internal threshold-comparison signal diverges from the xtopi CSR read path—e.g., the CSR reports a different priority-ordering result than the comparison logic uses—the hardware violates the normative definition that IPRIO 'is the value reported in the xtopi CSR.'
Consequence: denial_of_service
Pattern: iprio.*threshold|threshold.*iprio|xtopi.*IPRIO|priority.*compare.*xithreshold|xithreshold.*gte|threshold_mask.*per_source|interrupt.*threshold.*priority[^_]
