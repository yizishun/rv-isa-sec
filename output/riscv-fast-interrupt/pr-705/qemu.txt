PR #705  target=qemu  overall=compliant
Spec: ACLIC indirect register range 0x1000–0x1100 must trap xireg4–xireg6 as illegal instruction and must trap odd xiselect+xireg on XLEN=64; QEMU currently traps everything in this range via default rmw_xireg_csrind() fallthrough, but a future ACLIC handler must not silently expose reserved-register state or allow unaligned access
Violation: When QEMU adds ACLIC/Smidctrl indirect CSR access support (xiselect range 0x1000-0x1100) but (1) fails to reject xireg4–xireg6 accesses in that range with illegal-instruction exception, or (2) on XLEN=64 hosts, fails to reject odd-valued xiselect in that range when accessing xireg (sireg/mireg/vsireg). Currently QEMU does not implement Smidctrl at all, so the range correctly falls through to the default illegal-instruction trap in rmw_xireg_csrind(); the risk is in a future implementation that adds an xiselect_aclic_range() handler without validating reserved sub-register indices and XLEN-dependent even/odd alignment constraints.
Consequence: info_leak
Pattern: xiselect_aclic_range.*0x100[0-f]|isel.*0x100[0-f]|rmw_xireg.*aclic|rmw_iprio.*xlen.*odd.*iselect — any added ACLIC range check in rmw_xireg_csrind() that neglects to validate csrno range for xireg4–xireg6 or neglects XLEN-dependent even-select constraint for xireg in 0x1000–0x1100

  QEMU currently does not implement Smidctrl/Ssidctrl (ACLIC) at all. The xiselect range 0x1000-0x10FF used by ACLIC is not handled by any existing range dispatch function (xiselect_aia_range covers 0x30-0x3F and 0x70-0xFF; xiselect_cd_range covers 0x40-0x5F; xiselect_ctr_range covers 0x200-0xFFF). All accesses with isel in 0x1000-0x10FF through xireg, xireg2-xireg6 correctly fall through to the default RISCV_EXCP_ILLEGAL_INST at line 2845, matching the specification requirement that unimplemented regions raise illegal instruction.

[potential_risk] target/riscv/csr.c:2829-2854  rmw_xireg_csrind
  If Smidctrl/ACLIC support is added in the future by inserting an xiselect_aclic_range() check into the rmw_xireg_csrind() dispatch chain (before the default illegal-instruction fallback), the implementation must enforce two constraints from the ACLIC spec: (1) xireg4–xireg6 (CSR_SIREG4–CSR_SIREG6, CSR_MIREG4–CSR_MIREG6, CSR_VSIREG4–CSR_VSIREG6) must raise illegal instruction when xiselect is in 0x1000–0x10FF since these sub-registers are reserved for ACLIC; (2) on XLEN=64 hosts, odd-valued xiselect in 0x1000–0x10FF must raise illegal instruction for xireg access. Failure to enforce either constraint would allow guest reads/writes to reserved register slots, leaking implementation state (info_leak).
