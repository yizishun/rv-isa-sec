PR #761  target=xiangshan  overall=compliant
Spec: Off-by-one in smidctrl xiselect reserved-range upper bound (0x1100 instead of 0x10FF) causes xireg4-6 illegal-instruction trap on the valid xiselect=0x1100 entry, blocking ACLIC interrupt-priority/sourcecfg register access at the last index
Violation: In XiangShan RTL, if the smidctrl indirect CSR access decoder implements the original (buggy) xireg4-xireg6 reserved range check as `xiselect >= 0x1000 && xiselect <= 0x1100` (inclusive upper bound 0x1100, i.e., `<= 0x1100.U` or `< 0x1101.U` in Chisel), then when xiselect = 0x1100, the hardware will raise an illegal instruction exception (EX_II) on xireg4/xireg5/xireg6 access, blocking legitimate access to acliciprio255 and aclicsourcecfg510/511 which the spec table lists as valid entries at xiselect=0x1100. The correct constraint is xiselect in range 0x1000-0x10FF (upper bound exclusive of 0x1100, i.e., `< 0x1100.U` or `<= 0x10FF.U`).
Consequence: denial_of_service
Pattern: xiselect[>=]0x1000.*xiselect[<=]0x1100|xiselect.*<.*0x1101|iselect.*MuxLookup.*0x1100|Range\.inclusive\(0x1000,\s*0x1100\)
