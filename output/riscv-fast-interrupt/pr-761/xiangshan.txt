PR #761  target=xiangshan  overall=compliant
Spec: Spec fixes xiselect upper bound from 0x1100 to 0x10FF (off-by-one: 0x1100 was the 257th index for 256-entry arrays). If RTL hardcodes the old 0x1100 bound in range-check comparators or uses it as the last valid table index, xireg/xireg2/xireg3 access at xiselect=0x1100 reads/writes array index 256 beyond the allocated 256-entry register file, leaking adjacent hardware register state or corrupting unrelated CSR storage
Violation: XiangShan RTL implements the old (pre-fix) xiselect range check where xireg4-xireg6 raise illegal instruction only when xiselect is in 0x1000-0x1100 (inclusive) instead of the corrected 0x1000-0x10FF, AND/OR the iprio/sourcecfg indirect access array is sized for 256 entries (index 0-255) but the decode logic treats xiselect=0x1100 as a valid index, causing an off-by-one out-of-bounds access to register array index 256 for both read (xireg/xireg2/xireg3) and write paths
Consequence: info_leak
Pattern: (0x1100|0x1100U|h1100).*xiselect|xiselect.*(0x1100|>=.*0x1100|<=.*0x1100)|acliciprio.*255.*0x1100|aclicsourcecfg.*511.*0x1100|MuxLookup.*xiselect.*256|VecInit.*256.*iprio|WireInit.*xireg.*0x1100
