PR #761  target=qemu  overall=bug_confirmed
Spec: PR #761 fixes the Smidctrl xiselect reserved-range upper bound from 0x1100 to 0x10FF (off-by-one correction); QEMU does not yet implement Smidctrl ACLIC indirect access, but when adding it, a boundary comparison using the old <=0x1100 would wrongly trap legitimate access to entry 256, denying functionality
Violation: When QEMU implements the Smidctrl ACLIC indirect CSR access (xiselect range 0x1000-0x10FF for xireg4-xireg6 iprio/sourcecfg) and the upper-bound check uses '<=' or '<=' with the old off-by-one value 0x1100 instead of 0x10FF, xiselect=0x1100 is incorrectly rejected as reserved. Conversely, if the xiselect writable mask (ISELECT_MASK_SXCSRIND=0xfff, which truncates bits 12+) is applied before the range comparison, values like 0x1100 could be aliased to 0x100 and mishandled.
Consequence: function_loss
Pattern: off-by-one range boundary: xiselect <= 0x1100 or xiselect < 0x1100 vs correct xiselect <= 0x10FF; also masking xiselect before ACLIC range check causing alias collisions with lower regions
------------------------------------------------------------
[bug_confirmed] target/riscv/cpu_bits.h:1050-1050  
  ISELECT_MASK_SXCSRIND is defined as 0xfff (12 bits), which masks out bit 12 and above. The Smidctrl ACLIC indirect CSR access range is xiselect 0x1000-0x10FF, which requires bit 12 to be set. When smcsrind/sscsrind is enabled, rmw_xiselect() applies wr_mask &= ISELECT_MASK_SXCSRIND (csr.c:2456), silently truncating xiselect=0x1000 to 0x000, xiselect=0x10FF to 0x0FF, and xiselect=0x1100 to 0x100. This would alias Smidctrl ACLIC register accesses to lower register regions (undefined/IMSIC range), causing silent guest state corruption when Smidctrl is implemented.
  | #define ISELECT_MASK_SXCSRIND              0xfff

[bug_confirmed] target/riscv/csr.c:2455-2456  rmw_xiselect
  rmw_xiselect() applies ISELECT_MASK_SXCSRIND (0xfff) unconditionally when smcsrind/sscsrind is enabled, regardless of whether Smidctrl is also enabled. Since 0xfff masks out bit 12, any write of xiselect values in the Smidctrl ACLIC range (0x1000-0x10FF) is silently truncated. Verified: 0x1000 & 0xfff = 0x000, 0x10FF & 0xfff = 0x0FF, 0x1100 & 0xfff = 0x100. When a future Smidctrl implementation is added, the guest will observe miselect/siselect values different from what it wrote, breaking ACLIC register access.
