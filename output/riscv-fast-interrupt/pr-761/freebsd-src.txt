PR #761  target=freebsd-src  overall=compliant
Spec: FreeBSD has no xiselect/xireg implementation yet, but any future kernel CLIC/SMIDCSR emulation or bhyve virtualized CSRs using the old 0x1100 inclusive bound would fail to trap xiselect=0x1100 as illegal, leaking reserved state
Violation: If FreeBSD kernel or bhyve VMM implements xiselect/xireg indirect CSR emulation and uses the pre-fix upper bound of 0x1100 (inclusive) instead of 0x10FF (inclusive) for the ACLIC reserved-raise-illegal range, then xiselect=0x1100 accessing xireg4/xireg5/xireg6 will silently read/write undefined microarchitectural state instead of raising an illegal instruction trap, either in the kernel itself or in a bhyve guest escaping virtualization boundaries
Consequence: info_leak
Pattern: xiselect > 0x10FF|xisel.*0x1100|case.0x11[0-9A-F]{2}.*xireg|xireg.*bound.*0x11
