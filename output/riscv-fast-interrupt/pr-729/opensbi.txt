PR #729  target=opensbi  overall=compliant
Spec: Smivt IVT mode hardware now auto-clears interrupt-pending bits on trap entry; OpenSBI M-mode handlers that read pending registers after trap entry to identify the interrupt source will see stale/zero bits on edge-triggered interrupts, causing interrupt source loss and unhandled interrupts.
Violation: In OpenSBI M-mode interrupt trap handler, when the hardware (via Smivt IVT mode) automatically clears the interrupt-pending bit before the firmware handler executes, any firmware code that reads the pending register (e.g., mip, sip, or ACLIC interrupt-pending registers) to identify the interrupt source will observe already-cleared bits, losing information about which interrupt triggered the trap—especially for edge-triggered interrupts where clearing is guaranteed.
Consequence: function_loss
Pattern: reading_cleared_pending_bit|mip_read_in_trap_handler|interrupt_source_from_pending_register
