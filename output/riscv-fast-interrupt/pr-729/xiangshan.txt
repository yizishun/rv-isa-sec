PR #729  target=xiangshan  overall=compliant
Spec: ACLIC spec requires hardware to clear corresponding interrupt-pending bit in IVT mode upon successful handler fetch; missing this clear causes level-sensitive interrupts to remain pending, triggering immediate re-trap upon handler entry and creating an infinite trap-loop denial-of-service
Violation: In XiangShan RTL, when ACLIC IVT mode is implemented and a trap is taken due to an interrupt, the entry logic in TrapHandleModule.scala and TrapEntryMEvent/TrapEntryHSEvent/TrapEntryVSEvent modules transitions to the handler PC via the in-memory vector table read, but does NOT write to or clear the corresponding interrupt-pending bit (e.g., CLIC/ACLIC per-interrupt pending register bits or standard mip/sip CSR pending bits). Specifically, for level-sensitive interrupts (e.g., software interrupts), the pending bit remains asserted after trap entry because no hardware clear path exists between the IVT handler-fetch logic and the interrupt pending register bank. The trap entry event modules only update mstatus/mepc/mcause/mtval registers with no side effect to interrupt pending state.
Consequence: denial_of_service
Pattern: IVT mode trap handler fetch at (VTBASE+XLEN/8*exccode) followed by PC redirect WITHOUT corresponding interrupt-pending bit write/clear operation; absence of Mux/Bool/Reg write targeting interrupt pending register (ip_reg, ipReg, interruptPending, irq_pending) in the trap-entry-to-IVT-handler data path; TrapHandleModule/TrapEntryEvent contains no connection to InterruptFilter/InterruptBundle for pending-bit deassertion

[potential_risk] src/main/scala/xiangshan/backend/fu/NewCSR/MachineLevel.scala:260-311  mip CSR register logic
  The mip register logic shows that interrupt pending bits (MSIP, SSIP, VSSIP) are software-writable via CSR writes, while external/timer pending bits (MEIP, SEIP, MTIP, STIP) are read-only and driven by platform interrupt sources. If Smivt IVT mode is added in the future, the mip register would need a new write path for hardware-initiated pending-bit clearing (specifically for edge-triggered interrupts where software-writable pending bits must be cleared by hardware on IVT trap entry). The current register logic has no such path.
