PR #729  target=xiangshan  overall=compliant
Spec: No RTL path clears CLIC interrupt-pending bits on IVT-mode trap entry; pending bits are RO-hardwired, causing infinite interrupt re-triggering and hart livelock (DoS)
Violation: When XiangShan RTL implements CLIC IVT (Interrupt Vector Table) mode for xtvec but DOES NOT clear the corresponding interrupt-pending bit during trap entry after fetching the handler address from the in-memory table. Specifically: (a) the trap entry event modules (TrapEntryMEvent/VSEvent/HSEvent) and TrapHandleModule do not touch CLIC interrupt-pending registers at all—the pending bits are defined as RO (hardwired from external sources), so no existing RTL path clears them on trap entry; (b) for level-sensitive interrupts, the RTL must NOT clear the pending bit (since the external source still asserts it), but if the RTL implements a blanket clear-all-pending-bits approach without distinguishing edge-triggered vs level-sensitive interrupt sources, level-sensitive interrupts would be incorrectly de-asserted, masking the ongoing interrupt condition; (c) the xtvec CSR fields in XiangShan currently only encode Direct and Vectored modes—no IVT mode bits exist, so the entire IVT fetch-and-clear sequence is unimplemented.
Consequence: denial_of_service
