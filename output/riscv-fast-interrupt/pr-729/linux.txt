PR #729  target=linux  overall=compliant
Spec: Spec change clarifies that level-sensitive CLIC IVT interrupts may retain pending bit after hardware entry; kernel handlers must explicitly clear it to prevent interrupt storms
Violation: In the Linux kernel, a CLIC IVT-mode interrupt handler assumes the hardware has already cleared the interrupt-pending bit upon trap entry and skips explicitly writing to the interrupt-pending-clear register (clicintip[i] MMIO or claimi window). For level-sensitive interrupts, the hardware cannot clear the pending bit (per the 'if possible' qualifier), so the interrupt remains asserted and re-fires immediately upon sret/mret, creating an unbounded interrupt storm.
Consequence: denial_of_service
Pattern: CLIC IVT-mode interrupt handler that enters via xtvec=IVT mode but does not write to clicintip clear/claimi before sret/mret, or that gates the clear on a condition evaluating false for level-sensitive interrupts
