PR #729  target=linux  overall=compliant
Spec: Smivt IVT mode now auto-clears interrupt-pending bits on trap entry; kernel/KVM irqs_pending tracking and mip-read-based IRQ dispatch can observe cleared bits and lose or misroute interrupts
Violation: The kernel's IRQ entry path (do_irq / handle_arch_irq) or KVM's interrupt dispatch reads mip/sip/hvip to determine which external interrupt fired, but in Smivt IVT mode the hardware auto-clears the corresponding interrupt-pending bit on vector-trap entry before the handler executes, so software observes a stale (cleared) pending bit and either misses the interrupt source or incorrectly dispatches.
Consequence: race_condition
Pattern: csrr.*mip|csrr.*sip|csrr.*hvip in IRQ entry/dispatch paths that assume interrupt-pending bits remain set across IVT-mode hardware vectoring
