PR #718  target=linux  overall=potential_risk
Spec: Spec correction: xithreshold on trap entry must reflect the effective interrupt priority level (IPRIO), not the per-source priority iprio[i]; kernel nested-interrupt and context-switch paths that assume the old behavior are vulnerable to incorrect interrupt masking and handler reentrancy.
Violation: On hardware implementing the buggy (pre-fix) behavior where xithreshold ← iprio[i] instead of IPRIO, the kernel's nested-interrupt handler executes with an incorrect interrupt-enable threshold. If IPRIO reflects a priority level different from the per-source iprio[i] (e.g., after priority-inheritance, delegation, or selectable priority groups), the wrong threshold either (a) permits lower-priority interrupts to preempt the handler, creating reentrancy races on per-CPU kernel data structures, or (b) masks higher-priority interrupts needed for correctness, such as an IPI or timer tick that must not be deferred indefinitely.
Consequence: race_condition
Pattern: xithreshold CSR save/restore in trap entry/exit paths that assumes threshold equals the fixed per-interrupt priority rather than the effective priority level IPRIO; any kernel code reading xithreshold in a nested handler and comparing it against a pre-computed iprio[i] array to decide whether to re-enable interrupts.
------------------------------------------------------------

[potential_risk] arch/riscv/kernel/traps.c:173-196  do_trap_insn_illegal
  User-mode synchronous exception handlers call local_irq_enable() (line 179) which sets sstatus.SIE without touching sithreshold. On Smnip hardware, if a prior interrupt handler set sithreshold to a high (permissive) value and then a synchronous exception occurred (which does NOT modify sithreshold per spec line 834), calling local_irq_enable() would re-enable interrupts at whatever sithreshold was left by the prior interrupt. This becomes a reentrancy risk on buggy hardware where sithreshold was set to iprio[i] instead of IPRIO — the wrong threshold could allow lower-priority interrupts to preempt. The DO_ERROR_INFO macro (line 155), do_trap_misaligned (line 225), and do_trap_break (line 311) have the same pattern.
  | if (user_mode(regs)) {
  |     irqentry_enter_from_user_mode(regs);
  |     local_irq_enable();              // line 179 -- SIE=1, threshold unchanged
  |     handled = riscv_v_first_use_handler(regs);
  |     ...
  |     local_irq_disable();             // line 186

[potential_risk] arch/riscv/kernel/entry.S:421-471  __switch_to
  Context switch saves/restores only callee-saved GPRs and sstatus.SUM bit (lines 442-451). On Smnip hardware, sithreshold and spistatus are per-hart state that must be saved/restored across context switches to prevent leakage of one task's interrupt threshold context to another. The current code does neither, meaning a task's sithreshold value would persist across context switches.
