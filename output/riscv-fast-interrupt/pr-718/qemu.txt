PR #718  target=qemu  overall=compliant
Spec: Smnip trap entry must set xithreshold to IPRIO (current priority level) not iprio[i] (incoming interrupt priority) — using iprio[i] incorrectly resets threshold to the incoming interrupt's priority, allowing lower-priority interrupt preemption when threshold was already higher
Violation: QEMU emulates a trap taken on interrupt i into level x under Smnip and sets {xithreshold} to iprio[i] (the priority of the incoming interrupt) rather than the current IPRIO (the active interrupt priority before trap entry). If the previous threshold was already elevated above iprio[i] (e.g., a higher-priority interrupt was being serviced), this incorrectly lowers the threshold, allowing lower-priority interrupts to preempt the handler.
Consequence: privilege_escape
Pattern: xithreshold = iprio[interrupt_id] or xithreshold = interrupt_priority (value derived from the triggering interrupt, not from the current IPRIO CSR field) during trap entry in ACLIC/Smnip interrupt handling path
