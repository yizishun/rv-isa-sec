PR #775  target=linux  overall=compliant
Spec: APLIC index-0 entities (acliciprio[0] target[0] bits, aclicsourcecfg[0]) are read-only zero; writes via indirect CSR (xiselect/xireg) are silently dropped, causing firmware/hypervisor to operate on stale assumed state for source 0
Violation: Kernel or M-mode firmware writes to acliciprio[0] or aclicsourcecfg[0] via the Smaia/Ssaia indirect CSR access mechanism (xiselect/xireg), expecting the write to configure interrupt source 0 or target 0, but hardware silently drops the write because APLIC domains do not implement target[0] and aclicsourcecfg[0] is read-only zero
Consequence: function_loss
Pattern: xiselect.*0x[0-9a-fA-F]*01|write.*xireg.*sourcecfg.*0|acliciprio\[0\]|aclicsourcecfg\[0\]|sourcecfg.*index.*0
