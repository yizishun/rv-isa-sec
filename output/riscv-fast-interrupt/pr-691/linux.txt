PR #691  target=linux  overall=compliant
Spec: Removal of conditional stack swap (cspspush/cspspop) from CLIC fast interrupt entry/exit means the hardware now unconditionally saves registers onto the interrupted context's stack; in KVM this is the guest-controlled stack pointer, creating a data corruption surface if the hypervisor does not ensure guest sp validity before enabling fast interrupts during guest execution.
Violation: In KVM, when HS-mode enables CLIC fast interrupts (selected interrupt files configured with Smip-style hardware save/restore) while the hart is executing in VS/VU-mode, the hardware unconditionally saves x10-x15 onto the guest's stack. If the guest stack pointer (sp) is malicious, unmapped, or misaligned, the hardware save triggers a fault at a point where the hypervisor cannot safely recover, or silently corrupts guest memory that the hypervisor relies on for paravirtualized state.
Consequence: data_corruption
Pattern: KVM CLIC interrupt enablement paths where guest stack pointer validity is not verified before allowing hardware register save to the guest-owned stack during VS/VU-mode execution — grep for CLIC/Smip interrupt file configuration combined with KVM guest entry/exit paths (kvm_riscv_vcpu_enter, __kvm_riscv_switch_to, clic interrupt routing)
