PR #691  target=freebsd-src  overall=compliant
Spec: FreeBSD currently has no Smip implementation, but any future port must not assume hardware stack isolation — the new spec leaves the interrupted context's stack exposed to handler save/restore, so the handler's ABI frame must be compatible with whatever stack the interrupted code was using
Violation: A FreeBSD Smip interrupt handler implementation that assumes the hardware performs automatic stack pointer swapping (cspspush/cspspop per the old spec) and therefore does not reserve frame space on the interrupted context's stack, or relies on automatic stack isolation to protect the interrupted context's stack from handler spill. Under the new spec, the handler unconditionally saves x10-x15 directly onto the interrupted context's stack without any swap, so any gap between the interrupted frame and the handler's assumed save area results in silent register corruption on the victim stack.
Consequence: data_corruption
Pattern: riscv_cspspush|riscv_cspspop|sstatus\.sxsp|sstatus\.mxsp|SP_SWAP|stackptr_swap|smip_stack_switch|condition.*stack.*swap
