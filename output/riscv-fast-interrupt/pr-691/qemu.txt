PR #691  target=qemu  overall=compliant
Spec: Stale conditional stack-swap (cspspush/cspspop) in QEMU interrupt entry/exit corrupts interrupted-context stack when guest targets post-PR#691 no-swap behavior
Violation: QEMU TCG implements Smip fast interrupt entry/exit with the old conditional stack-swap behavior (cspspush during save, cspspop during restore), but guest software is written against the new spec where context is saved directly on the interrupted context's own stack — no swap occurs — causing the handler to save/restore to the wrong memory region
Consequence: data_corruption
Pattern: cspspush OR cspspop in interrupt-entry/exit TCG translation; conditional stack-swap logic in CLIC/Smip trap handling path; stack pointer swap gating on xsp/SPP state during hwint save-restore
------------------------------------------------------------
