PR #691  target=xiangshan  overall=compliant
Spec: Removing conditional stack swap (cspspush/cspspop) from CLIC trap entry/exit means interrupt context is now saved on the interrupted context's stack; hardware that still performs the swap would corrupt the wrong stack and break OS thread switching semantics
Violation: XiangShan RTL's CLIC/Smip trap entry FSM still executes cspspush (stack pointer swap to xsp) during ipush, or trap exit FSM still executes cspspop during ipopxret, after the spec has removed these conditional stack swaps. The hardware would switch to a different stack (the dedicated interrupt stack via xsp) instead of using the interrupted context's own stack for saving x10-x15 and the stack frame.
Consequence: data_corruption
Pattern: ipush.*cspspush|ipopxret.*cspspop|clic_trap_entry.*stack_swap|clic_trap_exit.*stack_swap|SmipFSM.*csps|smippush.*xsp|smippop.*xsp
