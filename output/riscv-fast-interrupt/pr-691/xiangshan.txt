PR #691  target=xiangshan  overall=compliant
Spec: Stale cspspush/cspspop stack-swap micro-ops in Smip trap entry/exit instructions cause interrupted context to be saved on an attacker-controlled interrupt stack instead of the victim's own stack, enabling privilege escalation via stack-pointer hijack
Violation: The XiangShan RTL implementation of the Smip fast-interrupt handler instructions (ipopxresprestore on trap entry, ipopxret on trap exit) still executes the conditional stack-pointer swap micro-operations (cspspush sp / cspspop sp) that were removed from the spec. Specifically, during ipopxresprestore, the hardware reads the xsp CSR and swaps it with sp, saving the interrupted context's registers to the swapped-in interrupt stack instead of the interrupted context's own stack. During ipopxret, the hardware performs the reverse swap before xret, restoring the original sp from xsp. This stale behavior persists if the Chisel-generated RTL or microcode ROM for these pseudo-instructions was not updated to match the spec change.
Consequence: privilege_escape
Pattern: cspspush|cspspop|ConditionalStackSwap|xsp_csr|SMIP_STACK_SWAP|ipopx.*swap|CspsPush|CspsPop|spSwap
