PR #760  target=qemu  overall=compliant
Spec: Smivt vector table handler address must use vtoffset not exccode; computing the handler slot via exccode/cause would fetch from wrong table entry, redirecting execution to attacker-controlled memory
Violation: If QEMU were to implement Smivt/ACLIC vector table mode and compute the in-memory handler address using exccode (the trap cause number) instead of vtoffset (the vector table offset index), the handler address fetch would target the wrong vector table slot. The spec change clarifies that vtoffset, not exccode, indexes the handler table. Using exccode would cause the hart to fetch an XLEN-sized value from VTBASE + XLEN/8 * exccode rather than VTBASE + XLEN/8 * vtoffset, which are semantically different fields (cause codes and vector offsets are independently assigned).
Consequence: function_loss
Pattern: VTBASE.*XLEN.*exccode|handler.*addr.*cause|vectored.*fetch.*exccode
