PR #656  target=opensbi  overall=compliant
Spec: Removal of explicit mithreshold CSR in favor of interrupt-file eithreshold means OpenSBI HSM context save/restore must use indirect CSR access (siselect+sireg) instead of direct CSR read/write to preserve M-mode interrupt threshold across hart suspend/resume
Violation: OpenSBI HSM hart suspend/resume saves M-mode CSR context but fails to save/restore the M-mode interrupt file eithreshold (accessed indirectly via siselect/sireg, not via a dedicated CSR number), because the explicit mithreshold CSR was removed and eithreshold now serves as the interrupt enable threshold for nested preemption under Smnip.
Consequence: denial_of_service
Pattern: HSM suspend handler saves M-mode CSRs by CSR number list but omits indirect CSR save/restore of eithreshold via siselect+sireg sequence; resume restores stale or zero eithreshold causing all M-mode interrupts to be incorrectly masked or unmasked after hart wakeup
