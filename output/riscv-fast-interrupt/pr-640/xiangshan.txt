PR #640  target=xiangshan  overall=compliant
Spec: Removal of Smaiae embedded subset and direct routing of ACLIC dependencies to full Smaia/Ssaia means virtual interrupt CSRs (mvip/mvien) must follow AIA WARL rules — hardcoding them to read-only zero (the old Smaiae behavior) causes silent virtual interrupt delivery failure, which is a hardware-level privilege escape where supervisor interrupts that should be injectable per spec are permanently masked
Violation: XiangShan RTL hardcodes mvip/mvien (or hip/hvip/hvien) CSR fields to read-only zero based on the removed Smaiae extension's constraints, but the CSR module now claims direct Smaia/Ssaia dependency per the updated spec — software relying on virtual interrupt injection via these CSRs (e.g., supervisor-level interrupt preemption or delegated interrupt handling) will silently fail because the hardware ignores writes to virtual interrupt pending/enable bits that the full AIA spec permits to be implemented as WARL-writable
Consequence: privilege_escape
Pattern: mvip.*readOnly|mvien.*readOnly|hvip.*readOnly|hvien.*readOnly|virtualInterrupt.*false|RO_ZERO.*mvip|RO_ZERO.*mvien|Smaiae.*hardcoded|embeddedSubset.*aia
