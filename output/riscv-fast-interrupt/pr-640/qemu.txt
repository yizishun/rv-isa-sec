PR #640  target=qemu  overall=compliant
Spec: PR removes Smaiae (AIA-for-embedded); Smaclic/Ssaclic/Smnip now depend directly on Smaia/Ssaia — QEMU must update its extension dependency logic to drop Smaiae gating, remove Smaiae from ISA strings, and ensure xvip/xvien WARL behavior reflects full Smaia/Ssaia semantics rather than the deleted Smaiae read-only-zero constraint
Violation: QEMU continues to gate CSR accessibility or extension enablement on the now-removed 'Smaiae' extension (e.g., Smaclic/Ssaclic/Smnip still requiring Smaiae in an extension dependency table), OR QEMU continues to expose 'Smaiae' in the ISA string or misa extension bitmap when the spec has deleted it, causing guest kernels to make incorrect assumptions about available AIA features (especially xvip/xvien/xviph/xvienh behavior previously mandated as read-only zero under Smaiae)
Consequence: denial_of_service
Pattern: smaiae|Smaiae|SMAIAE|smaia_dependency|ext_smaiae
