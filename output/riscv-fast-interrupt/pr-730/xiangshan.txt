PR #730  target=xiangshan  overall=potential_risk
Spec: CLIC nested trap entry must preserve original interrupt epc in xepc/mnepc during synchronous exceptions in context save path, or interrupt handler silently dropped causing privilege-level control flow hijack
Violation: In XiangShan RTL, when a synchronous exception (e.g., page fault from stack access) occurs during CLIC hardware context save/restore, the trap entry CSR logic must write the original interrupt's exception PC into xepc/mnepc of the second trap, NOT the PC of the faulting instruction. If the hardware overwrites xepc/mnepc with the faulting instruction's own PC (the standard trap behavior), then after the exception handler executes MRET/SRET, execution resumes at the faulting instruction instead of the original interrupt handler entry point, causing the interrupt handler to be silently skipped.
Consequence: privilege_escape
Pattern: when (isCLICDoubleTrap || isNestedTrapInHandler) && (exceptionDuringContextSave) => xepc/mnepc must load from saved_original_epc, NOT from excuting_pc
