PR #730  target=freebsd-src  overall=compliant
Spec: Smip fault handling requires double-trap extensions for recoverability; FreeBSD neither implements Smip nor probes for Ssdtcp/Smdbltrp in identcpu.c, so any future CLIC enablement without first adding double-trap recovery would make synchronous exceptions during fast-interrupt save/restore permanently unrecoverable (unbounded re-trap loop)
Violation: In FreeBSD's RISC-V port, if Smip fast-interrupt context save/restore (via mnxti/mscratchcsw) is implemented without also implementing the double-trap extension (Ssdtcp/Smdbltrp), any synchronous exception (page fault, TLB miss) occurring during the hardware-injected register save/restore sequence produces unrecoverable trap state: mnepc/xepc holds the *first* trap's PC rather than the faulting instruction's PC, the kernel cannot distinguish the nested-trap scenario, and returning to the first trap's PC immediately re-traps without forward progress.
Consequence: denial_of_service
Pattern: mnxti|mscratchcsw|CSR_MNXTI|CSR_MSCRATCHCSW without Ssdtcp|Smdbltrp|double.?trap check in ISA extension probing or init code
