PR #699  target=xiangshan  overall=compliant
Spec: xivt bit[0] EHV field must be implemented as WARL (not hardwired-zero) and correctly gates synchronous exception vectoring path; off-by-one bit mapping between Chisel CSR Bundle and spec-defined encoding causes BASE corruption or silent EHV disable
Violation: The xivt CSR in XiangShan CSR module hardwires bit[0] (EHV) as read-only-zero or ignores it during exception trap vectoring address generation. When software sets xivt.EHV=1 to enable synchronous exception hardware vectoring, the hardware either silently reads back 0 (WARL violation: field must be WARL per spec, not hardwired-zero in implementations claiming Smehv support) or ignores EHV and still uses the standard xtvec-based trap path without vectoring. Additionally, if the EHV bit position is misaligned in the Chisel Bundle field definition (off-by-one shifting BASE address bits), writing xivt corrupts the vector table base address or the EHV control state leaks into the address path.
Consequence: privilege_escape
