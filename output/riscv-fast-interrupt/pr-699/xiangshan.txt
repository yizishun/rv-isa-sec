PR #699  target=xiangshan  overall=potential_risk
Spec: xivt bit 1 redefined as EHV enable for synchronous exception vectoring; hardware must either hardwire EHV=0 with complete BASE masking or fully implement xtvec+cause*32 trap target computation, otherwise exception traps route to attacker-controlled addresses
Violation: In XiangShan RTL, the xivt CSR (mivt at 0x307 or sivt at 0x107) implements bit 1 as a writable EHV field (WARL, not hardwired to 0), but the trap entry datapath in the CSR module does not implement synchronous exception hardware vectoring logic—i.e., when EHV=1, the exception trap target PC is not computed as xtvec + (mcause/scause × 32), causing traps to fall through to the default xtvec handler or an unpredictable address. Conversely, if bit 1 is hardwired to 0 but the BASE field incorrectly extends down to bit 1, writing bit 1 of the BASE address could be misinterpreted as setting EHV by software expecting Smehv/Ssehv semantics.
Consequence: privilege_escape
Pattern: mivt.*bit.*1|sivt.*bit.*1|xivt.*EHV|xtvec.*cause|exception.*vector.*PC|trapEntry.*xtvec|cause.*32.*xtvec
