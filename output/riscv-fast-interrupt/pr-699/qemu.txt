PR #699  target=qemu  overall=compliant
Spec: Smehv/Ssehv repurposes xivt CSR low bits to hold a WARL EHV gate; if QEMU adds mivt/sivt without wiring EHV into exception dispatch, guest software relying on hardware-vectored synchronous exceptions traps to the wrong PC, breaking privilege boundary transitions
Violation: QEMU claims Smehv/Ssehv extension support (e.g., via misa or ISA string) but does not implement the EHV WARL bit in the xivt CSR (mivt=0x307, sivt=0x107) field layout, or implements the EHV bit as writable but ignores it during synchronous exception delivery — continuing to use the standard mtvec/stvec direct/vectored dispatch instead of the hardware-vectored entry point at xtvec + offset
Consequence: privilege_escape
Pattern: riscv_cpu_do_interrupt reads env->mtvec/env->stvec directly without checking a corresponding xivt.EHV WARL field to determine whether synchronous exceptions should be hardware-vectored; CSR write functions for mivt/sivt accept EHV bit writes but the value is never consulted in cpu_helper.c trap delivery
