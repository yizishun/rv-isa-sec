PR #699  target=freebsd-src  overall=compliant
Spec: Ssehv introduces supervisor-level synchronous exception hardware vectoring via sivt.EHV; FreeBSD's trap entry at stvec must ensure EHV is never enabled in kernel mode or properly save/restore it per-thread to prevent trap-routing bypass.
Violation: FreeBSD kernel context-switches a thread with sivt.EHV set without sanitizing or saving/restoring the EHV bit, or the kernel itself runs with EHV enabled and synchronous exceptions are hardware-vectored through the ivt-based offset instead of the stvec handler, bypassing the kernel's trap entry code that expects a unified synchronous exception path.
Consequence: function_loss
Pattern: sivt|SIE_EHV|EHV.*sivt|csr_write.*sivt|xivt.*EHV|mtrap.*vectored|sscratch.*sivt
------------------------------------------------------------
[compliant] sys/riscv/riscv/locore.S:230-236  va (primary boot)
  Boot path initializes stvec to cpu_exception_handler in Direct mode (address written without mode bits), which neutralizes any EHV vectoring effect. However, sivt (CSR 0x107) is never cleared — the CSR retains whatever value firmware left. This is a defense-in-depth gap but not exploitable because stvec Direct mode (mode=00) means EHV has no effect per ACLIC spec: synchronous exceptions always go to stvec.BASE regardless of EHV setting.
  | la	t0, cpu_exception_handler
  | csrw	stvec, t0
  | 
  | li	t0, 0
  | csrw	sscratch, t0

[compliant] sys/riscv/riscv/exception.S:208-216  cpu_exception_handler
