PR #699  target=linux  overall=potential_risk
Spec: sivt CSR gains EHV control bit at bit 0: kernel must save/restore full sivt (not just BASE) on context switch, or synchronous exceptions (page faults, ecalls) from one task may be vectored through another task's handler table, leaking control flow.
Violation: Linux kernel context-switch path saves/restores only the sivt BASE field without preserving the EHV bit, or kernel code writes sivt with a hardcoded value that clears EHV (e.g., masking bits [5:0]), causing one task's synchronous exception vectoring configuration to leak into another task or be silently disabled.
Consequence: info_leak
Pattern: csr_write.*CSR_SIVT|csr_read.*CSR_SIVT|sivt.*&=|sivt.*mask|__switch_to.*sivt
------------------------------------------------------------

[potential_risk] arch/riscv/kernel/entry.S:421-471  __switch_to
  The __switch_to context-switch path saves/restores GPRs (ra, sp, s0-s11), the SUM bit in sstatus, and the shadow call stack pointer, but does NOT save/restore the sivt CSR. On hardware implementing Ssivt/Smehv, if a task configures sivt.EHV for synchronous exception hardware vectoring, that configuration will leak to the next scheduled task on the same hart. Similarly, task-specific sivt BASE addresses would not be preserved across context switches.

  | 	add   a4, a1, a4
  | 	REG_S ra,  TASK_THREAD_RA_RA(a3)
  | 	/* ... GPR save/restore only ... no sivt handling */
