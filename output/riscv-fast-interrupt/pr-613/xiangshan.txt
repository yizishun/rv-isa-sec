PR #613  target=xiangshan  overall=compliant
Spec: Mandatory negative-offset stack layout replaces recommended positive-offset layout; hardware using old offsets corrupts trap frame causing wrong register/EPC/privilege restoration on MRET/MNRET, enabling privilege escape if restored privilege level is incorrect
Violation: Hardware CLIC/SMTP trap context push/pop (e.g. Smtpush/Smtpop microcode or CLIC FSM) uses old recommended positive stack offsets from unadjusted SP instead of new mandatory negative offsets from post-adjustment SP; or uses incorrect offset 60/56 for xpistatus/xpepc in XLEN=64 mode instead of corrected -64/-56, causing registers to be saved/restored at wrong stack positions
Consequence: data_corruption
Pattern: hardcoded positive stack offset constants (24,20,16,12,8,4 or 48,40,32,24,16,8) without explicit negative sign in trap push/pop microcode or FSM; xpistatus offset 60 or xpepc offset 56 in XLEN=64 paths; stack offset computation lacking sign extension or using pre-adjustment SP as base
