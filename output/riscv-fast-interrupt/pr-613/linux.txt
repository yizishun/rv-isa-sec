PR #613  target=linux  overall=compliant
Spec: CLIC stack layout changed from recommended to mandated with corrected negative offsets; kernel code accessing hardware-saved CLIC frames with stale positive-offset assumptions will corrupt register save/restore and break ECALL mepc advancement.
Violation: Linux kernel trap handler or context-switch code that accesses the CLIC hardware-saved stack frame using positive (pre-mandate) offsets or an otherwise non-conforming layout, instead of the now-mandated negative-offset layout (e.g., reading x10 at SP+4 instead of SP-4). This causes the kernel to read/write the wrong register slots when inspecting or modifying the CLIC-pushed context (e.g., failing to correctly advance mepc for ECALL, or restoring wrong register values on return).
Consequence: data_corruption
Pattern: hardcoded positive stack offsets (e.g., SP+4, SP+8, SP+24, SP+48) in CLIC/smtp trap handling or context-switch paths that should use the mandated negative offsets (SP-4, SP-8, SP-24, SP-48); also any code that treats the CLIC stackframe layout as implementation-defined rather than architecturally fixed.
