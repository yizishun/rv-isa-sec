PR #727  target=qemu  overall=compliant
Spec: Missing alignment check on source register in TCG translation of Smcsps/Sscsps conditional-stack-pointer-swap instructions silently executes with misaligned SP, violating the ISA-mandated illegal-instruction trap that gates the stack-swap mechanism on 128b-aligned x2.
Violation: QEMU TCG translates c.mtss/c.mtss_pop/c.stss/c.stss_pop without checking that the source register's lower 4 bits (rs[3:0]) are zero, executing the stack pointer swap with a misaligned pointer instead of raising an illegal-instruction exception.
Consequence: privilege_escape
Pattern: trans_c_mtss|trans_c_stss|stack.*swap|smcsps.*translate|decode.*mtss|decode.*stss
------------------------------------------------------------
[compliant] target/riscv/insn16.decode:148-150  decode (compressed quadrant 1)
  Smscps instructions (c.mtss/c.mtss_pop/c.stss/c.stss_pop) are not implemented in this QEMU version. The existing Zicfiss compressed variants (c.sspush/c.sspopchk) use fixed register assignments (rs2=x1, rs1=x0 for sspush; rs1=x5, rd=x0 for sspopchk) carved from c.mop encoding slots, so there are no variable register operands to validate for alignment. The vulnerability pattern 'trans_c_mtss|trans_c_stss|mtss|stss' has zero matches in the codebase.

[potential_risk] target/riscv/csr.c:861-866  write_ssp
  write_ssp performs no WARL validation on the written ssp value — any arbitrary value is accepted. While the spec allows writes to ssp, an unaligned ssp value could cause subsequent sspush/sspopchk to access misaligned shadow-stack locations. The hardware memory access (MO_ALIGN in trans functions) would trap misaligned accesses, but the CSR itself should enforce alignment constraints per the Zicfiss spec.
