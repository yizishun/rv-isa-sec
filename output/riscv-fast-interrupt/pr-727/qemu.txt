PR #727  target=qemu  overall=compliant
Spec: Missing x2[3:0]==0 trap on Smcsps conditional stack swap allows misaligned SP value bits to alias with PUSH/PPUSH metadata stored in msp/ssp CSR lower 4 bits, corrupting interrupt context swap control state
Violation: QEMU TCG translates an Smcsps conditional stack swap instruction (c.sspush, c.sspopchk, m.sspush, m.sspopchk) without generating a runtime check that the source register (x2/sp) has its lower 4 bits zero (rs[3:0] == 0), causing the instruction to execute successfully with a misaligned stack pointer instead of raising an illegal instruction exception as required by the spec
Consequence: data_corruption
Pattern: trans_.*sspush|trans_.*sspopchk without preceding gen_helper_raise_exception for ILLEGAL_INST on (get_gpr.*x2|rs)[3:0] != 0
------------------------------------------------------------

The sspush/sspopchk instructions in trans_rvzicfiss.c.inc are Zicfiss shadow-stack instructions that operate on the ssp CSR, not Smcsps conditional-stack-pointer-swap instructions that operate on x2/sp. No Smcsps opcodes (mcspspush/mcspspop/scspspush/scspspop) exist in any decode file, no mspcs/sspcs CSRs exist, and no ext_smcsps/ext_sscsps flags exist. The vulnerability pattern (missing lower-4-bit-zero check on x2/sp) does not apply.
