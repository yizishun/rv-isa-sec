PR #630  target=qemu  overall=potential_risk
Spec: Smtp tpush now writes major interrupt identity (from xtopi) to a0 and minor identity (from xtopei) to a1 for external interrupts; previously minor identity went to a0 and a1 was left unwritten — QEMU must match the new register assignment or guest interrupt handlers will misidentify interrupt sources
Violation: When QEMU implements the Smtp tpush instruction for vectored external interrupts, if it writes the minor interrupt identity (from xtopei) to a0 instead of a1, or fails to write the minor identity to a1 at all — matching the old spec where a0 received the minor identity and a1 was left unmodified for external interrupts — the guest interrupt handler will receive incorrect source identification arguments, causing it to dispatch to the wrong software vector table entry.
Consequence: function_loss
Pattern: tpush instruction TCG translation that writes CSR_MTOPEI/STOPEI/VSTOPEI (xtopei) result into a0 instead of a1 for external interrupt vectoring, or reads CSR_MTOPI/STOPI/VSTOPI (xtopi) into a1 instead of a0 — the new spec mandates a0=major_identity, a1=minor_identity for external interrupts

  Bitmask inconsistency: IMSIC_TOPEI_IID_MASK (0x7ff, 11 bits) differs from TOPI_IID_MASK (0xfff, 12 bits). In the AIA spec, the IMSIC TOPEI register and the TOPI CSR encode IID at bits [31:16], but TOPEI has an 11-bit IID field while TOPI has 12 bits. These are different register types so the mismatch is intentional, but future tpush code must use the correct mask for each register type.
