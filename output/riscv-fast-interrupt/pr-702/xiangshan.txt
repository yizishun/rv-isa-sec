PR #702  target=xiangshan  overall=compliant
Spec: Old ipopxret encoding (funct7=0x8) reassigned to sipopret using sret; stale decoder mapping funct7=0x8 to mret would allow S-mode code to escalate to M-mode via the new sipopret instruction
Violation: XiangShan instruction decoder maps funct7=0x8 in the SYSTEM opcode space (the old ipopxret encoding) to mret-based M-mode return behavior instead of the new sipopret/sret-based S-mode return. Specifically, when S-mode code executes the sipopret instruction (encoded as 0x73 with rd=0, funct3=0, rs=0, funct7=0x8), a stale decoder matching the pre-rename ipopxret encoding would perform mret instead of sret, returning to M-mode with the xPP field of mstatus unmodified—effectively escalating privilege from S-mode to M-mode without a trap.
Consequence: privilege_escape
Pattern: decoder table entry with funct7=0x8, funct3=0x0, opcode=SYSTEM that maps to micro-op performing mret instead of sret; or Chisel BitPat("b00001000000000000000000000000000".U) targeting MretOp instead of SretOp in IDU decode logic
