PR #702  target=qemu  overall=compliant
Spec: Opcode funct7=0x08 was repurposed from M-mode cspspush/cspspop/ipopxret to S-mode scspspush/scspspop/sipopret; QEMU TCG must enforce the new privilege-level decode or risk U-mode executing supervisor stack-pointer-swap and sipopret(sret) as a privilege-escape vector.
Violation: QEMU TCG translates the old cspspush/cspspop/ipopxret opcodes (funct7=0x08) as M-mode instructions, but the spec repurposes funct7=0x08 for the new S-mode scspspush/scspspop/sipopret instructions. If QEMU decodes funct7=0x08 without checking the privilege mode against the new S-mode semantics, U-mode guest code could execute supervisor-level stack pointer swap operations (scspspush/scspspop) and sipopret (which ends in sret), bypassing the spec-mandated illegal-instruction trap for insufficient privilege. Additionally, if funct7=0x08 is still decoded as the old M-mode semantics in QEMU but guest software expects the new S-mode semantics, the emulation silently corrupts the wrong privilege level's shadow stack pointer state (msp vs ssp).
Consequence: privilege_escape
Pattern: trans_*(cspspush|cspspop|ipopxret|mcspspush|mcspspop|scspspush|scspspop|mipopret|sipopret) && (funct7 == 0x08 || funct7 == 0x18) && !check_privilege(mode, required_priv)
