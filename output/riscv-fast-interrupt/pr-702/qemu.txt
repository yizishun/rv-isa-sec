PR #702  target=qemu  overall=potential_risk
Spec: sipopret bundles implicit sret into interrupt-return; missing TCG privilege check (>=S-mode) lets U-mode guest craft stack frames for controlled S-mode privilege escalation
Violation: QEMU TCG translates sipopret (opcode 0x73, funct3=0x0, rd=x0, funct7=0x08) without first checking current privilege >= S-mode. sipopret is a compound operation: (1) scspspop — conditionally swaps x2(sp) with ssp CSR based on ssp.PPUSH, (2) restores x10-x15 from guest stack memory at OFFSET(sp), (3) addi sp,sp,FRAMESIZE, (4) executes sret to return to lower privilege with sepc as target PC. If TCG permits U-mode execution (missing privilege gate, or incorrectly inheriting the old Smip-only decode tables where this encoding was invalid), a guest U-mode attacker can: craft a fake interrupt stack frame at an arbitrary VA with attacker-chosen x10-x15, sepc, and sstatus values in the corresponding CSRs; point sp at this frame; execute sipopret which silently transitions to S-mode at attacker-controlled sepc.
Consequence: privilege_escape
Pattern: sipopret|mipopret|scspspush|scspspop|mcspspush|mcspspop|has_ssip|has_smip|gen_helper_ipop|decode_xipop|trans_ipop|opcode_0x73.*funct7_0x08

[potential_risk] target/riscv/csr.c:861-866  write_ssp
  No TLB flush or icount update triggered on SSP write. While the Zicfiss spec does not require a TLB flush for SSP writes (SSP is a data pointer, not a page-table-affecting CSR), the act of changing SSP may affect the shadow stack page table walk behavior (SS-MMU-index-based access to PTE.W-only pages). If a guest writes a new SSP value pointing to a region whose PTEs have not yet been walked, the cached TLB entries may not reflect the shadow-stack interpretation of PTE.W-only pages, potentially allowing an sspush to succeed on a non-shadow-stack page.
