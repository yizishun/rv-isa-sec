PR #702  target=linux  overall=bug_confirmed
Spec: New Ssip extension adds ssp CSR and sipopret instruction; kernel must context-switch ssp or risk cross-task stack-pointer corruption and unintended conditional stack swaps on interrupt return
Violation: Linux kernel context-switches between tasks that use scspspush/sipopret without saving and restoring the ssp CSR (which holds the S-mode shadow stack pointer and PUSH/PPUSH bits), causing one task to resume with another task's S-mode stack pointer and conditional-swap state.
Consequence: data_corruption
Pattern: context_switch.*(?:ssp|CSR_SSP)|__switch_to.*(?:ssp|0x[0-9a-fA-F]+.*ssp)|sipopret|scspspush|scspspop
------------------------------------------------------------
[bug_confirmed] arch/riscv/kernel/entry.S:421-471  __switch_to
  __switch_to does not save or restore the sspcs CSR (0x149, S-mode conditional-swap stack pointer with PUSH/PPUSH bits). If hardware implements the Sscsps extension and kernel context-switches between tasks that use scspspush/scspspop/sipopret, the next task inherits the previous task's sspcs.SP, sspcs.PUSH, and sspcs.PPUSH state. The spec text at aclic.adoc:965-967 explicitly states: 'The PPUSH bit ... corresponds to the value of the PUSH bit in the previous context. This bit is part of the context of an interrupt handler, and needs to be saved and restored if a handler can be preempted.' The kernel's __switch_to saves ra, sp, s0–s11, STATUS, SUM, and shadow call stack but has no code path for sspcs.
  | SYM_FUNC_START(__switch_to)
  | 	/* Save context into prev->thread */
  | 	li    a4,  TASK_THREAD_RA
  | 	add   a3, a0, a4
  | 	add   a4, a1, a4
  | 	REG_S ra,  TASK_THREAD_RA_RA(a3)
  | 	...
  | 	/* No save/restore of sspcs CSR (0x149) */
  | 	ret
  | SYM_FUNC_END(__switch_to)

  The switch_to macro sequences FPU save/restore, vector save/restore, icache flush, envcfg switch, and __switch_to — but has no handling for sspcs (0x149). The __switch_to_envcfg inline only writes CSR_ENVCFG; there is no analogous __switch_to_sspcs or any mechanism to context-switch the Sscsps conditional-swap state.

[compliant] arch/riscv/include/asm/csr.h:332-336  
  CSR_SSP (0x011) is correctly defined. However note this is the Zicfiss user-mode shadow stack pointer — a different CSR from the sspcs (0x149) described in the Sscsps spec. The CSR numbering gap between STIMECMPH (0x15D) and STIMECMP (0x14D) shows that sspcs at 0x149 is not defined here. The kernel handles CSR_SSP (0x011) correctly via save_userssp/restore_userssp in entry.S, but this is a different CSR from what the security spec's violation condition describes.
  | #define CSR_STIMECMP           0x14D
  | #define CSR_STIMECMPH          0x15D
  | 
  | /* zicfiss user mode csr.  CSR_SSP holds current shadow stack pointer */
  | #define CSR_SSP                 0x011

[compliant] arch/riscv/kernel/entry.S:99-110  save_userssp
  save_userssp correctly reads CSR_SSP (0x011, Zicfiss user shadow stack pointer) via csrrw and stores it to TASK_TI_USER_SSP (thread_info.user_cfi_state.user_shdw_stk) when returning from userspace. It also zeroes CSR_SSP for sanitization. This mechanism correctly context-switches the user-mode shadow stack pointer, but it only fires on exception entry from U-mode — it saves the value into the current task's per-task storage, not into a per-CPU area, so cross-task contexts are properly isolated.
  | .macro save_userssp tmp, status
  | 	ALTERNATIVE("nops(4)",
  | 		__stringify(
  | 		andi \tmp, \status, SR_SPP;
  | 		bnez \tmp, skip_ssp_save;
  | 		csrrw \tmp, CSR_SSP, x0;
  | 		REG_S \tmp, TASK_TI_USER_SSP(tp);
  | 		skip_ssp_save:),

[compliant] arch/riscv/kernel/entry.S:112-123  restore_userssp
  restore_userssp correctly restores CSR_SSP (0x011) from TASK_TI_USER_SSP when returning to userspace. This properly restores the user-mode shadow stack pointer for the current task.
  | .macro restore_userssp tmp, status
  | 	ALTERNATIVE("nops(4)",
  | 		__stringify(
  | 		andi \tmp, \status, SR_SPP;
  | 		bnez \tmp, skip_ssp_restore;
  | 		REG_L \tmp, TASK_TI_USER_SSP(tp);
  | 		csrw CSR_SSP, \tmp;
  | 		skip_ssp_restore:),
