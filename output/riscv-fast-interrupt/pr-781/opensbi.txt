PR #781  target=opensbi  overall=potential_risk
Spec: OpenSBI PMP configuration must grant execute permission to S/U-mode for shared vector table regions when CLIC-style xivt/xeivt sharing is enabled, or S-mode interrupt delivery fails due to PMP execute faults.
Violation: OpenSBI M-mode firmware configures PMP/ePMP entries during domain protection setup (sbi_hart_oldpmp_configure / sbi_hart_smepmp_configure) that deny execute permission from S/U-mode to memory regions containing shared vector tables, when CLIC-style xivt/xeivt (or analogous mivt/meivt) CSRs are programmed to share a single vector table across M-mode and S-mode.
Consequence: denial_of_service
Pattern: PMP entry with L=1 and X=0 (or Smepmp locked-shared-code with X=0) whose address range covers the vector table base in a system where xivt/xeivt enables cross-privilege vector-table sharing; also: domain memory regions that omit the vector table page entirely from the S-mode domain's allowed-PMP set.
------------------------------------------------------------

[potential_risk] lib/sbi/sbi_hart_pmp.c:273-296  sbi_hart_oldpmp_configure
  Old PMP configure iterates domain regions and programs PMP entries via pmp_set() in index-priority order. Firmware regions (M-only) come first in the sorted region list and will match before the SU catch-all. If a shared vector table page falls within a firmware region's address range, S/U-mode execute/read is denied with no recovery path. The function has no awareness of CLIC-style vector table sharing and provides no mechanism to carve out an exception for the shared vector table page.
