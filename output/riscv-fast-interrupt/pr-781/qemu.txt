PR #781  target=qemu  overall=compliant
Spec: CLIC/ACLIC vector table fetch must enforce PMP execute permission under the handler's privilege mode; omitting or mis-scoping this check allows a guest to vector interrupts to code pages the handler's privilege level should not be able to execute
Violation: QEMU emulates a CLIC/ACLIC vector table fetch (hardware vectoring during interrupt delivery) without performing PMP/Smepmp execute-permission check using the privilege mode of the interrupt handler. Specifically: if xivt/xeivt CSR fields configure a shared vector table across privilege levels, QEMU must (a) validate the vector table address against PMP with the handler's effective privilege mode, (b) reject the fetch with a fault if X permission is absent, and (c) not silently use M-mode permissions when the handler runs in S-mode.
Consequence: privilege_escape
Pattern: vector table fetch path that reads guest memory (e.g. cpu_ldl_code or address_space_ldl) without a preceding pmp_hart_has_privs or pmp_retry-style check scoped to the handler's effective privilege level
