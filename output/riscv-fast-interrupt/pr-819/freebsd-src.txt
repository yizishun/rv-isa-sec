PR #819  target=freebsd-src  overall=potential_risk
Spec: bhyve VMM cannot restrict guest access to seivt via mstateen0.ACLIC—guest S-mode can read/write the external interrupt vector table despite the hypervisor intending to deny ACLIC access, enabling interrupt redirection or info disclosure
Violation: In the FreeBSD kernel (or a bhyve-virtualized guest), when M-mode firmware/hypervisor sets mstateen0.ACLIC=0 to disable S-mode ACLIC access, the seivt CSR remains accessible to S-mode due to the spec omission—hardware allows read/write to seivt instead of raising an illegal instruction exception.
Consequence: privilege_escape
Pattern: csr_write|csr_read|csr_set|csr_clear.*seivt|CSR_SEIVT|0x155
------------------------------------------------------------

The CSR number space 0x150-0x155 for AIA interrupt-file CSRs (siselect, sireg, stopi, stopei, sieh, siph, seivt) is entirely absent from FreeBSD's CSR definitions — only standard privileged CSRs (sstatus, sie, stvec, sip, etc.) and M-mode CSRs are defined.
