PR #819  target=qemu  overall=compliant
Spec: Missing mstateen0.ACLIC gate on seivt allows S-mode to read/write the external interrupt vector table CSR when the ACLIC extension is administratively disabled, bypassing M-mode's intended privilege restriction
Violation: QEMU allows S-mode (or lower) read/write access to the seivt CSR when mstateen0.ACLIC (bit 53) is zero, because the Smstateen access-control check was only applied to sivt but not to seivt
Consequence: privilege_escape
Pattern: CSR read/write handler for seivt (0x15A) missing mstateen0 bit 53 ACLIC check that the corresponding handler for sivt (0x15C) has
------------------------------------------------------------
[compliant] target/riscv/cpu_bits.h:353-365  (global defines)
  No SMSTATEEN0_ACLIC (bit 53) define exists, and CSR 0x15A (seivt) is absent from the entire codebase. The vulnerability described in the security spec — S-mode access to seivt without mstateen0.ACLIC check — cannot occur because neither the CSR nor the access-control bit exists. The current codebase is consistent: if seivt/sivt were to be added (as distinct from the AIA STOPEI at 0x15C), both the CSR definition and the SMSTATEEN0_ACLIC bit would need to be introduced together.
