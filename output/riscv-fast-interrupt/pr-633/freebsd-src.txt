PR #633  target=freebsd-src  overall=compliant
Spec: FreeBSD currently only supports APLIC direct mode (no IMSIC/ACLIC), so this ACLIC spec-level operator-precedence bug in the xithreshold preemption gate has no current code impact, but any future AIA/IMSIC implementation that follows the old spec would have broken priority-based interrupt preemption logic.
Violation: In the FreeBSD kernel, if/when AIA IMSIC/ACLIC support is implemented (currently unsupported in mainline — sys/riscv/riscv/aplic.c:456-457 explicitly disallows IMSIC pairing), code that writes xithreshold (via miselect/siselect indirect CSR access) and then checks preemption using the old precedence rule `iprio[i] & NIPPRIO_MASK >= xithreshold` would incorrectly treat the masked-priority-vs-threshold comparison as a boolean-AND between iprio[i] and (NIPPRIO_MASK >= xithreshold), causing high-priority interrupts to potentially be spuriously masked or low-priority interrupts to incorrectly preempt critical sections.
Consequence: denial_of_service
Pattern: xithreshold.*&=|iprio.*NIPPRIO|niprio.*mask.*>=|threshold.*priority.*mask
