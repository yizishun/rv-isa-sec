PR #633  target=qemu  overall=compliant
Spec: C operator precedence bug in interrupt preemption/priority-masking logic: '&' binds weaker than '>=' so mask-and-compare without parentheses evaluates mask-threshold comparison first, yielding 0/1 instead of the intended priority field extraction
Violation: Any QEMU C code implementing Smnip preemption that writes 'iprio & NIPPRIO_MASK >= xithreshold' without explicit parentheses, causing operator precedence to evaluate NIPPRIO_MASK >= xithreshold (producing 0 or 1) before ANDing with iprio, instead of masking iprio first then comparing against the threshold
Consequence: denial_of_service
Pattern: iprio[.*]\s*&\s*MASK\s*[><=!]=
