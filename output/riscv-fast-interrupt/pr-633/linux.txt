PR #633  target=linux  overall=compliant
Spec: Operator-precedence bug in AIA preemption condition causes hardware to ignore interrupt priority levels and priority groups during preemption decisions, violating kernel's expectation that high-priority interrupts reliably preempt lower-priority ones
Violation: Linux kernel writes per-interrupt priorities (iprio[i]) and xithreshold CSR values expecting hardware to enforce correct priority-group-aware preemption, but hardware implementing the buggy expression 'iprio[i] & NIPPRIO_MASK >= xithreshold' evaluates the preemption gate as 'iprio[i] & (NIPPRIO_MASK >= xithreshold)', which reduces to 'iprio[i] & 1' when NIPPRIO_MASK >= xithreshold — checking only bit 0 of the interrupt priority and ignoring both the actual priority level and priority group bits.
Consequence: denial_of_service
Pattern: writes to xithreshold CSR OR iprio[] configuration in IMSIC/APLIC interrupt file registers where the kernel depends on correct hardware preemption between different priority-group interrupts; also KVM trap-and-emulate paths that compute preemption in software using the same precedence-buggy expression
