Spec: Spec typo fix: operator precedence bug where `iprio[i] & MASK >= threshold` was missing parentheses around `threshold & MASK`. OpenSBI could replicate this in software priority logic (e.g., HSM interrupt save/restore or AIA CSR manipulation), causing incorrect interrupt preemption decisions that block higher-priority interrupts.
Violation: OpenSBI M-mode code that reads the (pre-fix) ACLIC spec and implements software interrupt priority comparison replicates the operator precedence bug: writing expressions like `prio & MASK >= threshold` which evaluates as `prio & (MASK >= threshold)` instead of `prio >= (threshold & MASK)`. This would occur in any OpenSBI handler that does software-based priority filtering, or when OpenSBI configures interrupt priority thresholds via AIA CSRs and later validates priority values in software.
Consequence: denial_of_service
Pattern: bitwise AND operator (`&`) combined with comparison operator (`>=`, `<=`, `>`, `<`) on the same line without explicit parentheses around the mask operation — specifically patterns like `expr & MASK >= threshold` or `expr & MASK <= threshold`
