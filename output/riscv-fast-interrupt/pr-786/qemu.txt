PR #786  target=qemu  overall=compliant
Spec: sireg2 at iselect=0x1000 maps to aclicsourcecfg[0] where only bits[15:0] are read-only zero (sourcecfg[0]), while bits[31:16] are writable (sourcecfg[1]); full-register read-only-zero blocks legitimate sourcecfg[1] config causing function loss, while omitting the read-only-zero on bits[15:0] allows write to hardwired-zero sourcecfg[0] bypassing platform interrupt policy
Violation: QEMU indirect CSR access handler for iselect=0x1000 (aclicsourcecfg base) makes the full sireg2/mireg2 register read-only zero instead of only enforcing read-only zero on bits [15:0]; OR fails to enforce read-only zero on bits [15:0] while exposing writable bits [31:16]
Consequence: function_loss
Pattern: iselect dispatch table or xiselect_aia_range() not handling iselect ∈ [0x1000, 0x10FF] as aclicsourcecfg with per-index WARL masks; wr_mask unconditionally zeroing full dword at iselect==0x1000; missing per-bit WARL constraint that bits[15:0] are read-only zero only for k==0

[compliant] target/riscv/csr.c:2451-2455  rmw_xiselect
  When smcsrind/sscsrind ISAs are enabled, iselect writes are masked with ISELECT_MASK_SXCSRIND (0xfff). A guest write of 0x1000 has bit 12 masked off, silently collapsing to 0x000. This is correct per the Sxcsrind spec: 0x1000 is not a defined indirect-access select value, so no WARL register should preserve it. The guest's next sireg/sireg2 read gets the iselect=0x000 encoding, which raises ILLEGAL_INST via rmw_xireg_csrind.

  |     wr_mask &= ISELECT_MASK_SXCSRIND;
  | } else {
  |     wr_mask &= ISELECT_MASK_AIA;
  | }
