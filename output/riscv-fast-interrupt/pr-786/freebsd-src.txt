PR #786  target=freebsd-src  overall=compliant
Spec: FreeBSD does not yet implement ACLIC/Smidctrl indirect CSR access, but if/when it does, code must treat only aclicsourcecfg[0][15:0] as read-only zero — not the full register — to avoid corrupting source configuration for interrupts 1–3 (XLEN=64) or interrupt 1 (XLEN=32) that share the same xireg2/xireg3 window.
Violation: Kernel code treats the entire aclicsourcecfg[0] indirect register as read-only zero (e.g., skipping save/restore of xireg2/xireg3 when xiselect=0x1000, or writing zero to all 32/64 bits expecting it to be ignored), when in fact only bits [15:0] (sourcecfg[0][15:0]) are read-only zero — the upper bits map to live sourcecfg[1] (XLEN=32) or sourcecfg[1..3] (XLEN=64) and control real interrupt source configuration.
Consequence: data_corruption
Pattern: "xiselect.*0x1000" OR "xireg[23].*read.only.zero" OR "aclicsourcecfg.*zero" OR "sourcecfg\[0\].*zero" AND NOT "\[15:0\]" — code that assumes full-register read-only-zero semantics for indirect sourcecfg[0] access instead of the partial [15:0]-only zeroing corrected in this PR.
