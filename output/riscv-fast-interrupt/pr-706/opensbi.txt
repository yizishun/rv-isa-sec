PR #706  target=opensbi  overall=bug_confirmed
Spec: Unpreserved MIPU/SIPU bits across OpenSBI mstatus save/restore silently disable automatic interrupt stacking, degrading fast-interrupt guarantees after HSM resume
Violation: OpenSBI saves/restores mstatus during HSM suspend/resume or context switch without preserving the MIPU/SIPU state bits, or inadvertently clears these bits during mstatus writes in init/trap handling, causing the automatic interrupt stacking behavior to be silently disabled after a context switch or resume
Consequence: function_loss
Pattern: CSR write to mstatus that uses a hardcoded immediate mask (e.g., csrw mstatus, csrs mstatus, csrrc mstatus) without reading back MIPU/SIPU bit positions, or save/restore of mstatus in context_switch/HSM suspend-resume that omits newly defined status bits
------------------------------------------------------------
[bug_confirmed] lib/sbi/sbi_hart.c:32-48  mstatus_init
  mstatus_init() writes CSR_MSTATUS with a hardcoded value initialized to zero, setting only FS/VS bits. This is a blind csrw that destroys ALL other mstatus bits including any MIPU/SIPU state bits defined by the Smip extension. After this write, the automatic interrupt stacking behavior controlled by MIPU/SIPU would be silently disabled.
  | unsigned long mstatus_val = 0;
  | ...
  | mstatus_val |=  MSTATUS_FS;
  | ...
  | mstatus_val |=  MSTATUS_VS;
  | csr_write(CSR_MSTATUS, mstatus_val);
