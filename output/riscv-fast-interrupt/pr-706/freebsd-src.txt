PR #706  target=freebsd-src  overall=potential_risk
Spec: SIPU/MIPU bits in sstatus/mstatus control automatic interrupt stacking; FreeBSD must clear SIPU on boot and ensure sstatus is sanitized per-thread, or hardware stacking corrupts trap frames during interrupt delivery
Violation: FreeBSD kernel enables the Smip/Smaclic fast interrupt extension but does not save, restore, or sanitize the SIPU bit in sstatus across context switches. When a thread is rescheduled with SIPU inadvertently set (inherited from firmware, a previous privilege level, or a misconfigured bhyve guest), any subsequent supervisor interrupt trap triggers hardware automatic stacking that the kernel's trap entry path does not expect, corrupting the trap frame layout.
Consequence: data_corruption
Pattern: sstatus.*save|sstatus.*restore|SSTATUS_.*MASK|SIE|SPIE|sstatus_write|CSR_WRITE.*sstatus|trapframe.*sstatus|frame.*tf_sstatus
------------------------------------------------------------
[potential_risk] sys/riscv/riscv/exception.S:103-131  save_registers (macro) / load_registers (macro)
  Trap entry captures the raw hardware sstatus value (including all WPRI bits) into the trapframe via 'csrr t0, sstatus; sd t0, (TF_SSTATUS)(sp)' without masking any undefined/reserved bits. Trap return restores the full tf_sstatus value back to hardware via 'csrw sstatus, t0', only toggling SIE/SPIE but leaving all other bits (including future SIPU encoding at an as-yet-unallocated bit position) unchanged. If SIPU were ever set (by firmware, a hypervisor, or future hardware), the bit would persist in tf_sstatus across the entire trap round-trip and propagate to subsequent context switches.

  | sd      t0, (TF_SSTATUS)(sp)
  | ...
  | ld      t0, (TF_SSTATUS)(sp)
  | csrw    sstatus, t0

  fork_trampoline restores sstatus from the trapframe for a newly forked process, only masking SIE before writing back via 'csrw sstatus, t0'. [potential_risk] sys/riscv/riscv/vm_machdep.c:108-118  cpu_fork
  cpu_fork copies the parent's entire trapframe (including tf_sstatus) to the child via bcopy(), then only modifies SPIE and SPP bits. Any SIPU bit set in the parent's tf_sstatus is inherited by the child without inspection or sanitization. This means a SIPU bit introduced at any point (firmware, hypervisor, kernel bug) would silently propagate across fork() to all child processes.
