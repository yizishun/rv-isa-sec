PR #706  target=linux  overall=potential_risk
Spec: Unvalidated SIPU bit in sstatus allows userspace (via ptrace/KVM ONE_REG) to toggle automatic interrupt stacking, corrupting the kernel's manually-constructed trap frame in entry.S
Violation: sstatus.SIPU is written (via ptrace PTRACE_SETREGSET, KVM ONE_REG sstatus write, or CSR write from M-mode firmware) without the kernel masking/clearing it, and a subsequent interrupt trap at S-mode triggers hardware automatic stacking that corrupts the pt_regs frame the kernel's entry.S manually constructs at arch/riscv/kernel/entry.S:183
Consequence: data_corruption
Pattern: csr[wcrs].*CSR_STATUS|sstatus.*=|pt_regs.*status|user_regs_struct.*status|PTRACE_SETREGSET
------------------------------------------------------------

[potential_risk] arch/riscv/include/asm/csr.h:12-65  
  No SR_SIPU or equivalent bit definition exists in csr.h. The kernel has no awareness of the SIPU bit (bit 51 on rv64, value 0x0008000000000000). This is the root cause for all SIPU-handling gaps: the bit is transparently passed through all save/restore paths because the kernel doesn't know it exists. Without an SR_SIPU definition, no code can mask, clear, or validate this bit.
