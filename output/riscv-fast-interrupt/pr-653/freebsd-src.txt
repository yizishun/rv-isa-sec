PR #653  target=freebsd-src  overall=compliant
Spec: Smip removes xepc/xpistatus from the stack frame (only unprivileged x10-x15 are auto-saved), but FreeBSD's nested interrupt and context-switch paths require sepc/sstatus to survive across handler execution—any SIE=1 window without manual sepc save corrupts the return target on ipopxret
Violation: In the FreeBSD kernel, when Smip is implemented and the S-mode interrupt handler execution path (e.g., intr_event_handle → ithread_execute_handlers or a trap-time context-switch via ast()) enables S-mode interrupts via sstatus.SIE without explicitly saving sepc/sstatus to the kernel trapframe first, a nested interrupt overwrites sepc with the nested handler's return address. On ipopxret, the kernel executes sret targeting the corrupted sepc—returning to the wrong address with potentially attacker-influenced privilege state.
Consequence: privilege_escape
Pattern: interrupt handler path enabling sstatus.SIE after Smip automatic push but before an explicit CSR read of sepc/sstatus into a software-maintained trapframe; or any ipopxret/sret where sepc was not re-validated after interrupt re-enable
