PR #653  target=qemu  overall=compliant
Spec: Smip moves interrupt context save from explicit tpush instruction into implicit trap-entry behavior; QEMU must ensure the implicit stack writes (x10-x15) are consistent with ipopxret restore offsets, atomic with respect to late-preemption, and that removal of xepc/xpistatus from the save frame doesn't leak privileged CSR values through stale stack slots
Violation: QEMU TCG implements implicit interrupt-entry context save (x10-x15 to stack) in riscv_cpu_do_interrupt() as a non-atomic sequence of guest memory stores, and a higher-priority interrupt arrives mid-save (late preemption), leaving partially-saved or clobbered x10-x15 values on stack that the preempting handler may overwrite before the original save completes. Additionally, if the TCG-generated ipopxret restore uses stack offsets or access sizes that differ from those used during the implicit trap-entry save (both 'implementation defined' per spec), restored x10-x15 values are corrupt.
Consequence: data_corruption
Pattern: riscv_cpu_do_interrupt implicit stack write x10-x15 non-atomic + ipopxret stack offset mismatch + late preemption during trap-entry save
