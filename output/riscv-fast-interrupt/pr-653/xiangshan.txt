PR #653  target=xiangshan  overall=compliant
Spec: Smip replaces explicit tpush/tpopxret instructions with automatic trap-entry context save/restore that no longer saves xepc/xpistatus or trap info to GPRs; XiangShan trap-entry FSM must drop Smtp-era xepc/xpistatus stack save/restore and GPR argument writes, otherwise nested interrupt late-preemption or tail-chaining causes silent xepc/xpistatus corruption and privilege-level context escape
Violation: In XiangShan RTL, the automatic trap entry context save (now part of trap behavior per Smip instead of explicit tpush instruction) saves only x10-x15 and adjusts sp, but hardware microcode or trap-entry FSM was originally designed for Smtp semantics that also saved xepc/xpistatus to the stack frame and wrote trap info (xcause, xtval, xtval2, xtinst) to GPRs a0-a3. If the RTL incorrectly retains the Smtp save/restore of xepc/xpistatus at specific stack offsets while software compiled for Smip expects a different (implementation-defined) stack layout, or conversely if the RTL fails to save/restore any privileged context that a nested interrupt preemption (late-preemption or tail-chaining) relies upon, the interrupted context's xepc and xpistatus are silently lost or overwritten during nested interrupt handling.
Consequence: privilege_escape
Pattern: (tpush|tpopxret|ipopxret|Smtp|Smip|trap_entry_save|context_push|auto_save|stack_frame|sp_adjust|xepc_save|xpistatus_save|cspspush|cspspop|late_preempt|tail_chain|XCause|XTval|XTval2|XTinst).*
