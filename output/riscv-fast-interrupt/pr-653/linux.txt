PR #653  target=linux  overall=compliant
Spec: ipopxret restores x10-x15 from opaque hardware stack frame, silently undoing any kernel modifications to the interrupted context's argument registers
Violation: Linux kernel interrupt handler returns via ipopxret (generated by __attribute__((interrupt)) with Smip-aware compiler) after the kernel has modified the interrupted context's saved x10-x15 registers in pt_regs for signal delivery, ptrace register writes, or seccomp filter return-value rewriting; ipopxret restores x10-x15 from the hardware-private stack frame at implementation-defined offsets, silently discarding all kernel modifications to those registers
Consequence: data_corruption
Pattern: ipopxret|__attribute__\(\(interrupt\)\)|_restore_all.*a[0-5]|pt_regs.*a[0-5]
------------------------------------------------------------

[compliant] arch/riscv/kernel/entry.S:160-167  handle_exception
  The interrupt/exception entry path explicitly saves all registers x1-x31 (including x10-x15 / a0-a5) to the pt_regs structure on the kernel stack via save_from_x6_to_x31 at line 167. This is a full software save — there is no ipush instruction or hardware-private stack frame. The Smip spec (aclic.adoc:1480) says that with Smip, registers x10-x15 are saved to a hardware-private stack frame at implementation-defined offsets, bypassing pt_regs. Since this kernel has no Smip support, the full software save to pt_regs is correct.

[potential_risk] arch/riscv/kernel/signal.c:468-472  setup_rt_frame
  Signal delivery modifies regs->a0, a1, a2 in pt_regs to set up signal handler calling convention. On a non-Smip system this is safe because ret_from_exception restores all registers from pt_regs via software loads before sret. However, this code is a documented risk point: if the kernel were ever compiled with Smip support (__attribute__((interrupt)) or sipopret in the return path), these pt_regs writes would be silently discarded by sipopret which restores x10-x15 from the hardware-private stack frame instead of from pt_regs. The signal handler would receive garbage in a0/a1/a2.
