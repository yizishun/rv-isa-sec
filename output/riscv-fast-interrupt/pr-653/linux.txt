PR #653  target=linux  overall=compliant
Spec: Smip makes interrupt push automatic trap behavior: hardware pre-saves x10-x15 and adjusts SP before the kernel's handler runs; the kernel must not duplicate the save and must use ipopxret instead of xret for interrupt return
Violation: Linux kernel RISC-V interrupt entry path executes without awareness that Smip hardware has already saved x10-x15 to the stack and adjusted SP before delivering the first handler instruction, causing the kernel to either double-save/overwrite the hardware-saved frame, compute incorrect stack offsets for the remaining context, or return via plain xret/sret/mret instead of ipopxret—leaving the stack corrupted and x10-x15 unrestored.
Consequence: data_corruption
Pattern: arch/riscv/kernel/entry.S save/restore of x10-x15 or sp adjustment on interrupt path without gating on Smip extension presence
------------------------------------------------------------
[compliant] :0-0  
  The interrupt entry unconditionally saves x1, x3, x5, then x6-x31 via save_from_x6_to_x31 (which covers x10-x15 at PT_A0 through PT_A5 offsets). SP is adjusted by -(PT_SIZE_ON_STACK) at line 163. This is correct behavior on a non-Smip system. No Smip ISA extension exists in this kernel tree (no RISCV_ISA_EXT_SMIP in hwcap.h, no ipopxret instruction anywhere), so unconditional save of x10-x15 is appropriate.

[compliant] :0-0  
  The return path restores all registers including x10-x15 via restore_from_x6_to_x31, then restores SP from PT_SP, and uses sret/mret. On a non-Smip system this is correct. No ipopxret exists in the kernel, which is appropriate since no Smip hardware save frame exists to unwind.

[compliant] :0-0  
  KVM saves/restores all GPRs including x10-x15 (a0-a7) in both SAVE_GUEST_GPRS and SAVE_HOST_GPRS macros. No Smip awareness. Correct on current hardware.

[compliant] :0-0  
  save_sigcontext and restore_sigcontext operate on pt_regs directly, saving and restoring all registers including x10-x15. No Smip-specific logic.

[compliant] :0-0  
  Saves/restores only callee-saved registers (ra, sp, s0-s11). Caller-saved x10-x15 are not saved here — they live in the caller's pt_regs frame from the trap entry or are on the caller's stack. Correct for non-Smip.

[compliant] :0-0  
  The complete list of ~90 ISA extensions (RISCV_ISA_EXT_*) has no Smip entry. Smip is not recognized as an extension by this kernel. Any Smip hardware would be treated as a standard system, meaning the kernel would correctly interoperate with any Smip-disabled hardware configuration.
