PR #716  target=freebsd-src  overall=compliant
Spec: a6 (register x16) is no longer restored by the Smip fast interrupt popret sequence, so code relying on hardware-assisted a6 restore across CLIC fast interrupts will see the IRQ-clobbered value instead
Violation: FreeBSD kernel implements Smip fast interrupt handlers and relies on a6 being callee-saved across mipopret/sipopret (i.e., a6 is not re-loaded/restored by software after the Smip handler returns), expecting the hardware-assisted fast interrupt return to restore a6 from the stack frame
Consequence: data_corruption
Pattern: Smip fast interrupt handler that uses a6 for temporary state without explicitly saving it; or a6 used as a live register across CLIC interrupt windows without re-load
------------------------------------------------------------
[compliant] sys/riscv/riscv/exception.S:86-86  save_registers
  FreeBSD's save_registers macro correctly saves a6 (x16) into the software trapframe at offset TF_A+6*8. This is the standard RISC-V trap entry path, covering both exceptions and basic (non-CLIC) interrupts. Since FreeBSD does not implement Smip — no sipopret/mipopret instructions exist in the entire source tree, no misa.Smip detection gate, no CLIC CSRs — the kernel never enters Smip fast interrupt mode where hardware would push x10-x15 and rely on sipopret to pop them. a6 is explicitly saved and restored by software, independent of the SIPOPRET pop set change.
  | sd	a6, (TF_A + 6 * 8)(sp)

[compliant] sys/riscv/riscv/exception.S:178-178  load_registers
  FreeBSD's load_registers macro correctly restores a6 (x16) from the software trapframe at offset TF_A+6*8. The standard sret-based return path restores all caller-saved registers (a0-a7) from the trapframe. There is no sipopret instruction anywhere in the kernel, so the spec change removing a6 from sipopret's pop set has zero impact: a6 is always restored by the software ld instruction, not by hardware pop.
  | ld	a6, (TF_A + 6 * 8)(sp)

[compliant] sys/riscv/riscv/swtch.S:410-410  fork_trampoline
  fork_trampoline restores a6 from the inherited trapframe. This is the initial userspace entry path for new processes, using sret (not sipopret). The sret instruction is correct for this context — it is not an interrupt return and there is no hardware interrupt frame to unwind. a6 is properly loaded from the software trapframe.
  | ld	a6, (TF_A + 6 * 8)(sp)

[compliant] sys/riscv/riscv/identcpu.c:444-476  identify_cpu
  identify_cpu parses ISA extension strings but contains no Smip detection logic. There is no misa.Smip bit extraction, no CLIC awareness, and no conditional branching between Smip-aware and standard trap handling. This absence is compliant with the spec because Smip is not implemented — the kernel cannot be affected by the a6 pop behavior change in a feature it doesn't use. The absence of detection prevents accidental Smip activation.
  | /* No Smip/CLIC ISA string parsing exists in this function */

[compliant] sys/riscv/riscv/locore.S:230-236  cpu_exception_handler setup
  Boot code unconditionally installs cpu_exception_handler at stvec with mtvec.mode=0 (direct mode). The ACLIC spec (aclic.adoc:1488-1490) explicitly states that mtvec.mode=0 is incompatible with Smip because Smip requires separate entry points for interrupts and synchronous exceptions. By using direct mode, FreeBSD structurally prevents Smip hardware from activating its push/pop behavior, keeping a6 fully under software trapframe control.
  | la	t0, cpu_exception_handler
  | csrw	stvec, t0
  | csrw	sscratch, zero
