PR #635  target=xiangshan  overall=compliant
Spec: mcause/scause ExceptionCode is written as flat interrupt ID without checking xtvec.mode; under Smivt vector table mode (mode=3) external interrupts must split major identity (bits 15:0) and minor identity (bits XLEN-2:16), but the flat hardware path silently produces a mis-encoded cause causing wrong handler dispatch and potential cross-privilege ISR execution
Violation: When xtvec.mode=3 (vector table mode per Smivt), XiangShan RTL writes a flat interrupt number (highPrioTrapNO / intrNO-1) into mcause/scause.ExceptionCode bits [62:0], but the Smivt spec requires external interrupts to encode major identity in bits [15:0] and minor identity in bits [XLEN-2:16] as a split WLRL field. The hardware never inspects xtvec.mode nor applies the conditional split encoding; the CauseBundle (single flat ExceptionCode[62:0]) cannot represent the dual-field format, and XtvecMode.legalValues excludes mode=3, causing WARL coercion to mode 0 or 1, making vector table mode silently impossible to enter.
Consequence: privilege_escape
Pattern: mcause/scause.*ExceptionCode.*:=.*highPrioTrapNO|CauseBundle.*ExceptionCode.*RW\(62,\s*0\)|XtvecMode.*legalValues.*Seq\(Direct,\s*Vectored\)|xtvec\.mode.*===|xtvec.*MODE.*0 or 1
