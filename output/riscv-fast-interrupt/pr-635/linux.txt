PR #635  target=linux  overall=potential_risk
Spec: CLIC Smivt repurposes scause exception code field when stvec.MODE=11 for external interrupts, splitting into major[15:0]/minor[XLEN-2:16] identity; kernel scause parsing assumes unpartitioned flat interrupt numbering and would yield garbage hwirq values and incorrect trap dispatching.
Violation: The kernel extracts the interrupt identifier from scause by masking with ~CAUSE_IRQ_FLAG and using the full remaining XLEN-1 bits as a flat interrupt number (e.g., in riscv_intc_irq at drivers/irqchip/irq-riscv-intc.c:31). Under Smivt/CLIC with stvec.MODE=11, external interrupts encode Major Interrupt Identity in bits 15:0 and Minor Interrupt Identity in bits XLEN-2:16 of xcause, producing a corrupted composite value when parsed with the standard flat-numbering mask. The kernel also uses raw scause values to index the excp_vect_table in entry.S by left-shifting the full scause value, which would compute a wildly incorrect table offset if scause were in CLIC format. Any code path where the kernel or KVM host sets stvec.MODE=11 without corresponding updates to scause parsing triggers this mismatch.
Consequence: denial_of_service
Pattern: cause & ~CAUSE_IRQ_FLAG
------------------------------------------------------------
