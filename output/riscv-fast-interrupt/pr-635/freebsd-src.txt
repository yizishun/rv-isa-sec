PR #635  target=freebsd-src  overall=potential_risk
Spec: FreeBSD always runs stvec in direct mode (mode=0); if Smivt mode=11 is accidentally activated—especially via the bhyve VMM stvec-swap path—external interrupts encode scause as split major/minor identity, breaking all kernel consumers of the standard SCAUSE_CODE-masked exception code and causing misdispatch or panic
Violation: In the FreeBSD kernel, if stvec.mode is inadvertently set to 11 (Smivt interrupt vector table mode) via any code path—most critically the VMM (bhyve) context-switch path in vmm_switch.S that swaps the real stvec CSR with a guest-influenceable value, or through a bare CSR write in locore.S/bootstrap—then when an external interrupt arrives, the hardware encodes scause with major identity in bits 15:0 and minor identity in bits XLEN-2:16 instead of the standard flat exception code. Existing trap dispatch reads this via 'frame->tf_scause & SCAUSE_CODE' (which masks only bit 63) and receives a composite value that no longer matches any SCAUSE_* constant, nor the expected supervisor external interrupt code (9). The DDB tracer (db_trace.c), GDB stub (gdb_machdep.c), page_fault_handler fault-type comparisons, and crashdump analysis tools all consume tf_scause assuming standard encoding and would misinterpret the restructured field.
Consequence: denial_of_service
Pattern: csrw\s+stvec.*|csr_write\(stvec.*|csr_swap\(stvec.*|tf_scause\s*&\s*SCAUSE_CODE|tf_scause\s*==\s*SCAUSE_
