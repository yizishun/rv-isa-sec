PR #825  target=qemu  overall=compliant
Spec: Smnip fast-interrupt enable (xfie) creates a new interrupt-gating path that bypasses the traditional xie bit when IPRIO < FITHRESH; writing xfie=0 must side-effect-clear xie, and trap entry must save-then-zero xfie to xpfie — failure in any coupling rule silently breaks guest interrupt masking
Violation: QEMU emulates a CSR write to mipreemptcfg (0x348) that sets mfie=0 or sipreemptcfg (0x148) that sets sfie=0, but does NOT also clear the corresponding xie bit (mie in mstatus/sie in sstatus) as a side-effect. Conversely, QEMU allows the TCG interrupt delivery path to signal interrupts when xie=0 but xfie=1 and IPRIO < FITHRESH, without checking the FITHRESH condition — the xie bit is no longer the sole gate for fast interrupts.
Consequence: privilege_escape
Pattern: CSR write to mipreemptcfg/sipreemptcfg where mfie/sfie transitions 1→0 must atomically clear mstatus.MIE/sstatus.SIE; conversely, riscv_cpu_do_interrupt must check xfie+FITHRESH as an alternate interrupt-gating path that bypasses xie
