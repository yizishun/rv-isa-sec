PR #825  target=xiangshan  overall=potential_risk
Spec: Fast interrupt enable (mfie/xfie) creates a hardware bypass of the global interrupt gate (mie/xie); incorrect qualification of the bypass condition (missing IPRIO < FITHRESHOLD gating) allows privilege-domain escape where any pending interrupt traps during critical sections with interrupts nominally disabled
Violation: In XiangShan CSR/interrupt module, when mfie=1 in mipreemptcfg but mie=0 in mstatus, the interrupt-pending evaluation logic incorrectly computes the 'interrupt enabled' condition as (mie OR mfie) without first qualifying mfie with the fast-interrupt eligibility check (IPRIO < FITHRESHOLD, i.e., (IPRIO & 2^fithresh) == 0). This allows non-fast interrupts to bypass the global interrupt disable gate (mie=0), breaking the spec constraint that only interrupts with IPRIO < 2^fithresh are eligible for mfie-based bypass. Equivalently, in the Verilog/Chisel combinational logic generating the 'take_interrupt' signal, the fast-interrupt path is not gated by the result of the IPRIO-vs-FITHRESHOLD comparator or the equivalent bitwise AND check.
Consequence: privilege_escape
Pattern: mie.*mfie|mfie.*fast|interrupt.*enable.*bypass|take.*interrupt.*fie|is_fast_int|fithresh.*compare|IPRIO.*FITHRESH|mipreemptcfg.*mfie
