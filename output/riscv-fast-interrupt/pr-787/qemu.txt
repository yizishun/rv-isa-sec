PR #787  target=qemu  overall=compliant
Spec: mcsps SP field width changed from SP[XLEN-1:4] to SP[XLEN-1:2]; QEMU's WARL write mask must only zero bits [1:0] (4B alignment) not bits [3:0] (128b alignment), else guest SP values with non-zero bits [3:2] are silently corrupted
Violation: QEMU implements the mcsps CSR with a WARL write mask that forces SP[3:2] to zero (enforcing the old 128b/16B alignment), but guest software relies on the new spec where only SP[1:0] must be zero (4B alignment). When the guest writes a 4B-aligned SP value with non-zero bits [3:2] (e.g., SP=0x80000008), QEMU silently clears bits [3:2] to produce SP=0x80000000, corrupting the stack pointer used for conditional stack swaps.
Consequence: data_corruption
Pattern: mcsps WARL write mask AND SP[3:2] forced-to-zero AND ~(ext_smcsps alignment assumed 128b)
