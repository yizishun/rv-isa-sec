PR #787  target=opensbi  overall=compliant
Spec: mcsps SP field widened from XLEN-1:4 to XLEN-1:2 (former WPRI bits 3:2 now hold SP data); OpenSBI CSR save/restore that zeros bits 3:2 as WPRI will truncate the M-mode shadow stack pointer, causing misaligned-stack corruption on mret after SBI call handling or HSM resume
Violation: OpenSBI M-mode trap handler or HSM context-save/restore code reads mcsps, masks off bits [3:2] as WPRI per the pre-787 spec, then writes the masked value back to mcsps on hardware implementing the new spec (where bits [3:2] are part of the SP field, SP[XLEN-1:2])
Consequence: data_corruption
Pattern: mcsps.*(&|AND|mask|~|clear|WPRI|>>.*2.*<<|>>.*4.*<<).*|=.*mcsps
