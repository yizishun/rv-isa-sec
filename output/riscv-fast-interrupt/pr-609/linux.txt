PR #609  target=linux  overall=bug_confirmed
Spec: ACLIC drops its distinct eidelivery=0x20000000 delivery mode and presents as APLIC-direct-delivery subset with numbered (not bit-array) interrupt control registers and integrated IE/IP/IPRIO fields in sourcecfg; kernel driver code written for full APLIC register layout will silently fail interrupt management on ACLIC hardware
Violation: The Linux kernel's AIA interrupt controller driver (running on hardware implementing Smaclic/Ssaclic) configures ACLIC using full APLIC register assumptions — writing to setip/clrip/setie/clrie bit-array registers that ACLIC does not implement, or interpreting sourcecfg without the new IE (bit 31), IP (bit 30), and IPRIO (bits 23:16) field layout — because ACLIC no longer advertises a distinct eidelivery delivery mode (0x20000000 was removed) and instead presents as a subset of APLIC in direct delivery mode
Consequence: denial_of_service
Pattern: riscv_aplic.*setip_le|riscv_aplic.*clrip_le|riscv_aplic.*setie_le|riscv_aplic.*clrie_le|writel_relaxed.*APLIC.*SETIP|writel_relaxed.*APLIC.*CLRIP|writel_relaxed.*APLIC.*SETIE|writel_relaxed.*APLIC.*CLRIE|aplic_direct.*setip|sourcecfg.*0x1FF|SM_SHIFT
