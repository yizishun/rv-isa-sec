PR #609  target=opensbi  overall=bug_confirmed
Spec: OpenSBI must configure an undefined mstateen0 bit to gate S-mode ACLIC register access; failure renders S-mode external interrupt management inoperable, and the removed Smaiae dependency means IMSIC CSR access (eidelivery/eip/eie) is no longer valid on ACLIC systems
Violation: OpenSBI initializes an ACLIC-configured hart but does not set the appropriate mstateen0 CSR bit (specified as '??' in the spec — bit number undefined) to enable S-mode access to ACLIC CSRs (setipnum, clripnum, setienum, clrienum, idelivery, ithreshold, topi, claimi), causing all S-mode attempts to configure external interrupts to trap with illegal instruction exceptions.
Consequence: denial_of_service
Pattern: mstateen0 CSR write operations that omit the ACLIC-enable bit, or conditional paths that assume Smaclic/Ssaclic implies Smaiae CSRs (eidelivery, eip, eie) are present when the spec removes that dependency

[bug_confirmed] lib/sbi/sbi_hart.c:89-98  mstatus_init
  mstateen0 bits for ACLIC are never set because the code at line 95 gates SMSTATEEN0_AIA (bit 59) and SMSTATEEN0_IMSIC (bit 58) on SBI_HART_EXT_SMAIA. On an ACLIC-only system (Smaclic/Ssaclic without IMSIC), CSR_MTOPI does not exist, so SBI_HART_EXT_SMAIA is never detected, and the else branch at line 98 explicitly clears both bits. Additionally, bit 53 (ACLIC) — the dedicated mstateen0 enable for ACLIC CSRs per the Smaclic/Ssaclic spec — is never set because no SMSTATEEN0_ACLIC define exists in OpenSBI. Per the ACLIC spec section 'State Enable', bit 58 (IMSIC) in mstateen0 is implemented even when IMSIC is not present, gating access to the reused IMSIC CSRs (stopei, eip[k], eie[k]). With both bits 53 and 58 at zero, all S-mode accesses to ACLIC CSRs (setipnum, clripnum, setienum, clrienum, idelivery/ithreshold via indirect CSR, topi, claimi) trap with illegal instruction exceptions, causing denial of service for S-mode external interrupt handling.

  | else

[potential_risk] include/sbi/riscv_encoding.h:857-878  
  SMSTATEEN0 bit definitions include bit 58 (IMSIC) and bit 59 (AIA) but lack a definition for bit 53 (ACLIC). The ACLIC specification (src/aclic.adoc:656) assigns bit 53 of mstateen0 as the ACLIC enable bit. Without a SMSTATEEN0_ACLIC macro, any code attempting to enable S-mode ACLIC CSR access has no bit constant to reference. Additionally, the existing SMSTATEEN0_IMSIC (bit 58) comment in riscv_encoding.h describes it as controlling IMSIC access 'provided by the Ssaia extension', but the ACLIC spec clarifies that bit 58 is implemented even without IMSIC and controls the reuse of IMSIC-form CSRs (stopei, eip[k], eie[k]) in ACLIC contexts.

  | #define SMSTATEEN0_IMSIC		(_ULL(1) << SMSTATEEN0_IMSIC_SHIFT)
  | #define SMSTATEEN0_AIA_SHIFT		59
  | #define SMSTATEEN0_AIA			(_ULL(1) << SMSTATEEN0_AIA_SHIFT)

[potential_risk] lib/sbi/sbi_hart.c:646-648  hart_detect_features
  hart_detect_features() detects SBI_HART_EXT_SMAIA by probing CSR_MTOPI (line 648). On an ACLIC-only system, CSR_MTOPI is defined by the Smaia extension — not by Smaclic/Ssaclic — so this probe fails.
