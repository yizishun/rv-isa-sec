PR #822  target=linux  overall=bug_confirmed
Spec: Access to ACLIC-reused IMSIC CSRs (stopei, eip, eie) from S-mode is now gated by mstateen0 bit 58; if M-mode firmware or early kernel init neglects to check/set this bit, any AIA interrupt delivery path will trap with an illegal instruction exception, crashing the kernel.
Violation: Linux kernel in S-mode accesses stopei, eip[k], or eie[k] CSRs while mstateen0 bit 58 (IMSIC state enable) is zero, either because M-mode firmware (e.g., OpenSBI) did not set it, or because the kernel failed to check the bit before touching these CSRs even though the Smstateen extension is implemented in hardware.
Consequence: denial_of_service
Pattern: csr_read|csr_write|__ASM_STR("csrr|csrw).*(stopei|eip|eie)
------------------------------------------------------------

  S-mode csr_swap(CSR_TOPEI, 0) accesses STOPEI (0x15c) on the critical external-interrupt hot path without any prior check that mstateen0 bit 58 (IMSIC state enable) is set. [compliant] arch/riscv/include/asm/csr.h:233-243  CSR definitions
