PR #735  target=freebsd-src  overall=compliant
Spec: Smip hardware pop re-accesses interrupted context's stack using previous-privilege-mode translation that may be stale after FreeBSD pmap operations between push and pop on the same hart
Violation: FreeBSD kernel modifies the page tables or TLB state for the interrupted context's stack page between a Smip hardware interrupt push (cspspush stores using previous privilege mode translation) and the corresponding hardware pop (sipopret/mipopret loads using SPP/MPP-era translation with implicit SUM/MPRV), causing the pop to dereference through stale virtual-to-physical mappings
Consequence: data_corruption
Pattern: pmap_remove|pmap_activate|pmap_qremove|sfence.vma|cpu_switch|cpu_throw|sstatus.*SUM|mstatus.*MPRV co-located in trap-return or interrupt-service window with implicit sipopret/mipopret semantics
------------------------------------------------------------
