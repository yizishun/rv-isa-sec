PR #735  target=xiangshan  overall=compliant
Spec: CLIC hardware push saves registers to the interrupted context's stack, requiring store translation at the victim privilege level; mipopret/sipopret hardware pop restores registers from stack, requiring load translation at mstatus.MPP/sstatus.SPP respectively. Any mismatch in the effective privilege used for these hardware-generated memory accesses is a privilege-escape vulnerability: stores could corrupt memory the victim cannot access, and loads could leak data across privilege boundaries.
Violation: During hardware-implemented CLIC interrupt push (register save sequence), the store address translation uses the current (post-trap) privilege mode instead of the interrupted context's privilege mode. During mipopret/sipopret hardware pop (register restore sequence), the load address translation uses the current privilege mode instead of mstatus.MPP/sstatus.SPP respectively, or the MPRV/SUM-equivalent translation override is not atomically set before the first load and not atomically cleared after the last load, creating a window where speculative or concurrent accesses observe incorrect translation attributes.
Consequence: privilege_escape
Pattern: search for hardware FSM or microcode that generates automatic memory accesses during CLIC push/pop sequences; verify that the TLB translation request carries the correct `effective_priv` field (previous privilege for push saves, MPP for mipopret loads, SPP for sipopret loads) rather than the architectural `cur_priv`; check that MPRV-equivalent and SUM-equivalent translation overrides are temporally scoped exactly to the hardware-generated load/store window with no speculative leakage outside that window
