PR #735  target=linux  overall=compliant
Spec: Ssip push/pop use interrupted privilege's MMU translation; kernel must preserve user stack mappings between push and sipopret
Violation: Kernel S-mode fast-interrupt handler (between CLIC hardware push and sipopret) modifies the user page table entries for the interrupted task's stack region—e.g., via munmap, mprotect, COW page break, or signal frame setup overwriting saved register slots—causing sipopret's implicit loads (which use sstatus.SPP=U translation with implicit SUM) to read from unmapped or stale physical pages instead of the original register save area
Consequence: data_corruption
Pattern: user page table modification or user stack write in S-mode interrupt handler path reachable before sipopret/sret return
------------------------------------------------------------
[potential_risk] arch/riscv/kernel/signal.c:413-481  setup_rt_frame
  setup_rt_frame writes signal frame data to the interrupted task's user stack via __copy_to_user (line 432) and __put_user (lines 428-432). It then changes regs->sp to point to the new frame (line 469). If the kernel were running under Ssip between CLIC push and sipopret, sipopret's implicit loads from the original user sp would read from stack pages whose contents have been overwritten by the signal frame, or from the new sp that sipopret doesn't know about. Currently compliant because Ssip/sipopret is not implemented.
