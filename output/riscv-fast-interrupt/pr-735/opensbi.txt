PR #735  target=opensbi  overall=compliant
Spec: mipopret now internally sets MPRV and translates register-reload loads via MPP; OpenSBI must not corrupt MPP between CLIC interrupt entry and mipopret execution, or the register restore will access memory with wrong translation and PMP context
Violation: OpenSBI modifies mstatus.MPP between the moment a CLIC interrupt is taken (hardware latches the interrupted privilege level into MPP) and the execution of mipopret (which now internally sets MPRV and uses MPP for memory translation of register-reload loads). If MPP is overwritten—e.g., during an HSM suspend flow that saves/restores mstatus, or a nested-trap handler that rewrites mstatus fields—then mipopret loads will be translated and PMP-checked under the wrong privilege mode, potentially reading from an unintended physical address or bypassing PMP protections on the interrupted context's stack.
Consequence: info_leak
Pattern: CSR write to mstatus (MPP field) in an M-mode interrupt handler path before mret/mipopret; CSR write to mstatus during HSM hart_suspend save/restore that corrupts MPP; any code between CLIC vector entry and mipopret that clobbers mstatus.MPP
