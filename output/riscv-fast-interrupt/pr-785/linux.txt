PR #785  target=linux  overall=compliant
Spec: Kernel ACLIC driver implicitly trusts that inactive interrupt sources return read-only zero for eip/eie bits; hardware violating this guarantee causes phantom interrupts and spurious handler invocation
Violation: Linux kernel ACLIC/APLIC interrupt driver reads eip (external interrupt pending) or eie (external interrupt enable) bits for an interrupt source that is inactive, and acts on the returned value assuming it reflects real interrupt state, when the hardware implementation returns non-zero values for inactive sources in violation of the read-only-zero guarantee.
Consequence: denial_of_service
Pattern: readl.*eip|readl.*eie|for_each_set_bit.*pending|plic.*pending|aclic.*pending|aplic.*pending
