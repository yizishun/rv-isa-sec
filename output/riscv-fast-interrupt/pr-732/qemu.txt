PR #732  target=qemu  overall=compliant
Spec: CLIC trap-entry code path must not modify xithreshold on pure exception entry, and must not clobber pithreshold on M-mode double traps, or the guest interrupt-priority lineage is corrupted causing deadlocks and wrong interrupt masking.
Violation: On synchronous exception entry, QEMU's riscv_cpu_do_interrupt writes the interrupt IPRIO value to xithreshold instead of leaving it unchanged; OR on an M-mode double trap (Smdbltrp), QEMU overwrites xpistatus.pithreshold with the current xithreshold instead of preserving the pre-double-trap pithreshold value.
Consequence: denial_of_service
Pattern: riscv_cpu_do_interrupt.*xithreshold|trap.*pithreshold.*write|smtrap.*threshold.*set|mnstatus.*pithreshold.*double_trap
------------------------------------------------------------
[compliant] target/riscv/cpu_helper.c:2206-2547  riscv_cpu_do_interrupt
  Smnip extension (including xithreshold, pithreshold, mpistatus, mithreshold CSRs) is completely unimplemented in this QEMU version. riscv_cpu_do_interrupt() never writes any threshold CSR on synchronous exception entry, nor does it overwrite pithreshold on M-mode double trap. The claimed vulnerability patterns (writing IPRIO to xithreshold on sync exception, overwriting pithreshold on double trap) cannot manifest because the code paths for Smnip threshold management simply do not exist.
  | The function handles traps via mstatus (MPIE/MPP/MIE=0/MDT/SDT), scause, sepc, stval, htval, htinst, and mepc, mcause, mtval, mtval2, mtinst. No xithreshold/mithreshold/sithreshold CSR access exists anywhere in the function body (lines 2206-2547).
