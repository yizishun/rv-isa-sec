PR #732  target=opensbi  overall=bug_confirmed
Spec: Pre-fix Smnip hardware fails to snapshot mithreshold into mpistatus.pithreshold on synchronous M-mode exceptions, causing mret to restore a stale interrupt threshold and silently break the priority ceiling—OpenSBI's trap context lacks mpistatus/mithreshold fields to compensate
Violation: OpenSBI M-mode trap handler (or any M-mode code path) writes to mithreshold CSR to raise/lower the interrupt priority threshold, then a synchronous exception (e.g., page fault, illegal instruction) occurs before mret. On pre-fix Smnip hardware, the exception entry does NOT capture the current mithreshold into mpistatus.pithreshold. When the exception handler eventually executes mret, the hardware restores mithreshold from the stale mpistatus.pithreshold value—not from the software-intended threshold. Additionally, struct sbi_trap_regs (include/sbi/sbi_trap.h:129-205) saves only mstatus/mstatusH with no mpistatus or mithreshold field, so OpenSBI has no software fallback to detect or correct this corruption.
Consequence: race_condition
Pattern: csr_write CSR_MNTHRESH | csrw mithreshold | csr_set mithreshold | csr_clear mithreshold followed by any load/store/instruction that can fault in M-mode before mret, without explicit mpistatus save/restore
