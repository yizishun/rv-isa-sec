PR #732  target=linux  overall=bug_confirmed
Spec: PR#732 fixes Smnip spec to guarantee that synchronous exceptions do NOT alter xithreshold, so the kernel's exception handler paths that enable interrupts (page fault, breakpoint, syscall) are safe; without this fix, exception-triggered threshold elevation could silently mask lower-priority interrupts causing priority inversion and interrupt starvation
Violation: In the Linux kernel with Smnip enabled, if a synchronous exception handler (e.g., page fault, breakpoint) calls local_irq_enable() while the hardware has the pre-fix buggy behavior of raising xithreshold to the triggering interrupt's IPRIO on exception entry, then lower-priority interrupts remain masked despite interrupts being architecturally enabled, because sithreshold was incorrectly elevated by the exception trap itself.
Consequence: denial_of_service
Pattern: local_irq_enable() called inside a synchronous exception handler path (handle_exception → excp_vect_table → do_page_fault / do_trap_break / do_trap_ecall_u / handle_break) without verification that sithreshold was not adulterated by the trapping exception; also, any KVM HVICTL injection path that fails to distinguish interrupt vs exception when managing the virtual sithreshold for the guest
------------------------------------------------------------
[bug_confirmed] arch/riscv/kernel/entry.S:125-238  handle_exception
  Smnip CSR 'sithreshold' is never saved on the stack during exception entry. CSRs saved are STATUS, EPC, TVAL, CAUSE, SCRATCH (lines 184-194) but not sithreshold (0x1B1). On hardware with the pre-fix behavior where exception entry raises xithreshold to the triggering interrupt's IPRIO, the elevated threshold persists throughout exception handling. When sret executes at ret_from_exception (line 315), sithreshold is not restored to its pre-trap value, causing a persistent silent masking of lower-priority interrupts even after the handler returns.
  | csrr s1, CSR_STATUS
  | csrr s2, CSR_EPC
  | csrr s3, CSR_TVAL
  | csrr s4, CSR_CAUSE
  | csrr s5, CSR_SCRATCH

[bug_confirmed] arch/riscv/kernel/entry.S:247-319  ret_from_exception
  Trap return only restores CSR_STATUS (line 301) and CSR_EPC (line 302), then executes sret (line 315). Does not restore sithreshold from any saved copy. If handle_exception failed to save it, ret_from_exception cannot restore it. The combined effect is a permanent elevation of sithreshold that survives the trap return, which would mask interrupts below the threshold indefinitely.
  | csrw CSR_STATUS, a0
  | csrw CSR_EPC, a2
  | /* no csrw CSR_SITHRESHOLD anywhere */
  | sret

[bug_confirmed] arch/riscv/kernel/entry.S:421-471  __switch_to
  Context switch saves/restores callee-saved integer registers, SR_SUM bit in sstatus, and SCS pointer, but does NOT save/restore sithreshold. If a task is preempted during a synchronous exception handler where sithreshold was elevated, the next task inherits the corrupted sithreshold. If that next task runs with interrupts supposedly enabled, it would experience silent interrupt masking. This is a cross-task pollution of per-hart architectural state.
  | REG_S s0, TASK_THREAD_SUM_RA(a3)
  | /* no save of CSR_SITHRESHOLD */
  | REG_L s0, TASK_THREAD_SUM_RA(a4)
  | /* no restore of CSR_SITHRESHOLD */

[potential_risk] arch/riscv/kvm/vcpu.c:749-775  kvm_riscv_vcpu_swap_in_guest_state
  KVM VCPU state swap exchanges SCOUNTEREN, SENVCFG, and conditionally SSTATEEN0 between host and guest, but does NOT save/restore sithreshold (host) or vsthreshold (guest). If the host takes a synchronous exception while in HS-mode and the pre-fix hardware elevates hithreshold, the elevated threshold would persist in the host context and could leak into the guest context if not properly managed at VCPU boundaries. Conversely, if the guest's vsthreshold is not saved/restored across VCPU exits, guest interrupt prioritization state is lost.
  | vcpu->arch.host_scounteren = csr_swap(CSR_SCOUNTEREN, csr->scounteren);
  | vcpu->arch.host_senvcfg = csr_swap(CSR_SENVCFG, csr->senvcfg);
  | /* no swap of CSR_SITHRESHOLD / CSR_VSITHRESHOLD */
