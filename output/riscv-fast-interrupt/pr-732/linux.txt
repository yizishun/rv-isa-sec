PR #732  target=linux  overall=compliant
Spec: CLIC trap entry must snapshot xpistatus.pithreshold with interrupts disabled, or nested exceptions silently corrupt the threshold lineage causing xRET to restore the wrong interrupt priority floor
Violation: In arch/riscv/kernel/entry.S, the kernel's CLIC-aware trap entry path enables interrupts (IE=1) before saving xpistatus (which carries pithreshold in CLIC mode), so a nested synchronous exception snapshotting the current xithreshold into pithreshold overwrites the threshold lineage that the outer handler's eventual xRET will restore from — or equivalently, the handler restores a saved xpistatus copy after an intervening exception has already clobbered the hardware pithreshold with a lower-priority value.
Consequence: data_corruption
Pattern: sequence where IE is set (sstatus.SIE=1) before xpistatus is saved to a stack/struct, or xpistatus is restored from a snapshot after a window where a synchronous exception could have silently overwritten hardware pithreshold
