PR #732  target=freebsd-src  overall=compliant
Spec: Nested exception inside CLIC interrupt handler can corrupt interrupt priority threshold lineage, causing IRQ starvation or spurious preemption when xRET restores wrong threshold
Violation: In a FreeBSD kernel with CLIC/Smnip enabled, a synchronous exception (page fault, illegal instruction, etc.) occurring inside an interrupt handler corrupts the interrupt priority nesting when hardware implements the pre-fix behavior where xithreshold is unconditionally set on exception entry, or when the kernel's exception path does not correctly distinguish interrupt-from-exception traps in its xpistatus save/restore sequence—leaving xithreshold either stuck at a wrong IPRIO value on exception entry or failing to restore pithreshold lineage on xRET through nested exception+interrupt stacks.
Consequence: denial_of_service
Pattern: trap handler saves/restores xpistatus or xithreshold without checking scause.INTR bit first; exception path modifies xithreshold; xRET path reads stale xpistatus.pithreshold after a nested exception+interrupt sequence where the threshold lineage was overwritten by a double-trap in M-mode
