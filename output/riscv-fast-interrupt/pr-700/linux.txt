PR #700  target=linux  overall=potential_risk
Spec: Smip reorders stack pointer swap to trap-exit boundaries so GPRs always reside on the interrupted context's stack, enabling safe OS thread switching without moving saved context between stacks
Violation: When the Linux kernel performs a context switch during Smip trap handling and expects the saved GPRs (x10-x15) to reside on the handler's stack (old ordering: cspspush before save), but the hardware now saves them on the interrupted context's stack (new ordering: save before cspspush). Conversely, on trap exit, if kernel code accesses GPRs after stack adjustment but before cspspop (old ordering), the GPRs are now already restored and the stack already swapped back.
Consequence: data_corruption
Pattern: arch/riscv/kernel/entry.S or arch/riscv/kvm/ trap save/restore paths that perform or emulate cspspush/cspspop at positions inconsistent with the new mandatory ordering: save GPRs → adjust sp → cspspush on entry; cspspop → restore GPRs → adjust sp on exit. Grep for CSR writes to the shadow stack pointer or cspspush/cspspop pseudo-instructions positioned before GPR save or after GPR restore.
------------------------------------------------------------
