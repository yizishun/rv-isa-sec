PR #668  target=xiangshan  overall=compliant
Spec: Threshold comparison in interrupt controller using raw iprio[i] instead of IPRIO allows low-default-priority interrupts with iprio[i]=0 to bypass the priority threshold, enabling guest/hypervisor interrupt priority escape; IPRIO=255 (lowest effective) must be used for iprio[i]=0 when default priority < MEI
Violation: When the interrupt priority threshold comparison (used to suppress low-priority interrupts) compares raw iprio[i] against xithreshold instead of IPRIO — specifically for interrupts where iprio[i]=0. If the interrupt has a lower default priority than machine external interrupts, iprio[i]=0 should yield IPRIO=255 (lowest effective priority), but raw comparison of 0 >= xithreshold evaluates to false for any nonzero threshold, allowing the interrupt to bypass threshold filtering. Conversely, for iprio[i]=0 with higher default priority than external interrupts (e.g. MSI=3, MTI=7, SSI=1), IPRIO should be 0 — raw iprio[i]=0 comparison yields the same result, masking this discrepancy for those cases. The discrepancy only manifests for architecturally low-priority interrupts (default priority below MEI) configured with iprio[i]=0.
Consequence: privilege_escape
Pattern: iprioNum > xithreshold | prioNum >= .*threshold | raw_priority.*>=.*threshold | (isZero === false|!isZero).*threshold where isZero is not mapped to IPRIO before the comparison
