PR #695  target=opensbi  overall=compliant
Spec: Incorrect Smnip CSR addresses cause M-mode stack pointer save/restore and interrupt preemption/threshold CSRs to alias into each other, enabling interrupt-configuration corruption that could unpark a malicious S-mode handler's preemption window or leak M-mode stack state to S-mode via a wrong-CSR swap
Violation: OpenSBI M-mode code compiled against the pre-fix (incorrect) Smnip CSR addresses accesses CSRs that have been renamed/renumbered — e.g., writing to old msp (0x348) actually hits new mipreemptcfg (0x348), or reading old mipreemptcfg (0x347) hits new mithreshold (0x347). This occurs when firmware CSR address constants are stale relative to hardware that implements the corrected spec.
Consequence: privilege_escape
Pattern: CSR address constant definitions for Smnip CSRs (msp, mipreemptcfg, mithreshold, ssp, sithreshold) that match the old spec values (0x348, 0x347, 0xFB1, 0x148, 0x1B1) instead of the corrected values (0x349, 0x348, 0x347, 0x149, 0x147) — search for CSR_* or csr_write/csr_read with raw addresses in interrupt context save/restore paths
