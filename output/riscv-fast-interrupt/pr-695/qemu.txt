PR #695  target=qemu  overall=compliant
Spec: Smnip CSR address renumbering: 5 CSRs had their addresses fixed—stale QEMU code using old addresses will access wrong registers (msp/mipreemptcfg collide at 0x348, mithreshold at invalid 0xFB1), causing silent corruption of interrupt preemption state and stack pointer values
Violation: QEMU hardcodes Smnip CSR addresses using the pre-fix (incorrect) values from the draft spec: msp at 0x348 instead of 0x349, ssp at 0x148 instead of 0x149, mithreshold at 0xFB1 instead of 0x347, mipreemptcfg at 0x347 instead of 0x348, or sithreshold at 0x1B1 instead of 0x147. Any CSR read/write using stale address constants will access the wrong logical register, causing msp writes to alias into mipreemptcfg (0x348 collision) and mithreshold to land at an unmapped custom-range address (0xFB1) that may read as zero or be silently ignored.
Consequence: data_corruption
Pattern: #define CSR_MSP\s+0x348|#define CSR_SSP\s+0x148|#define CSR_MITHRESHOLD\s+0xFB1|#define CSR_MIPREEMPCFG\s+0x347|#define CSR_SITHRESHOLD\s+0x1B1|msp.*0x348|mithreshold.*0xFB1|sithreshold.*0x1B1
------------------------------------------------------------
