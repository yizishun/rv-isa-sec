PR #695  target=linux  overall=compliant
Spec: Incorrect CSR addresses in kernel headers would alias Smnmi interrupt-control CSRs (mithreshold→0xFB1 was mipreemptcfg, msp→0x348 is now mipreemptcfg, ssp→0x148 was sithreshold) onto different registers, enabling guest-to-host CSR write escalation in KVM and corrupting interrupt preemption/delivery state across context switches
Violation: Linux kernel (KVM, context-switch, or interrupt handling) accesses Smnmi/Smcip CSRs using the pre-correction CSR addresses (e.g., mithreshold at 0xFB1, sithreshold at 0x1B1, msp at 0x348, ssp at 0x148) instead of the corrected final addresses, causing reads/writes to alias into wrong CSRs on hardware that implements the final spec.
Consequence: privilege_escape
Pattern: #define\s+(CSR_|CSR_VS)?(MITHRESHOLD|SITHRESHOLD|MIPREEMPTCFG|MSP|SSP|MPISTATUS|SPISTATUS)\s+0x(FB1|1B1|348|148|346|146)
------------------------------------------------------------
[compliant] arch/riscv/include/asm/csr.h:251-610  (none — CSR macro definitions)
  No Smnmi/Smcip CSR address constants (pre-correction or otherwise) are defined in this file. The only CSR_SSP defined (line 336) is 0x011 for Zicfiss shadow stack, which is unrelated to the Smcip supervisor SSP. The kernel has no Smnmi/Smcip support at all at this revision, so there is nothing to mis-address.
