PR #695  target=freebsd-src  overall=compliant
Spec: Stale Smnip CSR address constants cause cross-register aliasing: msp↔mipreemptcfg at 0x348 and mithreshold↔mipreemptcfg at 0x347 create a write-what-where primitive where stack pointer values land in interrupt preemption/threshold config, potentially escalating to M-mode interrupt hijack in bhyve guests
Violation: FreeBSD kernel or bhyve hypervisor compiled against the pre-correction Smnip CSR address definitions uses the stale CSR number constants: msp at 0x348 (now mipreemptcfg), mipreemptcfg at 0x347 (now mithreshold), mithreshold at 0xFB1 (now unmapped), or sithreshold at 0x1B1 (now unmapped). A CSR read-modify-write on the old msp address 0x348 writes a stack pointer value into mipreemptcfg; conversely, a read of old mithreshold at 0xFB1 targets custom CSR space and returns garbage, corrupting interrupt enable logic. In FreeBSD's bhyve, guest CSR emulation using the old addresses passes incorrect register semantics to the VMM, allowing a guest to configure M-mode interrupt preemption by writing to what it believes is its stack pointer.
Consequence: privilege_escape
Pattern: (0x348|0x148|0x347|0xFB1|0x1B1)\s*(,|//|/*).*(msp|ssp|mithreshold|mipreemptcfg|sithreshold|SMPNIP|CLIC)
