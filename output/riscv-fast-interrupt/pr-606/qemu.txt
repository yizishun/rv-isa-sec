PR #606  target=qemu  overall=compliant
Spec: Removal of mithreshold/sithreshold in favor of unified eithreshold: QEMU must stop exposing per-privilege threshold CSRs and gate all interrupt delivery (including major interrupts from CLINT) through the single eithreshold when ACLIC mode is active, otherwise guest interrupt masking is silently bypassed.
Violation: When QEMU still implements the now-removed per-privilege interrupt threshold CSRs mithreshold (0xFB1) and sithreshold (0x1B1), or internally consults per-privilege thresholds instead of the unified eithreshold, after this spec PR removes them in favor of a single eithreshold that controls interrupt masking for all interrupt sources (major + external) in ACLIC mode.
Consequence: denial_of_service
Pattern: mithreshold|sithreshold|0xFB1|0x1B1|xithreshold.*threshold|threshold.*xs|threshold.*[ms]mode
------------------------------------------------------------
[compliant] target/riscv/cpu_bits.h:1-1200  (CSR definitions, file-wide)
  QEMU does not define the per-privilege interrupt threshold CSRs mithreshold (0x347) or sithreshold (0x147), nor any CSR at addresses 0xFB1/0x1B1. Grep for 'mithreshold', 'sithreshold', '0xFB1', '0x1B1', '0x347', '0x147' returned zero results in target/riscv/. The only threshold mechanism in QEMU is the standard AIA IMSIC eithreshold (ISELECT 0x72) in riscv_imsic.c, which is the page-based ISELECT mechanism, not a standalone CSR. No implementation of Smidctrl/Ssidctrl (ACLIC) extension exists in QEMU, so there are no legacy per-privilege thresholds to remove or unify.
