PR #606  target=linux  overall=compliant
Spec: ACLIC mode unifies timer/software/external interrupts into a single ACLIC domain, breaking kernel code that performs per-class dispatch via scause major identities or assumes independent sie-maskable interrupt classes still exist
Violation: Linux kernel runs on hardware with ACLIC mode enabled (eidelivery=1, ACLIC is the primary interrupt controller) while kernel interrupt dispatch still branches on scause major interrupt identities (IRQ_S_TIMER=5, IRQ_S_SOFT=1, IRQ_S_EXT=9) or independently manipulates sie.STIE/sie.SSIE/sie.SEIE bits, because the spec now unifies all major interrupts into a single ACLIC interrupt source whose identity flows through xtopei/topi rather than scause/sip
Consequence: race_condition
Pattern: reads CSR_CAUSE and compares against IRQ_S_TIMER, IRQ_S_SOFT, or IRQ_S_EXT without a prior eidelivery/ACLIC-mode guard; writes to CSR_SIE or CSR_SIP to individually mask/unmask timer/software/external interrupt classes without checking whether ACLIC overrides these bits; sets CSR_STVEC to vectored mode assuming OBASE+4*exccode dispatch when ACLIC mode repurposes mode=01 for memory-indirect vectoring
