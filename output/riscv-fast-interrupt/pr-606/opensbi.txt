PR #606  target=opensbi  overall=compliant
Spec: ACLIC vectored mode uses memory-indirect interrupt dispatch; missing fence.i between vector table write and interrupt enable causes stale handler addresses
Violation: In ACLIC mode (eidelivery enabled) with mtvec.mode=01 (vectored), interrupt dispatch uses M[mtvec_base + XLEN/8 * IID] memory-indirect vectoring. If OpenSBI writes new entries to this M-mode vector table and enables interrupts without a fence.i, the hart may jump to stale handler addresses fetched from the I-cache. Additionally, if PMP is configured to deny M-mode read access to the vector table region, the hardware interrupt vector fetch faults with unrecoverable consequences since Smivt/Smehv double-trap recovery extensions are removed in this spec revision.
Consequence: race_condition
Pattern: write to interrupt vector table memory region followed by interrupt enable (mstatus.MIE=1 or CSR write setting MIE) without intervening fence.i
