PR #606  target=opensbi  overall=compliant
Spec: mtvec.mode=01 branch target semantics silently change when ACLIC mode is active, causing OpenSBI's vectored-mode mtvec setup to be misinterpreted as an in-memory interrupt vector table base, enabling arbitrary control-flow hijack
Violation: OpenSBI writes CSR_MTVEC with mode=01 (vectored) while eidelivery (ACLIC mode) is active, or eidelivery is later enabled without updating mtvec mode. The spec diff redefines mtvec.mode=01 behavior: in ACLIC mode, the hardware performs an in-memory vector table lookup at M[mtvec.BASE + XLEN/8*interrupt_identity] instead of the legacy branch to mtvec.BASE + 4*exccode. OpenSBI's mtvec base address (fw_base.S:112,136,401) is configured assuming legacy vectored semantics and is not laid out as an interrupt vector table, causing the hardware to fetch arbitrary memory as handler addresses.
Consequence: privilege_escape
