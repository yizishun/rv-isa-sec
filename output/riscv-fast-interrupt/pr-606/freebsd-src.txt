PR #606  target=freebsd-src  overall=compliant
Spec: FreeBSD's RISC-V trap handler has no ACLIC awareness — if firmware enables ACLIC mode, all interrupts are redirected through ACLIC instead of the native CLINT/SIP mechanism, but FreeBSD neither configures ACLIC nor understands the unified interrupt identity space, causing complete interrupt delivery failure
Violation: FreeBSD kernel boots on hardware where ACLIC mode is enabled (eidelivery != 0), but the kernel has no code to configure ACLIC, read the unified interrupt identity from xtopei/topi, or handle the fact that all interrupts (timer, software, external) are now delivered through the ACLIC domain rather than through the traditional CLINT-based SIP/STIP/SSIP/SEIP mechanism. The trap handler in sys/riscv/riscv/trap.c dispatches all interrupts via intr_irq_handler() using only scause bits, and locore.S configures stvec in direct mode (mode=00) with no awareness of the vectored-mode table-fetch behavior change when ACLIC is active.
Consequence: denial_of_service
Pattern: csrw\s+stvec.*cpu_exception_handler|do_trap_supervisor.*SCAUSE_INTR|intr_irq_handler.*INTR_ROOT_IRQ|csr[srw].*stvec(?!.*[Ss]ave|restore|swap)
