PR #606  target=xiangshan  overall=compliant
Spec: xtvec.mode=11 (vector table mode) demoted to Reserved; hardware that still accepts mode=11 and/or computes interrupt-trap PC using the old dual-table fetch logic (mivt/meivt for internal vs external) can vector to attacker-controlled addresses, bypassing the now-unified OBASE-based memory-indirect scheme gated on eidelivery
Violation: When xtvec.mode is written with value 0b11 (previously 'interrupt vector table mode', now Reserved per this PR), if the XiangShan RTL does not reject the write as WARL-illegal or does not raise an illegal instruction exception on subsequent interrupt-taking when mode==0b11, the hardware may execute the old vector-table fetch behavior (using stale mivt/sivt/meivt/seivt base addresses or a miscomputed VTBASE). Additionally, in ACLIC mode (eidelivery=1) with xtvec.mode=01, if the hardware unconditionally computes PC=OBASE+4*exccode instead of conditionally performing the memory-indirect fetch M[OBASE+XLEN/8*vtoffset] & VTMASK, the trap handler address is incorrect.
Consequence: privilege_escape
Pattern: search xtvec.mode WARL legalization logic for mode value 0b11 being accepted as legal; search interrupt-trap PC generation logic for unconditional OBASE+4*exccode without checking eidelivery to select memory-indirect vectoring; search CSR address decode for 0x307(mivt) 0x308(meivt) 0x107(sivt) 0x108(seivt) that should raise illegal-instruction exception
