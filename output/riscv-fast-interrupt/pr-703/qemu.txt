PR #703  target=qemu  overall=potential_risk
Spec: Smip SP swap must only fire on async==true (interrupts, not exceptions), and QEMU must reject Smip + mtvec.MODE=0, otherwise guest kernel exception handlers execute with the wrong stack pointer after a prior interrupt silently swapped SP↔XSP
Violation: In QEMU TCG, Smip's SP↔XSP stack-pointer swap is triggered for both synchronous exceptions and asynchronous interrupts at trap entry (riscv_cpu_do_interrupt, line 2206), rather than being gated on the 'async' flag (line 2221). Additionally, QEMU permits Smip to be active while mtvec.MODE=0 or stvec.MODE=0 (direct mode), where the spec declares direct-mode-with-shared-entry-points incompatible because the trap handler cannot distinguish an interrupt (SP was swapped) from an exception (SP was not swapped).
Consequence: data_corruption
Pattern: SP↔XSP swap code at trap-entry (cpu_helper.c:riscv_cpu_do_interrupt epilogue, ~line 2531) lacking "if (async)" guard; AND/OR absence of startup validation that ext_smip requires (mtvec & 3) != 0 and (stvec & 3) != 0 (vectored mode only)
