PR #669  target=linux  overall=potential_risk
Spec: eidelivery/eithreshold removed from Smidctrl/Ssidctrl scope: kernel must not assume eidelivery indicates ACLIC mode nor write eithreshold for ACLIC thresholds—use mithreshold instead
Violation: Kernel code that detects Smidctrl/Ssidctrl and then reads eidelivery to infer ACLIC delivery mode, or writes to eithreshold for interrupt threshold control instead of using mithreshold. The old spec guaranteed eidelivery=0x20000000 when Smidctrl/Ssidctrl present, but the new spec removes eidelivery/eithreshold from Smidctrl/Ssidctrl scope entirely, making their values implementation-defined and their semantics unrelated to ACLIC operation.
Consequence: data_corruption
Pattern: (?:riscv_isa_extension_available|riscv_has_extension).*(?:SMIDCTRL|SSIDCTRL).*?(?:eidelivery|eithreshold|EIDELIVERY|EITHERSHOLD)|csr_(?:read|write).*?(?:EIDELIVERY|EITHERSHOLD).*(?:aclic|smidctrl)
