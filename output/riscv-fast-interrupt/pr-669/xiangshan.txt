PR #669  target=xiangshan  overall=bug_confirmed
Spec: Removal of eithreshold/eidelivery from Smidctrl scope and introduction of mithreshold with major+minor identity thresholding creates a semantic mismatch: RTL hardwiring old eidelivery ACLIC-only mode or implementing old priority-only eithreshold will silently break interrupt priority ceiling enforcement, allowing untrusted interrupts to escape threshold gating
Violation: XiangShan RTL implements Smidctrl/Ssidctrl with hardwired eidelivery=0x20000000 (ACLIC-only mode) and an eithreshold CSR that applies only to interrupt priority levels, but software following the updated spec attempts to use the new mithreshold CSR (which applies to both major and minor interrupt identities) for priority ceiling synchronization. The hardware either (a) ignores writes to mithreshold because the decoder routes threshold through the old eithreshold register, or (b) applies old threshold semantics that do not filter on minor interrupt identities, allowing low-priority minor interrupts to preempt critical sections protected by Priority Ceiling Protocol.
Consequence: privilege_escape
Pattern: search for CSR decode logic where (eithreshold CSR address is decoded but mithreshold is not) OR (eidelivery is hardwired to constant 0x20000000 via WireInit/RegInit) OR (interrupt threshold comparator only checks priority bits but not major/minor identity fields)
