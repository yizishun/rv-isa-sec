PR #219  target=qemu  overall=compliant
Spec: QEMU indiscriminately writes badaddr to stval for all breakpoint exceptions, violating Sstvala clarification that only breakpoints defined to write an address should update stval, and that EBREAK/C.EBREAK are explicitly excluded
Violation: QEMU unconditionally writes env->badaddr to stval for every RISCV_EXCP_BREAKPOINT exception (cpu_helper.c:2303-2308), including: (a) EBREAK/C.EBREAK exceptions, which the spec explicitly excludes from stval writes, and (b) debug-trigger breakpoints (e.g., icount triggers via debug.c:289) that are not defined to write an address to stval. The stale badaddr from a prior operation leaks into stval for triggers that never set badaddr.
Consequence: info_leak
Pattern: case RISCV_EXCP_BREAKPOINT: tval = env->badaddr — no check distinguishing ebreak vs trigger-source vs whether the breakpoint cause is defined to write stval
