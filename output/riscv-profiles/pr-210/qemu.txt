PR #210  target=qemu  overall=compliant
Spec: CHERI capability instructions introduced by RVYA25 must be correctly bounds-checked in QEMU TCG — failure to emit capability authorization checks per Zydefaultcap/Zys/Zylevels1 encoding in translated host code is a direct guest-to-host escape via arbitrary memory access beyond authorized capability bounds.
Violation:
  QEMU TCG translates CHERI capability-aware load/store instructions (CLR/CSR
  variants) without enforcing capability bounds, permissions, and tag validity
  in the generated host code — i.e., the softmmu fast-path dereferences the
  raw capability address without checking base/top/perms fields, or capability
  register writes do not properly invalidate cached capability metadata,
  allowing a malicious guest to craft a capability with widened bounds and
  then access memory outside the originally authorized region.
Consequence: function_loss
Pattern:
  TCG translator for CHERI capability load/store does not emit bounds-check or
  permission-check host instructions before the memory access; capability
  register writes (to c1–c31) do not flush cached capability metadata in
  DisasContext; Zydefaultcap capability encoding fields (base, top, perms,
  otype) are decoded with incorrect bit positions or widths matching
  uycfg.base=0 format; Svucrg page-revocation walk does not invalidate
  capability tags in QEMU's internal tag memory on PTE A/D bit transitions.
