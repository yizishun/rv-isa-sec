PR #210  target=freebsd-src  overall=compliant
Spec: RVYA25 profile mandates Zydefaultcap capability encoding but omits the actual encoding format specification; FreeBSD's context-switch and signal-delivery paths (cpu_switch.S, sendsig, ptrace) rely on knowing the exact in-memory and in-register capability layout to safely save/restore process capability state without privilege-boundary corruption
Violation: In the FreeBSD kernel, when cpu_switch() or savectx() saves/restores CHERI capability registers (PCC, DDC, CSP, CGP, CTP, and all GPR capability metadata/tags) using an implicitly assumed capability encoding format, but the RVYA25 profile mandates only Zydefaultcap (uycfg.base=0) without specifying the actual encoding layout—if the kernel's struct pcb or trapframe uses a fixed-size capability representation that diverges from the hardware's actual encoding (e.g., 128-bit vs 256-bit capabilities, different tag-bit positions, or different bounds-compression schemes), capability bounds, permissions, or tag bits are silently truncated, widened, or corrupted across context switches.
Consequence: privilege_escape
Pattern: struct pcb.*cap|savectx.*cap|restorectx.*cap|CHERICap|cap_register|sizeof.*pcb|trapframe.*cap|cpu_switch.*cap|__capability.*struct|capability.*encoding|szcap|CAP_SIZE
