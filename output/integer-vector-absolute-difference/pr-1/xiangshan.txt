PR #1  target=xiangshan  overall=compliant
Spec: Hardware decode logic must trap vabd/vabdu/vwabda/vwabdau on reserved SEW={32,64} else undefined ALU behavior causes silent data corruption on spec-reserved encodings
Violation: In XiangShan RTL, if the vector instruction decoder (typically in the IDU/dispatch stage) decodes vabd 0x11, vabdu 0x13, vwabda 0x15, or vwabdau 0x16 with SEW != 8 and SEW != 16 without raising an illegal instruction exception, the execution pipeline will proceed to compute absolute difference on undefined SEW widths (32/64). The vector ALU datapath may lack correct signed/unsigned subtraction-comparison logic for these widths under these specific funct6 codes, producing architecturally undefined results that software cannot rely on.
Consequence: data_corruption
Pattern: vabd.*SEW|vabdu.*SEW|vwabda.*SEW|vwabdau.*SEW|OPMVV.*0x11|OPMVV.*0x13|OPMVV.*0x15|OPMVV.*0x16|funct6.*0x(11|13|15|16).*sew|illegal_inst.*vabd|reserved.*SEW
