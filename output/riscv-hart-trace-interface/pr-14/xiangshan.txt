PR #14  target=xiangshan  overall=bug_confirmed
Spec: trcstate priority rule (lowest-value-wins) and sdsec mapping contradiction cause silent trace data leakage when security inhibit is overridden by lower-value debug inhibit; multi-hart arbitration and CDC glitches further compound the exposure
Violation: In XiangShan RTL trace interface, the spec-mandated trcstate priority rule ('prioritize lowest numerical value') creates a priority inversion: debug mode (01) numerically dominates security inhibit (10). When both are asserted simultaneously and debug subsequently exits while security inhibit remains active, trcstate transitions 01→00 instead of holding at 10, causing the encoder to emit a synchronization packet and resume tracing despite an active security fence. Additionally, the sdsec section mandates mapping sec_inhibit to trcstate=01 (the debug value), contradicting the encoding table where security reasons = 10, making security-vs-debug trace stops indistinguishable at the decoder. In multi-hart configurations, trace interconnect arbitration can starve a hart's security inhibit if another hart continuously asserts lower-value debug inhibit.
Consequence: info_leak
Pattern: trcstate.*priority|Mux1H.*trcstate|sec_inhibit.*0?1|halted.*OR.*trcstate|multi.*hart.*trace.*arbit|trcstate.*CDC.*glitch|synchronization.*packet.*timing
