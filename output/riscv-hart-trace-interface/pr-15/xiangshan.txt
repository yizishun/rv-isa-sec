PR #15  target=xiangshan  overall=not_implemented
Spec: Hardware notrace[1] security-inhibit signal driven by insufficiently privileged software state enables attackers to selectively blind trace-based security monitoring during exploits
Violation:
  In XiangShan RTL, when the notrace[1] (security inhibit) signal is driven by
  a CSR bit or internal state that is writable by software running below
  machine mode (e.g., supervisor or user mode), or when the reserved encoding
  notrace=2'b11 is not properly handled and defaults to tracing-uninhibited
  behavior, an attacker can suppress trace output during privilege escalation
  or side-channel exploitation, making the attack invisible to external trace-
  based security monitors. Additionally, if backwards-compatibility wiring
  (wiring halted to notrace[0], tying notrace[1] to 0) is hardcoded in the
  RTL, the security inhibit dimension is permanently disabled, violating the
  sdsec extension's security intent.
Consequence: info_leak
Pattern:
  notrace[1] assigned from software-writable CSR without M-mode-only write
  protection; notrace == 2'b11 defaulting to 2'b00; trace_enable gated only on
  debug_mode without security_inhibit signal path
