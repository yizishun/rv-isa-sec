PR #84  target=xiangshan  overall=compliant
Spec: Spec tightens multi-access instruction trace ordering from permissive 'may report simultaneous' to mandatory 'dretire must complete no later than iretire' — hardware trace encoder must enforce dretire drain-before-iretire ordering for Zcmp/vector multi-access instructions, or trace-based security monitors will observe unmatched instruction retirements with missing data access records
Violation: XiangShan trace encoder asserts iretire for a multi-access instruction (Zcmp cm.push/cm.pop, vector ld/st) while one or more dretire events for that same instruction remain pending in the trace output buffer/FIFO, violating the new 'must be reported no later than' timing constraint
Consequence: info_leak
Pattern: trace encoder iretire assertion without first draining pending dretire entries for the same instruction; multi-access instruction dretire posted after iretire in the trace packet stream; Zcmp/vector load-store trace reporting with unconstrained dretire-to-iretire ordering
