PR #84  target=xiangshan  overall=not_implemented
Spec: Spec tightens final MMA data-access retirement deadline from permissive 'may' to normative 'must report no later than instruction retirement,' requiring XiangShan trace-interface RTL to guarantee dretire timing for the last access of Zcmp/vector multi-access instructions does not lag behind iretire.
Violation:
  In XiangShan RTL, if the final load/store access of a multi-memory-access
  instruction (Zcmp push/pop, vector load/store) has its dretire signal
  asserted AFTER the instruction's iretire is asserted (i.e., the data trace
  retirement pulse occurs in a cycle subsequent to instruction trace
  retirement), the hardware violates the tightened normative requirement that
  the final data access 'must be reported no later than when the instruction
  is reported as retired.' This can occur when the load/store unit's
  completion pipeline is decoupled from the commit/retirement stage in an out-
  of-order design, such that a straggling final MMA access completes post-
  retirement.
Consequence: data_corruption
Pattern:
  when (dretire && dtype_is_mma && is_final_access_of_instruction &&
  iretire_past) in trace interface output logic; or $past(iretire) && dretire
  && is_final_mma_access without corresponding iretire in same cycle
