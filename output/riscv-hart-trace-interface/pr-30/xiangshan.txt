PR #30  target=xiangshan  overall=compliant
Spec: PR#30 expands itype=6 to explicitly include C.JALR/C.JR instructions; trace encoder hardware that uses a stale instruction-classification table will emit wrong itype values for these compressed instructions, corrupting branch-trace output and misleading security analysis relying on trace integrity
Violation: Trace encoder's instruction classification hardware (itype assignment logic) assigns an obsolete itype encoding for C.JALR or C.JR instructions — for example, failing to map C.JALR/C.JR to itype=6 ('Uninferrable jump + Return') in narrow mode or to itype=13 ('Return') in wide mode when rs=link. This occurs if the encoder still uses the pre-PR#30 classification table that did not explicitly enumerate C.JALR and C.JR under itype=6/13, or if the wide-mode encoder incorrectly treats itype values 6 and 7 as a combined reserved field instead of two separate reserved entries.
Consequence: info_leak
Pattern: trace.*itype.*assign|classify.*C\.JALR|classify.*C\.JR|itype.*6.*JALR|itype.*13.*JALR|InstType.*JALR|TraceEncoder.*itype|itype_width.*branch.*classify
