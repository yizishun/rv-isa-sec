PR #59  target=xiangshan  overall=bug_confirmed
Spec: tval signal in hart-trace interface must be gated on itype==1 (exception only); outputting tval during interrupt retirement (itype==2) leaks stale CSR data or uninitialized microarchitectural state to the off-core trace encoder — the spec diff splits cause/tval validity so that cause is valid for both exception and interrupt, but tval is valid only for exceptions
Violation:
  In XiangShan RTL, when an interrupt trap (itype=2) occurs at retirement, the
  hart-to-trace-encoder interface (HTI) incorrectly outputs the tval signal as
  valid data. The RTL must gate tval output on itype==1 (exception) only — if
  the hardware unconditionally wires the internal mtval/stval CSR register
  value to the HTI tval port regardless of itype, then during interrupt
  retirement (itype=2) the trace encoder receives undefined data. This
  undefined tval may be stale residual state from a prior exception, an
  uninitialized register pipeline stage, or arbitrary microarchitectural state
  propagated through unflushed pipeline latches. The spec change corrects the
  validity window: cause is valid for both itype=1 and itype=2, but tval is
  valid ONLY for itype=1 (exceptions). Violation occurs if the Chisel/Verilog
  HTI module lacks the condition `when (io.itype === Itype.exception)` (or
  equivalent MUX select) on the tval output path, causing the signal to carry
  live internal state to the off-core trace encoder on every interrupt
  retirement.
Consequence: info_leak
Pattern:
  Mux(itype === Itype.exception, tval_csr, 0.U) | WireInit(tval, DontCare) |
  when(!itype_is_exception) { tval := DontCare } | io.hti.tval := tval_reg |
  Cat(cause, tval).asUInt | Valid(tval) | Output(tval) | TraceIngress.tval

[potential_risk] src/main/scala/xiangshan/backend/trace/Interface.scala:50-53  TraceCoreInterface (trap bundle definition)
  trap.cause and trap.tval are structurally bundled as a paired composite in
  the TraceCoreInterface. This bundling encourages downstream logic to treat
  cause and tval as jointly valid, when in fact tval is valid only for

[potential_risk] src/main/scala/xiangshan/backend/trace/Interface.scala:127-127  Itype.isTrap
  Itype.isTrap() predicate matches both Exception(1) and Interrupt(2),
  returning true for interrupt retirement. While semantically correct (both
  are 'traps'), downstream logic (L2Top.scala:275-278) uses this predicate as
