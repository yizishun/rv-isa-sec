PR #57  target=xiangshan  overall=not_implemented
Spec: When dretire fires without iretire for multi-access vec/Zcmp instructions, instruction-trace context signals must remain valid; current ROB commit-to-trace path in XiangShan invalidates context on iretire boundaries only, causing trace decoder to misattribute data accesses to wrong instructions
Violation:
  In XiangShan RTL, the instruction trace interface (TraceCoreInterface)
  signals (itype, iaddr, ilastsize, priv) are only updated and valid when a
  new instruction block retires (iretire non-zero). If data trace were
  implemented with dretire for multi-memory-access instructions (vector
  load/store, Zcmp cm.push/cm.pop), the instruction context signals would be
  stale or invalid during cycles where dretire is asserted without iretire,
  because XiangShan currently ties all instruction context validity to iretire
  > 0 in the ROB commit path (Rob.scala:1284: traceValids(i) :=
  io.commits.isCommit && io.commits.commitValid(i)). There is no mechanism to
  hold/latch instruction trace context across cycles when only data sub-
  accesses retire without corresponding instruction retirement.
Consequence: info_leak
Pattern:
  dretire asserted without corresponding iretire context validity; multi-
  memory-access instruction trace context not preserved/stalled during split
  data retirement; trace instruction context signals (itype/iaddr/ilastsize)
  not qualified by dretire-only validity window
