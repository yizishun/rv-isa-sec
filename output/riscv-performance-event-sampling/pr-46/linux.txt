PR #46  target=linux  overall=not_implemented
Spec: PDIS v1.0 record format redefines address-validity from bit[63] self-tagging to explicit ADR1V/ADR2V header bits, and encodes physical addresses right-shifted-by-2 in pdisadr2 (matching PMP/PTE encoding for XLEN-beyond addresses); kernel perf/KVM consumers using the pre-v1.0 interpretation will leak bogus virtual/physical addresses into userspace profiles.
Violation:
  Linux kernel PDIS sample-record parser checks bit 63 of pdisadr1/pdisadr2
  for address validity instead of the new ADR1V/ADR2V fields in pdishdrev, OR
  consumes the right-shifted physical/guest-physical address from pdisadr2
  without left-shifting by 2 bits to recover the full address.
Consequence: info_leak
Pattern:
  pdisadr[12]\s*\[\s*63\s*\]|pdisadr2.*[Pp]hys|guest.phys.*pdisadr2|(spdisdata
  |vsireg|pdis.*record|pdis.*sample).*addr
