PR #27  target=xiangshan  overall=compliant
Spec: New Sspesa extension CSRs (shpmsdetailsbt1/2, shpmsdetailsdata, shpmsdetailscc) expose detailed microarchitectural pipeline execution state—including cache/TLB miss events, branch targets, and retire stall causes—creating hardware-level info-leak if not properly isolated across VM/privilege boundaries or if AutoRun streaming lacks privilege gating
Violation: In XiangShan RTL, the new shpmsdetailsdata CSR exposes microarchitectural pipeline state (INSTRET count, RSTATE stall/flush/drain states, CTs branch counts, CTOFFSET1/2 branch positions, and CAUSE bits encoding I$/D$/ITLB/DTLB miss and branch mispredict events) to M-mode or S-mode software. If the CSR module does not clear or context-switch shpmsdetailsdata (and the companion shpmsdetailsbt1/2 branch target registers) on VM boundary transitions (e.g., satp write, hgatp switch, or VM enter/exit in hypervisor scenarios), a guest VM or lower-privilege context can observe the microarchitectural execution profile—including cache miss patterns, retire stall causes, and branch targets—of a previously executing higher-privilege or cross-VM context. Additionally, if the AR (AutoRun) bit in shpmsdetailscc is writable by S-mode without M-mode override, an attacker can enable autonomous sample streaming to the trace unit, creating a hardware-level data exfiltration channel that bypasses software security monitors.
Consequence: info_leak
Pattern: shpmsdetails(bt[12]|data|cc).*wen|shpmsdetails.*priv|shpmsdetails.*context|shpmsdetails.*flush|shpmspc.*access|AR.*AutoRun.*wen|CAUSE.*\b(I\$miss|ITLBmiss|D\$miss|DTLBmiss|branch.mispredict)\b|sample.*trace.*unit.*wen
