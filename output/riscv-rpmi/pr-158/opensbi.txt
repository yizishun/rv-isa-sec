PR #158  target=opensbi  overall=bug_confirmed
Spec: OpenSBI implementing TEE memory parcel operations must fence PMP/ePMP changes before returning to S-mode, or REE/TEE memory access boundaries are not architecturally enforced
Violation:
  When OpenSBI (M-mode, acting as the RPMI TEE 'framework') modifies PMP/ePMP
  CSR entries to change memory access permissions during
  TEE_MEMORY_PARCEL_CREATE, TEE_MEMORY_PARCEL_ACCEPT,
  TEE_MEMORY_PARCEL_RELEASE, or TEE_MEMORY_PARCEL_RECLAIM service
  handling—specifically writing to pmpcfg/pmpaddr CSRs to grant, revoke, or
  re-map memory between REE and TEE domains—without executing SFENCE.VMA (or
  the hart-specific PMP synchronization sequence) between the CSR write and
  the return-to-S-mode mret, stale PMP/TLB state may leave the previous access
  permissions in effect on the calling hart.
Consequence: privilege_escape
Pattern:
  pmpcfg_write|pmpaddr_write|csrw.*pmpcfg|csrw.*pmpaddr followed by mret
  without intervening sfence\.vma|fence\.i|fence w,o within same SBI trap
  handler
------------------------------------------------------------
