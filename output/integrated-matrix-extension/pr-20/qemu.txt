PR #20  target=qemu  overall=compliant
Spec: IME tile load/store emulation must substitute LD=eff_lambda*LMUL when rs2=0, or QEMU collapses all matrix rows to the same memory offset, corrupting guest tile data and leaking stale register state through agnostic fills
Violation: In QEMU's TCG translation or helper implementation of IME matrix tile load/store instructions (vmflt.v, vmfst.v, vmttl.v, vmtts.v), the leading dimension LD from rs2 is used directly in row-address computation (base + i*LD + j) without first checking LD==0 and substituting LD = eff_lambda * LMUL. When a guest passes rs2=0 intending the compact-layout shorthand, all rows compute to the same memory offset, causing every row to read from or write to the same base-relative addresses instead of advancing by the effective line size.
Consequence: data_corruption
Pattern: matrix tile load/store address computation using LD from rs2 without prior guard `if (LD == 0) LD = eff_lambda * LMUL` — check TCG translator gen_helper_* calls and vector_helper.c tile helpers for missing zero-LD substitution
