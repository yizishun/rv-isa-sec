PR #27  target=xiangshan  overall=compliant
Spec: Floating-point IME partial-sum rounding must use hardwired round-to-odd (rto), not frm-based rounding; incorrect rounding mode causes double-rounding data corruption in matrix accumulators
Violation: The XiangShan IME floating-point matrix multiply-accumulate datapath rounds partial-sum S using the rounding mode from frm CSR (or any mode other than round-to-odd) before accumulating into C[m,n], violating the mandatory round-to-odd (rto) requirement for partial-sum rounding. Specifically, when SEW=32 or SEW=64 floating-point, W>1 (packed variants), and G>1 (multi-group microarchitecture), the intermediate rounding step incorrectly applies frm-based rounding instead of rto, causing double-rounding errors that deviate from the architectural accumulator state.
Consequence: data_corruption
Pattern: IME floating-point partial-sum accumulator rounding logic using frm rounding mode instead of hardwired round-to-odd; look for rounding unit instantiation in IME MAC pipeline stage that connects frm CSR bits to the partial-sum rounder rather than forcing odd-bit tie-break
