PR #5  target=qemu  overall=compliant
Spec: IME tile store pseudocode drops init_masked_source overlap checks — QEMU must not spuriously illegal-instruction on valid mask-source overlap in vmts.v/vmtts.v
Violation: QEMU implements the IME tile store instructions (vmts.v, vmtts.v) reusing the base vector store infrastructure that calls init_masked_source() to validate the mask register, which checks for illegal overlap between v0 (mask) and the vs3 source register group. The spec PR removes init_masked_source from store pseudocode entirely, replacing it with a direct read_vmask + per-element mask-bit check. If QEMU retains the init_masked_source call, any guest using an IME tile store where the v0 mask register group overlaps with the vs3 tile data register group will receive a spurious illegal-instruction exception that the spec no longer authorizes.
Consequence: denial_of_service
Pattern: init_masked_source used in vmts.v or vmtts.v emulation path; trans_ime_store or equivalent helper calling vext_check_mask_overlap or similar mask-source overlap validation that raises illegal-instruction
------------------------------------------------------------
[compliant] target/riscv/:0-0  N/A
  IME tile store instructions (vmts.v, vmtts.v) are not implemented in this QEMU codebase. No decode patterns, translation handlers, or helper functions exist for these instructions. The vulnerability pattern (init_masked_source call in the vmts.v/vmtts.v emulation path causing spurious illegal-instruction exceptions) cannot occur because there is no code path to trigger it. The masked-store overlap check via require_vm() on the existing vector store path (vse*.v) is spec-compliant behavior for the standard vector extension — it is only the IME tile store semantics that the spec PR changes.
