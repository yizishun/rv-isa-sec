PR #34  target=xiangshan  overall=compliant
Spec: Spec removes illegal-instruction trap on vfmmacc.vv with mixed E4M3×E5M2 or FP16×BF16 inputs; XiangShan decoder must drop the 'mixed-format requires widening' guard and add subextension-requirement rows for non-widening mixed FP16/BF16 vfmmacc.vv — failure to do so causes spurious illegal-instruction denial-of-service on valid mixed-format matrix code
Violation: In XiangShan RTL, the instruction decoder (IDU) for the matrix unit raises an illegal-instruction exception when vfmmacc.vv is issued with altfmt_A ≠ altfmt_B (mixed E4M3×E5M2 at SEW=8, or mixed FP16×BF16 at SEW=16), due to a decoder check that enforces the old spec restriction permitting mixed-format only on widening instructions (vfwmmacc.vv/vfqwmmacc.vv). Alternatively, the subextension-validity check (CSR-based feature-enable logic) omits the two new vfmmacc.vv rows for mixed FP16/BF16 and fails to require both Zvvfp16mm AND Zvvbf16mm, causing either spurious illegal-instruction traps when both extensions ARE present, or privilege escapes when one extension is missing but the instruction is nevertheless permitted.
Consequence: denial_of_service
Pattern: Chisel when/switch on altfmt_A=/=altfmt_B that gates isWidening before permitting mixed-format vfmmacc; CSR misa/isecfg subextension check table missing Zvvfp16mm+Zvvbf16mm rows for non-widening vfmmacc.vv; decode stage exception-gen for mixed-format vfmmacc without checking altfmt_A =/= altfmt_B ONLY for widening ops
