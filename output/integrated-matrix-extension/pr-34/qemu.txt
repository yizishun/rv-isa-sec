PR #34  target=qemu  overall=compliant
Spec: QEMU must remove illegal-instruction traps for mixed-format vfmmacc.vv (8-bit and 16-bit) and add dual-subextension checks for mixed FP16/BF16 vfmmacc.vv per new permissive spec
Violation: QEMU's decode/validation logic for vfmmacc.vv still raises an illegal-instruction exception when altfmt_A != altfmt_B (mixed-format inputs: E4M3×E5M2 at SEW=8, or FP16×BF16 at SEW=16), because the emulator enforces the old restrictive rule that only widening instructions (vfwmmacc.vv, vfqwmmacc.vv) permit mixed formats. Alternatively, QEMU omits the subextension check requiring both Zvvfp16mm AND Zvvbf16mm to be present for mixed-FP16/BF16 vfmmacc.vv.
Consequence: function_loss
Pattern: decode check comparing altfmt_A != altfmt_B and branching to illegal-instruction when opcode is vfmmacc.vv (non-widening); or missing Zvvfp16mm/Zvvbf16mm dual-extension requirement check for vfmmacc.vv with mixed 16-bit formats
