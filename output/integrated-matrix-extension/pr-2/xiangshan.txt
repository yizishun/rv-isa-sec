PR #2  target=xiangshan  overall=compliant
Spec: CMUL formula changed from LMUL/λ² to VLENE/λ², making accumulator register group sizing independent of LMUL; XiangShan CSRVTypeBundle lacks lambda and altfmt bitfields entirely, guaranteeing data corruption if Integrated Matrix instructions are decoded with the existing vtype CSR layout
Violation: In XiangShan RTL, when computing CMUL (accumulator C register group multiplier) for Integrated Matrix instructions, the hardware uses the legacy formula CMUL = LMUL / λ² instead of the new spec-mandated CMUL = VLENE / λ². Since VLENE is an implementation constant (VLEN/SEW) while LMUL is a dynamic CSR field, the two formulas produce different values whenever LMUL ≠ 1. Specifically, at LMUL=8 the old formula yields CMUL=8/λ² while the correct formula yields CMUL=VLENE/λ², causing the accumulator register group to span the wrong set of physical vector registers. The vtype CSR (CSRVTypeBundle in CSRBundles.scala:240) also defines VSEW at bits 5:3 and has no lambda[2:0] field at bits 62:60 nor altfmt at bits 9-10, meaning the hardware literally cannot read λ to compute either formula correctly without a CSR encoding change.
Consequence: data_corruption
Pattern: CMUL.*LMUL|LMUL.*lambda|CMUL.*=.*LMUL|register.*group.*multiplier.*C|accumulator.*group.*size|lambda.*vtype.*field|altfmt.*vtype.*bit
