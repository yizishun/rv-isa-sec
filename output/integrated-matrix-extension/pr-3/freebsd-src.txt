PR #3  target=freebsd-src  overall=compliant
Spec: New vtype CSR fields (lambda at bits XLEN-2:XLEN-4, altfmt_A at bit 9, altfmt_B at bit 10) extend vector configuration state; if FreeBSD's context-switch vtype save/restore in cpu_switch.S or vfp.c does not mask these bits, thread A's tile geometry configuration leaks to or corrupts thread B's matrix operations, violating process isolation
Violation: FreeBSD kernel context-switch code saves/restores vtype CSR via a read-modify-write sequence that only preserves known fields (vsew, vlmul, vta, vma, vill) but silently drops or corrupts the newly-defined lambda[2:0] (bits XLEN-2:XLEN-4), altfmt_A (bit 9), and altfmt_B (bit 10) fields introduced by the Integrated Matrix extensions. This occurs when one thread configures vtype with non-default lambda/altfmt values, is preempted, and another thread's vtype restore overwrites those bits because the kernel vtype save/restore mask does not include the new field positions.
Consequence: info_leak
Pattern: vtype.*save|vtype.*restore|csrw.*vtype|csrr.*vtype|SET_FP_VTYPE|vstate_save|vstate_load|vtype_mask|VTYPE_RESERVED
