PR #269  target=xiangshan  overall=not_implemented
Spec: MMA/CAS extension restructures data trace packet format/subformat fields with different bit widths and encodings from v2.0; hardware trace encoder implementing mismatched format version produces bit-level decoding failures across all trace packet fields
Violation:
  XiangShan hardware trace encoder (TraceEncoder module) generates data trace
  packets using the old v2.0 format field encoding (3-bit format:
  000/001/010/011/100/101/110) while an external trace decoder expects the
  MMA/CAS extension format (variable 0/1/2-bit format: 00=load/store,
  01=multi-memory-access, 10=atomic/CSR, 11=split-load-data) — or vice versa.
  Additionally, the subtype field width mismatch (old: 2-3 bits, new
  subformat: 2 bits for load/store, 4 bits for atomic/CSR) causes bit-level
  misalignment of all subsequent fields (size, diff, data, address),
  completely corrupting the decoded trace stream.
Consequence: function_loss
Pattern:
  TraceEncoder.*format.*Cat\(|te_data.*format.*UInt|data_trace.*packet.*encode
  |trTeData.*packet|EfficientTrace.*packet.*format|dtype.*encoding|TraceEncode

[potential_risk] /home/yzs/riscv/XiangShan/src/main/scala/xiangshan/backend/trace/Interface.scala:151-158  Priv (object)
  The Priv enum encoding (HU=0, HS=1, M=3, D=4, VU=5, VS=6) skips value 2
  between HS(1) and M(3). While this matches the RISC-V privilege mode
  encodings (U=0, S=1, H=2, M=3, VU=5, VS=6) with H(2) corresponding to the
  hypervisor-specific state that might not need a distinct trace encoding, the
  priv field in XiangShan's TraceCoreInterface uses only 3 bits — but the
  rocket-chip reference TraceCoreInterface uses 4 bits for priv. If an
  external encoder expects a 4-bit priv field, this 3-bit encoding could cause
  misalignment at the encoder input boundary. However, since the actual
  downstream encoder is external to XiangShan, this is a potential integration
  risk rather than a confirmed bug.
  | object Priv extends NamedUInt(3) {

  |   def HS = 1.U
  |   def M  = 3.U
  |   def D  = 4.U
  |   def VU = 5.U
  |   def VS = 6.U
