PR #38  target=xiangshan  overall=not_implemented
Spec: irdepth field bit-width miscalculation omits required +1 term when return_stack_size_p > 0, causing trace encoder to generate malformed packets with truncated stack-depth/call-count values, corrupting program-flow reconstruction for all trace consumers
Violation:
  When XiangShan trace encoder parameter return_stack_size_p > 0, the irdepth
  field width is computed as return_stack_size_p + call_counter_size_p (old
  formula) instead of return_stack_size_p + 1 + call_counter_size_p (new
  formula). This occurs when the Chisel/Verilog hardware trace packet
  generator instantiates the irdepth field width as a compile-time Wire or Reg
  parameter using the uncorrected expression, causing the field to be 1 bit
  too narrow in Format 0/1/2 packets. The bit-level packet serializer then
  shifts subsequent fields (irreport or padding) into the bit position that
  should belong to irdepth[MSB], corrupting the entire packet bitstream
  alignment for any downstream trace decoder.
Consequence: data_corruption
Pattern:
  return_stack_size_p\+\s*call_counter_size_p
