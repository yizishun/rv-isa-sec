PR #276  target=xiangshan  overall=potential_risk
Spec: XiangShan TraceCoreInterface has no encoder-configuration readback channel; external encoder's Standard Support Packet content (feature flags, sizing parameters, protocol version) is unverifiable by the core, enabling trace-decoder mis-synchronization that can silently drop or misattribute privilege transitions, exception sequences, and branch behavior in security-audit trace streams.
Violation:
  XiangShan TraceCoreInterface FromEncoder struct carries only enable/stall
  Booleans (Interface.scala:37-40) with no encoder configuration readback
  path. The external encoder (XSTOP/Tessent) independently generates the
  Standard Support Packet. If the encoder advertises features in the support
  packet (implicit_return=1, branch_predictor=1, resync_disabled, sizing
  parameters) that diverge from what the core actually emits on the trace
  interface—or if the encoder implements protocol version >=2.1 without this
  extension—the trace decoder reconstructs an instruction stream inconsistent
  with architectural execution. The core has zero visibility into or
  validation of support packet content.
Consequence: info_leak
Pattern:
  TraceCoreInterface.*FromEncoder|class FromEncoder|io\.in\.fromEncoder\.(enab
  le|stall)|support.*packet|format3.*subformat.*3|trTeImpl|trTeProtocol(Versio
  n|Major|Minor)

[potential_risk] src/main/scala/xiangshan/backend/trace/Interface.scala:42-62  TraceCoreInterface
  TraceCoreInterface defines the complete trace boundary. fromEncoder is
  Input({enable, stall}) — the encoder can only assert enable or stall.
  toEncoder is Output with priv/mstatus/trap/groups — the core pushes trace
  groups out. There is no signal path for encoder→core readback of support
  packet fields. A MUX-based encoder that claims implicit_return=1 (Format 2
  branch prediction mode) while the core emits explicit return types
  (Itype=FunctionReturn=13) would cause the trace decoder to skip return stack
  validation, producing an incorrect instruction trace. Similarly, if
  resync_disabled is advertised but the encoder falls back to Format 0 resync,
  the decoder's expectation of continuous trace would silently produce wrong
  output.
  | class TraceCoreInterface(hasOffset: Boolean = false) extends Bundle ... {
  |   val fromEncoder = Input(new Bundle {
  |     val enable = Bool()
  |     val stall  = Bool()
  |   })
  |   val toEncoder = Output(new Bundle {
  |     val priv   = Priv()
  |     val mstatus = UInt(XLEN.W)
  |     val trap   = new Bundle{
  |       val cause = UInt(CauseWidth.W)
  |       val tval  = UInt(TvalWidth.W)
  |     }
  |     val groups = Vec(TraceGroupNum, ValidIO(new Bundle{
  |       val iaddr     = UInt(IaddrWidth.W)
  |       val ftqOffset = if (hasOffset) Some(...) else None
  |       val itype     = UInt(ItypeWidth.W)
  |       val iretire   = UInt(IretireWidthCompressed.W)
  |       val ilastsize = UInt(IlastsizeWidth.W)
  |     }))
  |   })

[potential_risk] src/main/scala/xiangshan/backend/trace/Interface.scala:151-158  Priv
  Priv encoding uses NamedUInt(3) with values: HU=0, HS=1, M=3, D=4, VU=5,
  VS=6. Encoding 2 is undefined/left unencoded. The RISC-V privilege spec
  defines M=3, S=1, U=0 — so HS=1 and HU=0 are consistent with H-extension
  virtualization (S→HS, U→HU). However, the trace spec version 1.0 (rocket-
  chip TraceCoreInterface) uses 4-bit priv encoding. XiangShan uses only 3
  bits. While sufficient for the currently supported privilege modes, encoding
  2 is reserved and could cause ambiguity with future privilege modes or when
  passed to a decoder expecting 4-bit standard encoding.
  | object Priv extends NamedUInt(3) {
  |   def HU = 0.U
  |   def HS = 1.U
  |   def M  = 3.U
  |   def D  = 4.U
  |   def VU = 5.U
  |   def VS = 6.U
  | }
