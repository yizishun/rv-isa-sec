PR #150  target=opensbi  overall=compliant
Spec: CSR rename from msdcfg to mdtcfg splits debug/trace security fields into a new independent CSR; OpenSBI targeting old spec would write to wrong CSR address, leaving mdtcfg at reset-0 and silently disabling all external debug and trace
Violation: OpenSBI writes debug/trace security configuration fields (SEDBGALW, VSEDBGALW, UEDBGALW, SETRCALW, VSETRCALW, UETRCALW) to the old msdcfg CSR address instead of the new mdtcfg CSR, causing the security policy to silently fail because mdtcfg remains at its reset value (all 0s, i.e., all debug/trace disallowed)
Consequence: function_loss
Pattern: csr_write.*msdcfg|csr_read.*msdcfg|SEDBGALW|SDEDBGALW|SDETRCALW|USEDBGALW|USETRCALW
