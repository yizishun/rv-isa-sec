PR #109  target=xiangshan  overall=not_implemented
Spec: Repurposing reserved bit-10 of trTeControl as trTeDisSelfHosted (WARL) to hide self-hosted trace CSRs from software; if RTL decode of bit-10 does not gate trSr* CSR accessibility, software gains unauthorized trace control despite debugger reservation, constituting privilege escape.
Violation:
  When trTeDisSelfHosted bit is set to 1 in trTeControl CSR but the RTL's CSR
  decode/access logic for self-hosted trace CSRs (Smstrc*/Ssstrc* trSr*
  registers) fails to gate those CSRs as inaccessible—i.e., reads of trSr*
  CSRs return non-trap values or writes have hardware effect despite
  trTeDisSelfHosted=1, because the previously-reserved bit-10 decode signal is
  not plumbed to the self-hosted trace CSR access-control logic in the Chisel
  CSR module.
Consequence: privilege_escape
Pattern:
  trTeDisSelfHosted.*(?:=|:=)\s*0\.U|bit 10.*reserved|trSr(?:[A-Z][a-
  z])+.*CSR.*access|self.hosted.*trace.*gate|Smstrc.*Ssstrc.*implement
------------------------------------------------------------
[not_implemented] N/A:0-0  N/A
  The XiangShan processor RTL does not implement the RISC-V Efficient Trace
  Specification (Smstrc/Ssstrc extensions). No trTe* or trSr* CSRs exist in
  the design at all — grep for trTeControl (0x7A1), trTeImpl (0x7A2),
  trTeDisSelfHosted, trSr*, Smstrc, and Ssstrc across all .scala files
  returned zero matches. The only 'trace' references in the codebase are to
  pipeline execution tracing (Trace.scala, TraceBuffer.scala), which is
  unrelated to the RISC-V standardized trace encoder CSRs. Since the target
  component is not implemented, the trTeDisSelfHosted access-control
  vulnerability condition does not apply — there is no trTeControl CSR to
  misconfigure, and no self-hosted trace CSRs whose accessibility could be
  incorrectly gated.
  | N/A — no relevant RTL exists
