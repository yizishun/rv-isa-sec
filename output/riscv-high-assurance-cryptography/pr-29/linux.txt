PR #29  target=linux  overall=compliant
Spec: ACE CC state is non-architecturally invisible to the kernel but persists across context switches per the spec's inheritance model; kernel must explicitly export/import all live CCs on context-switch boundaries or leak cryptographic context between processes
Violation: Linux kernel context-switches a task with active ACE Cryptographic Contexts (CCs) without first issuing ace.export to serialize all in-use CC state to memory, or resumes a task without ace.import to restore it. The spec mandates that ace.export/ace.import are resumable across interrupts (like vector whole-register stores), meaning a partially-completed export interrupted by a trap or context switch leaves CC state in an indeterminate hardware state. The spec's explicit inheritance model — 'When a process domain that has enabled ACE is preempted, the parent process inherits the state' — means the kernel cannot rely on implicit state isolation; it must explicitly snapshot and clear CC state across address-space transitions, or the next scheduled task inherits the prior task's live cryptographic context.
Consequence: info_leak
Pattern: context switch path (__switch_to, switch_to, cpu_switch_to) or trap return path that does not call ace.export on all bits set in CC_USED CSR before switching mm, or that does not call ace.import on resume; also preempt notifier or KVM vcpu_put path missing ace.export
