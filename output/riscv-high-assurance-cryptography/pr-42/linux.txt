PR #42  target=linux  overall=compliant
Spec: aceerror now has a normative error priority table; kernel trap handlers and KVM virtualization must inspect exc.code bits in decreasing priority order (6→5→3(top)→3→2/1→1→3(bottom)→4→0) or risk reporting a masked low-priority error to userspace while a higher-priority error (e.g., Unconfigured CR) remains undiagnosed.
Violation: Linux kernel trap handler or KVM reads aceerror CSR bits in non-prioritized order (e.g., checking lower-priority exc.code bits before higher-priority ones) when reporting ACE instruction faults to userspace or virtualizing the CSR for a guest, potentially masking a higher-severity error behind a lower-severity one.
Consequence: info_leak
Pattern: csr_read.*aceerror|ACEERROR|aceerror.*csr|case.*0x[0-9a-fA-F].*aceerror|ace.*trap.*handler
