PR #617  target=freebsd-src  overall=not_implemented
Spec: If DC.iohgatp.MODE=Bare and DC.msiptp.MODE!=Off, MSI page table translation proceeds without a valid GSCID address-space tag, allowing a guest-owned MSI page table to intercept MSIs from a host-owned device or misroute interrupts across VM boundaries—a guest-to-host or cross-VM privilege escape in bhyve.
Violation:
  In the FreeBSD kernel IOMMU driver, when a Device-Context (DC) is programmed
  with iohgatp.MODE=Bare (no guest physical address translation, e.g., bare-
  metal pass-through or host-owned device context) but msiptp.MODE is left as
  Flat or any non-Off value. This leaves the MSI page table walker active
  without a valid GSCID to scope translations, causing MSI writes to be
  translated through a stale or guest-affiliated MSI page table, or producing
  translations not associated with any VM address space.
Consequence: privilege_escape
Pattern:
  iohgatp.*MODE.*Bare.*msiptp|msiptp.*MODE.*(Flat|[^O])\s*[^.]*iohgatp.*Bare|D
  C\.iohgatp|DC\.msiptp|device_context.*iohgatp|device_context.*msiptp

[not_implemented] sys/contrib/device-tree/Bindings/iommu/riscv,iommu.yaml:1-50  N/A
  FreeBSD does not implement a RISC-V IOMMU driver. The only RISC-V IOMMU-
  related file in the entire source tree is a device-tree binding schema
  (sys/contrib/device-tree/Bindings/iommu/riscv,iommu.yaml, lines 1-50), which
  is imported DT binding documentation, not kernel driver code. The x86 IOMMU
  drivers (Intel VT-d at sys/x86/iommu/intel_ctx.c and AMD-Vi at
  sys/x86/iommu/amd_ctx.c) and the ARM SMMU driver (sys/arm64/iommu/smmu.c)
  use their respective hardware-specific register sets (DMAR context entries,
  AMD DTE, SMMU Stream Table Entries) — none of which implement the RISC-V
  IOMMU iohgatp/msiptp Device-Context registers. The spec reference tree at
  /home/yzs/riscv/rv-isa-sec/spec_ref/ also lacks the RISC-V IOMMU
  specification itself (referenced only as a bibliography citation in the
  IOPMP spec). Consequently, the vulnerability condition — iohgatp.MODE=Bare
  with msiptp.MODE≠Off — has no code to analyze in this codebase.
