PR #617  target=qemu  overall=compliant
Spec: Unchecked msiptp.MODE when iohgatp.MODE is Bare can route MSI translations without GSCID-bound VM isolation, enabling cross-guest MSI injection via the IOMMU
Violation:
  In QEMU, when the IOMMU processes a device context (DC) where iohgatp.MODE
  is Bare (second-stage translation disabled) but msiptp.MODE is not Off, the
  emulation violates the new spec requirement that msiptp.MODE must be Off
  when iohgatp.MODE is Bare. Without this check, MSI address translation would
  proceed using an MSI page table without a valid GSCID to associate
  translations with a VM address space. The `riscv_iommu_validate_device_ctx`
  function in hw/riscv/riscv-iommu.c:753-756 already gates this combination as
  a misconfiguration, but any path that bypasses DC validation (e.g., direct
  msiptp write via emulated register injection, snapshot restore, or migration
  of a VM with a pre-existing invalid DC state) could activate MSI translation
  in a Bare second-stage context.
Consequence: function_loss
Pattern:
  msiptp.MODE != Off && iohgatp.MODE == Bare && !dc_misconfiguration_check

  invalidated. While the transition rules only allow

[compliant] hw/riscv/riscv-iommu-pci.c:146-149  riscv_iommu_vmstate
