PR #679  target=qemu  overall=potential_risk
Spec: PDT data corruption fault must be reported as cause 269 (PDT_CORRUPTED), not cause 274 (PT_CORRUPTED); returning the wrong cause class misleads the guest IOMMU driver into treating a process-directory-table integrity failure as a regular second-stage page-table corruption, potentially causing the guest to attempt incorrect recovery (e.g., reloading page tables instead of re-validating the PDT) and leaking the true nature of the fault from the guest's error-handling logic
Violation: QEMU's process directory table (PDT) walk code in locate_process_context / riscv_iommu_spa_fetch detects a data corruption (e.g., checksum/integrity failure) on a PDT entry and reports fault cause 274 (RISCV_IOMMU_FQ_CAUSE_PT_CORRUPTED, 'second-stage PT load data corruption') instead of the correct cause 269 (RISCV_IOMMU_FQ_CAUSE_PDT_CORRUPTED, 'PDT data corruption fault'). This would occur if QEMU's future PDT corruption detection follows the old buggy reference model behavior where cause 274 is used in the GST_DATA_CORRUPTION path within the PDT walk.
Consequence: info_leak
Pattern: grep -rn 'PDT.*corrupt\|corrupt.*PDT\|FQ_CAUSE_PDT\|pdt.*FQ_CAUSE_PT_CORRUPT\|GST_DATA_CORRUPTION.*27[4-9]\|cause.*274.*pdt\|pdt.*cause.*274' hw/riscv/riscv-iommu.c

  RISCV_IOMMU_FQ_CAUSE_PDT_CORRUPTED (269) and RISCV_IOMMU_FQ_CAUSE_PT_CORRUPTED (274) are defined but never referenced in riscv-iommu.c. This is dead code.
