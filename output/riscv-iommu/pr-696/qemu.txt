PR #696  target=qemu  overall=compliant
Spec: IOMMU capabilities register is guest-writable (missing regs_ro mask); ATS command legality check uses s->enable_ats instead of the actual capabilities register bits, so a guest can observe CAP.ATS=0 while ATS commands remain accepted
Violation: IOMMU capabilities register (offset 0x0000) is stored in regs_rw without a corresponding regs_ro mask, making it fully guest-writable. A guest write clearing the ATS bit (capabilities.ATS=0) makes the CAP register report no ATS support, yet QEMU's command dispatch at lines 1933/1942 continues to accept ATS INVAL and PRGR commands because it gates on s->enable_ats (a separate QEMU property) rather than on the capabilities register value read back from regs_rw.
Consequence: function_loss
Pattern: regs_rw\[RISCV_IOMMU_REG_CAP\]
