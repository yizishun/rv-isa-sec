PR #731  target=qemu  overall=compliant
Spec: Fault report PV bit reflects post-modification ctx->process_id instead of original transaction pid_valid, causing guest system software to misidentify whether the faulting request carried a process ID
Violation:
  In QEMU, when riscv_iommu_ctx_fetch() implicitly assigns a default
  process_id via DPE (line 1167: ctx->process_id = 0, replacing NOPROCID),
  subsequent fault reports at line 699 and line 1658 use !!ctx->process_id or
  enable_pid (derived from DC_TC_PDTV) to set the PV bit in the fault queue
  record, instead of preserving the original pid_valid from the transaction
  request. This diverges from the spec requirement that fault reports must use
  orig_pid_valid — the pid_valid value as it was when the translation request
  entered the IOMMU, before any implicit PID assignment.
Consequence: info_leak
Pattern:
  !!ctx-
  >process_id.*report_fault|enable_pid.*report_fault|process_id.*=.*0.*ctx_fet
  ch
