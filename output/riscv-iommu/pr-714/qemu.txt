PR #714  target=qemu  overall=compliant
Spec: QEMU lacks D-bit update writeback for G-stage PTEs entirely (ade path) and doesn't guard against spurious D-bit updates on PTEs with W=0 during implicit ATS accesses, violating two-stage IOMMU A/D update semantics
Violation: QEMU's G-stage (second-stage) page table walk at riscv-iommu.c:456 uniformly applies the D-bit fault check for all write accesses without distinguishing implicit (ATS, is_implicit==1) accesses. The W-permission check at line 452 currently masks this by faulting writes to PTEs with W=0 before reaching the D-bit check. However, QEMU does not implement A/D-bit writeback to in-memory PTEs at all — when GADE/SADE is enabled (ade==true), lines 454-456 are bypassed and no PTE update occurs. If D-bit writeback is ever implemented, a write access (NW=0, is_implicit=1) to a G-stage PTE with W=0 and D=0 would incorrectly trigger a D-bit PTE modification, violating the spec rule that D-bit updates must only occur when gpte->W==1.
Consequence: data_corruption
Pattern: iotlb->perm & IOMMU_WO && !ade && !(pte & PTE_D) without gpte->W==0 guard for implicit/ATS accesses; also search for missing stl_le_dma/stq_le_dma PTE writeback when GADE/SADE enabled
