PR #183  target=qemu  overall=not_implemented
Spec: QEMU IOPMP MDCFG implementation must self-enforce the two improper-setting constraints (at-most-one-MD per entry, lower-index-MD → lower-index-entries) since the spec makes behavior implementation-dependent and dropped the safe-reference NOTE; failure to validate MDCFG monotonicity on write would allow a malicious guest to overlap memory domains, granting an I/O device access to regions outside its intended MD
Violation:
  If QEMU implements IOPMP MDCFG table write handling, and the emulation
  allows MDCFG(m).t values that create overlapping or inverted entry ranges
  (MDCFG(k).t > MDCFG(m).t for k < m) without enforcing the two mandatory
  constraints (at-most-one-MD ownership per entry, and lower-indexed MDs
  getting lower-indexed entries), then guest software relying on MDCFG entry
  partitioning to isolate I/O domains could have enforcement silently broken.
  The PR's removal of reference-behavior guidance (previously a NOTE listing
  options like 'correct the values', 'reject the write', or 'leave the
  improper setting') removes safe defaults that a QEMU developer might
  otherwise follow, placing full burden on the implementer to pick a secure
  implementation-dependent behavior.
Consequence: privilege_escape
Pattern:
  MDCFG write handler that stores t fields without validating monotonicity or
  without enforcing at-most-one-MD ownership post-write; lookup logic that
  double-assigns entries when MDCFG ranges overlap; missing W1C/WARL semantics
  on MDCFG registers allowing guest to craft improper settings

  QEMU does not implement IOPMP or MDCFG tables. A comprehensive search of the
  entire QEMU source tree found zero references to 'iopmp', 'IOPMP', 'mdcfg',
  or 'MDCFG' in any file. The RISC-V IOMMU (hw/riscv/riscv-iommu.c) implements
  I/O address translation but is architecturally separate from IOPMP, which is
  an I/O bus master access control mechanism. The CPU-side PMP
  (target/riscv/pmp.c) controls only hart-initiated memory accesses. The IOPMP
  specification exists at /home/yzs/riscv/rv-isa-sec/spec_ref/riscv-iopmp/
  with a complete reference model, but no corresponding QEMU emulation code
  exists. The PR titled 'Clarify MDCFG Table' appears to be a spec-only change
  removing reference-behavior guidance (the NOTE listing options like 'correct
  the values', 'reject the write', or 'leave the improper setting') from the
  IOPMP specification document itself, not a QEMU code change.
