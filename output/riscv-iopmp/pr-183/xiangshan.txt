PR #183  target=xiangshan  overall=bug_confirmed
Spec: PR removes hardware reference behaviors for improper MDCFG Table settings, leaving entry-to-MD assignment purely implementation-dependent; XiangShan RTL without explicit monotonicity enforcement on MDCFG(m).t writes risks entry misattribution across memory domains, enabling unauthorized memory access through RRID-to-MD association bypass
Violation:
  In XiangShan RTL, when the MDCFG Table has an improper setting (non-
  monotonic MDCFG(m).t values where MDCFG(k).t > MDCFG(m).t for k < m), the
  IOPMP entry-to-MD assignment logic produces implementation-dependent
  behavior. If the RTL implements a naive interval-based lookup (e.g., simple
  combinational comparators without monotonicity enforcement or write-
  rejection), a transaction with RRID associated to MD_m or MD_k may match
  entries belonging to an unintended memory domain, or entries may become
  orphaned and silently grant/deny access contrary to the programmer's intent.
  This is especially critical when HWCFG0.enable is set after programming
  improper MDCFG values—the spec now explicitly requires proper settings only
  when enable is set, creating a window where improper configurations can be
  latched into working state. The removed reference behaviors (auto-
  correction, write rejection, entry nullification) are no longer suggested
  guidance, so if XiangShan adopted or relied on any of those patterns, the
  RTL must now ensure its custom implementation-dependent behavior still
  satisfies the two remaining constraints: (a) an entry belongs to at most one
  MD, and (b) lower-indexed MD entries have lower indices than higher-indexed
  MD entries.
Consequence: privilege_escape
Pattern:
  MDCFG_t_non_monotonic | MDCFG improper setting | MDCFG(m).t comparator
  unsigned less-than | entry_index_range MDCFG lower_bound upper_bound |
  HWCFG0_enable MDCFG_proper_setting gate | MDCFG write no monotonicity check
