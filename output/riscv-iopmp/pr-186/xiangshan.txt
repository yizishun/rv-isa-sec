Spec: HWCFG0.no_err_rec field is absent from the RegHwcfg0 Chisel Bundle; hardware provides no capability discovery bit for error recording support, violating the spec requirement that no_err_rec be readable at bit 23 and wired to 1 when error record is not implemented
Violation: XiangShan IOPMP RegHwcfg0 Bundle (IopmpChecker.scala:495-517) omits the no_err_rec field entirely; the toUInt bit concatenation at line 516 does not include bit 23 for no_err_rec, and neither RegHwcfg0 object initialization (lines 470-493) nor the class field definitions (lines 495-517) declare this bit. Software reading HWCFG0 cannot discover whether the error capture record (ERR_INFO, ERR_REQADDR, ERR_REQADDRH, ERR_REQID) is implemented or wired to zero.
Consequence: function_loss

  RegHwcfg0 Bundle omits the no_err_rec field entirely. The toUInt Cat concatenation at line 516 allocates all 32 bits to existing fields (enable[1], addrh_en[1], md_num[6], md_entry_num[7], mfr_en[1], pees[1], peis[1], stall_en[1], no_w[1], no_x[1], chk_x[1], rrid_transl_prog[1], rrid_transl_en[1], prient_prog[1], user_cfg_en[1], sps_en[1], tor_en[1], srcmd_fmt[2], mdcfg_fmt[2]) with no reserved bit for no_err_rec. Bit position 23 is occupied by md_entry_num[6] (the MSB of the 7-bit md_entry_num field at bits [17:23]). A grep of the entire ChiselIOPMP source confirms zero instances of no_err_rec, ERR_INFO, ERR_REQADDR, ERR_REQADDRH, or ERR_REQID — the error capture record registers are not implemented at all. Software reading HWCFG0 cannot discover whether error capture records exist or are wired to zero; the bit position that should carry no_err_rec instead carries an unrelated functional field value.
