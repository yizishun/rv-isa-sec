PR #204  target=xiangshan  overall=compliant
Spec: Entry iteration loop lacks the spec-mandated 'break when cur_entry >= HWCFG1.entry_num' guard, allowing cross-MD entry-range aliasing and unbounded scan cycles when MDCFG.t exceeds physical entry count
Violation:
  In XiangShan's IopmpChecker Ctrl FSM (sPriority state), the entry iteration
  loop increments j_indx from md_t_pre to md_t but never compares j_indx
  against HWCFG1.entry_num. When MDCFG(m).t is programmed >= entry_num, the
  FSM iterates past the available entry region. Due to 9-bit truncation of the
  SRAM address (entry_j_indx), indices >= 512 wrap back to physical entries
  0-511, causing (a) cross-MD entry aliasing: MD(N).t = 512 makes MD(N+1)
  start scanning from physical entry 0 instead of 512, and (b) redundant
  multi-pass scans of the same physical entries per transaction check,
  degrading throughput.
Consequence: privilege_escape
Pattern:
  Ctrl FSM sPriority state: j_indx increment/comparison without
  HWCFG1.entry_num bound; grep for 'j_indx.*md_t|entry_num|hwcfg1' in entry
  iteration context
