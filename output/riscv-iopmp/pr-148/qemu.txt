PR #148  target=qemu  overall=compliant
Spec: IOPMP spec reorg moves security-critical global access-deny bits (no_w, no_x, chk_x) from HWCFG0 into new HWCFG2/HWCFG3 registers and relocates ENTRYOFFSET from 0x0014 to 0x002C; if QEMU emulates the old register map, guest capability discovery reads wrong registers, causing silent failure of global write/execute protection
Violation: QEMU emulates the pre-reorg IOPMP register map (HWCFG0 at 0x0008 holding no_w[12], no_x[11], chk_x[10], ENTRYOFFSET at 0x0014) while guest software uses the post-reorg spec (no_w/no_x in HWCFG3 at 0x0014, chk_x in HWCFG2 at 0x0010, ENTRYOFFSET at 0x002C). Guest reads HWCFG3 at 0x0014 to check global write-deny capability but QEMU returns the old ENTRYOFFSET value at that offset, causing the guest to mis-evaluate whether hardware-backed global write/execute denial is active.
Consequence: privilege_escape
Pattern: IOPMP HWCFG0/HWCFG2/HWCFG3 register offset and bitfield layout mismatch between spec versions; guest reads capability bits (no_w, no_x, chk_x) from wrong offset or bit position
