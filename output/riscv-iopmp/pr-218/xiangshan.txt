PR #218  target=xiangshan  overall=compliant
Spec: IOPMP NAPOT entry address bits [G-2:0] must be force-read as all-ones when G>=2 before computing the NAPOT range; failure to do so causes incorrect address range derivation, allowing unauthorized I/O DMA transactions to bypass memory protection and access protected physical memory regions
Violation:
  In XiangShan IOPMP hardware checker, when computing the NAPOT address range
  for an entry with granularity G>=2, if bits [G-2:0] of the entry address
  register are NOT force-set to all-ones before deriving the NAPOT mask and
  range boundaries, the generated start/end address will be narrower or
  misaligned compared to the architectural definition. Specifically, without
  this masking, the hardware would use the raw (potentially zeroed or partial)
  lower bits of the iopmpaddr register to compute napot_mask = addr ^
  (addr+1), producing an incorrect power-of-two range that does not cover the
  full architecturally-intended region.
Consequence: privilege_escape
Pattern:
  iopmpaddr.*napot|NAPOT.*addr_range|napot_mask.*G_mask|gen_granularity_napot|
  G.*>=.*2.*napot|addr\[G-2:0\]|entry_addr.*G_minus
