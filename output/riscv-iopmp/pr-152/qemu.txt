PR #152  target=qemu  overall=not_implemented
Spec: IOPMP spec v0.8.1 reorganizes bit fields across HWCFG0/HWCFG2/HWCFG3 with conditional register presence and write-1-clear sticky bits; incorrect QEMU emulation of this register-remap allows a malicious guest VM to bypass IOPMP DMA access controls, enabling privilege escape from the guest to other guests or the host via misconfigured IO memory protection
Violation:
  QEMU emulates the IOPMP register map using the pre-v0.8.1 layout (HWCFG0
  fields at wrong bit positions, ENTRYOFFSET at 0x14 instead of 0x2C, no
  HWCFG2/HWCFG3 registers) while the guest kernel is compiled against spec
  v0.8.1, OR QEMU incorrectly reports HWCFG0.HWCFG2_en/HWCFG3_en as 0 when
  HWCFG2/HWCFG3 fields are implemented (or 1 when they are not), OR QEMU fails
  to implement write-1-clear sticky-bit semantics on HWCFG2.prio_ent_prog and
  HWCFG3.rrid_transl_prog, allowing a malicious guest to reprogram locked
  priority-entry count or RRID translation after IOPMP enforcement has been
  configured.
Consequence: privilege_escape
Pattern:
  hwcfg[023] bitfield layout mismatch with spec v0.8.1; ENTRYOFFSET register
  offset hardcoded to 0x14; HWCFG2_en / HWCFG3_en not conditionally exposed;
  write-1-clear sticky bits implemented as plain r/w; prio_ent_prog /
  rrid_transl_prog writable after lock; non_prio_en ignored when computing
  priority-entry range; hwcfg2_t / hwcfg3_t struct bit positions diverged from
  spec
