PR #152  target=xiangshan  overall=bug_confirmed
Spec: v0.8.0→v0.8.1 register field relocation across HWCFG0/2/3 changes all access-control bit positions; hardware decoder wired to old positions silently disables execute-check (chk_x), write-deny (no_w), and secondary permissions (sps_en), allowing DMA peripherals to bypass IOPMP enforcement entirely
Violation: XiangShan RTL implements IOPMP HWCFG register fields at v0.8.0 bit positions while system software programs them at v0.8.1 bit positions. Specifically: (1) chk_x, no_x, no_w, sps_en, peis, pees, stall_en, mfr_en all relocated between HWCFG0/HWCFG2/HWCFG3 across the spec version boundary; (2) ENTRYOFFSET register moves from offset 0x14 to 0x2C with HWCFG3 inserted at 0x14; (3) conditional presence of HWCFG2/HWCFG3 gated by new HWCFG2_en/HWCFG3_en bits is not honored, causing either missing registers to be read as zero or implemented registers to be invisible. A bit-level mismatch causes hardware access-control state machines (rule analyzer, permission checker) to consume wrong configuration bits, silently disabling execute-check, write-restriction, or secondary-permission enforcement.
Consequence: privilege_escape
Pattern: hwcfg[0-3]_t\.(chk_x|no_x|no_w|sps_en|peis|pees|stall_en|mfr_en|mdcfg_fmt|srcmd_fmt|rrid_transl_en|prio_ent_prog|non_prio_en)|ENTRYOFFSET_OFFSET.*0x14|HWCFG[23]_OFFSET|g_reg_file\.hwcfg[023]\.(chk_x|no_x|no_w|sps_en|mfr_en|peis|pees|stall_en|rrid_transl_en)|iopmpRuleAnalyzer.*hwcfg|iopmpCheckPerms.*hwcfg
