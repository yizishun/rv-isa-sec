PR #152  target=opensbi  overall=not_implemented
Spec: IOPMP v0.8→v0.8.1 reorganizes HWCFG regs: HWCFG0 shrinks to enable/HWCFG2_en/HWCFG3_en/md_num/addrh_en/tor_en; chk_x/peis/pees/sps_en/stall_en/mfr_en/prio_entry move to HWCFG2; no_x/no_w/rrid_transl/mdcfg_fmt/srcmd_fmt/md_entry_num move to new HWCFG3; ENTRYOFFSET shifts 0x14→0x2C; firmware using old layout reads reserved bits (all zero) and silently disables DMA execute-check/interrupt-suppression/error-suppression
Violation:
  OpenSBI platform firmware compiled against IOPMP v0.8 register layout
  reads/writes HWCFG0 at MMIO offset 0x08 using old bit positions for fields
  (chk_x@bit10, peis@bit12, pees@bit13, sps_en@bit5, stall_en@bit11,
  mfr_en@bit15, prient_prog@bit7, rrid_transl_en@bit8, rrid_transl_prog@bit9,
  no_x@bit11, no_w@bit12, mdcfg_fmt@bits[1:0], srcmd_fmt@bits[3:2],
  md_entry_num@bits[22:16]) that have relocated to HWCFG2 (offset 0x10) and
  new HWCFG3 (offset 0x14) in v0.8.1; also ENTRYOFFSET accessed at old offset
  0x14 now aliases HWCFG3
Consequence: privilege_escape
Pattern:
  IOPMP_HWCFG0 bitfield access using v0.8 layout (search: hwcfg0\.(chk_x|peis|
  pees|sps_en|stall_en|mfr_en|no_x|no_w|rrid_transl_en|rrid_transl_prog|mdcfg_
  fmt|srcmd_fmt|md_entry_num|prient_prog|user_cfg_en)) OR hardcoded
  ENTRYOFFSET at 0x14

[not_implemented] docs/domain_support.md:1-7  N/A
  OpenSBI contains no IOPMP driver code, register definitions, or MMIO access
  for IOPMP hardware. The only IOPMP reference is a single documentary mention
  in domain_support.md line 7 listing IOPMP as a potential platform isolation
  feature alongside PMP/ePMP/SiFive Shield. No source or header files define
  HWCFG0 (offset 0x08), HWCFG2 (offset 0x10), HWCFG3 (offset 0x14), or
  ENTRYOFFSET (offset 0x2C) registers. No code reads or writes any IOPMP
  bitfields (chk_x, peis, pees, sps_en, stall_en, mfr_en, prient_prog,
  rrid_transl_en, rrid_transl_prog, no_x, no_w, mdcfg_fmt, srcmd_fmt,
  md_entry_num) at any register offset. Therefore the v0.8-to-v0.8.1 register
  layout mismatch (fields relocated from HWCFG0 to HWCFG2/HWCFG3, ENTRYOFFSET
  moved from 0x14 to 0x2C) cannot manifest as a bug in this codebase.
