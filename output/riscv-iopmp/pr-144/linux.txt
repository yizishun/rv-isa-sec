PR #144  target=linux  overall=compliant
Spec: Spec revert eliminates HWCFG3 register, redistributing its capability-discovery fields into HWCFG0/HWCFG2 and moving ENTRYOFFSET to HWCFG3's old offset 0x0014; kernel code probing the stale HWCFG3 layout reads wrong register content, misidentifying IOPMP format/suppression capabilities and potentially leaving I/O DMA transactions unchecked or with incorrectly scoped permissions
Violation: In the Linux kernel, when the secure monitor or a kernel IOPMP driver reads hardware capability fields (srcmd_fmt, mdcfg_fmt, no_w, no_x, rrid_transl_en, peis, pees, chk_x, sps_en, mfr_en, stall_en) from the deprecated HWCFG3 register at offset 0x0014 after the spec revert has moved these fields into HWCFG0 (offset 0x0008) and HWCFG2 (offset 0x0010), the kernel reads ENTRYOFFSET register contents instead, misinterpreting IOPMP capabilities and potentially configuring memory protection rules with incorrect assumptions about SRCMD/MDCFG table formats or per-entry suppression support.
Consequence: privilege_escape
Pattern: HWCFG3|0x0014|srcmd_fmt|mdcfg_fmt|rrid_transl_en|no_w|no_x|peis|pees|chk_x|sps_en|IOPMP
