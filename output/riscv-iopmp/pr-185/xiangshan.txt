PR #185  target=xiangshan  overall=bug_confirmed
Spec: Field rename ERR_CFG.msi_en→msi_sel collides with new HWCFG2.msi_en capability bit; stale RTL signal names referencing 'msi_en' cause MSI interrupt path selection and address-register availability gating to read wrong CSR source, enabling MSI hardware interfaces when unsupported or routing interrupts to incorrect destination
Violation:
  RTL CSR module still references ERR_CFG field as 'msi_en' (bit 3) after spec
  rename to 'msi_sel', while simultaneously implementing HWCFG2.msi_en (bit
  26) as a new capability indicator. If the Chisel/Verilog CSR decoder uses
  name-based field resolution (e.g., auto-generated from spec JSON), the old
  wire name 'msi_en' now ambiguously maps to HWCFG2 bit 26 instead of ERR_CFG
  bit 3, causing the MSI wired-or-MSISelect signal to read from the wrong
  register — or causing ERR_MSIADDR/ERR_MSIADDRH availability gating to check
  ERR_CFG.msi_sel (configuration) instead of HWCFG2.msi_en (capability),
  exposing MSI address registers when hardware does not support MSI.
Consequence: privilege_escape
Pattern:
  ERR_CFG.*msi_en|msi_sel.*io_msi_en|HWCFG2.*msi_en.*WARL|ERR_MSIADDR.*msi_en.
  *avail|when.*msi_en.*MSI|addr_reg_avail.*msi_sel
