PR #169  target=linux  overall=compliant
Spec: The x (instruction-fetch) bit in ENTRY_CFG moves from an optional X_PERM extension to the baseline spec at bit 2; kernel/firmware code that constructs ENTRY_CFG bitfields without setting bit 2 risks I/O devices executing from data-only regions because the hardware default for x is implementation-defined (WARL, DC).
Violation: Linux kernel or M-mode firmware constructs ENTRY_CFG values without explicitly setting bit 2 (the now-baseline 'x' bit), causing the IOPMP to rely on the implementation-defined default for I/O device instruction-fetch permission to a protected memory region.
Consequence: privilege_escape
Pattern: ENTRY_CFG.*=.*\b(?:r|w)\b|ENTRY_CFG.*BIT\([0-1]\)|ENTRY_CFG.*GENMASK
