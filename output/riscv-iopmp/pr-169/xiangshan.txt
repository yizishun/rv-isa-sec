PR #169  target=xiangshan  overall=bug_confirmed
Spec: Removal of chk_x gating bit from baseline creates silent instruction-fetch bypass if RTL still uses HWCFG2[26] as fetch-check enable; software writes 0 to reserved bits but hardware interprets it as 'disable all instruction fetch checking'
Violation:
  IOPMP hardware checker RTL implemented against the pre-PR spec where
  instruction fetch permission checking is gated behind HWCFG2[26] (chk_x).
  Post-PR, chk_x is removed and bit 26 becomes reserved. If the RTL still
  evaluates chk_x as an internal enable signal for the x-permission check
  datapath — and software compliant with the new spec leaves HWCFG2[26]=0 (as
  reserved bits should be zero) — the entire instruction fetch permission
  checking pipeline is silently disabled. Every instruction fetch transaction
  passes regardless of ENTRY_CFG.x or no_x settings, because the hardware AND-
  gate at the check output is driven by chk_x=0.
Consequence: privilege_escape
Pattern:
  HWCFG2.*chk_x|chk_x.*HWCFG2|instruction.fetch.*enable.*gate|fetch_check_en.*
  HWCFG2\[26\]|HWCFG2\[26\].*inst_fetch|chk_x.*&&.*x_permission|x_perm.*chk_x
