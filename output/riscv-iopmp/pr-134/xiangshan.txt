PR #134  target=xiangshan  overall=bug_confirmed
Spec: HWCFG2 field bit positions reorganized (chk_x 24→26, peis 26→27, pees 27→28, prio_ent_prog 25→16, new non_prio_en@17); RTL using stale bit indices will misreport instruction-fetch-check capability, per-entry suppression support, and priority-entry programmability — all silently corrupting the IOPMP permission model without any architectural trap
Violation: XiangShan RTL implements HWCFG2 CSR bit assignments from the pre-PR#134 spec where chk_x is at bit 24, peis at bit 26, pees at bit 27, and prio_ent_prog at bit 25, but the updated spec moves chk_x to bit 26, peis to bit 27, pees to bit 28, and prio_ent_prog to bit 16 — causing the hardware to decode/return WRONG permission-check and suppression-enable flags for every RRID access evaluation
Consequence: privilege_escape
Pattern: HWCFG2.*chk_x.*\[24\]|HWCFG2.*peis.*\[26\]|HWCFG2.*pees.*\[27\]|prio_ent_prog.*\[25\]|HWCFG2\.chk_x\(24\)|HWCFG2\.peis\(26\)|HWCFG2\.non_prio_en|HWCFG2.*entry_num.*HWCFG2.*prio

[bug_confirmed] ChiselIOPMP/src/main/scala/IopmpChecker.scala:544-549  RegHwcfg2 Bundle — missing capability-reporting fields entirely
  RegHwcfg2 (HWCFG2 at offset 0x0010) contains only rrid_transl[31:16] and prio_entry[15:0]. It has NO chk_x, peis, pees, or prient_prog fields.
