PR #219  target=xiangshan  overall=compliant
Spec: New rridscp_unselectable[] HW config gate on RRIDSCP writes: if RTL omits or incorrectly implements this check, software can stall/unstall RRIDs that hardware intends to protect from cherry-pick stall control, bypassing IOPMP stall enforcement
Violation: When software writes RRIDSCP with op=1 (stall) or op=2 (unstall) and an RRID that is hardware-configured as unselectable (rridscp_unselectable[rrid]=1), but the XiangShan RTL fails to check the unselectable array and permits the stall/unstall operation to proceed on that RRID's transactions
Consequence: privilege_escape
Pattern: RRIDSCP write CSR logic that does not index into an rridscp_unselectable bit-array before committing rrid_stall state changes; or rridscp_unselectable tied to constant false instead of hardware configuration

[potential_risk] ChiselIOPMP/src/main/scala/IopmpChecker.scala:41-41  IopmpParams.stall_en
  stall_en is hardwired to 0 with comment '// [R] stall feature is not imp'. This feeds into reg_hwcfg0.stall_en (a read-only hardware configuration bit), correctly informing software that stall is unsupported. However, the RRIDSCP register address 0x0038 is still within the valid info-region address range (info_base_addr to info_base_addr+0x80) and is routed to RegMap, where writes are silently dropped and reads return 0.
