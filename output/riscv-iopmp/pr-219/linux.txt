PR #219  target=linux  overall=not_implemented
Spec: RRIDSCP writes to unselectable RRIDs now set stat=3 and are silently ignored; kernel/firmware callers must check stat post-write or risk operating on the wrong transaction state (unstall silently failing → permanent DoS; stall silently failing → unauthorized DMA proceeds)
Violation:
  kernel or hypervisor code writes RRIDSCP.op to stall/unstall an RRID that is
  marked rridscp_unselectable[rrid]=1 by hardware, then proceeds without
  checking that RRIDSCP.stat != 3, silently assuming the operation took effect
Consequence: denial_of_service
Pattern:
  write.*RRIDSCP|rridscp.*write|stall.*rrid|rrid.*stall|RRIDSCP_OFFSET
------------------------------------------------------------
[not_implemented] N/A (no IOPMP driver in Linux kernel):0-0  N/A
  The Linux kernel (arch/riscv and drivers/) contains no IOPMP driver. There
  is no code that writes RRIDSCP, MDSTALL, MDSTALLH, or implements the
  stall/unstall/resume programming sequence described in the RISC-V IOPMP
  specification. Consequently, the RRIDSCP vulnerability pattern — where
  software writes RRIDSCP.op to stall/unstall an RRID marked
  rridscp_unselectable[rrid]=1 by hardware, then proceeds without checking
  RRIDSCP.stat != 3 — cannot manifest because no such code exists. The only
  'iopmp' references found in the tree are clock gate definitions
  (CLK_IOPMP_*) in drivers/clk/thead/clk-th1520-ap.c, which gate clocks to an
  IOPMP hardware block on the T-Head TH1520 SoC but do not interact with IOPMP
  registers.
  | // No IOPMP register-access code exists in the Linux kernel.
  | // The only related references are clock gates:
  | static CCU_GATE(CLK_IOPMP_VOSYS_DPU_PCLK, iopmp_vosys_dpu_pclk,
  |                 "iopmp-vosys-dpu-pclk", video_pll_clk_pd, 0x0, 23, 0);
  | // drivers/clk/thead/clk-th1520-ap.c:1250
