PR #155  target=linux  overall=potential_risk
Spec: Ssamb repurposes reserved interrupt 14 as local asynchronous-memory-buffer interrupt; unaware kernel code risks interrupt storms, incorrect iprio saves, and unintended delegation via mideleg
Violation: Kernel runs on hardware with Ssamb but either (a) leaves interrupt 14 unmasked in (m|s)ie without installing a handler, causing an unhandled interrupt storm, or (b) iterates over local interrupts using a bound that excludes interrupt 14, failing to save/restore its iprio and enable/disable state across context switches, or (c) treats bits 13-15 in mideleg as a single block, unintentionally delegating the unhandled LAMBI to S-mode
Consequence: denial_of_service
Pattern: BIT(14) missing in mie/mip/mideleg mask constants; iprio shift macros limited to interrupt 13; local-interrupt enumeration assuming counter-overflow-only at positions 13-15; hardcoded '13' as max local interrupt index
------------------------------------------------------------
[potential_risk] arch/riscv/include/asm/csr.h:101-103  (macro definitions)
  IRQ_LOCAL_MAX is defined as (IRQ_PMU_OVF + 1) = 14, and IRQ_LOCAL_MASK = GENMASK(13, 0). This excludes interrupt 14 (LAMBI) from the local interrupt mask. If Ssamb hardware were present, interrupt 14 would not be covered by mask/unmask logic (riscv_intc_irq_mask/unmask use BIT(d->hwirq) which would work, but IRQ_LOCAL_MASK is used in KVM to distinguish local from external interrupts). The spec (machine.adoc:1820-1826) reserves interrupts 14-15, so no current bug, but this mask boundary is a single point that must be updated if interrupt 14 is assigned to Ssamb.
  | #define IRQ_PMU_OVF         13
  | #define IRQ_LOCAL_MAX       (IRQ_PMU_OVF + 1)
  | #define IRQ_LOCAL_MASK      GENMASK((IRQ_LOCAL_MAX - 1), 0)

[potential_risk] arch/riscv/include/asm/csr.h:186-191  (macro definitions)
  VSIP_VALID_MASK whitelists only IRQ_S_SOFT (bit 1), IRQ_S_TIMER (bit 5), IRQ_S_EXT (bit 9), and IRQ_PMU_OVF (bit 13). Interrupt 14 (LAMBI) is not in the valid mask. If Ssamb were supported, injected LAMBI interrupts via VSIP would be filtered out by this mask in kvm_riscv_vcpu_has_interrupts() and kvm_riscv_vcpu_general_get_csr(sip).
  | #define VSIP_VALID_MASK     ((_AC(1, UL) << IRQ_S_SOFT) | \
  |                  (_AC(1, UL) << IRQ_S_TIMER) | \
  |                  (_AC(1, UL) << IRQ_S_EXT) | \
  |                  (_AC(1, UL) << IRQ_PMU_OVF))
