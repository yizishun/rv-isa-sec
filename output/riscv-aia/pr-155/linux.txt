PR #155  target=linux  overall=potential_risk
Spec: Ssamb defines interrupt 14 as local asynchronous memory buffer interrupt (LAMBI) — kernel/KVM mask constants and CSR save/restore paths that treat bit 14 as reserved will leak or corrupt LAMBI interrupt state across context switches and VM boundaries
Violation: Linux kernel (or KVM) context-switch save/restore of interrupt CSRs (mip, mie, sip, sie, mvien, mvip, hvien, hvip) uses a bitmask that omits bit 14, treating the LAMBI interrupt as reserved. This causes the Ssamb interrupt pending/enable/virtual-enable state to silently leak across process or VM boundaries during context switch, or to be spuriously cleared.
Consequence: info_leak
Pattern: CSR mask constant or inline bitfield omitting bit 14 in any CSR_{READ,WRITE}(mip|mie|sip|sie|mvien|mvip|hvien|hvip|mideleg|sideleg) path, especially in __switch_to, kvm_riscv_vcpu_switch, or interrupt controller initialization
------------------------------------------------------------

[compliant] arch/riscv/include/asm/switch_to.h:113-126  switch_to
  The context-switch macro switch_to() saves/restores FPU, Vector, and ENVCFG state but does not explicitly save/restore sip/sie/mip/mie CSRs. On RISC-V, these CSRs are per-CPU (not per-thread) hardware registers managed by the interrupt controller. The kernel enters interrupt handlers with interrupts disabled (sstatus.SIE cleared), and the interrupt controller tracks pending/enable state per-CPU. No explicit CSR save/restore is expected here for LAMBI or any local interrupt. Compliant for the current architecture.
