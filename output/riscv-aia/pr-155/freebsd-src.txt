PR #155  target=freebsd-src  overall=bug_confirmed
Spec: Ssamb repurposes reserved interrupt 14 as a local interrupt; FreeBSD's intc blindly enables all 16 IRQ slots on AP boot without Ssamb awareness, creating a stray-interrupt storm if hardware asserts MIP[14] before a handler is registered—and bhyve's hideleg omits it, risking HS-mode traps from guest execution
Violation: On a RISC-V hart where hardware implements Ssamb (interrupt code 14 masked as local), FreeBSD's intc_init_secondary() unconditionally sets SIE[14] via csr_set(sie, 1<<14) during AP boot (iterating irq=0..15 in intc.c:243). If the hardware subsequently asserts MIP[14], the trap flows through exception.S -> trap.c do_trap_supervisor/do_trap_user -> intc_intr() where active_irq=14 passes the >=INTC_NIRQS(16) guard, but intr_isrc_dispatch on the handlerless isrcs[14] fails. The stray-isr path in intc.c:284 calls intc_disable_intr() which does csr_clear(sie, 1<<14), yet NOTHING clears the SIP[14] pending bit. If any code path re-enables SIE[14] (e.g., intc re-init across suspend/resume, or a driver blindly re-enabling all sources), the latched pending bit causes immediate re-entry, forming a tight interrupt storm. For bhyve: hideleg only delegates bits 2/6/10 (vmm_riscv.c:155), so interrupt 14 traps to HS-mode during guest execution where no handler exists, potentially halting the host.
Consequence: denial_of_service
Pattern: csr_set\(sie,\s*1\s*<<\s*(1[4-5]|[89])\s*\)|csr_set\(mie|INTC_NIRQS\s*(<|<=)\s*15|for.*irq.*INTC_NIRQS.*intc_enable_intr|hideleg\s*(&=|\|=).*IRQ

[bug_confirmed] sys/riscv/riscv/intc.c:188-197  intc_disable_intr
  intc_disable_intr() only clears the SIE enable bit via csr_clear(sie, 1ul<<irq) but never clears the corresponding SIP pending bit. Since the RISC-V spec requires SIP bits to be cleared by writing 1 to them (csr_set(sip, 1<<irq)), a stray interrupt's pending state survives the disable operation, enabling the interrupt-storm re-entry scenario.
  | csr_clear(sie, 1ul << irq);

[potential_risk] sys/riscv/riscv/intc.c:199-209  intc_enable_intr
  intc_enable_intr() blindly performs csr_set(sie, 1ul<<irq) for any irq < INTC_NIRQS (0-15) without checking whether the interrupt source is architecturally valid or has a registered handler. Interrupt codes 12-15 correspond to reserved/local RISC-V extensions (COFI, LAMBI, etc.) that FreeBSD does not handle.
  | csr_set(sie, 1ul << irq);

[potential_risk] sys/riscv/vmm/vmm_riscv.c:141-158  vmmops_delegate
  hideleg only delegates bits 2 (VSSIP), 6 (VSTIP), and 10 (VSEIP) to VS-mode. All other local interrupts including 14 (LAMBI) trap to HS-mode during guest execution. The bhyve vmmops_run() loop (line 460-467 in riscv_handle_world_switch) catches interrupt-triggered HS-mode traps and exits with VM_EXITCODE_BOGUS. This causes the guest to be kicked out on any LAMBI assertion, but the host's stray-handler path (intc_intr) inherits the same SIP[14]-not-cleared bug as the non-bhyve path. In HS-mode, the interrupt remains enabled via sie[14] set during intc_init_secondary.
  | hideleg  = (1UL << IRQ_SOFTWARE_HYPERVISOR);
  | hideleg |= (1UL << IRQ_TIMER_HYPERVISOR);
  | hideleg |= (1UL << IRQ_EXTERNAL_HYPERVISOR);
