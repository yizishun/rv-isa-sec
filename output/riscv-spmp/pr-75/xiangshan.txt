PR #75  target=xiangshan  overall=compliant
Spec: PR #75 merges hSPMP into baseline SPMP: when V=1 and hgatp.MODE=Bare, SPMP violations on VS/VU accesses must raise guest page fault codes (20/21/23) not supervisor page fault codes (12/13/15); incorrect exception code routing in hardware would deliver hSPMP violations to the guest OS instead of the hypervisor, allowing a malicious guest to handle its own SPMP faults and bypass hypervisor-enforced memory protections
Violation:
  In XiangShan RTL, when V=1 and hgatp.MODE=Bare, the SPMP checker generates
  VS/VU access violations but the exception generation logic in the CSR module
  incorrectly raises supervisor page fault exception codes (12/13/15) instead
  of guest page fault codes (20/21/23). This occurs when the hardware fails to
  conditionally select the exception code based on the (virtualization_active
  AND hgatp_mode_bare) predicate, routing hSPMP violations to VS-mode trap
  handlers instead of HS-mode.
Consequence: privilege_escape
