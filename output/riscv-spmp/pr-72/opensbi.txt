PR #72  target=opensbi  overall=compliant
Spec: SPMP CSR writes via miselect/mireg/mireg2 are explicitly unordered with respect to subsequent memory accesses; missing SFENCE.VMA before MRET allows S-mode to execute with stale or unenforced SPMP protections, undermining M-mode sandboxing
Violation:
  OpenSBI M-mode writes SPMP entries via miselect/mireg/mireg2 indirect CSR
  accesses (e.g., to sandbox S-mode, restore SPMP state on HSM resume, or
  clear locked SPMP entries) and then executes MRET to S-mode or relies on
  those SPMP protections for subsequent M-mode memory accesses without first
  executing SFENCE.VMA with rs1=x0 and rs2=x0
Consequence: privilege_escape
Pattern:
  miselect.*write|mireg.*write|mireg2.*write.*(?!.*SFENCE\.VMA.*x0.*x0)|csr_wr
  ite.*miselect|csr_write.*mireg
