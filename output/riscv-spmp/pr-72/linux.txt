PR #72  target=linux  overall=not_implemented
Spec: SPMP CSR writes are explicitly not ordered with respect to subsequent memory accesses; omitting SFENCE.VMA after SPMP reprogramming allows incoming task to operate under stale SPMP rules, potentially granting unauthorized memory access
Violation:
  In the Linux kernel, when S-mode writes SPMP CSRs (spmpaddr/spmpcfg via
  sireg/sireg2/siselect, or sspmpswitch) during a context switch or dynamic
  reconfiguration and resumes execution of the incoming task without first
  issuing SFENCE.VMA with rs1=x0 and rs2=x0, subsequent memory accesses from
  the incoming task may be checked against stale SPMP entries rather than the
  newly written configuration.
Consequence: race_condition
Pattern:
  siselect|sireg|sireg2|sspmpswitch\s.*\n(?!.*sfence\.vma)
------------------------------------------------------------
[not_implemented] arch/riscv/include/asm/csr.h:348-349  N/A (CSR definitions only)
  SPMP (S-mode Physical Memory Protection) is not implemented in this Linux
  kernel tree. The siselect/sireg CSRs (0x150/0x151) are defined but used
  exclusively for KVM AIA IMSIC interrupt controller access, not for SPMP. No
  sspmpswitch CSR is defined. No SPMP-related writes occur in context-switch
  paths, signal delivery, or SMP hotplug paths, so the spec's violation
  condition (writing SPMP CSRs without subsequent SFENCE.VMA) cannot be
  triggered.
  | #define CSR_SISELECT		0x150
  | #define CSR_SIREG		0x151
