PR #70  target=linux  overall=not_implemented
Spec: mpmpdeleg writes can implicitly shrink hspmpdeleg below locked hSPMP entry indices, silently converting locked hypervisor protections into vSPMP entries bypassable via vsireg2 unlock
Violation:
  Kernel in HS-mode writes to mpmpdeleg.pmpnum to increase the PMP share,
  which implicitly reduces hspmpdeleg.pmpnum below the index of a locked hSPMP
  entry, causing a hypervisor-locked protection entry to silently fall into
  the vSPMP region where it can be unlocked via vsireg2.
Consequence: privilege_escape
Pattern:
  write to mpmpdeleg CSR without first ensuring no locked hSPMP entries exist
  at indices >= (total_pmp_entries - new_mpmpdeleg_value -
  current_hspmpdeleg_value_saturated)
------------------------------------------------------------
[not_implemented] arch/riscv/include/asm/csr.h:125-428  (none — CSR definitions only)
  The Linux kernel contains no SPMP (S-mode PMP) support, no PMP delegation
  CSR definitions (mpmpdeleg, hspmpdeleg, spmpdeleg, pmpdeleg), no
  sireg2/vsireg2 CSR definitions, and no KVM SPMP virtualization code. The
  only PMP support present is standard M-mode PMP (CSR_PMPCFG0/CSR_PMPADDR0)
  with bit constants PMP_R/W/X/A/L. The spec's vulnerability condition —
  writing to mpmpdeleg without checking locked hSPMP entry indices — cannot
  manifest because the kernel has zero code paths that touch mpmpdeleg or any
  SPMP-related CSR.
