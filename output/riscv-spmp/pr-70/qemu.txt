PR #70  target=qemu  overall=compliant
Spec: mpmpdeleg write must cascade-update hspmpdeleg.pmpnum bypassing the locked-entry constraint, while direct hspmpdeleg writes must enforce it — conflating the two paths breaks hSPMP lock semantics and can expose locked hSPMP entries to vSPMP control
Violation:
  In QEMU, when a write to mpmpdeleg CSR triggers a cascaded update of
  hspmpdeleg.pmpnum (due to the invariant mpmpdeleg.pmpnum + hspmpdeleg.pmpnum
  <= total_PMP_entries), QEMU incorrectly enforces the hSPMP locked-entry
  constraint on hspmpdeleg.pmpnum and rejects or clamps the cascaded update.
  Conversely, on a direct write to hspmpdeleg CSR, QEMU fails to enforce the
  locked-entry constraint and allows hspmpdeleg.pmpnum to be set <= the index
  of a locked hSPMP entry.
Consequence: privilege_escape
Pattern:
  mpmpdeleg write handler that calls a shared hspmpdeleg update helper which
  unconditionally checks (or unconditionally skips) hSPMP entry lock bits
  (spmpcfg[i].L) without distinguishing direct-vs-cascaded write context
