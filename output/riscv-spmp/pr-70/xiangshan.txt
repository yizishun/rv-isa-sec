Spec: hspmpdeleg.pmpnum reduction below locked hSPMP entry indices is only legal when triggered by mpmpdeleg writes; hardware must distinguish direct vs indirect write paths or risk locked-entry bypass through CSR writes
Violation:
  In XiangShan RTL, when a write to mpmpdeleg.pmpnum triggers an indirect
  update of hspmpdeleg.pmpnum (due to the hardware invariant that
  mpmpdeleg.pmpnum + hspmpdeleg.pmpnum ≤ total_PMP_entries), the hardware must
  reduce hspmpdeleg.pmpnum even if the new value is ≤ the index of a locked
  hSPMP entry. A violation occurs if: (1) The CSR write logic unconditionally
  blocks hspmpdeleg.pmpnum from dropping below a locked entry's index for ALL
  write paths, preventing the mpmpdeleg-triggered update and leaving
  hspmpdeleg in an architecturally stale state that contradicts mpmpdeleg; OR
  (2) The CSR write logic fails to enforce the locked-entry-index guard on
  DIRECT writes to hspmpdeleg.pmpnum, allowing malicious HS-mode software to
  shrink hspmpdeleg below locked hSPMP entries by writing hspmpdeleg directly
  rather than through mpmpdeleg, thereby re-delegating locked entries to vSPMP
  and stripping hypervisor protections.
Consequence: privilege_escape
Pattern:
  hspmpdeleg.*pmpnum.*locked|mpmpdeleg.*update.*hspmpdeleg|hspmpdeleg.*index.*
  lock|locked.*hSPMP.*deleg|pmpnum_lock|hspmpdeleg_write.*WARL.*constraint
------------------------------------------------------------
[not_implemented] N/A (feature not implemented):0-0  N/A
  The hspmpdeleg and mpmpdeleg CSRs referenced in the security spec are not
  implemented in the XiangShan RTL. The codebase has only a conventional PMP
  with 32 real entries (pmpcfg0-15, pmpaddr0-63), Smepmp support via mseccfg
  (MML/MMWP/RLB), and Ssnpm/Smmpm support via mseccfg.PMM. There is no sPMP,
  no hypervisor-PMP delegation mechanism, no pmpnum field, and no HS/VS PMP
  entry split. The audit condition describes a feature that has not yet been
  added to this branch (kunminghu-v3).
