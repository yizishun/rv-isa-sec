PR #76  target=freebsd-src  overall=not_implemented
Spec: spmpcfg register widened from 16-bit field to SXLEN-bit register; FreeBSD context-switch save/restore must use SXLEN-bit (uint64_t/uint32_t) storage width to preserve WPRI bits in upper region, otherwise zeroing them leaks or corrupts per-hart hardware state across protection domains
Violation:
  FreeBSD kernel saves/restores spmpcfg[i] as a 16-bit value (e.g., uint16_t
  in struct pcb or vm context) across context switches, but the spec now
  defines spmpcfg as a full SXLEN-bit register. On RV64, bits 63:10 are WPRI
  (54 bits), and on RV32, bits 31:10 are WPRI (22 bits). Writing only 16 bits
  via the sireg2 indirect access (right-justified) zeroes upper WPRI bits,
  violating the WPRI contract that those bits be preserved.
Consequence: info_leak
Pattern:
  uint16_t.*spmpcfg|spmpcfg.*uint16_t|\b16\b.*spmpcfg|spmpcfg.*\b16\b|spmp_sav
  e|spmp_restore
