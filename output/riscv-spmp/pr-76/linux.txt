PR #76  target=linux  overall=not_implemented
Spec: spmpcfg redefined from a 16-bit field within an SXLEN-bit register to a full SXLEN-bit register; kernel must treat spmpcfg as SXLEN-bit on sireg2 read-modify-write to preserve WPRI bits [SXLEN-1:10]
Violation:
  Kernel S-mode code writes an spmpcfg entry via the sireg2 indirect CSR
  access using only the lower 16 bits (e.g., a u16 value or value & 0xFFFF
  mask), causing SXLEN-16 upper WPRI bits to be zeroed instead of preserved,
  corrupting the full SXLEN-bit spmpcfg register state
Consequence: data_corruption
Pattern:
  csr_write.*sireg2.*0xFFFF|uint16_t.*spmpcfg|spmpcfg.*mask.*0xFFFF|u16.*sireg
  |spmp.*cfg.*16
------------------------------------------------------------
[not_implemented] arch/riscv/include/asm/csr.h:348-357  (CSR definitions)
  SPMP (Sspmp) is not implemented in this kernel tree. CSR_SISELECT (0x150)
  and CSR_SIREG (0x151) are defined only for AIA interrupt controller access,
  not for SPMP. CSR sireg2 (0x152) is not defined at all. There is no spmpcfg
  CSR number allocation, no spmpaddr definition, and no code that writes
  spmpcfg entries through indirect CSR access. The vulnerability pattern
  (kernel writes spmpcfg via sireg2 with only lower 16 bits, corrupting upper
  WPRI bits) cannot occur because the SPMP infrastructure is entirely absent.
