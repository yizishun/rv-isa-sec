PR #80  target=freebsd-src  overall=not_implemented
Spec: Writes to sspmpswitch during SPMP context switch require a subsequent SFENCE.VMA(x0, x0) fence to order SPMP entry activation with memory accesses; omitting it creates a window where the old thread's memory protections are lifted before the new thread's are enforced, enabling cross-process memory access
Violation:
  In the FreeBSD kernel, when Sspmpsw is implemented, a context switch writes
  sspmpswitch to activate the incoming thread's SPMP entries and deactivate
  the outgoing thread's entries, but the code path omits the mandatory
  SFENCE.VMA (rs1=x0, rs2=x0) after the CSR write — allowing subsequent S-mode
  memory accesses (load/store/instruction fetch) to be reordered before the
  sspmpswitch write takes effect.
Consequence: privilege_escape
Pattern:
  csrw sspmpswitch.*(?!SFENCE\.VMA|sfence_vma)|writes to sspmpswitch CSR not
  immediately followed by SFENCE.VMA with rs1=x0 and rs2=x0 before any
  subsequent load, store, or instruction fetch in the same code path
