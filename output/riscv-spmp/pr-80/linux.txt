PR #80  target=linux  overall=not_implemented
Spec: SPMP context switch via sspmpswitch CSR write is not architecturally ordered with subsequent memory accesses; missing SFENCE.VMA fence allows memory accesses to be checked against the prior task's SPMP configuration, potentially granting the incoming task access to memory regions it should not reach.
Violation:
  In the Linux kernel, after writing to sspmpswitch to activate/deactivate
  SPMP entries during a context switch, the kernel omits the required
  SFENCE.VMA instruction (rs1=x0, rs2=x0), causing subsequent memory accesses
  to be checked against stale SPMP state rather than the newly written
  configuration.
Consequence: privilege_escape
Pattern:
  csr_write\s*\(\s*CSR_SSPMPSWITCH|write.*sspmpswitch|__asm__.*sspmpswitch(?!.
  *sfence\.vma)
------------------------------------------------------------
[not_implemented] arch/riscv/kvm/vcpu_switch.S:198-219  __kvm_riscv_switch_to
  SPMP (S-mode Physical Memory Protection) does not exist in this kernel tree.
  There are no spmpcfg/spmpaddr/sspmpswitch CSR definitions, no SPMP
  save/restore code, and no SPMP CSR writes anywhere in arch/riscv/. The
  vulnerability condition — writing to sspmpswitch without a subsequent
  sfence.vma — cannot be triggered because SPMP is not implemented. The
  __kvm_riscv_switch_to assembly performs sret-based VM entry (line 206) but
  has no SPMP awareness, only saving SSTATUS/STVEC/SEPC/SSCRATCH. If SPMP
  support were added, this path would need SPMP CSR save/reload and sfence.vma
  after sspmpswitch writes.
  | SAVE_HOST_AND_RESTORE_GUEST_CSRS .Lkvm_switch_return
