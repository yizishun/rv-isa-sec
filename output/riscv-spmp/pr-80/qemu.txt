PR #80  target=qemu  overall=not_implemented
Spec: SPMP L bit is now mandatory (was optional); QEMU must enforce that locked SPMP entries are immutable via S-mode siselect and only clearable by M-mode miselect, otherwise M-mode sandboxing of S-mode is defeated
Violation:
  QEMU does not enforce the SPMP L (lock) bit as mandatory, allowing S-mode
  writes via siselect to modify locked spmpcfg[i] or spmpaddr[i] entries, or
  does not require M-mode access (via miselect) to clear the lock bit
Consequence: privilege_escape
Pattern:
  spmpcfg.*\.L|spmp_lock|siselect.*write.*locked|miselect.*lock|hardwire.*L.*0
  |spmp.*lock.*optional
------------------------------------------------------------
[not_implemented] target/riscv/:0-0  N/A
  SPMP (S-mode Physical Memory Protection) is not implemented in this QEMU
  codebase. No spmpcfg[] CSRs, spmpaddr[] CSRs, SPMP lock-bit handling, SPMP
  state structures (spmp_table_t), or SPMP VMState migration exist. The
  siselect/miselect CSRs present are only used for AIA and S*csrind, not for
  SPMP entry selection. The spec violation condition ('QEMU does not enforce
  the SPMP L lock bit as mandatory, allowing S-mode writes via siselect to
  modify locked spmpcfg[i]') cannot be triggered because the entire SPMP
  subsystem is absent.
  | N/A — no SPMP code exists in target/riscv/
