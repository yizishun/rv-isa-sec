PR #80  target=opensbi  overall=not_implemented
Spec: OpenSBI must store-and-clear affected PMP/SPMP config registers before writing mpmpdeleg.pmpnum, or stale inherited configs can grant S-mode access to M-mode-only physical memory
Violation:
  OpenSBI writes a new value to mpmpdeleg.pmpnum to reallocate entries between
  PMP and SPMP without first storing and clearing the affected PMP/SPMP
  configuration registers. When pmpnum is changed, the configuration bits
  (pmpcfg/spmpcfg) and address registers (pmpaddr/spmpaddr) of the reallocated
  entries inherit stale values from their previous role, which may grant
  S-mode unintended memory access permissions.
Consequence: privilege_escape
Pattern:
  csrw\s+mpmpdeleg.*\n(?!.*csrw\s+pmpcfg|.*csrw\s+pmpaddr|.*miselect|.*mireg)
------------------------------------------------------------
[not_implemented] (none — SPMP/mpmpdeleg not implemented in OpenSBI):0-0  (none)
  OpenSBI does not implement the SPMP (S-mode Physical Memory Protection)
  extension. The mpmpdeleg CSR, pmpnum field, miselect/mireg/mireg2 indirect-
  access registers, sspmpswitch, and all SPMP-related CSR encodings (spmpcfg,
  spmpaddr) have zero references in OpenSBI C source, headers, or assembly
  files. The spec violation condition — writing mpmpdeleg.pmpnum to reallocate
  entries between PMP and SPMP without first storing+clearing affected
  configuration registers — cannot be analyzed against code that does not
  exist. This is a definitive 'not_implemented': the target firmware source
  contains no logic for the described RISC-V component.
  | (no code — SPMP extension is absent from the OpenSBI codebase)
