PR #90  target=linux  overall=compliant
Spec: vSPMP CSR writes via indirect CSR access are not ordered w.r.t. subsequent guest memory accesses; kernel must issue HFENCE.VVMA(rs1=x0,rs2=x0) before VM-entry after any vSPMP modification, or the guest may bypass memory protections via stale vSPMP state
Violation:
  In the Linux KVM hypervisor (HS-mode), when vSPMP entries are modified via
  vsiselect/vsireg/vsireg2 indirect CSR writes and the vCPU is resumed without
  first executing HFENCE.VVMA with rs1=x0 and rs2=x0, the guest (VS/VU-mode)
  may observe stale vSPMP configuration, causing memory accesses to be checked
  against outdated protection policies.
Consequence: privilege_escape
Pattern:
  vsireg|vsireg2|vspmpcfg.*write|vspmpaddr.*write.*HFENCE\.VVMA|__kvm_riscv_vs
  pmp
