PR #392  target=linux  overall=potential_risk
Spec: Kernel module loader must handle R_RISCV_ALIGN_DOWN (type 62) to strip nop padding when rounding-down alignment, otherwise un-stripped nops shift instruction boundaries, causing compressed/non-compressed instruction misdecode and arbitrary code execution divergence at module load time.
Violation: Linux kernel module loader (arch/riscv/kernel/module.c) processes an ELF relocation of type R_RISCV_ALIGN_DOWN (62) without a dedicated handler, either rejecting valid kernel modules or silently preserving nop bytes that were meant to be stripped for alignment rounding-down, causing the subsequent instruction stream to begin at a misaligned offset.
Consequence: data_corruption
Pattern: case R_RISCV_ALIGN_DOWN.*default.*apply_relocate|R_RISCV_ALIGN.*not.*ALIGN_DOWN|handle_R_RISCV_ALIGN.*missing.*_DOWN
------------------------------------------------------------
[potential_risk] arch/riscv/kernel/module.c:593-595  apply_relocate_add
  R_RISCV_ALIGN_DOWN (relocation type 62) has no handler in reloc_handlers[]. The array ends at index 61, causing type 62 to fall through to the NULL handler check at line 815-819, which prints 'Unknown relocation type 62' and returns -EINVAL. The safe-fail default correctly prevents silent data corruption (nop bytes are not silently preserved). However, the comment at line 593 incorrectly states '62-191 reserved for future standard use' when 62 is now R_RISCV_ALIGN_DOWN per the RISC-V psABI, and kernel modules built with newer toolchains emitting this relocation will fail to load.
  | /* 62-191 reserved for future standard use */
  |                 /* 192-255 nonstandard ABI extensions  */
  |         };
