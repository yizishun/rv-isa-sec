PR #392  target=linux  overall=compliant
Spec: R_RISCV_ALIGN_DOWN (type 62) rounds alignment down (addend→next-lower power-of-two) unlike R_RISCV_ALIGN (type 43) which rounds up; conflating the two in the module loader would corrupt code alignment and create misaligned instruction boundaries exploitable as ROP gadgets
Violation: The kernel module loader (module.c:apply_relocate_add) or kexec file loader (machine_kexec_file.c) encounters R_RISCV_ALIGN_DOWN (type 62) and either (a) has no handler causing an out-of-bounds array access if ARRAY_SIZE(reloc_handlers) implicitly grows past 62, or (b) handles it using R_RISCV_ALIGN's round-up semantics instead of the round-down semantics, corrupting the addend-derived alignment boundary
Consequence: data_corruption
Pattern: R_RISCV_ALIGN_DOWN.*reloc_handler|case R_RISCV_ALIGN_DOWN.*break|type == 62.*ALIGN
------------------------------------------------------------
