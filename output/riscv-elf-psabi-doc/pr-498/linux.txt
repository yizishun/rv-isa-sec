PR #498  target=linux  overall=bug_confirmed
Spec: RISC-V kernel has zero e_flags validation: a CHERI pure-capability binary (EF_RISCV_RVY) would silently load on a non-CHERI kernel, executing capability-aware code as bare-pointer code leading to undefined pointer corruption
Violation: Linux kernel loads any RISC-V ELF binary with EF_RISCV_RVY (0x40) set in e_flags, unaware that it targets a CHERI pure-capability ABI, because elf_check_arch at arch/riscv/include/asm/elf.h:37 inspects only e_machine and EI_CLASS — e_flags is completely ignored and no arch_check_elf exists for RISC-V
Consequence: data_corruption
Pattern: arch/riscv.*elf_check_arch|arch/riscv.*e_flags|CONFIG_ARCH_BINFMT_ELF_STATE.*riscv
------------------------------------------------------------
[bug_confirmed] arch/riscv/include/asm/elf.h:37-38  elf_check_arch
  elf_check_arch inspects only e_machine==EM_RISCV and EI_CLASS but completely ignores e_flags. An ELF binary with EF_RISCV_RVY (0x40) set — targeting the CHERI pure-capability ABI where all memory accesses use hardware capabilities instead of integer addresses — passes this gate unconditionally. No EF_RISCV_* constants are defined anywhere in the kernel tree (git grep returns zero results), so the kernel has no vocabulary to recognize or reject CHERI-ABI binaries.
  | #define elf_check_arch(x) (((x)->e_machine == EM_RISCV) && \
  |                    ((x)->e_ident[EI_CLASS] == ELF_CLASS))

[bug_confirmed] arch/riscv/kernel/process.c:119-124  compat_elf_check_arch
  compat_elf_check_arch (used for 32-bit compat ELF loading via fs/compat_binfmt_elf.c) also does NOT inspect e_flags. Only checks compat_mode_supported, e_machine==EM_RISCV, and EI_CLASS==ELFCLASS32. A 32-bit CHERI purecap binary with EF_RISCV_RVY set would also pass.
  | bool compat_elf_check_arch(Elf32_Ehdr *hdr)
  | {
  |   return compat_mode_supported &&
  |          hdr->e_machine == EM_RISCV &&
  |          hdr->e_ident[EI_CLASS] == ELFCLASS32;
  | }

[bug_confirmed] fs/binfmt_elf.c:1004-1008  load_elf_binary
  arch_check_elf() is called here as a second-layer validation gate after the primary elf_check_arch() passes. RISC-V does NOT override arch_check_elf (no arch/riscv/kernel/elf.c exists, no CONFIG_ARCH_BINFMT_ELF_STATE selected in arch/riscv/Kconfig), so the dummy fallback at fs/binfmt_elf.c:616-621 is used, which unconditionally returns 0 (proceed). Contrast: MIPS (arch/mips/kernel/elf.c:135) and ARM64 (arch/arm64/include/asm/elf.h:289) both override arch_check_elf to inspect e_flags before allowing the exec to proceed. This is the missing hook that should have caught EF_RISCV_RVY.
  | retval = arch_check_elf(elf_ex,
  |       !!interpreter, interp_elf_ex,
  |       &arch_state);
  | if (retval)
  |   goto out_free_dentry;

[bug_confirmed] fs/binfmt_elf.c:616-621  arch_check_elf
  Default/dummy arch_check_elf() — always returns 0 (proceed). Only compiled when the architecture does NOT provide its own override (i.e., CONFIG_ARCH_BINFMT_ELF_STATE is not selected). RISC-V relies on this dummy, meaning no architecture-specific ELF validation occurs after elf_check_arch passes.
  | static inline int arch_check_elf(struct elfhdr *ehdr, bool has_interp,
  |          struct elfhdr *interp_ehdr,
  |          struct arch_elf_state *state)
  | {
  |   /* Dummy implementation, always proceed */
  |   return 0;
  | }

[bug_confirmed] arch/riscv/Kconfig:13-13  (Kconfig RISCV entry)
  RISC-V Kconfig does NOT select ARCH_BINFMT_ELF_STATE. This means the struct arch_elf_state is empty (generic dummy), arch_elf_pt_proc() is a dummy that ignores PT_LOPROC..PT_HIPROC phdrs, and arch_check_elf() is the generic always-return-0 stub. Contrast: ARM64 (arch/arm64/Kconfig:16), MIPS (arch/mips/Kconfig:6), and LoongArch (arch/loongarch/Kconfig:11) all select ARCH_BINFMT_ELF_STATE to enable arch-specific ELF validation — specifically to inspect e_flags.
  | config RISCV
  |   def_bool y
  |   select ACPI_GENERIC_GSI if ACPI
  |   ...

[bug_confirmed] fs/binfmt_elf.c:863-864  load_elf_binary
  First ELF arch-validity check in load_elf_binary(). elf_check_arch(elf_ex) expands to the RISC-V macro that ignores e_flags. An RVY CHERI purecap binary passes this gate and execution continues without any further e_flags inspection at this point.
  | if (!elf_check_arch(elf_ex))
  |   goto out;

  Same elf_check_arch() gate applied to the ELF interpreter (ld.so). An RVY purecap dynamic linker would also pass unchecked, meaning the CHERI-ABI dynamic linker would be loaded into a non-CHERI kernel address space.
  | if (!elf_check_arch(interp_elf_ex) ||
  |     elf_check_fdpic(interp_elf_ex))
