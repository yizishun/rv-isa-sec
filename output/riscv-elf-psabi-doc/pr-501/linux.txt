PR #501  target=linux  overall=potential_risk
Spec: Kernel unwinder must use PTRSZ (pointer width), not XLEN, to index frame records; using XLEN on RV64ILP32 userspace would follow garbage frame pointers and crash the kernel
Violation: The kernel stack unwinder computes frame-record slot offsets using XLEN (or sizeof(unsigned long)) rather than the pointer size of the target context, causing misaligned reads of the saved return address and previous frame pointer on ABIs where PTRSZ != XLEN (e.g., RV64ILP32 userspace, or future RVY with YLEN=2*XLEN).
Consequence: denial_of_service
Pattern: XLEN/8 or sizeof(unsigned long) used as frame-record slot stride in arch/riscv/kernel/stacktrace.c or perf_callchain.c instead of the target pointer width
------------------------------------------------------------
