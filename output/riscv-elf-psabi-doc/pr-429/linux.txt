PR #429  target=linux  overall=potential_risk
Spec: FDPIC signal delivery requires kernel to dereference function descriptors to load both PC and gp before entering handler; without this, handler executes with attacker-controlled gp causing all GOT-relative data accesses to alias arbitrary memory
Violation: In arch/riscv/kernel/signal.c, when the target process has an FDPIC personality (EF_RISCV_FUNCDESC set), the kernel reads sa_handler or sa_sigaction as a raw code address and restores only sepc without also dereferencing the function descriptor to extract both the entry PC and the gp value, then loading gp into the user x3 register before returning to userspace.
Consequence: privilege_escape
Pattern: setup_return or setup_sigframe paths in arch/riscv/kernel/signal.c that write regs->epc from ka->sa.sa_handler without checking for EF_RISCV_FUNCDESC and without loading gp from the function descriptor
------------------------------------------------------------
[potential_risk] arch/riscv/kernel/signal.c:468-469  setup_rt_frame
  Signal handler PC is set from ksig->ka.sa.sa_handler as a raw code address without checking for FDPIC personality (FDPIC_FUNCPTRS) and without dereferencing a function descriptor to extract the entry PC and gp value. On FDPIC processes, sa_handler points to a function descriptor (entry PC + gp), not raw code. Writing the descriptor address directly to sepc causes the handler to execute descriptor data as code with an incorrect gp, enabling privilege escalation.
  | regs->epc = (unsigned long)ksig->ka.sa.sa_handler;
  | regs->sp = (unsigned long)frame;
  | regs->a0 = ksig->sig;                     /* a0: signal number */
  | regs->a1 = (unsigned long)(&frame->info); /* a1: siginfo pointer */
  | regs->a2 = (unsigned long)(&frame->uc);   /* a2: ucontext pointer */

[potential_risk] arch/riscv/kernel/signal.c:436-472  setup_rt_frame
  No gp (x3) register is set before returning to the signal handler. In FDPIC ABI, gp must be loaded from the function descriptor (descriptor[1]) before entering the signal handler, so the handler can access its GOT. Neither setup_rt_frame() nor compat_setup_rt_frame() writes regs->gp. Compare with ARM which sets ARM_r9 (the FDPIC GOT register) at signal.c:441 and xtensa which sets areg[base+11] at signal.c:436.

[potential_risk] arch/riscv/include/asm/elf.h:1-156  elf.h (global)
  RISC-V has FDPIC scaffolding (PTRACE_GETFDPIC, ELF_FDPIC_PLAT_INIT, ELF_FDPIC_CORE_EFLAGS, exec_fdpic_loadmap/interp_fdpic_loadmap in mmu.h) but no elf_check_fdpic() definition and no EF_RISCV_FUNCDESC flag.
