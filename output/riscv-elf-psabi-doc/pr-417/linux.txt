PR #417  target=linux  overall=compliant
Spec: Kernel as the loader gatekeeper: if the kernel does not parse RISC-V .note.gnu.property CFI bits and enable Zicfilp/Zicfiss in {m,s}envcfg before delivering control to userspace, CFI-marked binaries execute with landing-pad checking and shadow-stack protection silently disabled, creating a false sense of security while ROP/JOP attacks remain viable
Violation: Linux kernel ELF loader (load_elf_binary in fs/binfmt_elf.c) loads a RISC-V executable or shared library with GNU_PROPERTY_RISCV_FEATURE_1_AND containing CFI_LP_UNLABELED or CFI_SS bits set, but does not check for and enable the corresponding Zicfilp (landing pad) or Zicfiss/Zimop (shadow stack) hardware features before transferring control to userspace, nor does it refuse the load if hardware support is absent.
Consequence: function_loss
Pattern: load_elf_binary|arch_elf_pt_proc|ELF_PLAT_INIT|GNU_PROPERTY_RISCV_FEATURE_1_AND|PT_GNU_PROPERTY|START_THREAD
------------------------------------------------------------
[potential_risk] fs/binfmt_elf.c:776-831  parse_elf_properties
  parse_elf_properties() gates on CONFIG_ARCH_USE_GNU_PROPERTY (line 790). RISC-V does not set this Kconfig, so GNU property parsing is a no-op on RISC-V. The PT_GNU_PROPERTY phdr is captured (lines 878-881, 980-981) and passed to parse_elf_properties() (line 994-995), but the function returns immediately without inspecting GNU_PROPERTY_RISCV_FEATURE_1_AND bits. This means CFI_LP_UNLABELED (Zicfilp) and CFI_SS (Zicfiss) bits in .note.gnu.property are never checked by the kernel ELF loader.
  | if (!IS_ENABLED(CONFIG_ARCH_USE_GNU_PROPERTY) || !phdr)
  |     return 0;

[compliant] fs/binfmt_elf.c:592-599  arch_elf_pt_proc
  RISC-V uses the generic dummy arch_elf_pt_proc() because CONFIG_ARCH_BINFMT_ELF_STATE is not set. This stub returns 0 unconditionally — no PT_LOPROC..PT_HIPROC headers are inspected. However, this is by design: RISC-V CFI is managed via prctl() from userspace, not via ELF program header inspection at load time. The security guarantee is maintained at the prctl enablement gate, not at ELF load.

[compliant] arch/riscv/kernel/process.c:144-180  start_thread
  start_thread() correctly resets both shadow stack (Zicfiss) and landing pad (Zicfilp) state to disabled on every exec() via set_shstk_status(current, false) and set_indir_lp_status(current, false). This is the safe reset-before-userspace pattern: CFI starts off, and the dynamic linker (or static binary startup) must explicitly enable it via prctl. The prctl path in arch/riscv/kernel/usercfi.c guards enablement with cpu_supports_shadow_stack() and cpu_supports_indirect_br_lp_instr() hardware checks, so CFI cannot be enabled without hardware support.
  | /* clear shadow stack state on exec.
  |  * libc will set it later via prctl.
  |  */
  | set_shstk_status(current, false);
  | set_shstk_base(current, 0, 0);
  | set_active_shstk(current, 0);
  | /* disable indirect branch tracking on exec.
  |  * libc will enable it later via prctl.
  |  */
  | set_indir_lp_status(current, false);

[compliant] arch/riscv/include/asm/elf.h:1-156  (macro definitions)
  RISC-V elf.h does not define ELF_PLAT_INIT, START_THREAD, or any CFI-related ELF property handling. [compliant] arch/riscv/kernel/usercfi.c:510-520  is_user_lpad_enabled / is_user_shstk_enabled
  The prctl enablement gates correctly check hardware support before allowing CFI features to be turned on. is_user_shstk_enabled() checks cpu_supports_shadow_stack() (Zicfiss). is_user_lpad_enabled() checks cpu_supports_indirect_br_lp_instr() (Zicfilp). These functions are called by arch_set_indir_br_lp_status() and arch_set_shadow_stack_status() respectively, which are the prctl handlers. Hardware-absent systems will reject CFI enablement via prctl, preventing userspace from running with CFI features that lack hardware backing.
  | bool is_user_shstk_enabled(void)
  | {
  |     return (cpu_supports_shadow_stack() &&
  |         !(riscv_nousercfi & CMDLINE_DISABLE_RISCV_USERCFI_BCFI));
  | }
  | 
  | bool is_user_lpad_enabled(void)
  | {
  |     return (cpu_supports_indirect_br_lp_instr() &&
  |         !(riscv_nousercfi & CMDLINE_DISABLE_RISCV_USERCFI_FCFI));
  | }
