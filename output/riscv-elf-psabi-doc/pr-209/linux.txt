PR #209  target=linux  overall=compliant
Spec: Codifies RISC-V enum ABI: enums are int-sized unless values exceed UINT_MAX, then 64-bit. Kernel UAPI structs crossing the user boundary could silently change layout if a new large enum value is added, breaking ioctl size encoding and compat-layer assumptions.
Violation: In the Linux kernel, a UAPI structure exposed to userspace contains an enum field whose enumerator values exceed UINT_MAX (0xFFFFFFFF), causing the enum storage to become 64-bit per this ABI spec. If the kernel, userspace, or compat layer computes structure layout, ioctl command size encoding, or copy_from_user/copy_to_user bounds assuming the enum is 32-bit `int`, a size mismatch occurs across the kernel-user boundary.
Consequence: data_corruption
Pattern: enum.*=\s*(0x[89A-Fa-f]\d{8}|[0-9]{10,})|_IO[RWO]*\(.*sizeof.*enum|copy_(from|to)_user.*enum|struct\s+\w+.*\{[^}]*enum[^}]*\}.*__attribute__.*packed
