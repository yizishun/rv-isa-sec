PR #489  target=linux  overall=compliant
Spec: New ELF REGREL relocation types for gp-relative global-array relaxation: kernel module loader needs explicit handlers; silent fallthrough on unrecognized relocs would leave stale addresses in loaded code
Violation: The Linux kernel's module loader (arch/riscv/kernel/module.c) encounters R_RISCV_REGREL_ADD, R_RISCV_REGREL_LO12_I, or R_RISCV_REGREL_LO12_S relocations emitted by a new toolchain but has no handler for them, causing either a silent skip (unresolved symbol references in loaded code) or a module load failure
Consequence: denial_of_service
Pattern: case R_RISCV_REGREL_ADD: / case R_RISCV_REGREL_LO12_I: / case R_RISCV_REGREL_LO12_S: missing from apply_relocate_add() in arch/riscv/kernel/module.c; or R_RISCV_NONE fallthrough for unrecognized reloc types

[compliant] arch/riscv/kernel/module.c:808-819  apply_relocate_add
  No R_RISCV_REGREL_* relocation types exist in the current kernel (Linux 7.0-rc5). Neither arch/riscv/include/uapi/asm/elf.h (relocation type defines) nor arch/riscv/kernel/module.c (reloc_handlers[]) contain these symbols. The kernel correctly and safely handles unknown future relocation types via the explicit NULL-handler check at module.c:815-818: unrecognized types are rejected with pr_err() and -EINVAL — not silently skipped. Module load failure for truly unknown relocations is the correct defensive behavior; silently skipping would produce broken loaded code. If R_RISCV_REGREL_* are ratified by the ELF PSABI and assigned numbers, the kernel will need handler additions, but the current code is not vulnerable.
