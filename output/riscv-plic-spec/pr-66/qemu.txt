PR #66  target=qemu  overall=compliant
Spec: QEMU PLIC emulation lacks per-source enable check on completion writes and omits gateway blocking state, allowing a malicious guest to clear claimed bits for disabled sources and potentially interfere with interrupt delivery semantics
Violation:
  QEMU's sifive_plic_write() completion path (contextid==4,
  sifive_plic.c:246-250) clears the claimed bit for any value < num_sources
  without checking whether the interrupt source is currently enabled for the
  writing target context. The spec requires completion to be silently ignored
  if the source is not enabled for the target. Additionally, QEMU has no per-
  source gateway state — sifive_plic_irq_request() unconditionally sets
  pending on any rising edge regardless of whether the gateway should be
  blocking new interrupts pending a prior completion notification.
Consequence: denial_of_service
Pattern:
  sifive_plic_write.*contextid == 4.*set_claimed.*false(?!.*enable)
