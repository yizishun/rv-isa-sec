PR #66  target=xiangshan  overall=compliant
Spec: PLIC must internally assert a gateway completion notification wire upon valid claim/complete write; if this signal is missing and the implementation expects a separate MMIO write, interrupt sources become permanently blocked after first service
Violation:
  The PLIC hardware writes the completion ID to the claim/complete register
  but does NOT internally assert the per-source gateway notification signal
  (gateway_complete_o[src_id]). Instead, the implementation expects a separate
  MMIO write (e.g., to a gateway-specific register) to trigger gateway re-
  enablement. This means the gateway never receives the completion
  notification and its internal state machine remains in 'claimed' state,
  blocking all future interrupts from that source.
Consequence: denial_of_service
Pattern:
  plic.*gateway.*notif|gateway.*complete|intr_completion.*gateway|completion_m
  sg|gateway_reen|gw_.*_complete_o|plic_gateway_notify

[compliant] rocket-chip/src/main/scala/devices/tilelink/Plic.scala:261-267  Impl (completion routing)
  Completion notification routing is combinatorial: completerDev → UIntToOH →
  completedDevs → gateway.complete. Each gateway's .complete input is driven
  directly from the one-hot decode of the completed device ID on the same
  cycle as the MMIO claim/complete write. This is the critical signal path
  that proves the gateway completion notification IS internally asserted — no
  separate MMIO write is required, and the spec violation condition does NOT
  exist in this implementation.
  | val completerDev = Wire(UInt(log2Up(nDevices + 1).W))
  | val completedDevs = Mux(completer.reduce(_ || _), UIntToOH(completerDev, nDevices+1), 0.U)
  | (gateways zip completedDevs.asBools.tail) foreach { case (g, c) =>
  |    g.complete := c
  | }

  the written interrupt ID and asserts completer(i), which triggers the
  combinatorial chain that asserts gateway.complete. The assertion on line 292

  gateway.

  |     claimer(i) := valid
  |     (true.B, maxDevs(i))
  |   },

  |     completerDev := data.extract(log2Ceil(nDevices+1)-1, 0)

[compliant] rocket-chip/src/main/scala/devices/tilelink/Plic.scala:245-253  Impl (pending/gateway handshake on claim)
  Pending bit and gateway.ready handshake on claim: when a device is claimed,
  its pending bit is cleared AND gateway.ready is asserted (g.ready := !p).
  The pending bit stays cleared until the gateway asserts .valid again — which
  requires .complete to first clear inFlight. This correctly implements the
  full claim→complete handshake: the pending bit is not re-asserted until the
  gateway receives its completion notification, preventing stale-state
  exploits where an interrupt could be re-claimed before completion.
  | ((pending zip gateways) zip claimedDevs.tail) foreach { case ((p, g), c) =>
  |   g.ready := !p
  |   when (c || g.valid) { p := !c }
  | }
