PR #223  target=linux  overall=not_implemented
Spec: Kernel must handle local unknown NMI SSE event (0xffff0001) to completion; failure to register, save full interrupted context, or call sbi_sse_complete strands the event in RUNNING state, permanently blocking all lower-priority SSE events on the affected hart
Violation:
  In the Linux kernel, when the SBI SSE handler dispatches event_id 0xffff0001
  (local unknown NMI) and the kernel either (a) lacks a registered handler,
  leaving the event unacknowledged and permanently blocking lower-priority SSE
  events on that hart, or (b) the handler fails to save/restore the full
  interrupted context (sepc, sstatus.SPP/SPIE/SDT, A6) before invoking generic
  NMI handling, or (c) the handler fails to call sbi_sse_complete, stranding
  the event in RUNNING state and breaking the SSE state machine for all local
  events on that hart.
Consequence: denial_of_service
Pattern:
  sbi_sse_event_handler.*0xffff0001|case
  0xffff0001|SSE.*unknown.*nmi|local_unknown_nmi|event_id == 0xffff0001

[not_implemented] arch/riscv/kernel/traps.c:0-0  N/A (no SSE handler)
  No handler for SSE event 0xffff0001 (local unknown NMI) exists anywhere in
  the kernel. The traps.c NMI handling paths (DO_ERROR_INFO for illegal
  instructions, breakpoints, etc.) are CSRs-triggered NMIs from machine-mode
  hardware traps, not SBI SSE software-injected events. There is no code path
  that would save/restore the full interrupted context (sepc,
  sstatus.SPP/SPIE/SDT, A6) followed by sbi_sse_complete(), because the SSE
  extension is entirely unimplemented.
