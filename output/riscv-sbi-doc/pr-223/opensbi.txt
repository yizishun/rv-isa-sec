PR #223  target=opensbi  overall=not_implemented
Spec: New SBI_SSE_EVENT_GLOBAL_UNKNOWN_NMI (0xffff0001) allows forwarding M-mode unhandled NMIs to S-mode; OpenSBI must ensure M-mode CSR state from the NMI trap frame (mnepc, mnstatus, mncause) is not leaked through SSE event attributes accessible to S-mode.
Violation:
  When OpenSBI in M-mode receives an unknown/unrecognized NMI (e.g., RNMI via
  mncause with an unexpected cause code) and forwards it to S-mode as
  SBI_SSE_EVENT_GLOBAL_UNKNOWN_NMI without sanitizing M-mode CSR context
  (mnepc, mnstatus, mncause) that gets mapped into SSE event attributes
  (INTERRUPTED_SEPC, INTERRUPTED_FLAGS, ENTRY_ARG), S-mode can observe M-mode
  execution state.
Consequence: info_leak
Pattern:
  sbi_sse.*unknown.*nmi|mncause.*inject|RNMI.*SSE|mnepc.*event_attr|INTERRUPTE
  D_SEPC.*mnepc|INTERRUPTED_FLAGS.*mnstatus|unknown_nmi.*forward

[not_implemented] lib/sbi/sbi_sse.c:0-0  (no function — feature not implemented)
  The Smrnmi (Resumable NMI) extension is completely absent from OpenSBI.
  There is no SBI_SSE_EVENT_GLOBAL_UNKNOWN_NMI or
  SBI_SSE_EVENT_LOCAL_UNKNOWN_NMI event ID defined in
  include/sbi/sbi_ecall_interface.h. No CSR definitions for mnepc, mnstatus,
  mncause, or mnscratch exist in riscv_encoding.h. The trap handler in
  fw_base.S has no RNMI entry vector and no MNRET return path. The described
  vulnerability pattern (M-mode receiving an unknown RNMI and forwarding it to
  S-mode via SSE without sanitizing M-mode CSR context) is not implemented
  because the RNMI infrastructure itself does not exist. However, the existing
  sse_event_inject() function at sbi_sse.c:544-605 already provides the
  mechanism through which M-mode trap frame state (mepc via SEPC, mstatus
  flags) is mapped into SSE event attributes (INTERRUPTED_SEPC,
  INTERRUPTED_FLAGS) exposed to S-mode, which would become a direct info-leak
  vector if a future commit adds unknown NMI forwarding without sanitization.
  | (no code — SBI_SSE_EVENT_GLOBAL_UNKNOWN_NMI not defined; mnepc/mnstatus/mncause CSRs not declared; no Smrnmi trap handler; no unknown NMI forwarding path exists)
