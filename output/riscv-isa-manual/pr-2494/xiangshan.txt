PR #2494  target=xiangshan  overall=compliant
Spec: PMM field value 0b01 is now explicitly Reserved across all PMM CSR fields; any RTL treating it as a valid encoding (e.g. default case aliasing to PMLEN=7) violates WARL semantics and could enable pointer masking with undefined PMLEN, while HLVX.* must never traverse pointer-masking hardware
Violation: In XiangShan RTL, the 2-bit PMM field decoder in menvcfg/senvcfg/henvcfg/mseccfg CSR write logic does not reject value 0b01 as reserved, allowing a WARL-illegal encoding to alias to PMLEN=7 or PMLEN=16, or the load/store unit's effective-address masking datapath applies pointer masking to HLVX.* instruction memory accesses when spec mandates HLVX.* is exempt
Consequence: privilege_escape
Pattern: PMM.*===.*2'b01|PMM.*default|pointer_mask.*HLVX|addr_mask.*HLVX|mask_high_bits.*hypervisor|PMM_WARL|pmm_decoder
