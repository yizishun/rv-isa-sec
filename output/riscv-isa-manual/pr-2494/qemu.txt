PR #2494  target=qemu  overall=compliant
Spec: PMM change in two-stage translation with vsatp.MODE=Bare and PMLEN insufficient to cover GPA width can cause TLB aliasing: stale soft-MMU entries map distinct GPAs to same SPA, enabling guest-to-hypervisor address space confusion
Violation: In QEMU TCG, when a guest VM with vsatp.MODE=Bare changes henvcfg.PMM (or senvcfg.PMM for VU-mode) to a value where (XLEN-PMLEN) < GPA_width_required_by_hgatp.MODE (e.g., PMLEN=16 with hgatp.MODE=Sv48x4 requiring 50-bit GPA), QEMU's soft-MMU helper does not invalidate stale TLB entries via HFENCE.GVMA and continues to serve cached translations that were computed under the old PMLEN, causing guest physical addresses differing only in the now-masked top bits to alias to the same supervisor physical address.
Consequence: privilege_escape
Pattern: riscv_cpu_tlb_fill.*pointer_mask|get_physical_address.*pmlen|vext_hlv.*pmm|helper_hyp.*pmm|hstatus.*HUPMM|henvcfg.*PMM.*write.*hfence|PMM.*WARL.*reserved
