PR #2731  target=linux  overall=compliant
Spec: Zvvm adds lambda[2:0]/altfmt_A/altfmt_B/bs fields to vtype CSR at high bits; kernel context-switch/signal/ptrace/KVM paths must save/restore these bits or leak IME config across process boundaries
Violation:
  In the Linux kernel, when the RISC-V vector context (vtype CSR) is
  saved/restored during context switch, signal delivery, or ptrace access, if
  the kernel's save/restore mask for vtype does not cover bits [XLEN-7:XLEN-2]
  (lambda[2:0], altfmt_A, altfmt_B, bs), then one process's IME tile geometry,
  input format, signedness, block-size configuration silently leaks to or is
  corrupted for another process. Similarly, if the kernel writes an
  unsupported lambda encoding (0b000 or >max WARL) on restore but the CPU
  silently drops it, the process resumes with wrong K_eff and register-layout
  semantics, causing silent data corruption. For KVM, failure to switch these
  vtype bits across VM entries/exits leaks guest IME configuration between VMs
  or between VM and host.
Consequence: info_leak
Pattern:
  vtype.*save|vtype.*restore|__vstate_save|__vstate_restore|vstate_save|vstate
  _restore|vsetvli.*save|vsetvl.*save|CSR_VTYPE
