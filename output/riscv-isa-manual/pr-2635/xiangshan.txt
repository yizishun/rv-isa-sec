PR #2635  target=xiangshan  overall=compliant
Spec: If Zvknhb is independently configurable without automatically implying Zvknha, SHA-256 SEW=32 vector crypto instructions become falsely illegal when Zvknhb is enabled, breaking software correctness
Violation: When XiangShan RTL implements Zvknhb/Zvknha: if the Chisel configuration Parameters.scala ISAExtensions list treats Zvknhb and Zvknha as independently selectable without a hardware implication constraint (e.g. enabling Zvknhb without automatically setting Zvknha), then SHA-256 vector crypto instructions at SEW=32 could be incorrectly trapped as illegal when Zvknhb is enabled but Zvknha is not explicitly listed. Conversely, if the vtype/vsew legality check in the vector decode stage does not derive Zvknha from Zvknhb, the SEW=32 encoding for vsha2ms/vsha2c/vsha2cl would be treated as reserved, causing illegal instruction exceptions on valid code.
Consequence: function_loss
Pattern: Zvknhb_enabled && !Zvknha_enabled || !(Zvknhb implies Zvknha) in ISAExtensions implication logic
