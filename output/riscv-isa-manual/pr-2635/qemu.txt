PR #2635  target=qemu  overall=compliant
Spec: Zvknhb⇒Zvknha implication not enforced in QEMU ISA extension validation, allowing guest to observe inconsistent hart capability state where Zvknhb (SEW=32/64 SHA-256) is advertised but Zvknha (SEW=32 SHA-256) is absent, leaking an impossible CPU topology to guest software.
Violation: QEMU allows a CPU configuration with Zvknhb=enabled but Zvknha=disabled (in misa CSR bits, ISA string, or internal cpu->cfg flags), violating the 'Zvknhb implies Zvknha' dependency. Specifically, if riscv_cpu_validate_extensions() or the misa write WARL masking does not enforce that Zvknhb_enabled ⇒ Zvknha_enabled, guest software reading feature discovery CSRs or ISA string will observe an inconsistent/impossible hart capability state.
Consequence: info_leak
Pattern: Zvknhb.*without.*Zvknha|cfg\.ext_zvknhb.*!.*cfg\.ext_zvknha|Zvknhb.*depends|misa.*zvknhb
