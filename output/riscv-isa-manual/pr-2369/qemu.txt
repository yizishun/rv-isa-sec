PR #2369  target=qemu  overall=potential_risk
Spec: Zvkgs adds .vs variants of vghsh/vgmul with a new constraint that vd must not overlap the vs2 scalar element group; QEMU must reject this reserved encoding or risk silent cryptographic output corruption
Violation: QEMU executes vghsh.vs or vgmul.vs without checking that the vd register group overlaps the vs2 scalar element group. The spec marks such overlap as a reserved encoding. Since vd is both a source (partial hash / multiplier) and destination, and vs2 holds the hash subkey H broadcast to all element groups, overlapping vd with vs2 causes the scalar subkey to be overwritten mid-computation, corrupting the GHASH result.
Consequence: data_corruption
Pattern: vd.*overlap.*vs2|vs2.*overlap.*vd|vghsh.*\.vs|vgmul.*\.vs|vext_check_isa_ill|reserved.*encoding.*overlap

  Only vghsh_vv (@r_vm_1 → arg_rmrr) and vgmul_vv (@r2_vm_1 → arg_rmr) are decoded. No vghsh_vs or vgmul_vs encodings exist. Per the RISC-V crypto spec, .vs variants use different funct6 encodings and treat vs2 as a scalar element group (single subkey H broadcast). Without these encodings, guest code using vghsh.vs or vgmul.vs hits the illegal-instruction path — safe by absence, but Zvkgs is a required dependency for Zvkn (full vector crypto) so the ISA extension is effectively incomplete.
