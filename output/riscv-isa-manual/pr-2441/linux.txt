PR #2441  target=linux  overall=compliant
Spec: RVWMO generalized the single-memory-operation guarantee from RV32GC/RV64GC to all ≤XLEN-bit aligned instructions, but the 'unless specified otherwise' carve-out means future extensions can decompose such accesses — kernel lock-free code assuming indivisibility of natural-width aligned accesses would silently break on those extensions.
Violation:
  Linux kernel code assumes that an aligned memory instruction accessing ≤XLEN
  bits always gives rise to exactly one memory operation (single-copy atomic),
  but an ISA extension explicitly overrides this via the 'unless specified
  otherwise' clause, causing a single aligned ≤XLEN-bit instruction to
  decompose into multiple memory operations observable by other harts —
  breaking lock-free concurrency primitives (e.g., seqlocks, RCU, lockless
  ring buffers) that rely on natural-width aligned loads/stores being
  indivisible.
Consequence: race_condition
Pattern:
  natural-width aligned READ_ONCE/WRITE_ONCE on shared data without explicit
  FENCE or AMO synchronization, where the access width ≤ XLEN but the
  underlying instruction belongs to a non-base extension that decomposes the
  access
