PR #2441  target=linux  overall=compliant
Spec: Generalized RVWMO single-memory-operation guarantee now applies only to accesses of XLEN bits or fewer, with an explicit escape hatch for extensions like V to generate multiple memory operations per instruction — kernel code emulating or intercepting vector memory accesses (KVM, ptrace, signal frames) must not assume single-copy atomicity for wider accesses
Violation: Kernel code (KVM emulation, ptrace, signal delivery, or context-switch save/restore) assumes that a single aligned memory instruction always produces exactly one memory operation for accesses wider than XLEN bits (e.g., vector V extension loads/stores), when the spec now explicitly carves out that ISA extensions may generate multiple memory operations per instruction.
Consequence: race_condition
Pattern: (vmad|vmov|vse|vle|vss|vls|vlux|vsox|vsuxei|vloxei|vsext|vlsext)\.|vector.*(load|store|memory|save|restore)|kvm.*riscv.*emulate.*mem|__kvm_riscv.*mem|kvm_riscv_vcpu.*load|kvm_riscv_vcpu.*store|regcopy.*vector|riscv_vr_get|riscv_vr_set|ptrace.*riscv.*vreg|signal.*frame.*riscv.*vector
