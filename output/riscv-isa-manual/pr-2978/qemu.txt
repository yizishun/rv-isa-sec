PR #2978  target=qemu  overall=potential_risk
Spec: mstatus fields MIE/MPIE/SIE/SPIE/MPRV/MXR/SUM/TVM/TW/TSR must be writable when their dependent modes exist, else read-only 0 — QEMU WARL masking must dynamically track implemented privilege modes and satp.MODE writability
Violation: QEMU's mstatus WARL write-mask (target/riscv/csr.c, typically in write_mstatus or a helper returning the legal writable bitmask) returns any of MIE, MPIE, SIE, SPIE, MPRV, MXR, SUM, TVM, TW, TSR as read-only zero when the corresponding privilege mode (S-mode, U-mode) or feature (page-based virtual memory via satp.MODE) IS implemented on the emulated hart. Conversely, the mask must return read-only zero when those modes/features are absent — over-approximating writability also leaks invalid state.
Consequence: function_loss
Pattern: write_mstatus.*mask|mstatus.*warl|mstatus.*ro_zero|SIE.*SPIE.*writable|MPRV.*writable|MXR.*satp.*MODE.*read.only|SUM.*satp.*MODE.*read.only|MIE.*MPIE.*writable

[potential_risk] target/riscv/csr.c:2012-2015  write_mstatus
  The WARL write-mask unconditionally includes SIE, SPIE, MPRV, SUM, MXR, TVM, TSR, TW regardless of whether S-mode (RVS), U-mode (RVU), or page-based virtual memory (satp.MODE != Bare) are implemented on the emulated hart. Per RISC-V privileged spec: SIE/SPIE must be read-only zero when S-mode is absent; MPRV must be read-only zero when U-mode is absent; SUM/MXR must be read-only zero when S-mode or paging is absent. The over-approximating mask allows guest software to write and subsequently read back WARL fields that hardware would force to zero, leaking false feature information and violating WARL constraints.
  | mask = MSTATUS_SIE | MSTATUS_SPIE | MSTATUS_MIE | MSTATUS_MPIE |
  |         MSTATUS_SPP | MSTATUS_MPRV | MSTATUS_SUM |
  |         MSTATUS_MPP | MSTATUS_MXR | MSTATUS_TVM | MSTATUS_TSR |
  |         MSTATUS_TW;

  read_mstatus returns env->mstatus without applying any conditional read-as-zero masking for SIE, SPIE, MPRV, SUM, MXR, TVM, TSR, or TW. This can confuse guest discovery probes (e.g., checking for S-mode support) and leaks internal emulator state.
