PR #2978  target=freebsd-src  overall=potential_risk
Spec: Spec now requires mstatus control bits (SUM, MXR, TVM, TSR, TW, MPRV, MIE/MPIE) to be writable when the corresponding feature is supported — a non-conformant implementation that makes these bits read-only 0 despite supporting the feature would silently break FreeBSD's memory protection model and trap virtualization controls
Violation: FreeBSD kernel (running in S-mode) writes to sstatus.SUM, sstatus.MXR, or the M-mode firmware writes to mstatus.TVM/TSR/TW/MPRV expecting the bit to take effect, but the RISC-V implementation incorrectly makes the bit read-only 0 despite the spec-required condition for writability being met (e.g., S-mode supported with satp.MODE writable for SUM/MXR/TVM, U-mode supported for MPRV, modes less privileged than M exist for TW)
Consequence: function_loss
Pattern: csrw sstatus.*SSTATUS_SUM|csrs sstatus.*SSTATUS_MXR|writing mstatus CSR with TVM|TSR|TW|MPRV bits set without checking WARL readback
------------------------------------------------------------
[potential_risk] sys/riscv/include/asm.h:64-70  ENTER_USER_ACCESS macro
  ENTER_USER_ACCESS/EXIT_USER_ACCESS macros use csrs/csrc on sstatus.SUM without WARL readback verification. If a RISC-V implementation incorrectly makes SUM read-only 0 (despite the spec-required condition of S-mode with writable satp.MODE being met), all copyin/copyout/fueword/suword operations would fail, resulting in function_loss. The kernel blindly trusts the CSR write succeeded with no readback check.

  | 	csrs	sstatus, tmp
  | 
  | #define	EXIT_USER_ACCESS(tmp)						\
  | 	li	tmp, SSTATUS_SUM;					\
  | 	csrc	sstatus, tmp

[compliant] sys/riscv/riscv/exception.S:105-109  save_registers (macro, mode=1 branch)
  On S-mode exception entry, SUM is explicitly cleared via csrc sstatus,SSTATUS_SUM before the saved sstatus is stored to the trapframe. This is correct defensive practice ensuring SUM is never left set across exception handlers. The KASSERTs in trap.c:315 and trap.c:396 further verify SUM is always 0 on trap entry for both S-mode and U-mode exceptions.

[compliant] sys/riscv/include/riscvreg.h:82-105  (definitions only)
  The kernel defines MSTATUS_MPRV (bit 17) but never writes mstatus CSR from S-mode (confirmed: zero csrw/csrs/csrc on mstatus).
