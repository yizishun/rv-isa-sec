PR #2978  target=xiangshan  overall=compliant
Spec: mstatus conditional-writability fields (MXR/SUM/TVM/MPRV/SIE/SPIE/TW/TSR) are hardcoded as CSRRWField without satp.MODE-dependent or privilege-mode-dependent write gating, violating spec-mandated read-only-0 behavior when virtual memory or lower privilege modes are absent
Violation: In XiangShan RTL, MstatusBundle.MXR and MstatusBundle.SUM are declared as unconditional CSRRWField (always read/write) at MachineLevel.scala:515-516, lacking conditional writability logic that gates write access based on whether satp.MODE is read-only 0 or S-mode is unimplemented. When satp.MODE supports only Bare (no virtual memory), these bits remain writable but the spec requires them to be read-only 0. The writability control is purely static in the Chisel CSR field type declaration — no dynamic mux or write-mask is generated that qualifies writes with (satp.MODE != Bare) or (S-mode implemented). This affects the CSR module's reconnectReg() path in CSRModule.scala:73-75, which blindly connects wen to write-enable for RW-type fields without any satp.MODE-dependent gating.
Consequence: privilege_escape
Pattern: CSRRWField\(.*\)\.withReset.*MXR|CSRRWField\(.*\)\.withReset.*SUM|CSRRWField\(.*\)\.withReset.*TVM|CSRRWField\(.*\)\.withReset.*MPRV|CSRRWField\(.*\)\.withReset.*SIE|CSRRWField\(.*\)\.withReset.*TW|CSRRWField\(.*\)\.withReset.*TSR
