PR #2697  target=qemu  overall=bug_confirmed
Spec: Missing tcontrol CSR (0x7A5) causes illegal-instruction fault on spec-valid access and breaks global Sdtrig trigger-enable gating, allowing triggers to fire when the spec mandates they be suppressed
Violation: QEMU does not implement the tcontrol CSR (0x7A5) at all — no #define CSR_TCONTROL, no CSR table entry, no CPURISCVState field, and no read/write handlers. Guest M-mode software reading or writing CSR 0x7A5 receives an illegal-instruction exception instead of the spec-mandated MRW access. Additionally, the global trigger-enable bits (mte, mpte in tcontrol) that should gate whether Sdtrig triggers fire are absent, so QEMU may fire breakpoints/watchpoints at privilege levels where the spec says they should be suppressed.
Consequence: info_leak
Pattern: CSR array at index 0x7A5 is missing or maps to an unimplemented CSR; grep for CSR_TCONTROL or 0x7[aA]5 yields no definition or CSR table registration in target/riscv/csr.c
------------------------------------------------------------
[bug_confirmed] target/riscv/cpu_bits.h:458-464  (CSR definitions block, lines 458-464)
  CSR_TCONTROL (0x7A5) is not defined. The Sdtrig spec mandates tcontrol as an MRW CSR containing global trigger-enable bits (mte at bit 3, mpte at bit 7). The CSR definition block has CSR_TSELECT through CSR_TINFO, then jumps directly to CSR_MCONTEXT (0x7A8), leaving 0x7A5 and 0x7A6 undefined. Guest M-mode software accessing CSR 0x7A5 receives an illegal-instruction exception instead of the spec-mandated read/write behavior.

[potential_risk] target/riscv/debug.c:941-986  riscv_cpu_debug_check_breakpoint
  The trigger match logic in riscv_cpu_debug_check_breakpoint (and similarly riscv_cpu_debug_check_watchpoint at line 988) calls trigger_common_match() which checks per-trigger privilege bits (U/S/M/VU/VS in TDATA1) and textra matching, but has no global tcontrol.mte/mpte gate. In hardware, tcontrol.mte=0 means M-mode triggers are suppressed even if the per-trigger M bit is set. QEMU will fire triggers at privilege levels where the spec says they should be suppressed if tcontrol were programmed to disable them. However, since tcontrol is unimplemented and always raises #illegal-instruction, guest software cannot currently set tcontrol at all, making the practical impact limited to the CSR access fault rather than incorrect trigger firing.

[bug_confirmed] target/riscv/csr.c:6369-6375  (CSR table, debug group)
  CSR_SCONTEXT (0x7A6) is also completely missing — no #define in cpu_bits.h, no CPURISCVState field, no read/write handlers, and no CSR table entry. The scontext CSR is part of the Sdtrig spec and provides a means for M-mode software to communicate a 32-bit value to the Sdtrig textra matching mechanism, used for OS-level context filtering of triggers. Its absence means guest S-mode relying on scontext-based trigger filtering cannot use this mechanism.
