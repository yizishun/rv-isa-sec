PR #2697  target=qemu  overall=bug_confirmed
Spec: Newly-allocated Sdtrig CSRs tinfo (0x7A4) and tcontrol (0x7A5) must be registered in QEMU's CSR lookup table; absence causes illegal-instruction traps on valid guest CSR accesses, breaking debug/trace trigger functionality expected by spec-compliant guest software.
Violation:
  QEMU's CSR dispatch table does not register tinfo (0x7A4) and tcontrol
  (0x7A5) as valid Debug/Trace CSRs, causing accesses to these newly-allocated
  CSR addresses to fall through to the default unimplemented-CSR trap path
  (illegal instruction), or worse, to alias onto an unrelated CSR or return
  stale/uninitialized data from an unvalidated read path.
Consequence: function_loss
Pattern:
  riscv_csr_operations.*0x7A[0-9A-F].*|csr_ops\[.*\].*t(info|control)|case
  0x7a4|case 0x7a5|CSR_TINFO|CSR_TCONTROL
------------------------------------------------------------
[bug_confirmed] target/riscv/csr.c:6373-6379  csr_ops table (Debug CSRs block)
  CSR tcontrol (0x7A5) is missing from the CSR dispatch table. The RISC-V ISA
  manual (csrs.adoc lines 1001-1030) allocates 0x7A5 as the 'Trigger control
  register' (tcontrol) in the Debug/Trace Registers block alongside tselect,
  tdata1-3, tinfo, and mcontext. No CSR_TCONTROL macro is defined in
  cpu_bits.h, no read/write handler is implemented in csr.c or debug.c, and no
  entry exists in the csr_ops table. Any machine-mode access to CSR 0x7A5 hits
  the NULL predicate check in riscv_csrrw_check() (line 5588) and returns
  RISCV_EXCP_ILLEGAL_INST — the emulated guest sees an illegal instruction
  exception where a valid CSR read/write should succeed. This causes
  function_loss: debugging tools and external debuggers that rely on tcontrol
  for trigger configuration will malfunction.
  | /* Debug CSRs */
  |     [CSR_TSELECT]   =  { "tselect",  debug, read_tselect,  write_tselect  },
  |     [CSR_TDATA1]    =  { "tdata1",   debug, read_tdata,    write_tdata    },
  |     [CSR_TDATA2]    =  { "tdata2",   debug, read_tdata,    write_tdata    },
  |     [CSR_TDATA3]    =  { "tdata3",   debug, read_tdata,    write_tdata    },
  |     [CSR_TINFO]     =  { "tinfo",    debug, read_tinfo,    write_ignore   },
  |     /* CSR_TCONTROL (0x7A5) is MISSING — gap before MCONTEXT */
  |     [CSR_MCONTEXT]  =  { "mcontext", debug, read_mcontext, write_mcontext },
  References:
    - riscv-isa-manual/src/priv/csrs.adoc:1001-1030
      "Debug/Trace Registers (shared with Debug Mode): 0x7A0 tselect,
      0x7A1 tdata1, 0x7A2 tdata2, 0x7A3 tdata3, 0x7A4 tinfo, 0x7A5
      tcontrol, 0x7A8 mcontext. "

[compliant] target/riscv/csr.c:5418-5423  csr_ops table / read_tinfo / tinfo_csr_read
  CSR tinfo (0x7A4) is correctly implemented and registered. CSR_TINFO is
  defined in cpu_bits.h:463, read_tinfo() delegates to tinfo_csr_read() in
  debug.c:918, and the CSR is registered as read-only (write_ignore) in the
  dispatch table at line 6378. This matches the spec allocation at csrs.adoc
  lines 1001-1030.
  | static RISCVException read_tinfo(CPURISCVState *env, int csrno,
  |                                  target_ulong *val)
  | {
  |     *val = tinfo_csr_read(env);
  |     return RISCV_EXCP_NONE;
  | }

[bug_confirmed] target/riscv/cpu_bits.h:458-464  Debug/Trace CSR macros
  CSR_TCONTROL (0x7A5) macro is missing from cpu_bits.h. The Debug/Trace
  register block defines CSR_TSELECT (0x7A0) through CSR_TINFO (0x7A4), then
  jumps directly to CSR_MCONTEXT (0x7A8), skipping 0x7A5 (tcontrol) entirely.
  Without this macro, the CSR dispatch table in csr.c cannot register
  tcontrol.
  | /* Debug/Trace Registers (shared with Debug Mode) */
  | #define CSR_TSELECT         0x7a0
  | #define CSR_TDATA1          0x7a1
  | #define CSR_TDATA2          0x7a2
  | #define CSR_TDATA3          0x7a3
  | #define CSR_TINFO           0x7a4
  | /* CSR_TCONTROL (0x7A5) is MISSING */
  | #define CSR_MCONTEXT        0x7a8
