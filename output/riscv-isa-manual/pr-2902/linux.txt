PR #2902  target=linux  overall=compliant
Spec: MNPV bit in mnstatus is only defined when H extension is present; unconditionally reading it on non-H systems would cause the kernel to misinterpret the interrupted context's virtualization mode on RNMI return, potentially escaping to wrong privilege level.
Violation: Kernel RNMI trap handler reads mnstatus.MNPV to decide the virtualization mode of the interrupted context without first checking that the H extension is implemented (riscv_has_extension()). On systems with RNMI but no H extension, MNPV is not a defined field; reading it yields an implementation-defined value that the kernel may misinterpret as indicating V=1 or V=0, causing a wrong-mode RNMI return.
Consequence: privilege_escape
Pattern: csr_read.*MNSTATUS|MNPV[^_].*save|mnstatus.*MNPV|CSR_MNSTATUS.*MNPV
------------------------------------------------------------
[compliant] N/A:0-0  N/A
  The RISC-V RNMI (Resumable Non-Maskable Interrupt) feature is not implemented in Linux 7.0-rc5. No CSR definitions exist for MNSTATUS, MNEPC, MNCAUSE, or MNSCRATCH in arch/riscv/include/asm/csr.h. No RNMI trap handler code exists anywhere in arch/riscv/. The kernel has no code that reads mnstatus.MNPV or any other RNMI CSR, so the vulnerability condition (reading MNPV without an H-extension check) cannot trigger.
  | No RNMI CSRs defined in arch/riscv/include/asm/csr.h; no mnstatus/mnepc/mncause references in the entire arch/riscv/ subtree.
