PR #3000  target=xiangshan  overall=compliant
Spec: PR clarifies that the int_conv table's input-range clamping applies only to fcvt.w.s/wu.s/l.s/lu.s (float-to-integer), not fcvt.d.s (float-to-float); if XiangShan's FPU microarchitecture incorrectly shares the conversion datapath and applies int_conv clamping to fcvt.d.s, valid single-precision values exceeding the int_conv integer boundaries will be corrupted instead of correctly widened to double-precision
Violation:
  In XiangShan RTL, if the FPU conversion unit's decoder or micro-op dispatch
  incorrectly routes fcvt.d.s (double-precision float-to-float conversion)
  through the same execution path as fcvt.w.s/fcvt.wu.s/fcvt.l.s/fcvt.lu.s,
  the <<int_conv>> table's clamping behavior (e.g., clipping to −2^31 for out-
  of-range negative input) would be erroneously applied to fcvt.d.s results.
  Specifically, fcvt.d.s is a widening float-to-float conversion that must
  produce the exact double-precision representation of the single-precision
  source operand with no range clamping; applying the integer-bound clipping
  logic from the int_conv table would corrupt the output mantissa/exponent for
  legitimate float values that exceed the int_conv table's integer boundaries.
Consequence: data_corruption
Pattern:
  fcvt\.d\.s.*int_conv|FCVT.*\.S.*clamp|fp_to_int.*double|convertOp.*fcvt\.d\.
  s|FloatToInt.*D|FCVT_D_S.*overflow|fcvt_type.*int_conv_range
