PR #2782  target=xiangshan  overall=compliant
Spec: PR #2782 relaxes ssp-update-to-store ordering: hardware may update ssp speculatively before the shadow stack store is architecturally resolved, risking ssp corruption on fault/trap if the store ultimately fails
Violation: XiangShan pipeline commits ssp decrement before the shadow stack store is guaranteed architecturally complete (e.g., store still in store queue, or store issued speculatively past an unresolved branch/exception), and a trap, interrupt, or store fault subsequently occurs. The ssp is architecturally visible via CSR read while the corresponding shadow stack memory location still holds stale/unwritten data, violating the requirement that ssp shall decrement only when the store will complete successfully.
Consequence: data_corruption
Pattern: ssp_write|CSR_SSP.*:=|ssp_decrement|shadowStack|SSPUSH|C_SSPUSH|shadow_stack_store|ssp_update|commits.*ssp
