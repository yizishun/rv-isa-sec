PR #2782  target=qemu  overall=bug_confirmed
Spec: QEMU TCG may implement SSPUSH with stronger-than-spec ordering (atomic decrement-then-store), hiding race conditions in guest CFI shadow-stack code that real hardware's relaxed store/ssp-update ordering would expose, enabling shadow-stack bypass exploits to go undetected during emulation-based testing
Violation: QEMU TCG translates SSPUSH/C.SSPUSH as an atomic decrement-then-store sequence (old spec ordering), or serializes the ssp update and shadow-stack store with stronger ordering than the spec permits. In MTTCG mode, if SSPUSH is implemented as a single TCG helper that atomically updates ssp and performs the store without modeling the relaxed store/ssp-update ordering, QEMU enforces ordering guarantees that real RISC-V hardware does not provide.
Consequence: privilege_escape
Pattern: riscv_cfi_ssp_push|sspush|shadow_stack_push|gen_sspush|helper_sspush|ssp.*store|shadow.*stack.*store

[bug_confirmed] target/riscv/insn_trans/trans_rvzicfiss.c.inc:53-70  trans_sspush
  SSPUSH TCG translation emits the shadow-stack memory store (tcg_gen_qemu_st_tl, line 65-66) followed by the ssp CSR update (tcg_gen_st_tl, line 67) as sequential TCG ops within a single translation block. In MTTCG mode, other vCPUs observe both the store and the ssp update atomically with sequential consistency — there is no relaxed ordering between them. In real RISC-V hardware (RVWMO), the shadow-stack store and the ssp CSR update have relaxed ordering: another hart could observe the ssp update before the shadow-stack store becomes visible, or vice versa. QEMU TCG enforces strictly stronger ordering than real hardware permits, which can mask concurrency bugs that would manifest on silicon. Both the 32-bit SSPUSH (insn32.decode:1050-1051) and the compressed C.SSPUSH (insn16.decode:148) decode to this same trans_sspush function.

  | tcg_gen_qemu_st_tl(data, addr, SS_MMU_INDEX(ctx),
  |                    mxl_memop(ctx) | MO_ALIGN);
