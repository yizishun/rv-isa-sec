PR #2782  target=freebsd-src  overall=compliant
Spec: SSPUSH ssp-decrement and shadow-stack store now explicitly unordered; kernel must fence before reading ssp for cross-hart context save, or resume sees stale shadow-stack contents
Violation: In the FreeBSD kernel, any code that reads the ssp CSR (0x011) to capture a thread's shadow-stack state—during cpu_switch(), savectx(), sendsig(), fork(), or ptrace—without first issuing a FENCE w,w (or stronger) to ensure that all prior SSPUSH/C.SSPUSH shadow-stack stores from the outgoing hart are globally visible. Because the spec now explicitly states ssp decrement and the shadow-stack store are unordered with respect to each other, ssp may be observed as already decremented while the corresponding store to [ssp] has not yet completed, exposing stale/garbage data when the thread resumes on a different hart or when the kernel reads shadow-stack memory.
Consequence: data_corruption
Pattern: csr_read.*0x011|csrr.*ssp|SSP_SAVE|shadow_stack.*save|pcb.*ssp|savectx.*ssp|cpu_switch.*ssp|sendsig.*ssp|fork.*shadow
