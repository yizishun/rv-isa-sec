PR #2659  target=xiangshan  overall=bug_confirmed
Spec: mnstatus.NMIE resets to 1 (enabled) instead of 0 (disabled), allowing pre-initialization RNMI delivery that vectors to an undefined trap handler address before software configures RNMI data structures
Violation: At hart reset deassertion, XiangShan's MnstatusBundle initializes NMIE (bit 3) to 1'b1 via withReset(1.U), violating the spec mandate that NMIE resets to 0. The RTL comment at MachineLevel.scala:599 explicitly acknowledges this: 'OpenSBI does not support Smrnmi yet, so NMIE resets enabled for bring-up.' When an external RNMI interrupt signal (nmi_31 or nmi_43) is asserted before software executes its first mnstatus CSR write, the InterruptFilter does NOT gate the NMI (disableAllIntr is false because mnstatusNMIE=1), so the hart vectors to an uninitialized RNMI trap handler address, corrupting mnepc/mncause/mnstatus with the pre-initialization architectural state.
Consequence: privilege_escape
Pattern: withReset\(1\.U\).*NMIE|NMIE.*withReset\(1\.U\)|CSRRWField.*\(3\)\.withReset\(1\.U\)
------------------------------------------------------------
