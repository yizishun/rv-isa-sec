PR #2621  target=qemu  overall=compliant
Spec: QEMU TCG misses the PBMT=3 reserved-encoding page-fault check on leaf PTEs when Svpbmt is enabled, allowing a guest to use an architecturally-invalid PBMT value that could silently alias to undefined memory-type behavior
Violation: When Svpbmt is enabled (menvcfg.PBMTE=1), QEMU's get_physical_address() at target/riscv/cpu_helper.c:1492 only checks `!pbmte && (pte & PTE_PBMT)`, rejecting PBMT bits when Svpbmt is disabled. It does NOT check for the architecturally reserved PBMT=3 encoding (both bits 62:61 set) in leaf PTEs. A guest writing PBMT=3 into a leaf PTE will be accepted without page-fault, whereas the spec (norm:Svpbmt_leaf_pte_pbmt_reserved_3_fault) mandates a page-fault exception.
Consequence: privilege_escape
Pattern: if (!pbmte && (pte & PTE_PBMT))
