PR #2755  target=linux  overall=compliant
Spec: Kernel code paths in timer-riscv.c, suspend.c, and KVM vcpu_timer.c access stimecmp assuming SSTC implies hardware-managed STIP, but spec now requires menvcfg.STCE=1 for both stimecmp accessibility and STIP read-only behavior
Violation:
  The Linux kernel (in S-mode) accesses stimecmp CSR based solely on the SSTC
  ISA extension being reported, without verifying that M-mode firmware has set
  menvcfg.STCE=1. When stimecmp hardware exists but STCE=0, stimecmp is not
  accessible to S-mode (accesses trap) and STIP is writable by M-mode rather
  than being a read-only reflection of the hardware stimecmp comparator
  output.
Consequence: denial_of_service
Pattern:
  riscv_isa_extension_available\(.*SSTC\)|csr_(read|write)\(CSR_STIMECMP
