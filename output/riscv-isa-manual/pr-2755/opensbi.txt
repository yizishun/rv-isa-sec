PR #2755  target=opensbi  overall=compliant
Spec: STIP writability in mip depends on both stimecmp implementation AND STCE; OpenSBI must check STCE before assuming STIP is read-only, or S-mode timer interrupts may be silently lost when STCE=0
Violation:
  OpenSBI detects that stimecmp is implemented (e.g., via Sstc extension
  probing) but does not check STCE before deciding whether STIP in mip is
  writable. If STCE=0, stimecmp exists but is disabled, so STIP is actually
  writable — OpenSBI may incorrectly skip writing STIP to inject timer
  interrupts to S-mode. Conversely, if STCE=1 and OpenSBI attempts to write
  STIP, the write is silently ignored because STIP is read-only.
Consequence: denial_of_service
Pattern:
  Code path that checks for stimecmp/Sstc presence without also checking
  menvcfg.STCE before branching on STIP writability; CSR write to mip with
  STIP bit set when stimecmp probe has been done; HSM suspend/resume save-
  restore of mip that writes STIP unconditionally; SBI timer extension
  fallback that injects timer interrupts via STIP write without confirming
  STCE state.
