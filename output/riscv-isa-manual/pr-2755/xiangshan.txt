PR #2755  target=xiangshan  overall=compliant
Spec: STIP read-only in mip must depend on runtime menvcfg.STCE=1, not on hardware-implemented stimecmp alone; STCE=0 requires software-writable STIP even with stimecmp present
Violation:
  In the mip CSR hardware module, if STIP read-only behavior is gated on the
  elaboration-time presence of stimecmp hardware (e.g., a Chisel 'if
  (hasSstc)' guarding writability) rather than on the runtime menvcfg.STCE
  bit. Specifically, when menvcfg.STCE=0—meaning the Sstc extension is
  disabled by M-mode firmware—the hardware must allow M-mode software to write
  mip.STIP to inject timer interrupts to S-mode. If the implementation instead
  treats STIP as permanently read-only whenever stimecmp registers exist in
  the RTL, writes to mip.STIP are silently dropped when STCE=0.
Consequence: denial_of_service
Pattern:
  mip.STIP writability gated on compile-time/elaboration-time stimecmp
  presence (e.g., conditional 'when' block keyed on HasSstc parameter) rather
  than on runtime menvcfg.STCE via Mux(menvcfg.STCE.asBool, platformIRP.STIP,
  reg.STIP)
