PR #2755  target=xiangshan  overall=compliant
Spec: STIP writability must be gated by menvcfg.STCE=0 per spec: if stimecmp implemented AND STCE=1, STIP is read-only in mip; legacy CSR module allows unconditional STIP writes, enabling M-mode to inject spurious S-mode timer interrupts bypassing hardware stimecmp comparator
Violation: In the legacy CSR module (src/main/scala/xiangshan/backend/fu/CSR.scala:314), mipWMask unconditionally includes bit 5 (STIP) as writable via '((1 << 9) | (1 << 5) | (1 << 1)).U(XLEN.W)' — STIP is always software-writable regardless of menvcfg.STCE. In the new CSR module (MachineLevel.scala:247-257), the gating is correctly implemented: when menvcfg.STCE=1, STIP reads from hardware-generated platformIRP.STIP and writes are ignored; only when menvcfg.STCE=0 does the internal reg.STIP become the read source and accept writes. If the legacy CSR module is instantiated in any build configuration where EXT_SSTC=true (always true per CSRConfig line 65), M-mode software can directly set/clear mip.STIP via CSR write even when menvcfg.STCE=1, bypassing the SstcInterruptGen hardware comparator.
Consequence: privilege_escape
Pattern: mipWMask.*5\)|mip.*STIP.*writable|writeMask.*STIP|mip_wmask.*STIP|STIP.*wen.*!.*STCE|STIP.*!.*menvcfg
