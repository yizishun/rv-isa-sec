PR #2379  target=linux  overall=compliant
Spec: PR #2379 formalizes SFENCE.VMA ordering semantics and PTE-update atomicity rules as machine-extractable normative requirements; from the kernel perspective, the most acute exposure is the TLB-coherence contract: speculative translation execution must not set D-bit nor cache an invalid entry (norm:speculative_translation_execution), PTE updates appear in global memory order before the triggering access (norm:pte_update_ordering) but are explicitly not fence-ordered relative to memory (norm:pte_update_not_fence_ordered), meaning kernel TLB-shootdown paths relying on FENCE alone after remote PTE modifications may leave stale translations observable by in-flight page-table walks
Violation:
  The Linux kernel modifies a leaf PTE (e.g., during CoW, page migration, or
  mprotect) without executing SFENCE.VMA on the local hart to order the PTE
  store before subsequent implicit address-translation reads, or when a remote
  TLB shootdown via SBI RFENCE/IPI races with a concurrent page-table walker
  that speculatively caches the stale translation before the fence completes
  on the target hart
Consequence: privilege_escape
Pattern:
  ptep_set_access_flags|ptep_get_and_clear|set_pte_at|pte_mkwrite|pte_mkdirty|
  pte_mkyoung followed by flush_tlb_page|local_flush_tlb_page without a
  subsequent mb() or RISCV_FENCE() barrier on harts where the privileged spec
  now formalizes that PTE updates in memory are NOT ordered by FENCE relative
  to prior memory accesses (norm:pte_update_not_fence_ordered)
