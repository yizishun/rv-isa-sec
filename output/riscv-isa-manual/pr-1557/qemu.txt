PR #1557  target=qemu  overall=potential_risk
Spec: Compressed encodings of loads/stores must apply MO_ATOM_WITHIN16 identically to their 32-bit counterparts when zama16b is enabled; divergence silently strips guest atomicity guarantees
Violation: In QEMU TCG, when zama16b is enabled (ext_zama16b=true) but a compressed encoding (16-bit) of a base ISA load/store or F/D/Q load/store is translated without MO_ATOM_WITHIN16 set in the MemOp, violating the spec requirement that misaligned atomicity granule applies equally to compressed encodings. This occurs when a compressed load/store translator bypasses gen_load()/gen_store() and implements its own memory access path without independently checking ext_zama16b.
Consequence: data_corruption
Pattern: trans_c_(lw|sw|ld|sd|lbu|lhu|lh|sb|sh|flw|fsw|fld|fsd).*\{[^}]*tcg_gen_qemu_(ld|st)[^}]*\} (without preceding ext_zama16b check) OR any compressed load/store translator that does not delegate to gen_load/gen_store nor check ext_zama16b independently
------------------------------------------------------------

The memop is MO_UL or MO_UQ (4- or 8-byte loads >= MXLEN/2), so zama16b atomicity should apply. These are 16-bit compressed instructions performing multi-register stack loads, so they match the pattern 'compressed load translator not delegating to gen_load nor checking ext_zama16b independently'.

[compliant] target/riscv/insn_trans/trans_zilsd.c.inc:22-45  gen_load_i64
