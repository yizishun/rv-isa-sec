PR #1557  target=xiangshan  overall=not_implemented
Spec: If MAG PMA is implemented, compressed load/store encodings (RVC) must be treated identically to 32-bit encodings for misaligned atomicity granule coverage; failure to do so causes incorrect misalignment exceptions or non-atomic memory access within the granule, leading to data corruption
Violation:
  XiangShan currently does not implement the misaligned atomicity granule PMA
  (MAG) at all — the PMA checker tracks only R/W/X/A/ATOMIC/C/L bits with no
  MAG field. If MAG PMA support is added in the future, the load/store unit
  misalignment check at NewLoadUnit.scala:926 (`val am = !in.align.get &&
  accessType.isScalar() && isNC && !pmpUnaccessable`) and
  NewStoreUnit.scala:641 (`val am = !align && isScalar && isNC &&
  !pmpInaccessible`) must apply to both 32-bit and compressed encodings
  identically. If the MAG check were gated on instruction decode format (e.g.,
  checking `!isRVC` or matching only 32-bit opcode patterns), compressed
  load/store instructions (C.LW/C.SW/C.LD/C.SD/C.FLW/C.FSW/C.FLD/C.FSD) would
  bypass the MAG PMA atomicity guarantee, causing either spurious misaligned
  exceptions or non-atomic execution within the granule.
Consequence: data_corruption
Pattern:
  isRVC.*PMA|PMA.*isRVC|mag.*check.*(?!compressed)|misaligned.*atomicity.*gran
  ule.*(?!rvc|compressed)|MAG\d+.*opcode.*filter

  The load misalignment exception check uses accessType.isScalar(), which
  classifies instructions by InstrType (scalar/vector/prefetch) rather than by
  encoding format (32-bit vs compressed). Both C.LW/C.LD/C.FLW/C.FLD
  (compressed) and LW/LD/FLW/FLD (32-bit) are InstrType.scalar, so compressed
  encodings are treated identically. If MAG PMA were implemented in the
  future, gating the MAG check on isScalar() would correctly cover both 32-bit
  and compressed encodings per spec requirement (machine.adoc:3094-3096:
  'applies only to AMOs, loads and stores defined in the base ISAs... and
  compressed encodings thereof').

[compliant] src/main/scala/xiangshan/mem/pipeline/package.scala:108-115  InstrType / isScalar
  InstrType classifies instructions into three categories: scalar, vector,
  prefetch. The isScalar() method checks InstrType === scalar, which is
  encoding-format-agnostic — it does not distinguish between 32-bit and
  compressed encodings. Both compressed
  (C.LW/C.SW/C.LD/C.SD/C.FLW/C.FSW/C.FLD/C.FSD) and 32-bit
  (LW/SW/LD/SD/FLW/FSW/FLD/FSD) scalar memory instructions are classified as
  'scalar'. This means any future MAG PMA check gated on isScalar() would
  apply uniformly to both encoding formats.
