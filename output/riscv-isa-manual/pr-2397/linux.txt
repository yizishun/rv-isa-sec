PR #2397  target=linux  overall=potential_risk
Spec: PMP all-bytes-match rule now unconditionally supersedes M-mode L=0 bypass: M-mode accesses spanning PMP boundaries fault even on unlocked regions
Violation:
  In the Linux kernel, when M-mode code (early boot in head.S before PMP
  setup, or SBI firmware invoked via ecall) performs a memory access whose
  bytes are not all covered by the single highest-priority matching PMP entry,
  the access faults even if all matching entries have L=0 (unlocked). This is
  because the spec now explicitly says the all-bytes-must-match rule
  supersedes the M-mode-unlocked-bypass rule.
Consequence: denial_of_service
Pattern:
  M-mode memory accesses (including SBI handler code paths) that cross PMP
  region boundaries or target addresses not fully contained within any single
  PMP entry — detectable by auditing PMP configuration writes (CSR_PMPCFGx,
  CSR_PMPADDRx) for fragmented/partial-coverage setups combined with M-mode
  load/store paths.
------------------------------------------------------------

[not_implemented] arch/riscv/kvm/vcpu.c:584-602  kvm_arch_vcpu_load
  KVM vcpu_load/vcpu_put does not save/restore or virtualize PMP CSRs. The
  kvm_riscv_csr ONE_REG structure (kvm.h:75-87) has no PMP fields. NACL CSR
  sync does not cover PMP. This means guest M-mode code (if supported) sees
  host PMP state directly — a virtualization hole if the host uses PMP to
  restrict physical memory access. However, current RISC-V KVM typically only
  supports VS/VU-mode guests, so PMP virtualization is an unexercised gap
  rather than an active bug.

[potential_risk] arch/riscv/kernel/head.S:239-240  _start_kernel
  No read-back verification after CSR_PMPCFG0 write. PMP CSRs are WARL (spec
  §3.7.1: 'All PMP CSR fields are WARL and may be read-only zero'). If PMPCFG0
  silently ignores the write (e.g., due to a prior locked PMP entry configured
  by firmware with partial coverage), the kernel proceeds assuming full memory
  access but may fault on M-mode loads/stores that cross PMP region
  boundaries. The trap-vector skip only handles traps from illegal CSR access,
  not silent WARL write-ignore.
  | li a0, (PMP_A_NAPOT | PMP_R | PMP_W | PMP_X)
  | 	csrw CSR_PMPCFG0, a0
