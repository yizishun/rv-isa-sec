PR #2397  target=linux  overall=potential_risk
Spec: PMP partial-match access failures now explicitly apply to M-mode even for unlocked (L=0) regions, meaning kernel buffers passed to SBI firmware handlers must be fully contained within a single PMP entry or risk M-mode access faults and silent data corruption.
Violation: In the Linux kernel, when SBI ecalls pass kernel buffer addresses to M-mode firmware handlers, and those buffers cross PMP entry boundaries or are only partially covered by an unlocked (L=0) PMP entry, M-mode access faults despite the kernel's assumption that M-mode can unconditionally access any unlocked region. The PMP matching rules (partial match → fail) now explicitly apply to M-mode, meaning even a single PMP entry boundary crossing within a kernel buffer handed to M-mode causes an unrecoverable access fault in firmware context.
Consequence: data_corruption
Pattern: sbi_ecall\(|sbi_call\(|__sbi_.*buf|sbi_.*range|sbi_remote_sfence_vma|sbi_remote_fence_i|SBI_EXT_RFNC|sbi_send_ipi
