PR #2397  target=opensbi  overall=compliant
Spec: PMP 'match all bytes' rule fires before the M-mode privilege bypass—OpenSBI M-mode handlers that dereference pointers near PMP region boundaries will raise access-fault exceptions even on unlocked regions, risking unrecoverable M-mode traps during domain context switches or HSM flows
Violation:
  OpenSBI M-mode code performs a memory access that straddles a PMP entry
  boundary, where the highest-priority matching PMP entry does not cover all
  bytes of the access. Per the clarified spec, the 'match all bytes' rule is
  evaluated before the privilege-mode/L-bit check—so even an M-mode access to
  an unlocked (L=0) region faults if it spans a partial PMP entry boundary
  (e.g., a doubleword load at a domain page edge where only half the access is
  covered by one PMP entry).
Consequence: denial_of_service
Pattern:
  M-mode sd/ld/amoswap crossing PMP region boundary; sbi_domain_context
  save/restore with misaligned access near PMP edge; HSM suspend handler
  storing sbi_scratch to memory spanning PMP entry limit; M-mode memcpy/memset
  across PMP-configured domain ranges
