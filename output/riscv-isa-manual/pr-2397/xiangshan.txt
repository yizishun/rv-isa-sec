PR #2397  target=xiangshan  overall=compliant
Spec: M-mode L=0 bypass unconditionally overrides R/W/X permission bits, allowing M-mode to access PMP-protected regions even when R/W/X bits explicitly deny the access type, contradicting spec PR #2397 NOTE that R/W/X rule supersedes optional-M-mode rule
Violation: When PMP checks are applied to M-mode accesses, the PMPChecker.pmp_match_res method (PMP.scala:424-441) unconditionally forces R/W/X permission bits to true for M-mode accesses to unlocked (L=0) PMP entries via the `ignore = passThrough && !pmp.cfg.l` signal. This means an M-mode access that hits a PMP entry whose R/W/X bits deny the access type (e.g., read to W-only region, exec to non-X region) will incorrectly succeed. The spec NOTE clarifies that the R/W/X rule supersedes the optional-M-mode rule, so even M-mode to an unlocked region must fail when the R/W/X bits do not grant the access. The bypass must NOT override R/W/X when M-mode PMP checks are active.
Consequence: privilege_escape
Pattern: passThrough && !pmp.cfg.l → ignore forces cfg.r||ignore / cfg.w||ignore / cfg.x||ignore in pmp_match_res
