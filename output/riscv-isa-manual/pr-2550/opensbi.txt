PR #2550  target=opensbi  overall=compliant
Spec: OpenSBI must probe for mseccfg-defining extensions (e.g., Smepmp) before accessing mseccfg; blindly accessing it on hardware without those extensions is an unrecoverable M-mode trap
Violation: OpenSBI M-mode code reads or writes the `mseccfg` CSR without first checking that at least one extension defining mseccfg fields (e.g., Smepmp, Smmpm) is implemented. On hardware lacking all such extensions, `mseccfg` is reserved and accessing it raises an illegal instruction exception, which in M-mode is typically unrecoverable.
Consequence: denial_of_service
Pattern: csr_read/write/set/clear.*mseccfg (or CSR_MSECCFG) without a prior extension probe (e.g., misa bit check, ISA string check, or try-access with trap handling) confirming the CSR exists
