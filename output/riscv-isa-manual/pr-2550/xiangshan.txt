PR #2550  target=xiangshan  overall=compliant
Spec: mseccfg CSR unconditionally exists at 0x747 without a config-time gate checking whether any field-defining extension (Smmpm/Smepmp) is present; bare configs without these extensions expose a phantom CSR where the spec mandates illegal-instruction trap
Violation: In XiangShan RTL, the mseccfg CSR (address 0x747) is unconditionally instantiated in the CSR decode table (CSRs.machineLevelCSRs includes mseccfg) regardless of whether any extension that adds fields to mseccfg is actually configured. Per the updated spec, mseccfg exists only if an extension adding a field to it (e.g., Smmpm adds PMM, Smepmp adds MML/MMWP/RLB) is implemented; otherwise the CSR address is reserved and must trap as illegal instruction. XiangShan has no conditional existence gate (e.g., HasSmmpm || HasSmepmp) on mseccfg's decode entry, so even in a configuration where both Smmpm and Smepmp are disabled, CSR reads/writes to 0x747 succeed without trapping.
Consequence: privilege_escape
Pattern: machineLevelCSRs\s*\+=.*mseccfg(?!.*HasSmmpm|HasSmepmp|configGate|conditional)
