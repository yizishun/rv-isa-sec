PR #2550  target=qemu  overall=compliant
Spec: have_mseccfg() uses a hardcoded allowlist of extensions; if QEMU adds a new extension with mseccfg fields but omits it from this predicate, the CSR incorrectly traps, breaking guest security configuration silently
Violation: QEMU enables an extension that adds fields to mseccfg (e.g., Smepmp, Zkr, Smmpm) but the have_mseccfg() allowlist in csr.c:775-788 does not include that extension, causing the CSR access predicate to return RISCV_EXCP_ILLEGAL_INST — the CSR silently disappears even though the extension that needs it is active.
Consequence: function_loss
Pattern: have_mseccfg\(|ext_smepmp|ext_zkr|ext_smmpm|CSR_MSECCFG
