PR #2504  target=xiangshan  overall=compliant
Spec: Sstc makes STIP read-only in mip when stimecmp is active; if RTL CSR write-enable for mip.STIP is not dynamically gated by menvcfg.STCE, M-mode can inject fake timer interrupts to S-mode, constituting a privilege-level control-flow hijack
Violation: When Sstc is implemented and menvcfg.STCE=1, the spec mandates STIP in mip becomes read-only (reflecting the stimecmp timer signal). If XiangShan's CSR module still allows M-mode to write mip.STIP under this condition—either because the STIP writability is statically tied to !Sstc_implemented instead of dynamically gated by menvcfg.STCE, or because the write-enable logic in the CSR register file does not factor in (Sstc_enabled && STCE)—M-mode software can inject spurious supervisor timer interrupts, bypassing the stimecmp-based interrupt generation and subverting S-mode execution control.
Consequence: privilege_escape
Pattern: mip.STIP write-enable is not qualified by (Sstc_implemented && menvcfg_STCE), OR stimecmp CSR access check missing STCE/TM gating in decoder/CSR module, OR hip.VSTIP combinatorial logic missing htimedelta term in unsigned comparison, OR vstimecmp illegal-instruction trap not raised when V=1 and henvcfg.STCE=0
