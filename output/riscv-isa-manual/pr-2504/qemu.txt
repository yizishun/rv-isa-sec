PR #2504  target=qemu  overall=compliant
Spec: Failure to atomically gate stimecmp accessibility and STIP writability via STCE bits creates a window where S-mode can either access a timer CSR it shouldn't (bypassing M-mode interrupt control) or write to a now-read-only STIP bit (causing spurious/masked timer interrupts), enabling S-mode to manipulate timer interrupt delivery outside M-mode supervision
Violation: QEMU does not atomically gate stimecmp CSR accessibility and mip.STIP/sip.STIP writability based on menvcfg.STCE. When STCE=0, stimecmp accesses from S-mode must raise illegal-instruction exceptions AND STIP in mip must revert to writable (M-mode software-controlled). When STCE=1, stimecmp is accessible in S-mode AND STIP becomes read-only (hardware-driven from stimecmp comparison). A QEMU implementation that fails to synchronize these two state changes atomically — e.g., allowing a stale writable STIP while stimecmp is already accessible, or vice versa — violates the spec's requirement that STIP 'reverts to its defined behavior as if this extension is not implemented' when STCE=0.
Consequence: privilege_escape
Pattern: riscv_csrrw.*stimecmp.*menvcfg|STCE.*stimecmp.*check|sstc.*stimecmp.*enabled|mip.*STIP.*writable|riscv_sstc_enabled|stimecmp.*access.*check
