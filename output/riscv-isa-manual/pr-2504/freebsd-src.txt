PR #2504  target=freebsd-src  overall=potential_risk
Spec: S-mode direct stimecmp access traps fatally when menvcfg.STCE=0; FreeBSD must gate stimecmp usage on STCE probe before touching the CSR
Violation:
  FreeBSD kernel (S-mode) executes a CSR read or write to stimecmp when
  menvcfg.STCE=0 — either because OpenSBI/boot firmware never set the STCE
  bit, or because M-mode software dynamically cleared it. The resulting
  illegal-instruction exception is fatal in kernel mode.
Consequence: denial_of_service
Pattern:
  csr_read\(.*stimecmp.*\)|csr_write\(.*stimecmp.*\)|CSR_STIMECMP|csrr.*stimec
  mp|csrw.*stimecmp
------------------------------------------------------------
[potential_risk] sys/riscv/riscv/timer.c:88-96  set_timecmp
  FreeBSD S-mode kernel writes to stimecmp CSR guarded only by has_sstc
  (derived from ISA string parsing), without verifying menvcfg.STCE is set by
  M-mode firmware. Per spec (machine.adoc:2233-2235), when menvcfg.STCE=0, any
  non-M-mode access to stimecmp raises an illegal-instruction exception, which
  is fatal in kernel mode. If M-mode firmware advertises Sstc in ISA string
  but fails to set or later clears menvcfg.STCE, the kernel panics.

  | 	csr_write(stimecmp, timecmp);
  | else
  | 	sbi_set_timer(timecmp);
