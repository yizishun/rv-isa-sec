PR #2504  target=linux  overall=potential_risk
Spec: Sstc makes STIP/VSTIP read-only hardware-reflected bits; kernel code that writes STIP/VSTIP to manage timer state (context switch, KVM timer emulation, tick setup) silently fails, causing lost or stuck timer interrupts and potential CPU starvation or guest VM hangs.
Violation: Linux kernel code in S-mode writes to mip.STIP or sip.STIP (or KVM in HS-mode writes to hip.VSTIP via hvip.VSTIP) to inject or clear timer interrupts while the Sstc extension is implemented and STCE is enabled in menvcfg/henvcfg, making these bits read-only and hardware-driven from stimecmp/vstimecmp comparisons. The write is silently ignored or causes an unexpected trap, breaking the kernel's assumption of software-controlled timer interrupt delivery.
Consequence: denial_of_service
Pattern: csr_write.*[Ss]TIP|csr_set.*[Ss]TIP|csr_clear.*[Ss]TIP|write.*mip.*STIP|write.*sip.*STIP|__kvm_riscv_vcpu_timer|kvm_riscv_vstimecmp
