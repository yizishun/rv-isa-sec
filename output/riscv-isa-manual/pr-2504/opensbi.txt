PR #2504  target=opensbi  overall=bug_confirmed
Spec: When Sstc is enabled, STIP in mip is read-only and reflects stimecmp; OpenSBI must use stimecmp to clear timer interrupts instead of writing to mip.STIP, or writes are silently dropped causing unacknowledgeable timer interrupts.
Violation:
  OpenSBI M-mode code writes to mip.STIP to set or clear the supervisor timer
  interrupt, but the Sstc extension is enabled (menvcfg.STCE=1), making STIP
  read-only in mip. The CSR write is silently ignored per spec, so the timer
  interrupt state is not updated as the firmware expects. The only way to
  clear the timer interrupt condition when Sstc is active is to write stimecmp
  with a value greater than the current time value.
Consequence: denial_of_service
Pattern:
  csr_write.*CSR_MIP.*STIP|csr_set.*CSR_MIP.*STIP|csr_clear.*CSR_MIP.*STIP
------------------------------------------------------------

[bug_confirmed] lib/sbi/sbi_hsm.c:435-446  __sbi_hsm_suspend_non_ret_restore
  MENVCFG is restored at line 441 BEFORE MIP_STIP is re-injected via
  csr_set(CSR_MIP, ...) at line 445. When saved_menvcfg has STCE=1 in the STCE
  bit, the subsequent csr_set writing MIP_STIP is silently ignored because
  STCE makes STIP read-only in mip. If a timer interrupt was pending
  (hardware-set STIP from stimecmp comparison) before non-retentive suspend,
  it was captured in saved_mip, but the re-injection on resume is a no-op —
  the timer interrupt is permanently lost. S-mode resumes execution and never
  receives the timer IRQ, causing missed deadlines and denial of service.
