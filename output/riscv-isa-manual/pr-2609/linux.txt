PR #2609  target=linux  overall=compliant
Spec: Linux S-mode signal/ptrace/KVM store paths must not use regular store instructions to user pages protected by SPMP shadow-stack encoding (XWR=010, SHARED=0); doing so raises store/AMO access fault, causing denial of service for processes using Zicfiss shadow stacks when Sspmpss is active
Violation: In the Linux kernel, when satp.MODE != Bare and menvcfg.SSE is set, S-mode kernel code (e.g., signal frame delivery via put_user/copy_to_user, ptrace writes, or KVM guest memory access emulation) performs a regular store instruction to a user page whose matching SPMP entry has spmpcfg.XWR=010 and spmpcfg.SHARED=0 (shadow stack region), violating the rule that only Zicfiss shadow stack instructions may store to such regions; additionally, if the kernel performs instruction fetches or implicit accesses (e.g., icache fills) from such regions, those also raise access faults.
Consequence: denial_of_service
Pattern: 'put_user\|copy_to_user\|__put_user\|__copy_to_user' in signal frame setup (setup_sigframe, setup_rt_frame) or ptrace write paths (ptrace_request, generic_ptrace_pokedata) without prior SPMP entry inspection or temporary spmpcfg modification for shadow-stack-encoded regions; also 'prefetch\|__builtin_prefetch' or icache coherence operations touching shadow-stack SPMP regions
