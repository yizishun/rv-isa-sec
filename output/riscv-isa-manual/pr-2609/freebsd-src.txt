PR #2609  target=freebsd-src  overall=compliant
Spec: Sspmpss shadow-stack SPMP enforcement gates on satp.MODE!=Bare and menvcfg.SSE, both writable by FreeBSD's HS-mode kernel; bhyve's vsatp writes and any menvcfg manipulation can silently deactivate or misconfigure shadow-stack protection, turning CFI-guaranteed faults into unintended access grants or legitimate accesses into spurious faults
Violation:
  In the FreeBSD kernel (HS-mode), when bhyve writes vsatp.MODE=Bare for a
  guest VM via vmmops_vcpu_restore_csrs() at vmm_riscv.c:176, or when the
  kernel clears menvcfg.SSE, the Sspmpss extension deactivates: all XWR=010
  SPMP entries revert to reserved encodings, so shadow-stack instructions that
  were previously permitted against those regions instead raise guest-page
  faults (VS/VU) or access faults (S/U). Conversely, if the kernel sets
  menvcfg.SSE without properly initializing SPMP shadow-stack entries,
  existing XWR=010 encodings become live with no shadow-stack memory carved
  out, silently allowing shadow-stack instructions to write to arbitrary
  memory through any SPMP entry that happens to decode as XWR=010.
Consequence: privilege_escape
Pattern:
  csr_write\((satp|vsatp|menvcfg).*Bare|csr_write\(spmpcfg|spmpcfg.*XWR.*=.*01
  0|pmap_satp_mode.*Bare|csr_[a-z]*\(spmp
