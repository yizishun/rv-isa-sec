PR #2609  target=opensbi  overall=compliant
Spec: OpenSBI writing mseccfg.MSSE after locking PMP entries with RLB=0 silently fails — M-mode shadow stack is left unconfigured despite firmware believing it is enabled
Violation: OpenSBI writes to mseccfg.MSSE (to enable/disable M-mode shadow stack) after any PMP entry has been locked (pmpcfg.L=1) while mseccfg.RLB=0 — the write is silently ignored per the Smcfiss spec, so the actual MSSE value diverges from what firmware expects
Consequence: function_loss
Pattern: search for mseccfg CSR writes that occur after any pmpcfg CSR write setting the L-bit, or initialization ordering where PMP entries are locked before mseccfg.MSSE is configured during cold/warm boot or HSM resume
