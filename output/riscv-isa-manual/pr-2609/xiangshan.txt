PR #2609  target=xiangshan  overall=compliant
Spec: PMP/SPMP checker hardware must enforce new E-bit extended attribute mode and XWR shadow stack encodings (010=M-mode, 110=U-mode, 010+SHARED=0=S-level) gated by mseccfg.MSSE/menvcfg.SSE, with per-instruction-type and per-privilege-mode access fault generation; failure in any gate is a hardware-level privilege escape
Violation:
  In XiangShan RTL, the PMP checker module (pmp.scala / PMPChecker) and SPMP
  checker (spmp.scala / SPMPChecker) must enforce new memory access rules
  introduced by Smpmpind/Smcfiss/Smucfiss/Sspmpss. A hardware violation occurs
  when: (1) the PMP entry's E bit (pmpcfg[MXLEN-1]) is 1 and XWR encodes a
  shadow stack region (010 for M-mode Smcfiss, 110 for U-mode Smucfiss via
  PMP; 010 with SHARED=0 for Sspmpss via SPMP), but the access check logic
  does not gate on mseccfg.MSSE or menvcfg.SSE respectively, allowing shadow
  stack semantics to be enforced when the enable bits are 0; (2) the PMP/SPMP
  checker fails to distinguish between shadow stack instructions
  (sspush/sspopchk/ssload/sspop/ssrdp) and regular store/load instructions,
  causing regular stores to shadow stack regions to succeed without raising
  store/AMO access fault; (3) the privilege-mode gate in the PMP checker does
  not correctly block lower-privilege-mode accesses to M-mode shadow stack
  regions (mseccfg.MSSE=1, E=1, XWR=010) or non-U-mode accesses to U-mode
  shadow stack regions (menvcfg.SSE=1, E=1, XWR=110), enabling cross-privilege
  shadow stack corruption; (4) implicit accesses (instruction fetches, page
  table walks) to shadow stack regions are not trapped with the correct access
  fault exception, allowing code execution or PTW reads from shadow stack
  memory; (5) the SPMP checker does not raise guest-page fault for VS/VU
  accesses when XWR=010 in the matching SPMP entry, violating the two-stage
  isolation contract; (6) the mseccfg.MSSE write-ignore condition (when Smepmp
  RLB=0 and any pmpcfg.L=1) is not enforced in the CSR write path, allowing
  MSSE to be toggled after PMP lock-down; (7) the indirect CSR access path
  (Smcsrind + Smpmpind) for mireg→pmpaddr and mireg2→pmpcfg does not apply the
  same atomicity and locking semantics as direct pmpcfg/pmpaddr CSR accesses,
  creating a TOCTOU race between miselect write and mireg/mireg2 read/write.
Consequence: privilege_escape
