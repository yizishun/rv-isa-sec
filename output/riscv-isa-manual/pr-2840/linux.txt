PR #2840  target=linux  overall=compliant
Spec: Smcdeleg/Ssccfg now normatively depend on Sscsrind; the kernel must either encode this transitive dependency in its extension database or always check SSCSRIND when using siselect/sireg for delegated counter access.
Violation: Linux kernel detects Smcdeleg or Ssccfg (e.g., via ISA string or device tree) and uses siselect/sireg for indirect counter CSR access, but fails to also verify Sscsrind presence — on pre-spec-fix hardware or buggy implementations that expose Smcdeleg/Ssccfg without Sscsrind, indirect CSR access to delegated counters would fault or read garbage, since siselect/sireg behavior for non-AIA register windows is undefined without Sscsrind.
Consequence: denial_of_service
Pattern: riscv_isa_extension_available(.*SMCDELEG|.*SSCCFG)(?!.*SSCSRIND)
