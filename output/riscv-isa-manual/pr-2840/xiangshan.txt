PR #2840  target=xiangshan  overall=compliant
Spec: Smcdeleg/Ssccfg counter delegation through siselect range 0x40-0x5F depends on Sscsrind for stateen-based indirect CSR access control; XiangShan comments explicitly note Sscsrind is unimplemented, creating a hardware gap where counter delegation state may be accessible without proper mstateen0[60] CSRIND gating
Violation:
  In XiangShan RTL, the Sscsrind indirect-CSR access infrastructure
  (siselect/sireg*) is implemented for AIA interrupt-file purposes, but source
  comments in StateEnBundle.scala:20,31 explicitly state 'Smcsrind/Sscsrind is
  not implemented.' If the hardware exposes Smcdeleg/Ssccfg counter-delegation
  functionality (siselect range 0x40-0x5F mapping to hpmcounter/hpmevent
  aliases) through this same siselect/sireg* register file without properly
  implementing the Sscsrind dependency, the mstateen0[60].CSRIND state-enable
  access-control gate—which Sscsrind requires to block or allow indirect CSR
  access from lower privilege modes—is either missing or incorrectly wired.
  This means S/HS-mode software can access delegated counter state (cycle,
  instret, hpmcounters, hpmevents) through sireg* without the stateen-based
  access-control check that the Sscsrind-dependent spec mandates, and
  conversely, setting mstateen0[60]=0 may not actually block indirect counter
  access as expected.
Consequence: privilege_escape

[potential_risk] src/main/scala/xiangshan/Parameters.scala:297-298  XiangShanParameters.ISAExtensions
  The ISA string declares 'smcsrind' and 'sscsrind' as implemented extensions.
  While the Sscsrind indirect-CSR infrastructure IS partially implemented
  (siselect/sireg* for AIA interrupt-file access, with proper mstateen0[60]
  gating), the full Sscsrind framework (including support for counter-
  delegation siselect range 0x40-0x5F and indirect register expansion through
  sireg2-6) is not. Software that probes the ISA string may incorrectly assume
  full Sscsrind capability. However, this is not a security vulnerability
  because: (a) the counter-delegation range is blocked by siselect WARL, (b)
  sireg2-6 are zero stubs, and (c) the access-control stateen gates are
  functional. The risk is limited to software compatibility, not privilege
  escape.
  | "smcsrind",
  | "sscsrind",
