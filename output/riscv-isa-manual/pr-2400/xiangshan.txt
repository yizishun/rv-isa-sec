PR #2400  target=xiangshan  overall=compliant
Spec: menvcfg/henvcfg.ADUE changes require SFENCE.VMA/HFENCE.VVMA synchronization—XiangShan TLB/PTW must not cache A/D-update policy across ADUE writes, or stale cached translations will silently apply wrong A/D-bit behavior, breaking page eviction correctness and guest isolation
Violation:
  When menvcfg.ADUE or henvcfg.ADUE is written but the corresponding fence
  (SFENCE.VMA/HFENCE.GVMA/HFENCE.VVMA with rs1=x0 and rs2=x0) is not executed
  before the next address translation, the TLB or PTW-level translation caches
  in XiangShan may contain stale entries that reflect the old A/D-bit-update
  policy. Specifically: (1) if ADUE transitions 1→0, cached translations may
  still trigger hardware A/D-bit updates by the PTW instead of raising page-
  fault exceptions as required under Svade behavior; (2) if ADUE transitions
  0→1, cached translations may incorrectly raise page-fault exceptions when
  hardware should silently set A/D bits. In a hypervisor context, if
  henvcfg.ADUE is changed without executing HFENCE.VVMA, VS-stage translations
  cached under the active VMID continue using the old policy, enabling one
  guest to observe A/D-bit side effects that differ from the hypervisor's
  intended configuration. If the world-switch sequence does not place
  henvcfg.ADUE write between zeroing vsatp and writing the new vsatp,
  speculative execution can cache cross-VMID translations with inconsistent
  ADUE interpretation.
Consequence: privilege_escape
Pattern:
  menvcfg.ADUE OR henvcfg.ADUE sampled into TLB/PTW translation context
  without fence-triggered invalidation; ADUE bit propagated into page-walker
  FSM without SFENCE.VMA/HFENCE.VVMA flush path; translation cache valid bit
  not cleared on menvcfg/henvcfg ADUE write; world-switch logic reordering
  henvcfg.ADUE write relative to vsatp zero/store sequence
