PR #2400  target=xiangshan  overall=compliant
Spec: menvcfg.ADUE change without full TLB flush: stale cached A/D hardware-update decisions in TLB/PTW can cause illegal PTE writes (ADUE 1→0) or spurious page faults (ADUE 0→1), violating the Svade/Svadu hardware-software contract
Violation: When menvcfg.ADUE (or henvcfg.ADUE) is changed via CSR write, the XiangShan PTW/TLB may cache the A/D-bit-update-enable decision from the ADUE bit at the time of page walk inside TLB entries or PTW internal state. If SFENCE.VMA (or HFENCE.VVMA/HFENCE.GVMA) does not fully invalidate these cached entries, stale ADUE-dependent behavior persists: (a) ADUE 1→0 transition leaves TLB entries that still trigger hardware A/D writes to PTEs when Svade-mode should force page faults instead; (b) ADUE 0→1 transition leaves TLB entries that spuriously raise page faults when hardware should transparently set A/D bits.
Consequence: privilege_escape
Pattern: (ADUE|adue|hardware.*A.*D.*update|Svade|svade|PTW.*cache|TLB.*invalidate|SFENCE.*VMA|HFENCE.*VMA|setDirty|setAccessed|pmp_check_d_only).*(menvcfg|henvcfg).*(flush|invalidate|synchronize)

[potential_risk] /home/yzs/riscv/XiangShan/src/main/scala/xiangshan/backend/fu/NewCSR/NewCSR.scala:1480-1486  CSR→TLB envcfg forwarding (PBMTE via RegNext, no ADUE)
  Only `PBMTE` and `PMM` envcfg fields are forwarded to the TLB via `RegNext` (one-cycle delay). ADUE is neither forwarded nor has a `changed` detection signal. The PR context states that 'ADUE updates be synchronized in a fashion analogous to PBMTE.' However, PBMTE's RegNext-only synchronization is correct because PBMTE changes don't invalidate cached translations—they only affect interpretation of new PTE PBMT bits. ADUE is fundamentally different: toggling ADUE changes whether cached A/D=0 TLB entries should fault (Svade) or be silently updated (Svadu). RegNext-only would NOT suffice; a proper TLB invalidate or at minimum an `adue.changed` signal feeding the flush composition is architecturally required.
  | io.tlb.mPBMTE := RegNext(menvcfg.regOut.PBMTE.asBool)
  | io.tlb.hPBMTE := RegNext(henvcfg.regOut.PBMTE.asBool)
  | // NOTE: no ADUE forwarding exists
