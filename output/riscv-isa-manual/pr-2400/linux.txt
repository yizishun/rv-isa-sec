PR #2400  target=linux  overall=compliant
Spec: ADUE changes require TLB invalidation fences (SFENCE.VMA for menvcfg, HFENCE.VVMA/GVMA for henvcfg); kernel hot paths in vcpu_load, context switch, and suspend/resume write envcfg CSRs without corresponding fences, safe only while ADUE remains static across all runtime phases
Violation:
  Writing menvcfg or henvcfg with a modified ADUE bit without the
  architecturally required TLB invalidation fence afterward (SFENCE.VMA rs1=x0
  rs2=x0 for menvcfg; HFENCE.VVMA rs1=x0 rs2=x0 or HFENCE.GVMA rs1=x0 rs2=x0
  for henvcfg). Stale address-translation cache entries retain the prior
  A/D-bit-update interpretation, so after an ADUE 0→1 transition cached
  entries miss hardware A/D updates (lost young/dirty tracking), and after a
  1→0 transition cached entries may spuriously set A/D bits when the kernel
  expects page faults instead.
Consequence: data_corruption
Pattern:
  csr_write\(CSR_MENVCFG\)|csr_write\(CSR_HENVCFG\)|csr_set\(CSR_HENVCFG|csr_r
  ead_clear\(CSR_HENVCFG
