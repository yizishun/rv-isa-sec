PR #2400  target=freebsd-src  overall=potential_risk
Spec: FreeBSD bhyve writes henvcfg without ADUE-aware fence ordering; enabling Svadu/ADUE would cause stale TLB entries to misapply hardware A/D bit updates across guest boundaries
Violation:
  In FreeBSD's RISC-V bhyve VMM, when vmmops_run() writes henvcfg
  (vmm_riscv.c:632) with an ADUE field change during guest world-switch
  without a subsequent HFENCE.VVMA (rs1=x0, rs2=x0), stale VS-stage address-
  translation cache entries cached under the current VMID may interpret PTE
  A/D bits under the old ADUE setting. Per the spec's NOTE, ADUE should be
  switched after zeroing vsatp but before writing the new vsatp value to avoid
  needing an explicit HFENCE.VVMA. Currently FreeBSD does not set ADUE in
  henvcfg (only STCE), but the henvcfg write site has no fence and no ADUE-
  aware world-switch ordering, so any future Svadu enablement would
  immediately violate this synchronization requirement.
Consequence: data_corruption
Pattern:
  csr_write\(henvcfg,.*\)(?!.*hfence_vvma|.*csr_write\(vsatp)
------------------------------------------------------------

[potential_risk] sys/riscv/include/riscvreg.h:176-182  
  HENVCFG bit definitions are incomplete: STCE (63), PBMTE (62), CBZE (7),
  CBCFE (6), CBIE (5:4), FIOM (0) are defined. HENVCFG_ADUE (bit 61 per the
  ratified privileged spec hypervisor.adoc line 694) is not defined. Neither
  MENVCFG_ADUE nor SENVCFG_ADUE exist. This prevents any kernel code from
  referencing the ADUE field, making Svadu hardware-aware A/D update control
  impossible at the source level. While this is consistent with not enabling
  ADUE, it represents a spec-compliance gap for platforms implementing Svadu.

[not_implemented] sys/riscv/vmm/vmm_switch.S:41-204  vmm_switch
  The world-switch assembly saves/restores sstatus, hstatus, scounteren,
  sscratch, stvec (lines 73-84, 158-169) but does not save/restore henvcfg or
  senvcfg. If ADUE were per-VM state differing between guests, the world-
  switch would need to save henvcfg on guest exit and restore it on guest
  entry, with appropriate fencing (HFENCE.VVMA or the zero-vsatp interleave).
  Currently henvcfg is written once in vmmops_run() (line 632) and never
  changed per-VM. This is consistent with the current code not supporting per-
  VM ADUE, but represents missing infrastructure for any future Svadu
  enablement in bhyve.
  | ENTRY(vmm_switch)

  |     csrrw   t0, sstatus, t0
