PR #2976  target=xiangshan  overall=compliant
Spec: mscratch/mepc/mcause/mtval are now spec-mandatory M-mode CSRs; if any is missing or non-updating in XiangShan CSR RTL, M-mode trap handling collapses: MRET returns to garbage PC, trap dispatch breaks, page faults become unrecoverable, and M-mode context switching fails — functionally bricking M-mode and enabling privilege-boundary violations
Violation: In XiangShan RTL, if any of mscratch, mepc, mcause, or mtval CSR registers is not instantiated in the CSR module (CSRFile/CSRMap), or is instantiated but hardwired to zero/unimplemented without trap-side write logic (e.g., missing mcause/mepc/mtval update on exception entry, missing mscratch read/write path), the hardware fails to provide mandatory M-mode trap infrastructure. Specifically: (a) mscratch absent → M-mode handler loses context-swap capability; (b) mepc absent or not updated on trap entry → MRET returns to wrong/undefined address, breaking all trap return paths; (c) mcause absent or not updated on trap entry → M-mode handler cannot determine trap reason, making traps undispatched or misdispatched; (d) mtval absent or not updated on exception → page fault handlers lose faulting virtual address, breaking demand paging and memory management.
Consequence: privilege_escape
Pattern: (csr_map\[0x(340|341|342|343)\]|CSRs\.(mscratch|mepc|mcause|mtval)|"mscratch"|"mepc"|"mcause"|"mtval"|writeMepc|writeMcause|writeMtval|MSCRATCH|MEPC|MCAUSE|MTVAL)
