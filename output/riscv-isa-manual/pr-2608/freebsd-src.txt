PR #2608  target=freebsd-src  overall=compliant
Spec: Smstateen defines per-extension state-enable bits to prevent covert channels; FreeBSD must either context-switch all state corresponding to enabled sstateen* bits, or risk cross-thread information leakage through unswapped extension state
Violation:
  FreeBSD kernel (S-mode) sets a bit in sstateen* to grant U-mode access to
  extension state, but does not context-switch that state between user threads
  — e.g., enabling JVT (Zcmt), FCSR (Zfinx), or custom state (C bit) in
  sstateen0, then calling cpu_switch() in swtch.S without saving/restoring the
  corresponding CSR or state. Additionally, if OpenSBI (M-mode) does not set
  bit 63 of mstateen0 before booting FreeBSD, the kernel cannot access
  sstateen0 at all, and if OpenSBI fails to zero-initialize writable bits of
  sstateen* before entering S-mode, FreeBSD inherits stale enable values.
Consequence: info_leak
Pattern:
  sstateen[0-3]\s*(write|set|csrw|csrs)
