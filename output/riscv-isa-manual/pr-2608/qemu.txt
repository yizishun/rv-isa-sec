PR #2608  target=qemu  overall=compliant
Spec: Smstateen CSRs gate access to dozens of other CSRs at less-privileged levels; missing stateen bit checks in QEMU's CSR dispatch (target/riscv/csr.c) or TCG instruction translation (target/riscv/translate.c) would allow a guest VM or userspace process to read/write state that the hypervisor/OS intended to block, directly enabling cross-VM or cross-process covert channels that the extension was designed to prevent
Violation:
  QEMU CSR read/write handler for a stateen-controlled CSR (e.g., senvcfg,
  siselect, scontext, stopei, jvt, fcsr under Zfinx, srmcfg, hedelegh, or any
  sstateen*/hstateen* CSR) does not first check the corresponding bit in the
  controlling mstateen*/hstateen*/sstateen* register, allowing access to the
  controlled state even when the stateen bit is zero; or conversely, QEMU
  incorrectly implements WARL behavior on stateen CSRs by allowing writes to
  set bits that should be read-only zero (unimplemented state, reserved bits,
  or bits forced zero by a higher-privilege stateen register), causing the
  guest to believe state access is enabled when the emulated hardware should
  have rejected the write.
Consequence: info_leak
Pattern:
  csr_ops\[CSR_...\]|\.read\s*=.*stateen|\.write\s*=.*stateen|rmw_xlen.*statee
  n|RISCV_EXCP_ILLEGAL_INST.*stateen|case CSR_.*:.*return.*RISCV_EXCP_NONE
