PR #2608  target=qemu  overall=potential_risk
Spec: QEMU must enforce full stateen access-control hierarchy: check governing stateen CSR bit before every controlled-CSR access and raise illegal-instruction exception if bit is 0, with hstateen masking sstateen bits in VS-mode
Violation: QEMU implements smstateen CSRs (mstateen0-3, sstateen0-3, hstateen0-3) but fails to check the corresponding stateen bit before allowing access to a controlled CSR (e.g., senvcfg, siselect/sireg*, scontext, jvt, stopei, srmcfg). Specifically, when a guest in S-mode or U-mode accesses a CSR that is under stateen control, QEMU must raise an illegal-instruction exception if the governing stateen bit is 0, yet no check is performed in the CSR read/write handler. The hierarchical nature compounds this: mstateen0 bit 63 gates access to sstateen0/hstateen0 themselves, and hstateen0 bits mask sstateen0 bits when accessed in VS-mode — missing any link in this chain breaks the entire access-control hierarchy.
Consequence: privilege_escape
Pattern: check stateen bit before CSR access; sstateen hstateen mstateen access control illegal-instruction exception WARL ROZ masking VS-mode
