PR #2608  target=linux  overall=potential_risk
Spec: Smstateen implicit-update ambiguity (norm:smstateen_implicit_state_update) prevents kernel from safely relying on stateen traps for lazy context-switch save/restore, risking cross-process state leaks via silently-permitted implicit writes
Violation: Kernel disables user-mode access to extension state via sstateen* bits and omits explicit save/restore on context switch, expecting all access (including implicit updates) to trap, but instructions that implicitly modify controlled state may silently succeed without raising illegal-instruction per the smstateen spec's deliberate ambiguity, leaking or corrupting state across process boundaries
Consequence: info_leak
Pattern: csr_write CSR_SSTATEEN0 (or SSTATEEN1/2/3) with a zero bitmask, followed by a context-switch path (__switch_to, switch_to, cpu_switch_to) that does not explicitly save the corresponding extension state; also: lazy-FPU or lazy-vector patterns that guard state save on a trap that may never fire

[potential_risk] arch/riscv/include/asm/csr.h:233-243  SMSTATEEN0 bit definitions
  Only KVM-relevant SMSTATEEN0 bit masks are defined (AIA_IMSIC, AIA, AIA_ISEL, HSENVCFG, SSTATEEN0). Bits that control F/D/V extension access (typically in the lower bit positions per the smstateen spec) are NOT defined.
