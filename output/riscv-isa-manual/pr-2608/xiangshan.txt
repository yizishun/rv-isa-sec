PR #2608  target=xiangshan  overall=compliant
Spec: Smstateen normative rules formalize a three-level masking cascade (mstateen→hstateen→sstateen) with MSB-end mstateen-exclusive bits forever ROZ in sstateen; any hardware bypass of this cascade (missing AND-mask, stale privState.isVirtual, or writable encroachment bits in sstateen) is a hardware privilege-escape enabling lower-privilege modes to toggle state-enable bits owned by a higher privilege level.
Violation:
  In XiangShan RTL, if the sstateen0 read-out masking
  (SupervisorLevel.scala:167) incorrectly applies only fromMstateen0 without
  also applying fromHstateen0 when privState.isVirtual is true — or if the
  isVirtual signal is metastable/stale during a CSR read that spans a
  privilege transition — then a supervisor-level CSR read in VS-mode reveals
  mstateen-controlled bits that should have been AND-gated by hstateen0.
  Similarly, if any mstateen-exclusive bit allocated from the MSB end (bits
  63:32, per norm:mstateen_bit_allocation) is not forced to read-only-zero in
  the matching sstateen register (per norm:sstateen_encroachment_bits_roz),
  S-mode software can observe and potentially influence M-mode-only state
  enable controls, breaking the privilege separation guarantee that stateen
  CSRs at each level only control less-privileged access.
Consequence: privilege_escape
Pattern:
  sstateen0_regOut_masking_Mux_without_hstateen_cascade |
  sstateen_encroachment_bit_NOT_forced_ROZ |
  xstateen_WARL_write_without_mstateen_parent_mask |
  privState_isVirtual_stale_during_CSR_read |
  mstateen_bit63_writable_when_H_ext_implemented_but_forced_ROZ
