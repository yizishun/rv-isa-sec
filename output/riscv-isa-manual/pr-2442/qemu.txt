PR #2442  target=qemu  overall=compliant
Spec: Unconditional or misconditioned pointer masking on hardware *tval writes during exception delivery either corrupts fault-address visible to guest (masking when PM inapplicable) or leaks raw tagged address (not masking when PM applicable), violating the per-access applicability check required by the spec.
Violation: In QEMU TCG, when delivering an exception (e.g., page fault, misaligned access), the emulation writes the faulting address into *tval (stval/mtval). If QEMU unconditionally applies pointer masking to this address without checking whether PM is enabled for the privilege mode that was executing the faulting access, or if QEMU applies PM to addresses from instruction types not subject to pointer masking (e.g., implicit accesses), the emulation violates this spec clause in either direction: (1) masking when inapplicable leaks the fact that PM would have been disabled, corrupting the guest-visible *tval value; (2) not masking when applicable exposes raw tagged addresses that guest kernel expects to be masked, leaking tag metadata to exception handlers.
Consequence: info_leak
Pattern: riscv_cpu_do_interrupt|env->badaddr|riscv_cpu_tlb_fill|helper_raise_exception.*stval|mtval.*pm_mask|stval.*pm_mask|pointer_mask.*tval|get_physical_address.*PM
