PR #2442  target=freebsd-src  overall=compliant
Spec: FreeBSD kernel never initializes senvcfg, so if firmware left pointer masking enabled, hardware-masked stval values break VIRT_IS_VALID address checks, causing spurious SIGSEGV for userspace or kernel panic for kernel-mode faults misrouted to user map
Violation: FreeBSD kernel reads stval into frame->tf_stval (exception.S:110-111) without first ensuring senvcfg.PME=0 to disable pointer masking. If prior boot stages (M-mode firmware, UEFI, or previous kernel) left senvcfg.PME=1, the hardware applies pointer masking to the faulting address written to stval. In trap.c page_fault_handler, the masked stval is consumed raw: checked with VIRT_IS_VALID (which interprets sign-extended masked addresses as illegal), truncated to va=trunc_page(stval) for pmap lookups, and passed as si_addr to userspace signals. For kernel-mode faults at line 245, if PMM=0 zeroes upper bits of a kernel address, the masked stval falls below VM_MIN_KERNEL_ADDRESS, causing the fault to be routed to the user map instead of the kernel map.
Consequence: denial_of_service
Pattern: frame->tf_stval|csrr.*stval|CSR_STVAL|senvcfg|SENVCFG
