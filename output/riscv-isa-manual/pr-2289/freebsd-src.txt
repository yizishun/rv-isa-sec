PR #2289  target=freebsd-src  overall=compliant
Spec: Formal-model typo (RelAcqRel vs Rel|AcqRel) in PPO6/PPO7 RL definition causes herd7 verification to miss release-ordering violations for .aqrl-annotated AMOs; FreeBSD is not directly vulnerable since it uses full fence()+relaxed-store, but future adoption of .aqrl atomics for lock/unlock paths would bypass broken formal verification
Violation: When FreeBSD kernel code using .aqrl-annotated AMOs (e.g., amoswap.d.aqrl for mutex_unlock) is verified against the buggy formal memory model where RL = RelAcqRel (sequence composition), PPO6 and PPO7 fail to recognize AcqRel-only instructions as having release semantics, causing formal verification to miss broken release ordering in synchronization primitives. The FreeBSD kernel currently uses fence()+relaxed-store for release semantics, so this is latent—but if optimized to use .aqrl AMOs without correcting verification tooling, release ordering bugs would go undetected.
Consequence: info_leak
Pattern: formal verification of RISC-V release ordering using herd7/rmem with pre-fix RL = RelAcqRel definition; use of .aqrl-annotated AMOs for kernel synchronization release paths (mutex_unlock, rcu_read_unlock, sleepq_release) without correct model validation
