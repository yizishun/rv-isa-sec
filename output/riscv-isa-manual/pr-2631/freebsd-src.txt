PR #2631  target=freebsd-src  overall=compliant
Spec: FreeBSD S-mode kernel code that directly accesses hypervisor CSRs (addr[9:8]=0b10) without H-extension mediation causes unexpected illegal-instruction traps, since the kernel can't distinguish a missing H-extension from a true violation at runtime without explicit probing
Violation: FreeBSD kernel code running in S-mode directly accesses a CSR whose address has csr[9:8] == 0b10 (hypervisor-level CSR) without first checking for H-extension presence or delegating through the hypervisor interface, causing an illegal-instruction trap that the kernel does not expect or handle at that point.
Consequence: denial_of_service
Pattern: csr_[rw][w]?\(.*0x[2-3a-bA-B][0-9a-fA-F]0\)|CSR_.*H[A-Z]+.*0x[2-3][0-9a-f]0|mcounteren.*=.*0x[2-3]
