PR #2631  target=linux  overall=compliant
Spec: Hypervisor CSR address range (csr[9:8]=10) is now normatively reserved for HS-mode access; kernel S-mode paths touching these CSRs directly will unconditionally fault, requiring audit of all RISC-V CSR access wrappers to ensure hypervisor CSRs are gated behind is_hs_mode() or kvm_arch entry guards.
Violation:
  Linux kernel code running at S-mode (not HS-mode or M-mode) accesses a CSR
  with csr[9:8]=10 (hypervisor-level CSR address range), triggering an
  illegal-instruction or virtual-instruction exception per the Zicsr privilege
  encoding convention now explicitly clarified to reserve pattern '10' for
  hypervisor CSRs.
Consequence: denial_of_service
Pattern:
  csr_[read|write|read_write|set|clear|swap]\(.*\b(0x[23]|0x[67]|0x[AaEe][0-
  9a-fA-F])[0-9a-fA-F]{2}\b
