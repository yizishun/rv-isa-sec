PR #2631  target=xiangshan  overall=compliant
Spec: CSR address decoder must explicitly map csr[9:8]=2'b10 to hypervisor-minimum access privilege; default/fallthrough mapping to supervisor (01) or machine (11) causes virtualization privilege escape where S-mode code accesses hypervisor CSRs
Violation:
  The CSR privilege check logic in XiangShan's CSR access module incorrectly
  decodes csr[9:8]=10. This occurs when the hardware uses a direct numeric
  comparison (e.g., csr[9:8] mapped 1:1 to privilege level 00=U, 01=S,
  10=undefined, 11=M) without treating the 10 bit pattern as a distinct
  hypervisor privilege tier between supervisor (01) and machine (11). A Chisel
  switch/case that falls through to a default or maps 10 to supervisor level
  would cause wrong access grants.
Consequence: privilege_escape
Pattern:
  CSR privilege-level decode logic extracting csr_addr(9,8) via switch/case or
  lookup table; missing explicit case for 2'b10 (hypervisor); direct
  comparison curr_priv >= csr(9,8) without two-bit decode mapping
