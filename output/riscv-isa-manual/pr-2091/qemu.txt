PR #2091  target=qemu  overall=compliant
Spec: Zalasr load-acquire/store-release instructions require TCG to emit host acquire/release barriers and guarantee single-memory-operation atomicity; failure would break guest SMP synchronization, causing silent data corruption and race conditions in multi-hart emulated guests
Violation:
  QEMU TCG translates Zalasr load-acquire (lb.aq/aqrl, lh.aq/aqrl, lw.aq/aqrl,
  ld.aq/aqrl) or store-release (sb.rl/aqrl, sh.rl/aqrl, sw.rl/aqrl,
  sd.rl/aqrl) as plain host loads/stores without emitting the required
  acquire/release memory barriers, OR QEMU's decoder accepts RESERVED
  encodings (loads with aq=0, stores with rl=0) and executes them as valid
  operations, OR QEMU allows ld.aq/aqrl and sd.rl/aqrl on RV32 where they must
  raise illegal instruction exceptions, OR QEMU TCG fails to enforce the
  atomicity guarantee — the instruction must appear as a single memory
  operation for RVWMO purposes rather than decomposing into multiple sub-
  accesses.
Consequence: race_condition
Pattern:
  trans_*_atomic|gen_helper_atomic|tcg_gen_qemu_ld|tcg_gen_qemu_st|OPC_ATOMIC|
  decode_amo|amo_handler|RISCV_ATOMIC|atomic_load|atomic_store|tcg_mo_acquire|
  tcg_mo_release|TCG_BAR_ACQ|TCG_BAR_REL
