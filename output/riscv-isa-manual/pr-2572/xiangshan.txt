PR #2572  target=xiangshan  overall=potential_risk
Spec: Whole-register vector instructions bypass the vstart-reserved check in decode because isVArith excludes vmove and vecMem fuTypes; vstart >= evl silently passes without trap, violating the spec-mandated reserved-value enforcement
Violation: VecExceptionGen.vstartIllegal (line 280) uses `isVArith && (io.vstart =/= 0.U)` which checks only vecArith fuTypes (vecOPI ++ vecOPF). Whole-register moves (FuType.vmove, in vecMove) and whole-register loads/stores (FuType.vldu/vstu/vsegldu/vsegstu, in vecMem) are excluded from `isVArith`. Consequently, when vstart >= evl for vmv<nr>r.v, vl<nf>re<nf>.v, or vs<nf>r.v, the decode stage does not flag illegalInst. The spec requires these vstart values to be reserved (implementation-defined, SHOULD trap). For whole-register loads/stores, there is no vstart-based execution gating visible in the Vldu/Vstu datapath, so the hardware may execute the memory access with an out-of-bounds vstart rather than suppressing it or trapping. Additionally, Unprivileged.scala:67 has a TODO comment confirming the general vstart-reserved check is unimplemented.
Consequence: data_corruption
Pattern: vstartIllegal.*isVArith|isVArith.*vecArith.*excludes.*vmove.*vecMem|lsWholeInst.*not.*vstartIllegal|vmvWholeInst.*not.*vstartIllegal|Todo.*vstart.*reserved

[potential_risk] src/main/scala/xiangshan/backend/decode/VecExceptionGen.scala:280-280  VecExceptionGen.vstartIllegal
  vstartIllegal gates only on isVArith, so it raises illegalInst for arithmetic vector ops with nonzero vstart but silently passes whole-register moves (vmv<nr>r.v, FuType.vmove) and whole-register loads/stores (vl<nf>re<nf>.v, vs<nf>r.v, FuType.vldu/vstu). [potential_risk] src/main/scala/xiangshan/mem/vector/VSplit.scala:131-131  VSplit (GenFlowMask for whole-reg)

[compliant] src/main/scala/xiangshan/mem/vector/VecCommon.scala:708-719  GenFlowMask
  GenFlowMask correctly computes the element mask: maskVlStart = UIntToMask(vl, VLEN) & ~UIntToMask(start, VLEN). When start >= vl, the mask is all-zeros, preventing any element execution. This prevents data corruption for out-of-bounds vstart on whole-register instructions. The function itself is correct; the concern is that it is used as a substitute for trapping on reserved vstart values.
  | object GenFlowMask extends VLSUConstants {
  |   def apply(elementMask: UInt, start: UInt, vl: UInt, mod: Boolean): UInt = {
  |     val startMask = ~UIntToMask(start, VLEN)
  |     val vlMask = UIntToMask(vl, VLEN)
  |     val maskVlStart = vlMask & startMask
  |     if(mod) elementMask & maskVlStart
  |     else (~elementMask).asUInt & maskVlStart
  |   }
  | }
