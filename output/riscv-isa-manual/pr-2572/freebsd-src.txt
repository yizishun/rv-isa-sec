PR #2572  target=freebsd-src  overall=not_implemented
Spec: FreeBSD's vector context-switch code must clear vstart before using whole-register load/store/move instructions, as vstart >= evl is now reserved (implementation-defined) rather than the prior well-defined no-op behavior, risking silent register corruption on implementations that trap or misbehave
Violation:
  In the FreeBSD kernel, vector context-switch save/restore paths (e.g., in
  cpu_switch(), set_fpcontext(), or get_fpcontext()) that use whole-register
  load/store instructions (vl1r.v, vs1r.v, etc.) or the vmv<nr>r.v move
  instructions without first ensuring vstart < evl (where evl = NFIELDS * VLEN
  / EEW). This can occur when a vector instruction was interrupted mid-
  execution, leaving vstart non-zero, and the kernel subsequently uses whole-
  register instructions to save or restore vector state without explicitly
  clearing vstart. Under the new spec, vstart >= evl makes these instructions
  reserved (implementation-defined behavior), whereas previously the behavior
  was well-defined (no elements written).
Consequence: data_corruption
Pattern:
  vsetvli.*vstart|csrw.*vstart|csrr.*vstart|vl[1248]r|vs[1248]r|vmv[1248]r\.v|
  whole.register.*save|whole.register.*restore|vector.*context.*switch|fpu.*co
  ntext.*switch

  The FreeBSD RISC-V kernel has no vector (V ISA extension) support.
  cpu_switch() saves/restores only scalar integer registers (ra, sp, s0-s11)
  and scalar FP registers (via __fpe_state_save/__fpe_state_load). No vector
  registers (v0-v31), vstart CSR, vtype CSR, vl CSR, or vcsr are saved or
  restored. No whole-register vector instructions (vl1r.v, vs1r.v, vmv<nr>r.v)
  are used anywhere in the kernel. The vstart-vs-whole-register vulnerability
  is not present because the kernel does not implement vector context
  switching at all.
