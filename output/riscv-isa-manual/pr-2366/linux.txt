PR #2366  target=linux  overall=bug_confirmed
Spec: Kernel relying solely on Sstc extension probe without verifying menvcfg.STCE==1 may misread STIP behavior, causing lost or spurious timer interrupts and potential scheduler hang
Violation:
  Linux kernel checks for Sstc extension presence (via ISA string or DT) and
  assumes stimecmp-driven STIP semantics, but firmware has set menvcfg.STCE=0
  (or henvcfg.STCE=0 for VS-mode), causing the hardware to behave as if Sstc
  is not implemented — STIP in sip becomes execution-environment-controlled
  rather than stimecmp-reflected, yet kernel code still treats STIP as read-
  only and timer-driven.
Consequence: denial_of_service
Pattern:
  kernel code that tests Sstc extension availability
  (riscv_isa_extension_available, __riscv_isa_ext, DT property) and branches
  into stimecmp-based timer path without also reading menvcfg.STCE /
  henvcfg.STCE to confirm the enable bit is set

[bug_confirmed] arch/riscv/kernel/cpufeature.c:585-585  (extension table)
  SSTC is registered with __RISCV_ISA_EXT_DATA (no validate callback), unlike
  SVADU which has a validate callback via __RISCV_ISA_EXT_DATA_VALIDATE. No
  menvcfg.STCE check exists anywhere in the extension probe path. By contrast,
  extensions like smnpm/ssnpm declare riscv_xlinuxenvcfg_exts as subset, and
  SVADU has riscv_ext_svadu_validate. SSTC has neither, meaning the kernel
  trusts the ISA string unconditionally without verifying firmware enablement.

[potential_risk] arch/riscv/kvm/vcpu.c:551-552  kvm_riscv_vcpu_setup_config
  cfg->henvcfg |= ENVCFG_STCE is set based on the guest ISA string
  (riscv_isa_extension_available(isa, SSTC)), not on host menvcfg.STCE. If
  menvcfg.STCE=0, this write to henvcfg.STCE is a no-op (the bit is read-only
  zero), so the guest VCPU will see STCE=0 in henvcfg while its ISA string
  advertises Sstc. The guest kernel would then encounter the same
  vulnerability pattern when it tries to use stimecmp. This is a
  virtualization correctness bug: the guest ISA string and the actual henvcfg
  state are inconsistent.
