PR #2366  target=freebsd-src  overall=compliant
Spec: FreeBSD detects Sstc purely from ISA string (has_sstc) without verifying menvcfg.STCE=1; if STCE=0, S-mode stimecmp access traps (DoS) and STIP semantics silently revert to firmware-managed mode
Violation:
  In the FreeBSD kernel, when has_sstc is true (parsed from ISA string via
  FDT) but the M-mode firmware has not set menvcfg.STCE=1 (bit 63), code at
  sys/riscv/riscv/timer.c:93 and :147 directly executes
  csr_write(stimecmp,...) from S-mode, which per the spec raises an illegal-
  instruction exception when STCE=0. Additionally, the kernel interprets
  sip.STIP as reflecting the stimecmp timer signal, but when STCE=0, STIP
  reverts to 'not implemented' semantics (writable in mip, managed by
  execution environment rather than hardware comparison), breaking timer
  interrupt delivery.
Consequence: denial_of_service
Pattern:
  has_sstc.*csr_write\(stimecmp|has_sstc.*STIP|if \(has_sstc\).*stimecmp
