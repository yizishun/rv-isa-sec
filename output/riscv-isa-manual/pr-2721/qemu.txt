PR #2721  target=qemu  overall=compliant
Spec: ELEN>VLEN causes elements to span multiple vector registers; QEMU must update EMUL, evl, and scalar-access logic to use EMUL=ceil(EEW/VLEN) instead of assuming one register holds any SEW-width element, otherwise partial register reads leak stale vector state across security domains
Violation:
  QEMU's vector emulation computes EMUL = (EEW/SEW)*LMUL without clamping the
  effective element width to min(ELEN, VLEN). When ELEN > VLEN (e.g., ELEN=64,
  VLEN=32) and SEW=64 with LMUL=1, an element spans two vector registers. QEMU
  fails to model this multi-register spanning: vector load/store, reduction,
  scalar move (vmv.x.s/vmv.s.x/vfmv.f.s/vfmv.s.f), and whole-register
  instructions access only VLEN bits of a VLEN < EEW element from a single
  register, reading stale/uninitialized register bits for the upper portion or
  writing only part of the element, and incorrectly calculate evl/EMUL for
  whole-register and segment loads.
Consequence: info_leak
Pattern:
  EEW > VLEN element spanning, EMUL < EEW/VLEN, min(ELEN,VLEN) vs ELEN in
  vtype validation, vmv.x.s single-register access, vfredosum scalar EMUL=1,
  vmv<nr>r.v EEW=SEW, whole-register-load EEW not
  min(VLEN*NFIELDS,EEW_encoded)
