PR #2721  target=linux  overall=compliant
Spec: ELEN>VLEN redefines scalar move and reduction operands from single-register to register-group (EMUL=ceil(EEW/VLEN)); kernel code using these to peek/poke individual elements in ptrace/KVM/signals will corrupt state if EEW>VLEN
Violation: Kernel vector-state accessors (ptrace get/set, signal frame marshaling, KVM vreg ioctls) use vmv.x.s/vmv.s.x/vfmv.f.s/vfmv.s.f assuming a single-register operand, but when EEW > VLEN the spec now defines EMUL=ceil(EEW/VLEN) meaning the scalar spans a register group—reading/writing only the lowest-numbered register of the group silently accesses partial or wrong element data
Consequence: data_corruption
Pattern: vmv\.x\.s|vmv\.s\.x|vfmv\.f\.s|vfmv\.s\.f in arch/riscv/kernel/vector, arch/riscv/kernel/signal, arch/riscv/kvm, arch/riscv/kernel/ptrace without checking that ceil(EEW/VLEN)==1 or without accessing the full register group
