PR #2721  target=freebsd-src  overall=compliant
Spec: ELEN>VLEN relaxes single-register assumption: scalar/reduction operands now occupy ceil(EEW/VLEN)-register groups; FreeBSD's context-switch, signal, and bhyve paths save only individual registers via VLENB stride, silently corrupting cross-thread vector state.
Violation: FreeBSD kernel vector context save/restore path (cpu_switch.S signal delivery, or bhyve VMCS/VCPU state) saves/restores vector registers individually indexed by VLENB, without accounting for ELEN>VLEN register groups where EEW-wide scalars (reductions, vmv.s.x/vmv.x.s operands) span ceil(EEW/VLEN) registers. On context restore, the omitted group-member registers hold stale values from the previous thread, corrupting the new thread's vector architectural state. Additionally, bhyve's virtual vtype validation may reject legitimate LMUL settings computed against min(ELEN,VLEN) rather than ELEN alone.
Consequence: data_corruption
Pattern: vlenb[^a-zA-Z].*(?:for|while|loop).*reg|vmv\.[xs]\.s|vfmv\.[fs]\.f|vfredusum|vfredosum|whole.?register.*save|save.*vector.*ctx.*switch|vector.*save.*VLENB
