PR #2573  target=opensbi  overall=compliant
Spec: SPMP CSR writes (mpmpdeleg delegation, spmpen activation, or indirect SPMP entry configuration via miselect/mireg) are explicitly not ordered with respect to subsequent memory accesses per the Sspmp spec; missing SFENCE.VMA after such writes in M-mode firmware creates a window where stale SPMP rules apply to S/U-mode execution
Violation:
  OpenSBI M-mode code writes to SPMP CSRs (via miselect/mireg/mireg2 indirect
  access, mpmpdeleg CSR to delegate PMP entries, or spmpen CSR to
  activate/deactivate entries) to configure S-level physical memory
  protection, then returns control to S-mode or U-mode without first executing
  SFENCE.VMA with rs1=x0 and rs2=x0 to synchronize the SPMP state with
  subsequent memory accesses in less-privileged modes.
Consequence: race_condition
Pattern:
  CSR write to mpmpdeleg|spmpen|miselect (followed by mireg|mireg2) without a
  subsequent SFENCE\.VMA x0,\s*x0 before mret/sret or any control transfer to
  S/U-mode
