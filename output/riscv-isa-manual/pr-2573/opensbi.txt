PR #2573  target=opensbi  overall=compliant
Spec: Missing SFENCE.VMA after SPMP CSR writes lets S-mode observe stale SPMP state, bypassing M-mode-configured memory restrictions
Violation: OpenSBI M-mode code writes to mpmpdeleg, spmpen, or SPMP entries via indirect CSR access (miselect/mireg/mireg2), then transfers control to S-mode without first executing SFENCE.VMA with rs1=x0 and rs2=x0
Consequence: privilege_escape
Pattern: csr[wc].*mpmpdeleg|csr[wc].*miselect|csr[wc].*mireg|csr[wc].*spmpen(?!.*SFENCE\.VMA.*x0.*x0)
