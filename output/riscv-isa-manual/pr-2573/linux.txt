PR #2573  target=linux  overall=not_implemented
Spec: Non-atomic spmpen/spmpenh update on RV32 during SPMP context switch creates a window where a U-mode task can access another task's memory if an interrupt fires between the two CSR writes
Violation:
  On RV32 systems with the Sspmpen extension and more than 32 SPMP entries,
  the kernel context-switches SPMP entries by writing spmpen and spmpenh as
  separate CSR instructions without disabling supervisor interrupts
  (sstatus.SIE). An interrupt delivered between these two writes leaves the
  hart with a partially updated spmpen mask where some entries from the
  outgoing task remain active alongside entries from the incoming task,
  violating inter-task memory isolation.
Consequence: privilege_escape
Pattern:
  CSRRC.*spmpen|CSRRS.*spmpen|csrrc.*spmpen|csrrs.*spmpen|write.*spmpen[^h]
------------------------------------------------------------
[not_implemented] arch/riscv:0-0  (none)
  The Linux kernel (this tree) does not implement the RISC-V Sspmp
  (Supervisor-level Physical Memory Protection) extension. No spmpen/spmpenh
  CSR writes, SPMP entry context-switch logic, or SPMP configuration code
  exists anywhere in arch/riscv or the broader kernel. The vulnerability
  condition described in the spec — an interrupt window between spmpen and
  spmpenh writes on RV32 with >32 entries — cannot be triggered because the
  SPMP context-switch path simply does not exist.
