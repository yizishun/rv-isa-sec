PR #2573  target=freebsd-src  overall=compliant
Spec: Kernel has no SPMP awareness: boot-time Bare-mode window exposes unmanaged SPMP to deny critical memory accesses, and sstatus.SUM toggles cause unexpected Deny exceptions under U-mode SPMP rules whose hardware semantics differ from virtual-memory SUM
Violation:
  FreeBSD kernel early boot sequence (locore.S → initriscv()) executes with
  satp.MODE=Bare before MMU enablement, on hardware where M-mode firmware
  (OpenSBI) has delegated PMP entries to SPMP via mpmpdeleg CSR. During this
  window, SPMP is the active protection mechanism per the spec's exclusivity
  table (satp.MODE==Bare with Sspmp → SPMP only). The kernel accesses physical
  memory for page table construction and device probing without verifying SPMP
  entry coverage, and uses sstatus.SUM toggle (for copyin/copyout-like
  operations) whose semantics differ under SPMP: with U-mode SPMP rules and
  sstatus.SUM=0, all S-mode accesses to those regions are Deny (not just
  virtual-memory-level restrictions). The trap handler (trap.c) receives
  exception codes 12/13/15 for SPMP violations but would diagnose them as
  unexpected early-boot page faults, as the kernel has no SPMP fault
  differentiation logic (checking satp.MODE for Bare to distinguish SPMP vs
  page faults).
Consequence: denial_of_service
Pattern:
  satp write from Bare to non-Bare mode without prior siselect-based SPMP
  entry configuration; early-boot physical memory access in locore.S or
  initriscv() without verifying spmpen mask or mpmpdeleg delegation state;
  sstatus.SUM csrs/csrc in copyin/copyout macros (asm.h) without checking
  spmpcfg.U-region coverage when satp.MODE=Bare
