PR #2573  target=freebsd-src  overall=compliant
Spec: Non-atomic spmpen/spmpenh update on RV32 leaves a window where interrupt handlers see inconsistent SPMP masks, enabling cross-task memory access
Violation: On RV32 with Sspmpen enabled, if the kernel updates spmpen and spmpenh as two separate CSR writes without clearing SIE in sstatus (i.e., non-atomically with respect to interrupts), an interrupt delivered between the two writes observes a partially-updated spmpen mask, leaving SPMP in an inconsistent state where entries from both outgoing and incoming tasks are simultaneously active or OS-resident entries are momentarily disabled
Consequence: privilege_escape
Pattern: csrw.*spmpen[^h].*\n.*csrw.*spmpenh|csrc.*spmpen[^h].*\n.*csrc.*spmpenh|csrs.*spmpen[^h].*\n.*csrs.*spmpenh

[potential_risk] (entire codebase):0-0  (N/A - extension absent)
  While the codebase is currently compliant because Sspmp is not implemented, any future PR adding Sspmp support must ensure that spmpen and spmpenh (on RV32) are updated atomically with respect to interrupts. The required pattern is: (1) clear SIE in sstatus, (2) write spmpen, (3) write spmpenh if RV32, (4) restore SIE. Alternatively, use a single CSRRS/CSRRC instruction if only modifying a subset of bits, or disable SPMP entirely during the update window. FreeBSD's intr_restore()/intr_disable() provide suitable wrappers for this purpose.
