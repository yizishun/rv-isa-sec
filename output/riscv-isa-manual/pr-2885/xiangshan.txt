PR #2885  target=xiangshan  overall=compliant
Spec: Ziccamoc mandates AMOCASQ-level PMA for cacheable+coherent main memory, but XiangShan treats PMA 'atomic' and 'c' as independently configurable bits without hardware invariant enforcement, enabling a misconfigured region where cacheable memory silently degrades AMOCAS.Q to non-atomic banked writes; Zama16b MAG16 has no hardware implementation at all
Violation: A main-memory PMA region is configured with c=true (cacheable) and a=coherent but atomic=false, or a region with atomic=true allows AMOCAS.Q to proceed against DCache SRAM banks where coherency probes can tear a 16-byte CAS update between l_select and h_select bank writes without MAG16-boundary interlock
Consequence: data_corruption
Pattern: PMAConfigEntry(c = true, atomic = false) OR PMA atomic=true field not cross-validated against M_XA_CASQ MAG16 atomicity guarantee in DCache MainPipe banked writeback
