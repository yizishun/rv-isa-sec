PR #2570  target=linux  overall=potential_risk
Spec: stval receives HW-masked (sign-extended) faulting address when PM is enabled for the faulting privilege mode; kernel consumers (page fault handler, signal si_addr, ptrace) leak tag bits or operate on wrong effective address
Violation: Kernel exception handler reads stval (which HW has already applied the Pointer Masking ignore-transform to) and passes the masked address directly to do_page_fault(), sets si_addr in siginfo, or uses it for address-space validation without reversing the sign-extension that PM applied. Triggered when an exception is taken from U-mode (or VU-mode) while Ssnpm is active, or from S-mode while Smnpm is active.
Consequence: info_leak
Pattern: csr_read.*STVAL|badaddr.*fault|do_page_fault.*addr|si_addr.*stval|handle_exception.*stval
------------------------------------------------------------
[potential_risk] arch/riscv/kernel/entry.S:186-193  handle_exception
  CSR_TVAL (stval) is read directly into s3 and stored as PT_BADADDR without reversing any Pointer Masking ignore-transform that hardware may have applied. When Ssnpm is active for the faulting U-mode context, the HW zeroes the PM-masked bits in stval before writing it. For legitimate user VAs (bits[63:39]=0) this is a no-op, but if future code enables Smnpm (S-mode PM) or if a user process accesses an address with non-zero high bits, the captured badaddr is semantically incorrect.

  This erratum workaround sign-extends bit 38 of PT_BADADDR for the SiFive CIP-453 bug where instruction page faults fail to sign-extend the faulting address.
