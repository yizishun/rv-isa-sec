PR #2570  target=freebsd-src  overall=bug_confirmed
Spec: FreeBSD trap handler reads hardware-transformed stval without ZPM awareness; if Ssnpm is enabled by firmware, the kernel operates on canonicalized addresses in page-fault VM lookups and delivers wrong si_addr to user signal handlers, silently losing the original tag bits
Violation: FreeBSD reads stval directly into the trapframe (sys/riscv/riscv/exception.S:110-111) and page_fault_handler consumes tf_stval as the raw faulting effective address (sys/riscv/riscv/trap.c:228) for VIRT_IS_VALID checks, pmap_fault, vm_fault_trap, and signal si_addr delivery. Per norm:pm_csr_hw_apply, if Ssnpm is enabled for U-mode (or Smnpm for S-mode), the hardware has already applied the ignore transformation—sign-extending or zero-extending the upper PMLEN bits—before writing stval. The kernel's page-fault path, signal delivery, and fatal-panic messages all operate on the canonicalized address, breaking the invariant that stval equals the instruction's original effective address. The kernel has no CSR_SENVCFG definition and no PM-awareness whatsoever.
Consequence: info_leak
Pattern: csrr\s+\w+,\s*stval|tf_stval|frame->tf_stval|VIRT_IS_VALID\s*\(\s*stval|call_trapsignal\s*\([^,]+,[^,]+,[^,]+,\s*\(void\s*\*\)\s*stval|page_fault_handler
