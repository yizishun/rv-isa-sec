PR #2606  target=freebsd-src  overall=potential_risk
Spec: siselect/sireg* and vsiselect/vsireg* CSR state not saved/restored on context switch or VM entry/exit, leaking indirect CSR window configuration between threads and across VM boundaries
Violation: FreeBSD's RISC-V context switch (cpu_switch in swtch.S:258) and bhyve VCPU switch (vmmops_vcpu_save_csrs/vmmops_vcpu_restore_csrs in vmm_riscv.c:161-195) save/restore neither siselect/sireg* nor vsiselect/vsireg* across thread or VM boundaries. If Smcsrind/Sscsrind is implemented in hardware, a thread or guest VM that writes to siselect/vsiselect can have its indirect CSR window state silently inherited by the next scheduled thread or VM, which then reads/writes a different CSR than intended via sireg*/vsireg* because the select register was not sanitized on context switch. Additionally, the hypcsr struct (riscv.h:56-68) has no fields for vsiselect/vsireg*, so bhyve cannot virtualize this extension at all, leaving guest accesses to these CSRs with UNSPECIFIED behavior per the spec.
Consequence: info_leak
Pattern: struct pcb(?!.*siselect)(?!.*sireg)|struct hypcsr(?!.*vsiselect)(?!.*vsireg)|cpu_switch(?!.*siselect)|vmmops_vcpu_(save|restore)_csrs(?!.*vsiselect)
