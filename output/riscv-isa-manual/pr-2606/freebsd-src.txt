PR #2606  target=freebsd-src  overall=not_implemented
Spec: siselect/sireg* indirect CSR window is inherently TOCTOU-prone: a preemptible kernel path or missing context-switch save/restore of the selector register leaks CSR state between processes or VMs on the same hart
Violation:
  FreeBSD kernel code on RISC-V accesses sireg* (or vsireg*) without first
  saving/restoring the corresponding siselect (or vsiselect) across context
  switches, or performs a non-atomic siselect-write + sireg-read sequence on a
  preemptible kernel path. Because siselect and sireg* form an indirect
  register window, a context switch or interrupt handler that modifies
  siselect between the two operations causes the kernel to read CSR state
  selected by a different execution context, violating the spec's implicit
  atomicity expectation for the select+access pair.
Consequence: info_leak
Pattern:
  csr_write[^;]*siselect[^;]*;[^;]*csr_read[^;]*sireg|csr_write[^;]*vsiselect[
  ^;]*;[^;]*csr_read[^;]*vsireg

[not_implemented] sys/riscv/riscv/swtch.S:258-358  cpu_switch
  The context switch routine does not save or restore siselect or any sireg*
  CSRs, because the Sscsrind extension is not currently supported. If this
  extension were implemented without corresponding context-switch support, a
  context switch between the siselect write and sireg read would cause CSR
  state to be read from the wrong execution context (info leak).
  | cpu_switch:
  |   sd a1, PC_CURTHREAD(tp)
  |   ld x13, TD_PCB(a1)
  |   sd x13, PC_CURPCB(tp)
  |   ld x13, TD_PCB(a0)
  |   sd ra, (PCB_RA)(x13)
  |   ... // no siselect/sireg save/restore
