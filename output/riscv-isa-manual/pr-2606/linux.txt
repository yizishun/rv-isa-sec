PR #2606  target=linux  overall=potential_risk
Spec: siselect/sireg* are not saved/restored on context switch: any extension using Sscsrind leaks register state across task boundaries via residual siselect window selection
Violation:
  Linux kernel context-switches between tasks while Sscsrind is active (any
  extension using siselect/sireg* indirect CSR access is present), without
  saving and restoring siselect or sireg* in __switch_to or the entry.S trap
  context-save path. Task A sets siselect to select a specific indirect
  register window; preemption occurs; task B reads sireg* and observes the
  register state selected by task A's residual siselect value. Currently
  arch/riscv/kernel/entry.S and arch/riscv/kernel/process.c __switch_to save
  sstatus/sepc/stvec/sscratch but never touch siselect (CSR 0x150) or sireg*
  (CSR 0x151-0x157).
Consequence: info_leak
Pattern:
  context switch save/restore list missing siselect or sireg; switch_to
  without siselect save; grep for CSR_SISELECT or CSR_SIREG in
  arch/riscv/kernel/entry.S and arch/riscv/kernel/process.c returning no hits
  versus their definitions in arch/riscv/include/asm/csr.h at 0x150-0x157;
  indirect CSR window selector not in thread_struct
------------------------------------------------------------
[potential_risk] arch/riscv/kernel/entry.S:421-471  __switch_to
  __switch_to saves/restores callee-saved GPRs (ra, sp, s0-s11) and the SUM
  bit from sstatus, but never saves or restores siselect (CSR 0x150) or any
  sireg* CSR (0x151-0x157). If the hart implements Sscsrind, these CSRs exist
  as architectural supervisor state. Any siselect value set before a context
  switch persists into the next task, allowing task B to observe indirect
  register state through the window selected by task A's residual siselect
  value. Similarly, sireg2-sireg6 (0x152-0x153, 0x155-0x157) are entirely
  absent from the kernel's CSR definitions in csr.h, which only defines
  CSR_SIREG (0x151) but not CSR_SIREG2 through CSR_SIREG6.
  | SYM_FUNC_START(__switch_to)

  | 	add   a3, a0, a4
  | 	add   a4, a1, a4

  | 	[... no siselect/sireg save/restore ...]
  | 	REG_L s11, TASK_THREAD_S11_RA(a4)

[potential_risk] arch/riscv/include/asm/csr.h:347-349  (CSR definitions)
  Only CSR_SISELECT (0x150) and CSR_SIREG (0x151) are defined. The spec
  defines seven supervisor-level CSRs for Sscsrind: siselect (0x150), sireg
  (0x151), sireg2 (0x152), sireg3 (0x153), sireg4 (0x155), sireg5 (0x156),
  sireg6 (0x157). CSR_SIREG2, CSR_SIREG3, CSR_SIREG4, CSR_SIREG5, CSR_SIREG6
  are missing. Note that 0x154 is already used for CSR_SIPH (AIA), and
  sireg4-sireg6 (0x155-0x157) similarly have no definitions. Any future kernel
  code that needs to access these registers will need the definitions added.
  | /* Supervisor-Level Window to Indirectly Accessed Registers (AIA) */
  | #define CSR_SISELECT		0x150
  | #define CSR_SIREG		0x151

[not_implemented] arch/riscv/kernel/cpufeature.c:580-584  (ISA extension table)
  The kernel's ISA extension table does not include Sscsrind, Ssccfg,
  Smcdeleg, Smctr, or Ssctr. None of the extensions that depend on the
  Sscsrind indirect CSR access mechanism are detected or advertised. This
  means the kernel is unaware of whether the hardware implements Sscsrind and
  treats siselect/sireg* CSRs as non-existent. This is the root cause of the
  missing context-switch handling: the kernel cannot conditionally
  save/restore CSRs for an extension it doesn't know exists.
  | __RISCV_ISA_EXT_SUPERSET(smnpm, RISCV_ISA_EXT_SMNPM, riscv_xlinuxenvcfg_exts),
  | __RISCV_ISA_EXT_SUPERSET(ssnpm, RISCV_ISA_EXT_SSNPM, riscv_xlinuxenvcfg_exts),
  References:
