PR #2606  target=linux  overall=potential_risk
Spec: Sscsrind CSR window (siselect/sireg/vsiselect/vsireg) access from HS/S-mode requires mstateen0[60]=1; kernel currently assumes firmware enables this but has no runtime check, risking illegal-instruction panic on non-conformant firmware
Violation: In the Linux kernel, when Sscsrind is implemented and M-mode firmware leaves mstateen0[60]=0, any KVM host access to vsiselect/vsireg* (or S-mode kernel access to siselect/sireg*) from HS-mode triggers an illegal-instruction exception, crashing the kernel because the trap handler won't expect an illegal-instruction fault on these CSRs in host context.
Consequence: denial_of_service
Pattern: csr_write\(CSR_VSISELECT|csr_read\(CSR_VSIREG|csr_write\(CSR_SISELECT|csr_read\(CSR_SIREG
