PR #2598  target=xiangshan  overall=compliant
Spec: Ziccid mandates I-cache coherence with D-cache (stores eventually visible to all harts' I-fetches without FENCE.I) and in-order instruction fetch insertion into the instruction buffer; XiangShan's separate I$/D$ without snoop and speculative frontend fetch violate both, enabling stale/different instruction execution across harts even after stores complete globally
Violation:
  In XiangShan RTL, when the L1 I-cache is not kept coherent with the L1
  D-cache (no snoop/invalidate mechanism from D-cache stores to I-cache),
  stores to instruction memory by any hart never become visible to that hart's
  or other harts' instruction fetches without an explicit FENCE.I.
  Additionally, if the frontend's fetch buffer/instruction queue is populated
  by speculative fetch down a branch-predicted path (out of program order),
  instruction fetches no longer appear in program order in the global memory
  order — a younger (in program order) fetch may observe a store that an older
  fetch did not, because the older fetch was issued earlier (out of order) and
  missed the store. Finally, if FENCE.I does not drain the store buffer to
  global visibility before flushing the pipeline's instruction buffer, a store
  from the local hart may not be visible to subsequent instruction fetches
  even after FENCE.I completes.
Consequence: privilege_escape
Pattern:
