PR #2598  target=linux  overall=compliant
Spec: Ziccid scopes instruction-fetch coherence guarantees to cacheable+coherent PMAs only; kernel must not optimize away FENCE.I synchronization based on Ziccid eventuality without verifying PMA attributes, or non-coherent regions will silently execute stale instructions
Violation: Linux kernel code writes to instruction memory in a region that lacks both cacheability and coherence PMAs, then relies on Ziccid's eventuality guarantee (stores eventually visible to all harts' instruction fetches without explicit FENCE.I) to execute the modified code on a remote hart. The spec scopes Ziccid exclusively to cacheable+coherent PMA regions; non-coherent/uncacheable regions proceed as if Ziccid were not implemented, where stores may never become instruction-visible without FENCE.I.
Consequence: data_corruption
Pattern: flush_icache_all|flush_icache_mm|flush_icache_range|local_flush_icache_all|fence\.i|__patch_insn_write|patch_text|sbi_remote_fence_i
