PR #2996  target=linux  overall=compliant
Spec: WRS interrupt-wakeup criterion tightened from 'any pending interrupt even if disabled' to 'locally enabled pending interrupt regardless of global IE' (matching WFI); kernel __cmpwait() depends on reservation-break not interrupt-wakeup, but KVM emulation and future WRS uses must align with the clarified per-*ie-bit semantics.
Violation: Kernel executes wrs.nto/wrs.sto in __cmpwait() or any WRS-based wait while all sie bits are cleared and no other hart will break the reservation set (e.g., UP context or lock-holder preempted), causing indefinite stall because disabled-in-sie interrupts no longer qualify as wakeup sources under the clarified spec.
Consequence: denial_of_service
Pattern: wrs\.nto|wrs\.sto|ZAWRS_WRS_NTO|ZAWRS_WRS_STO in code paths where sie CSR may have zero relevant enables (e.g., local_irq_disable combined with sie clearing, or preempt_disable nested inside __cmpwait when no reservation-break expected).
