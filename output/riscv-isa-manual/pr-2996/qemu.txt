PR #2996  target=qemu  overall=bug_confirmed
Spec: WRS emulation never stalls, unconditionally resuming execution without the locally-enabled-interrupt gate that WFI correctly implements via riscv_cpu_has_work()
Violation: QEMU TCG unconditionally exits the TB on WRS.NTO/WRS.STO without entering a halted state or checking interrupt pending status. Unlike WFI (which sets halted=1 and gates resume on riscv_cpu_has_work() checking locally-enabled interrupts via mie/sie/vsie masks), WRS clears the load reservation and immediately falls back to the main loop. The spec requires WRS to stall 'as long as no locally enabled interrupts at any privilege level are pending' — QEMU never stalls at all, treating 'permitted to occasionally terminate' as justification for always skipping the stall.
Consequence: race_condition
Pattern: tcg_gen_exit_tb after WRS translation without prior halt or interrupt-mask check; WRS path missing cpu->halted=1 / EXCP_HLT / riscv_cpu_has_work gating that WFI uses
------------------------------------------------------------
[bug_confirmed] target/riscv/insn_trans/trans_rvzawrs.c.inc:19-41  trans_wrs_sto
  WRS.STO unconditionally exits the TB via tcg_gen_exit_tb(NULL, 0) without entering halted state. Unlike WFI which sets cpu->halted=1 and resumes only via riscv_cpu_has_work() checking (mip & mie) | sirq_pending | vsirq_pending, WRS returns to the main loop which immediately re-enters execution with no stall. The RISC-V Zawrs spec requires WRS to stall 'while there is no pending interrupt that is not inhibited by a relevant interrupt-enable bit'. The 'permitted to occasionally terminate' clause is a safety valve for imprecise interrupts, not justification to always skip the stall. This effectively makes WRS.STO a NOP (plus clearing load reservation), violating the intended idle-loop semantics.
