PR #1301  target=linux  overall=potential_risk
Spec: Spec now explicitly guarantees that accessing a vacant physical address region raises an access-fault exception; the kernel implicitly relies on this for safe probing (get_kernel_nofault), /dev/mem isolation, and KVM stage-2 fault injection — a non-conforming hardware implementation that silently returns data from vacant regions would leak bus-state or uninitialized data to kernel and userspace
Violation: In the Linux kernel, when code accesses a physical address that falls within a vacant region (e.g., via ioremap probing, /dev/mem read, early-boot memory detection in head.S, KVM guest physical address walk, or get_kernel_nofault-style safe probing), and the hardware implementation silently succeeds (returns garbage/undefined data) instead of raising an access-fault exception as the spec now mandates
Consequence: info_leak
Pattern: ioremap|memremap|devmem|read_phys|__va.*phys|pfn_valid|kvm_riscv.*gstage|handle_page_fault|do_page_fault|EXC_LOAD_PAGE_FAULT
------------------------------------------------------------

[potential_risk] arch/riscv/include/asm/page.h:145-180  __va
  __va() is a pure arithmetic conversion: it adds kernel_map.va_pa_offset to the physical address with zero bounds checking. The computed virtual address may fall within the linear mapping range even for physical addresses that have no corresponding page table entry (no memblock region). [compliant] arch/riscv/mm/fault.c:278-443  handle_page_fault
  The RISC-V page fault handler does not contain explicit pfn_valid() checks for vacant physical regions, but this is architecturally correct: page faults triggered by accessing unmapped virtual addresses are handled by the VMA lookup path (lock_mm_and_find_vma/lock_vma_under_rcu). If there's no VMA covering the faulting address, bad_area_nosemaphore() → no_context() → die_kernel_fault() kills the task for kernel faults, or delivers SIGSEGV for user faults. The kernel-mode fixup mechanism (fixup_exception) also provides a safety net for safe probing patterns like copy_from_kernel_nofault. The protection is at the virtual-address layer, not the physical-address layer.

  | if (unlikely(!vma)) {
  |   tsk->thread.bad_cause = cause;
  |   bad_area_nosemaphore(regs, code, addr);  // → no_context() for kernel faults
  |   return;
  | }
