PR #1301  target=qemu  overall=compliant
Spec: Spec now mandates access-fault on vacant region access; QEMU must ensure unmapped address-space reads/writes/fetches always invoke do_transaction_failed rather than silently returning 0 or dropping the write, otherwise guest fault-isolation assumptions break and silent data corruption / info leaks occur
Violation: QEMU TCG or the RISC-V memory subsystem returns MEMTX_OK (silently returning zero or dropping the write) for guest accesses that land in unmapped/unassigned address regions, instead of invoking riscv_cpu_do_transaction_failed to deliver an access-fault exception
Consequence: info_leak
Pattern: unassigned_mem_read|unassigned_mem_write|unassigned_io_{read,write} that returns without raising access-fault; memory_region_init_io without a backing read/write handler that properly faults; address_space_rw returning success for unmapped ranges on RISC-V targets; TCG helper that elides trap generation for decode-error responses on instruction fetch to vacant regions
