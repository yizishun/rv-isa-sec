PR #2712  target=xiangshan  overall=compliant
Spec: LR_SC_ALIGNMENT and LR_RESERVATION_SET_SIZE newly marked impl-def: XiangShan LSU must ensure misaligned LR sets reservation atomically across all accessed bytes, and reservation set size in hardware matches software-visible behavior, or else SC may spuriously succeed causing lock corruption in multi-hart scenarios
Violation: When XiangShan LSU executes a misaligned LR.W/LR.D instruction (address not naturally aligned to 4/8 bytes), the hardware silently splits the access into two aligned sub-accesses where only the first sub-access sets the reservation register but the second sub-access does not participate in the reservation. If a matching SC then checks only the reservation valid bit (set by the first half) without verifying both halves are within the same reservation granule, the SC succeeds despite the second half being potentially modified by another hart, violating LR/SC atomicity semantics. Additionally, if the reservation set size register in the LSU tracks reservation at cache-line granularity but the spec's newly explicit impl-def behavior allows the reservation to span a different granularity than what software running on XiangShan expects, mismatched assumption leads to spurious SC success or failure.
Consequence: data_corruption
Pattern: misaligned.*(lr|sc|load.reserved|store.conditional)|reservation.*(split|merge|combine)|reservation_set.*(size|granul)|lsu.*misalign.*atomic|AddrMisalign.*(LR|SC)
