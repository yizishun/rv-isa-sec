PR #1613  target=xiangshan  overall=compliant
Spec: vtype illegal-configuration checker uses ELEN-based (old spec SEW_MIN/ELEN) instead of VLEN-based (new spec SEW_MIN/VLEN) constraint for e8mf8, causing valid vsetvl instructions to trap illegally or invalid configs to pass on VLEN>=64,ELEN=32 implementations
Violation: In XiangShan RTL, when VLEN>=64 and ELEN=32, the vtype CSR checker in the vector instruction decode stage incorrectly rejects vlmul=101 (e8mf8, LMUL=1/8) as an illegal vtype configuration, or conversely, the checker allows e8mf8 for VLEN=ELEN=32 where it remains illegal because only 4 bits of storage would be available in a fractional vector register.
Consequence: function_loss
Pattern: vlmul.*101.*illegal|LMUL.*1/8.*check|e8mf8.*valid|SEW_MIN.*VLEN|SEW_MIN.*ELEN|vtypeCheck|VType.*illegal|VlmulReg
