PR #1613  target=qemu  overall=bug_confirmed
Spec: QEMU validates fractional LMUL against ELEN instead of VLEN per updated spec, incorrectly rejecting e8mf8 when ELEN=32,VLEN≥64
Violation: QEMU's vsetvl/vsetvli/vsetivli handler in vector_helper.c uses cpu->cfg.elen for fractional LMUL validation (elen >> (8 - vlmul) >= sew), but the spec now defines the minimum LMUL constraint as LMUL ≥ SEW_MIN/VLEN. When ELEN=32 and VLEN≥64, QEMU incorrectly rejects e8mf8 (vlmul=5, sew=8 → 32>>3=4 < 8 sets vill=1), while the VLEN-based check (64>>3=8 ≥ 8) would permit it. Conversely, if VLEN < ELEN were ever modeled, the elen-based check could accept configurations that violate the VLEN-based floor.
Consequence: denial_of_service
Pattern: cpu->cfg.elen >> (8 - vlmul)
------------------------------------------------------------
[bug_confirmed] target/riscv/vector_helper.c:75-86  vext_set_vl
  Fractional LMUL validation uses cpu->cfg.elen instead of VLEN. For vlmul=5 (mf8, sew=8), QEMU computes elen>>(8-5)=elen>>3. When ELEN=32 this yields 4 < sew(8), incorrectly setting vill=1 and denying a valid e8mf8 configuration per the updated spec. The fix is to replace cpu->cfg.elen with (cpu->cfg.vlenb << 3) so the constraint LMUL ≥ SEW_MIN/VLEN is correctly enforced.

  |          */

  |             (cpu->cfg.elen >> (8 - vlmul)) < sew) {
  |             vill = true;
  |         }
