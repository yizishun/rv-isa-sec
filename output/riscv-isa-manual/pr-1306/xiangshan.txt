PR #1306  target=xiangshan  overall=not_implemented
Spec: vghsh.vs/vgmul.vs reserve vd-vs2 overlap as illegal encoding; XiangShan RTL must trap on this overlap or GCM authentication tags are silently corrupted when software inadvertently aliases partial-hash output (vd) with Hash Subkey scalar element group (vs2)
Violation:
  In XiangShan RTL, when Zvkgs is implemented and the vector execution unit
  processes vghsh.vs or vgmul.vs instructions, if the decoder/dispatch logic
  does not check and trap on the reserved encoding where the vd register group
  overlaps the vs2 scalar element group (holding the Hash Subkey H), the
  hardware will write partial-hash results back to vd, corrupting the Hash
  Subkey in vs2 before subsequent element-group iterations can reload it. The
  Sail pseudocode loads Hinit = brev8(get_velem(vs2, EGW=128, helem)) and re-
  initializes H from Hinit per element group because the inner GF(2^128)
  multiplication loop destroys H; if vd overlaps vs2, the set_velem(vd, ...)
  at the end of each element-group iteration overwrites the Hinit source in-
  flight, causing subsequent element groups to use a corrupted hash subkey and
  producing silently wrong GCM/GMAC authentication tags.
Consequence: data_corruption
Pattern:
  vghsh\.vs|vgmul\.vs.*vd.*vs2.*overlap|reserved.*encoding.*vd.*overlap.*vs2|c
  heckRegisterOverlap.*vd.*vs2|illegal_inst.*vgmul.*vs|illegal_inst.*vghsh.*vs
