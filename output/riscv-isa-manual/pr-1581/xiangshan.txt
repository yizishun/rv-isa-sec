PR #1581  target=xiangshan  overall=compliant
Spec: CSRRS/CSRRC read-modify-write on pmpaddr spuriously clears 'reads as' G-bits when modifying unrelated writable bits, because the read path returns architecturally-masked values instead of underlying physical register state, corrupting PMP region boundaries
Violation: When CSRRS or CSRRC executes on a pmpaddr CSR, the CSR read path returns the architecturally-masked value (e.g., pmpaddr[G-1]=0 when underlying physical bit is 1). The read-modify-write datapath uses this masked read value as the base for bit-set/bit-clear, then writes back, inadvertently clearing the underlying G-bit because 0 was read and written back instead of the physical 1.
Consequence: privilege_escape
Pattern: CSR read-modify-write datapath that sources read data from the architecturally-masked read port (i.e., after applying "reads as" bit masking) rather than the raw physical register state for bits that read-as-zero/write-legal but hold nonzero underlying values; specifically grep for pmpaddr read mux logic combined with CSRRC/CSRRS writeback in Chisel CSR module
