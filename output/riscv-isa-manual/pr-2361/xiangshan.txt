PR #2361  target=xiangshan  overall=compliant
Spec: XiangShan has zero CTR implementation currently (no ctrtarget/ctrsource CSR, no CTR recording logic); futher implementation must ensure not-taken branch ctrtarget records sequential fall-through PC, not the architectural branch target — recording the wrong destination would corrupt control-flow trace integrity.
Violation: If XiangShan implements CTR and a not-taken conditional branch instruction retires, ctrtarget must be written with the PC of the next sequential instruction (branch_PC + 4 or branch_PC + 2 for compressed), NOT the branch's architectural target address. A hardware bug where the branch target (computed by the branch unit) is incorrectly latched into ctrtarget instead of the fall-through PC for a not-taken branch would violate this spec.
Consequence: info_leak
Pattern: ctrtarget.*not.taken|ctrtarget.*fall.through|ctrtarget.*branch.*mispred|ctrtarget_write_en|when.*!taken.*ctrtarget|ctr_record.*taken
