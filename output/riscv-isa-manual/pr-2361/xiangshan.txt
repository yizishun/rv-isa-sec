PR #2361  target=xiangshan  overall=not_implemented
Spec: Clarification that ctrtarget must hold sequential PC (PC+ilen) for not-taken branches; hardware CTR recorder must compute next-PC from retired instruction size, not reuse branch predictor's predicted target, especially on mispredicted-conditional branches where predictor state differs from architectural execution path
Violation:
  In XiangShan RTL, when the CTR recording logic (likely in the commit/retire
  stage) records a not-taken conditional branch (ctrctl.NTBREN=1), if
  ctrtarget is assigned from the branch predictor's computed target address
  (e.g., ftq_pc or predicted target from FTQ/TAGE) instead of the actual next
  sequential PC (current PC + ilen where ilen is 2 or 4 based on RVC), the
  implementation violates the clarified spec. This is most likely to occur
  when a conditional branch is mispredicted as taken: the frontend predicted a
  target, but the branch resolved as not-taken, and the CTR recording logic
  incorrectly latches the predicted target rather than computing PC+ilen from
  the actual retired instruction.
Consequence: info_leak
Pattern:
  ctrtarget\s*:?=.*(?:predictedTarget|ftq_pc|pred_tgt|branchTarget|btbTarget)|
  when\(.*notTaken.*\).*ctrtarget|WireInit.*ctrtarget.*io.*pred
