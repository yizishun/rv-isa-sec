PR #2600  target=xiangshan  overall=compliant
Spec: PR #2600 renames CSR mcounterinhibit→mcountinhibit and reclassifies trap cause 13 from Reserved to Counter-overflow interrupt; XiangShan RTL CSR decoder and trap dispatch must match new encodings or counter-overflow interrupts are silently dropped
Violation:
  In XiangShan RTL, the CSR address decoder maps the mcountinhibit CSR
  (address 0x320) using the old name mcounterinhibit, and the trap dispatch
  logic treats interrupt cause code 13 as 'Reserved' instead of routing it as
  a counter-overflow interrupt. Specifically: (1) if the Chisel CSR mapping
  uses the pre-rename string "mcounterinhibit" instead of "mcountinhibit", the
  CSR address decode will still function but CSR-level access from software
  using the new spec name will silently fail or hit a different CSR; (2) if
  the interrupt controller/trap handler in the CSR module hardcodes cause 13
  as reserved (raising an illegal instruction or ignoring it), then when the
  Sscofpmf extension triggers a counter-overflow interrupt (cause=13), the
  hart will either enter an undefined trap state or fail to deliver the
  interrupt, causing silent loss of the counter-overflow event
Consequence: denial_of_service
Pattern:
  (mcounterinhibit|mcountinhibit|CounterOverflow|cause.*13|0x320|CSR.*0x320|in
  terrupt_cause.*13|mcause_exccode.*13)
