PR #2502  target=opensbi  overall=compliant
Spec: OpenSBI's WFI calls are in M-mode (immune to TW), but any mstatus save/restore path that inadvertently corrupts mstatus.TW would break S-mode WFI semantics, causing spurious illegal-instruction traps when S-mode issues WFI with TW=1
Violation: OpenSBI HSM context save/restore in sbi_hsm.c clobbers mstatus.TW without preservation (e.g., reads mstatus, modifies an unrelated field, writes back without masking, accidentally clearing or setting TW). This corrupts the TW state visible to S-mode after mret.
Consequence: denial_of_service
Pattern: csr_write(CSR_MSTATUS, ...) without prior csr_read(CSR_MSTATUS) that masks MSTATUS_TW, OR direct MSTATUS_TW clear/set in save/restore without corresponding read-modify-write
