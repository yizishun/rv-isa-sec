PR #2501  target=linux  overall=potential_risk
Spec: menvcfg→senvcfg→henvcfg CBIE override chain: higher privilege mode can silently downgrade CBO.INVAL from invalidate to flush; kernel must not assume senvcfg write grants the semantic it requested
Violation: Linux kernel (S-mode) configures senvcfg.CBIE=11 to grant U-mode or self CBO.INVAL invalidate semantics, but M-mode firmware has menvcfg.CBIE=01, forcing flush-only behavior. Kernel code then executes CBO.INVAL expecting cache-line invalidation (dirty lines silently dropped), but hardware performs only a flush (dirty lines written back and remain valid), leaving kernel data structures with stale cache lines that were supposed to be discarded.
Consequence: data_corruption
Pattern: csr_write.*senvcfg.*CBIE|riscv_cbo_inval|CBO.INVAL.*senvcfg|__riscv_cbo_inval|KVM.*senvcfg.*save|KVM.*senvcfg.*restore
------------------------------------------------------------
