PR #1879  target=linux  overall=compliant
Spec: Smepmp MML=1 makes pmpcfg.L=0 regions S/U-mode-only (denied to M-mode); kernel SBI calls that pass S/U virtual addresses to M-mode firmware can fault if firmware hasn't mapped those addresses via M-mode-only or shared PMP regions
Violation:
  Linux kernel (S-mode) code or KVM assumes M-mode always has full access to
  S/U-mode memory, then calls into M-mode firmware (OpenSBI) via ECALL. Under
  Smepmp with MML=1 and MMAP=1, M-mode firmware is denied access to S/U-mode-
  only PMP regions, causing unexpected access-fault exceptions in firmware
  trap handlers that read/write S/U-mode pages (e.g., IPI, TLB shootdown,
  remote FENCE.I).
Consequence: denial_of_service
Pattern:
  sbi_ecall|sbi_hsm|sbi_ipi|sbi_remote_fence|__sbi_.*tlb|thead.*sbi
