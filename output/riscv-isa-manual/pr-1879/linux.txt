PR #1879  target=linux  overall=compliant
Spec: Smepmp MML/MMAP/RLB bits now explicitly reset to 0 (disabled); kernel/firmware must not rely on reading these sticky bits for feature discovery before they have been provisioned, otherwise M-mode memory access and execution prevention protections are silently absent, nullifying SMEP/SMAP-equivalent hardening for Machine mode.
Violation: Linux kernel (or firmware acting on its behalf, e.g., OpenSBI) reads mseccfg.MMAP or mseccfg.MML to detect Smepmp presence without first having those sticky bits explicitly set by boot ROM or early firmware, causing the kernel to operate under the assumption that Smepmp M-mode memory access/execution prevention is active when in fact the bits reset to 0 and Smepmp is disabled.
Consequence: privilege_escape
Pattern: mseccfg.*MML|mseccfg.*MMAP|mseccfg.*MMWP|CSR_MSECCFG|0x747|0x757
------------------------------------------------------------
[compliant] arch/riscv/include/asm/csr.h:429-430  (header definitions)
  CSR_MSECCFG (0x747) and CSR_MSECCFGH (0x757) are defined but never referenced by any code in the entire kernel tree. No Smepmp detection logic exists, so no violation of the security spec is possible.
  | #define CSR_MSECCFG		0x747
  | #define CSR_MSECCFGH		0x757

[compliant] arch/riscv/include/asm/csr.h:245-249  (header definitions)
  MSECCFG_PMM* macros are defined as aliases for ENVCFG_PMM* (pointer masking, not Smepmp). No MML, MMAP, or MMWP bit definitions exist. These mseccfg aliases are themselves never used by any kernel code.
  | /* mseccfg bits */
  | #define MSECCFG_PMM			ENVCFG_PMM
  | #define MSECCFG_PMM_PMLEN_0		ENVCFG_PMM_PMLEN_0
  | #define MSECCFG_PMM_PMLEN_7		ENVCFG_PMM_PMLEN_7
  | #define MSECCFG_PMM_PMLEN_16		ENVCFG_PMM_PMLEN_16

[potential_risk] arch/riscv/include/asm/csr.h:245-249  (header definitions)
  The MSECCFG_PMM* aliases and CSR_MSECCFG definitions exist in the header but the kernel has zero code that reads/writes the mseccfg CSR. If Smepmp re-integration proceeds and adds mseccfg CSR reads, the vulnerability pattern (reading mseccfg.MMAP/MML to detect Smepmp without firmware having set those sticky bits) must be avoided. The mseccfg.MMAP/MML bits reset to 0 on power-on and are sticky — software must never read them as a Smepmp presence test unless boot ROM/early firmware has explicitly set them.
  | /* mseccfg bits */
  | #define MSECCFG_PMM			ENVCFG_PMM
  | ...
  | #define CSR_MSECCFG		0x747
  | #define CSR_MSECCFGH		0x757
