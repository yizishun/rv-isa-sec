PR #2707  target=linux  overall=compliant
Spec: Newly formalized WARL rules for hypervisor delegation, interrupt, and trap-vector CSRs mean the kernel must read-back after CSR writes to verify accepted values; failing to do so risks silent misconfiguration of trap delegation (hedeleg/hideleg) causing guest exceptions to route to the wrong privilege level, breaking VM isolation.
Violation:
  In the Linux kernel KVM (arch/riscv/kvm) or trap entry path
  (arch/riscv/kernel/entry.S, traps.c), kernel writes a value to a WARL CSR
  (hedeleg, hideleg, hvip, hip, hie, hgeie, vsip, vsie, vstvec, stvec, sip,
  sie, mnepc, mncause, mnstatus) and relies on the written value having taken
  effect without an explicit read-back verification, causing the kernel to
  operate under an incorrect assumption about the hardware CSR state when
  hardware silently altered the written value on an implementation where the
  field is not fully writable.
Consequence: privilege_escape
Pattern:
  csr_write\((hedeleg|hideleg|hvip|hip|hie|hgeie|vsip|vsie|vstvec|stvec)\)(?!.
  *csr_read|.*csr_swap)
