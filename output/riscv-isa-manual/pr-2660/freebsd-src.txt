PR #2660  target=freebsd-src  overall=bug_confirmed
Spec: Smcntrpmf mcyclecfg/minstretcfg INH bits must be context-switched per thread, otherwise a thread can reprogram counter inhibition to time kernel or other processes via rdcycle/rdinstret
Violation: In the FreeBSD kernel, when Smcdeleg/Ssccfg delegates mcyclecfg/minstretcfg to S-mode, the kernel's context switch path (sys/riscv/riscv/swtch.S) does not save/restore these CSRs, allowing a thread to program mcyclecfg.___INH bits so that cycle/instret counters selectively skip counting during target execution, leaking timing information.
Consequence: info_leak
Pattern: mcyclecfg|minstretcfg|mcyclecfgh|minstretcfgh
------------------------------------------------------------
[bug_confirmed] sys/riscv/riscv/swtch.S:258-358  cpu_switch
  cpu_switch saves/restores GPRs (ra, sp, s0-s11) and FPE state, but does NOT save/restore mcyclecfg/minstretcfg/mcyclecfgh/minstretcfgh. When Smcdeleg delegates these CSRs from M-mode to S-mode, a thread setting ___INH bits in mcyclecfg will persist across context switches, selectively suppressing cycle/instret counting for subsequent threads. This leaks timing information across thread boundaries.
  | ENTRY(cpu_switch)
  | 	sd	a1, PC_CURTHREAD(tp)
  | 	/* ... GPR save/restore only; no mcyclecfg/minstretcfg handling */
  | 	__fpe_state_save x13
  | 	/* ... */
  | 	ret

[bug_confirmed] sys/riscv/riscv/swtch.S:206-248  cpu_throw
  cpu_throw (initial thread activation path) loads GPRs and optionally FPE state but does not initialize or sanitize mcyclecfg/minstretcfg for the new thread. A newly spawned thread inherits whatever filtering configuration the previous thread left in these CSRs.
  | ENTRY(cpu_throw)
  | 	call	_C_LABEL(pmap_activate_sw)
  | 	/* Loads GPRs, optionally FPE; no mcyclecfg/minstretcfg init */
  | 	ret

[bug_confirmed] sys/riscv/include/pcb.h:42-54  struct pcb
  struct pcb has no fields for mcyclecfg, minstretcfg, mcyclecfgh, or minstretcfgh. Without per-thread storage, the context-switch path has nowhere to save/restore these CSRs. This is a structural gap: even if swtch.S were updated, the PCB lacks the necessary slots.
  | struct pcb {
  | 	uint64_t	pcb_ra;
  | 	uint64_t	pcb_sp;
  | 	/* ... FPE fields ... */
  | 	/* MISSING: mcyclecfg, minstretcfg, mcyclecfgh, minstretcfgh */
  | };

[bug_confirmed] sys/riscv/include/encoding.h:1060-1080  (CSR definitions)
  encoding.h defines scounteren (CSR_SCOUNTEREN, 0x106) and mcounteren (CSR_MCOUNTEREN, 0x306) but has NO definitions for mcyclecfg (0x321), minstretcfg (0x322), mcyclecfgh (0x721), or minstretcfgh (0x722). These CSRs are completely absent from FreeBSD's kernel headers, making any save/restore code impossible to write without first adding the definitions.
  | DECLARE_CSR(scounteren, CSR_SCOUNTEREN)
  | DECLARE_CSR(mcounteren, CSR_MCOUNTEREN)
  | /* MISSING: mcyclecfg (0x321), minstretcfg (0x322) */
  | /* MISSING: mcyclecfgh (0x721), minstretcfgh (0x722) */

[bug_confirmed] sys/riscv/vmm/vmm_switch.S:41-203  vmm_switch
  vmm_switch atomically swaps sstatus, hstatus, scounteren, sscratch, stvec between host and guest but does NOT handle mcyclecfg/minstretcfg. If the host kernel sets ___INH bits, a guest VM exit does not restore host configuration. Conversely, a guest VM (if it could access these CSRs through nested virtualization) could poison the host's counter filtering state.
  | csrrw	t0, sstatus, t0
  | csrrw	t1, hstatus, t1
  | csrrw	t2, scounteren, t2
  | csrrw	t3, sscratch, a0
  | csrrw	t4, stvec, t4
  | /* mcyclecfg/minstretcfg NOT swapped */
