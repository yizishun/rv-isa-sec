PR #2569  target=freebsd-src  overall=compliant
Spec: Normative rule norm:sc_reservation_invalidate mandates SC invalidates any reservation—FreeBSD interrupt handlers executing SC/AMO can starve constrained LR/SC loops in interrupted kernel code (e.g., spinlock acquire on contended lock), breaking norm:constrained_lrsc_forward_progress and causing hart livelock
Violation: A FreeBSD kernel trap/interrupt handler executes an SC or AMO instruction while a constrained LR/SC sequence was in progress on the same hart, silently invalidating the interrupted code's reservation and potentially breaking its forward-progress guarantee indefinitely if the interrupt fires at a high enough rate
Consequence: denial_of_service
Pattern: trap_handler|interrupt_handler|intr_|trap_|exception_handler.*\.S|atomic.*context|savectx|restorectx.*lr|sc\.w|sc\.d|amoswap|amoadd|amoor
------------------------------------------------------------

[compliant] sys/riscv/include/atomic.h:391-412  atomic_cmpset_64
  The LR/SC sequence (lr.d/sc.d) has a proper retry loop. If an interrupt fires between lr.d and sc.d, the hardware clears the reservation, sc.d fails (returns nonzero in res), the bnez at 405 jumps back to 0b retrying the lr.d. This is the architecturally correct way to handle reservation loss — it's not a silent failure because sc.d returns an explicit failure code.

  |   li   %1, 1
  |   lr.d %0, %2
  |   bne  %0, %z3, 1f
  |   sc.d %1, %z4, %2
  |   bnez %1, 0b
  | 1:

  CAS in user-space uses lr.d/sc.d pattern.
