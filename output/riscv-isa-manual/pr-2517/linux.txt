PR #2517  target=linux  overall=compliant
Spec: WFI in U-mode unconditionally raises illegal-instruction; mstatus.TW controls only S-mode WFI trapping — kernel must never consult TW when handling a U-mode WFI trap
Violation: In the Linux kernel, if the illegal-instruction trap handler for U-mode WFI gates its behavior on mstatus.TW (e.g., skipping SIGILL delivery when TW=0 under the assumption that U-mode WFI is permitted), the handler would incorrectly suppress a mandatory exception. The spec now makes it unambiguous: U-mode WFI always raises illegal-instruction regardless of TW, so any TW-conditional WFI handling for U-mode is a spec violation.
Consequence: denial_of_service
Pattern: mstatus.TW checked in U-mode WFI trap handling path; or any code that conditionally permits U-mode WFI execution (e.g., do_notify_resume / exit_to_usermode_loop paths checking WFI permissiveness)
------------------------------------------------------------
