PR #2517  target=qemu  overall=compliant
Spec: WFI in U-mode must trap regardless of mstatus.TW when S-mode is implemented; incorrectly gating on TW=0 allows unprivileged guests to halt the hart, violating OS-controlled idle policy
Violation: QEMU's helper_wfi allows WFI to complete in U-mode when S-mode is implemented and mstatus.TW=0, instead of unconditionally raising an illegal-instruction exception
Consequence: privilege_escape
Pattern: get_field(env->mstatus, MSTATUS_TW).*wfi|wfi.*MSTATUS_TW|WFI.*U-mode.*TW
------------------------------------------------------------
[compliant] target/riscv/op_helper.c:541-559  helper_wfi
  helper_wfi correctly raises illegal-instruction for U-mode WFI when S-mode is implemented (rvs=true), unconditionally regardless of mstatus.TW. The condition (rvs && prv_u && !env->virt_enabled) on line 549 traps all U-mode WFI. mstatus.TW is only consulted for S-mode WFI (prv_s) and for U-mode WFI in no-S-mode systems (!rvs && prv_u), both matching the privileged spec. The fix (commit 719f0f603c22) explicitly clarifies that WFI in U-mode is unaffected by mstatus.TW.
