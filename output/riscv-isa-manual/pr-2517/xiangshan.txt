PR #2517  target=xiangshan  overall=compliant
Spec: WFI trap decision must raise illegal-instruction exception for U-mode unconditionally (regardless of mstatus.TW); TW should only gate WFI trapping in S-mode
Violation:
  When S-mode is implemented and mstatus.TW=0, the WFI instruction trap logic
  in XiangShan RTL incorrectly allows WFI to complete in U-mode without
  raising an illegal-instruction exception. The spec now mandates that WFI in
  U-mode must always trap regardless of TW. A hardware bug exists if the trap
  decision for WFI in U-mode is gated by (tw === 0.U) or if the WFI exception
  condition evaluates (privilege < M && tw) instead of (privilege == S && tw)
  || (privilege == U).
Consequence: privilege_escape
Pattern:
  WFI trap logic where mstatus.TW gates the illegal-instruction exception for
  U-mode; any condition expression like `tw && priv < PRV_M` that allows WFI
  to succeed in U-mode when TW=0; Chisel when() blocks that selectively
  suppress WFI exception based on TW without checking privilege level
  separately
