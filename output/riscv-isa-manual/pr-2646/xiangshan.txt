PR #2646  target=xiangshan  overall=compliant
Spec: PR removes redundant henvcfg.SSE check from VU-mode ssp access, relying solely on senvcfg.SSE effective value; if hardware implements 'read-only zero' as read-side gating while raw storage retains written value, the access-control FSM may use the raw bit, allowing VS-mode guest with henvcfg.SSE=0 to write senvcfg.SSE=1 (reads back as 0, spec-compliant) and then access ssp in VU-mode (privilege escape via shadow stack manipulation)
Violation:
  When henvcfg.SSE=0, senvcfg.SSE is spec-mandated as 'read-only zero' (reads
  as 0, writes ignored). The PR simplifies VU-mode ssp CSR access check to
  depend ONLY on senvcfg.SSE (removing the redundant henvcfg.SSE check),
  relying on the invariant that henvcfg.SSE=0 implies effective senvcfg.SSE=0.
  In hardware, if the implementation stores the raw written value of
  senvcfg.SSE in a physical register but only gates the READ path to return 0
  when henvcfg.SSE=0, the ssp access check in the decode/CSR-access FSM may
  use the raw (ungated) storage bit. A malicious VS-mode guest that writes
  senvcfg.SSE=1 while henvcfg.SSE=0 would see senvcfg.SSE read back as 0
  (spec-compliant) yet successfully access ssp CSR in VU-mode (spec
  violation), because the access-control logic samples the raw register bit
  rather than the effective gated value.
Consequence: privilege_escape
Pattern:
  senvcfg_SSE_read_gated_vs_raw_storage_mismatch OR
  ssp_csr_access_check_uses_raw_senvcfg_SSE OR
  henvcfg_SSE_zero_only_gates_read_path_not_access_control OR
  CSR_WARL_read_only_zero_effective_vs_raw_discrepancy
