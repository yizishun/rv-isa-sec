PR #2646  target=linux  overall=bug_confirmed
Spec: KVM does not manage henvcfg.SSE for guests and does not re-read hardware-enforced senvcfg.SSE after ONE_REG SET, so a VMM can observe a stale SSE=1 while the guest's VU-mode shadow stack is actually disabled by read-only-zero chaining — guest userspace runs without the CFI it expects
Violation: In the Linux kernel, when KVM writes the guest's senvcfg CSR via ONE_REG or directly swaps it into hardware during vcpu_enter_exit, but the hypervisor has henvcfg.SSE=0 (the current default since kvm_riscv_vcpu_setup_config never sets SSE), the spec mandates senvcfg.SSE is 'read-only zero' — meaning the hardware ignores writes and forces reads to return 0. If KVM's ONE_REG GET path (kvm_riscv_vcpu_general_get_csr) returns the in-memory csr->senvcfg value written by the VMM without re-reading the hardware-enforced effective value, the VMM observes a stale SSE=1 while the guest VU-mode actually has xSSE=0, causing guest userspace to silently run without shadow stack CFI protection it believes is active.
Consequence: function_loss
Pattern: csr_write(CSR_SENVCFG|CSR_HENVCFG).*ENVCFG_SSE|->senvcfg.*=|henvcfg.*SSE|kvm_riscv_vcpu_general_get_csr.*senvcfg|kvm_riscv_vcpu_setup_config.*henvcfg

[bug_confirmed] arch/riscv/kvm/vcpu.c:543-576  kvm_riscv_vcpu_setup_config
  henvcfg.SSE (ENVCFG_SSE, bit 3) is never set. Every other envcfg feature (PBMTE, STCE, CBIE, CBCFE, CBZE, ADUE) is conditionally enabled based on ISA extension availability, but ZICFISS (RISCV_ISA_EXT_ZICFISS=105) is never checked and ENVCFG_SSE is never OR'd into cfg->henvcfg. Per the Zicfiss privileged spec, when henvcfg.SSE=0, senvcfg.SSE is read-only zero — all VS-mode writes to SSR/SSP are silently dropped. This means guest VU-mode shadow stack CFI is unconditionally non-functional regardless of VMM intent.

[potential_risk] arch/riscv/kvm/vcpu_onereg.c:28-109  kvm_isa_ext_arr
