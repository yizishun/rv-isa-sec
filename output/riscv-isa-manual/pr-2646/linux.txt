PR #2646  target=linux  overall=not_implemented
Spec: henvcfg.SSE=0 makes senvcfg.SSE read-as-zero without clearing the underlying bit; kernel KVM code reading senvcfg.SSE to track guest SSE state may operate on a stale view, causing shadow stack state corruption when henvcfg.SSE is later set to 1
Violation:
  Kernel KVM code running in HS-mode reads senvcfg.SSE to determine whether
  shadow stacks are active for guest U/VU-mode while henvcfg.SSE=0. Under the
  clarified spec, senvcfg.SSE reads as 0 in this state but the underlying
  value is preserved—it is not cleared. If the kernel caches this zero read,
  or makes a security-sensitive decision (e.g., skipping shadow stack page-
  table setup, skipping ssp save/restore, or reporting SSE=0 to the guest)
  without accounting for the fact that the underlying SSE bit may be 1 and
  will take effect as soon as henvcfg.SSE transitions to 1, the kernel's
  internal SSE tracking diverges from hardware state.
Consequence: race_condition
Pattern:
  senvcfg.*read|csr_read.*SENVCFG|kvm.*senvcfg|__kvm_riscv.*senvcfg|vcpu_arch.
  *senvcfg|switch.*senvcfg
