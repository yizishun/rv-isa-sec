PR #2472  target=xiangshan  overall=compliant
Spec: PMP TOR entries cannot represent address 2^PPN_BITS as the top of a range; RTL PMP checker must correctly handle the all-1s pmpaddr edge case to prevent privilege escapes or denial of access at the uppermost physical memory window
Violation: In XiangShan RTL, PMP TOR (Top-of-Range) entry i with pmpaddr_i = all-1s (maximum representable value) still excludes the uppermost physical addresses — specifically the range from (max_pmpaddr << 2) to 2^PPN_BITS. On RV64 with 56-bit physical addresses, this is the top 4 bytes (0xFFFFFFFFFFFFFFFC to 0xFFFFFFFFFFFFFFFF). If software erroneously assumes TOR can cover the entire physical address space, the PMP checker will deny access to this window, or conversely, if the hardware fails to correctly compute the boundary, it may grant unauthorized access. An RTL bug where the TOR match logic uses an unsigned comparison with a truncated/incomplete top-of-range value (e.g., zero-extending instead of treating all-1s as the maximum address) would produce incorrect access control decisions at the upper boundary of physical memory.
Consequence: privilege_escape
Pattern: PMP TOR address comparison with incomplete upper bound; pmpaddr all-1s edge case not tested; TOR range_lo <= addr < range_hi comparison with overflow/truncation in range_hi computation; missing assertion on pmpaddr[i-1] >= pmpaddr[i] for TOR entries at top of memory
