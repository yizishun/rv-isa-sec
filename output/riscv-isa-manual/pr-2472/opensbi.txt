PR #2472  target=opensbi  overall=compliant
Spec: RV32 TOR PMP entries cannot represent the top 4 bytes of physical memory when PA > XLEN, creating an unreachable 4-byte gap in OpenSBI domain memory region coverage
Violation: In OpenSBI on RV32 with physical address width > 32 bits (e.g., Sv32x4 with 34-bit PA), when the domain/PMP library configures TOR-typed entries to grant S-mode access to memory that includes the uppermost 4 bytes of the physical address space, the highest TOR entry's top boundary saturates at (2^32 - 1) << 2 = 2^34 - 4, leaving addresses [2^PA_WIDTH - 4, 2^PA_WIDTH - 1] unmatched by any TOR entry and falling through to the default PMP policy (typically deny-all under Smepmp or locked-entry setups).
Consequence: function_loss
Pattern: pmp_set|pmp_region|sbi_domain.*addr|PMP_TOR.*addr|pmpaddr.*=(0x[fF]|~0|PMP_ADDR_MASK)|__pmp_entry_new|domain_memregion.*end
