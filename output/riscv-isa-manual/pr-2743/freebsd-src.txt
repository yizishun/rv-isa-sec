PR #2743  target=freebsd-src  overall=not_implemented
Spec: Zvfbfa adds altfmt bit (bit 8) to vtype CSR; FreeBSD currently has no V-extension support at all (no vtype in PCB/mcontext/context-switch), so any future V support addition must preserve the full vtype register including altfmt to prevent BF16/FP16 format corruption across context switches
Violation:
  FreeBSD RISC-V kernel has zero V-extension support: no vtype CSR
  save/restore in context switch, no SSTATUS_VS bit tracking, no vector fields
  in PCB. If rudimentary V support is added without preserving the full vtype
  register (including the new altfmt bit at position 8), a context switch
  between a process using altfmt=1 (BF16 mode) and one expecting altfmt=0
  (FP16 mode) would corrupt floating-point vector computation semantics for
  the victim process. Additionally, any kernel code that read-modify-writes
  vtype field-by-field (vsew, vlmul, vta, vma) without preserving bit 8 would
  silently clear altfmt.
Consequence: data_corruption
Pattern:
  vtype.*&=|vtype.*\|=|vtype.*mask|write_csr.*vtype|SSTATUS_VS|csr_write.*0xc2
  1|VTYPE_|pcb.*vtype|save.*vstate|restore.*vstate|altfmt
------------------------------------------------------------
