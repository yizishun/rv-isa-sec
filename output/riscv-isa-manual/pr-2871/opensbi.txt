PR #2871  target=opensbi  overall=compliant
Spec: MRET/SRET clearing MDT in M-mode is conditional on Smdbltrp; OpenSBI must guard MDT-dependent trap-return logic with Smdbltrp detection and account for silent MDT clearance on SRET/MRET side effects
Violation:
  OpenSBI M-mode trap handler executes SRET while mstatus.MDT=1 on an Smdbltrp
  system, causing MDT to be silently cleared as a side effect before the
  handler has re-established a reentrant state; a subsequent trap during this
  window then hits MDT=1 (unexpected trap) and triggers critical-error instead
  of being handled normally
Consequence: denial_of_service
Pattern:
  SRET instruction executed while current privilege mode is M, without
  preceding explicit MDT save and subsequent restore; or M-mode MRET code path
  that writes MDT=1 before executing MRET (dead store since MRET
  unconditionally clears MDT on Smdbltrp systems)
