PR #2871  target=opensbi  overall=compliant
Spec: Smdbltrp now clarifies that SRET in M-mode clears MDT; OpenSBI must not bypass this by manually restoring mstatus with MDT=1 via CSR writes during context-switch or HSM suspend/resume paths
Violation: OpenSBI M-mode trap handler saves mstatus (with MDT potentially set by a double-trap), then restores it via csrw mstatus (not MRET/SRET), preserving a stale MDT=1. Subsequent traps may incorrectly trigger double-trap handling.
Consequence: denial_of_service
Pattern: csr[rw]\s+mstatus.*save.*restore context (where MDT bit is not explicitly cleared before writing mstatus back, or where mstatus is restored from a saved copy without masking MDT)
