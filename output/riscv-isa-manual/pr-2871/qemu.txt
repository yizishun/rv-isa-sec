PR #2871  target=qemu  overall=compliant
Spec: QEMU helper_sret unconditionally clears sstatus.SDT regardless of current privilege mode, violating spec qualification that SRET SDT/MDT clearing only applies when SRET is executed in M-mode and only when returning to U/VS/VU
Violation:
  In helper_sret (target/riscv/op_helper.c:319-329), QEMU unconditionally
  clears MSTATUS_SDT when ext_ssdbltrp is enabled, without checking that (a)
  SRET is executing in M-mode (env->priv >= PRV_M) and (b) the destination
  privilege mode is U, VS, or VU. The spec (PR #2871) explicitly qualifies SDT
  clearing on SRET to only apply when 'executing an SRET instruction while the
  current privilege mode is M' AND 'the new privilege mode is U, VS, or VU'.
  Additionally, the spec now requires ext_smdbltrp to be implemented for the
  entire SRET-MDT/SDT block to apply, but QEMU gates SDT clearing on
  ext_ssdbltrp alone. The vsstatus.SDT clearing at line 324-326 similarly
  lacks the M-mode current-privilege guard, clearing vsstatus.SDT from HS-mode
  SRET when the spec restricts this to M-mode execution only.
Consequence: function_loss
Pattern:
  helper_sret.*MSTATUS_SDT.*set_field.*0(?!.*env-
  >priv.*>=.*PRV_M)(?!.*prev_priv.*==.*PRV_U)
