PR #2871  target=qemu  overall=compliant
Spec: SRET in M-mode must conditionally clear mstatus.MDT only when Smdbltrp is enabled, and sstatus.SDT only when Ssdbltrp is enabled — unconditional clearing violates the extension-gated behavior and breaks guest double-trap detection assumptions
Violation: QEMU TCG helper for SRET executed while current privilege mode is M clears mstatus.MDT or sstatus.SDT without first checking that the Smdbltrp extension (for MDT) or Ssdbltrp extension (for SDT) is actually enabled on this hart. Conversely, if Smdbltrp IS enabled but QEMU fails to qualify SRET's MDT-clear behavior by current privilege mode (clearing MDT on SRET-from-S instead of only SRET-from-M), the MDT bit is incorrectly modified.
Consequence: function_loss
Pattern: sret.*MDT|sret.*mstatus.*MDT|riscv_cpu_do_interrupt.*MDT|helper_sret.*mstatus|MDT.*sret|sstatus.SDT.*sret|mstatus.*MDT.*sret
