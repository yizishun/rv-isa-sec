PR #2871  target=linux  overall=compliant
Spec: SRET/MRET clearing of SDT/MDT is gated on DblTrp extension presence; kernel must not assume hardware clears these bits on xRET unless it first verifies Ssdbltrp/Smdbltrp is implemented, or stale SDT will cause spurious double-trap on next U-mode exception
Violation: The kernel sets sstatus.SDT (or a nested guest's vsstatus.SDT) as part of double-trap handling in S-mode/HS-mode, then executes SRET to return to U/VU-mode on hardware that does NOT implement Ssdbltrp, relying solely on the SRET instruction to clear the SDT bit.
Consequence: denial_of_service
Pattern: sstatus.*SDT|SDT.*sstatus|mstatus.*MDT|MDT.*mstatus
