PR #2871  target=freebsd-src  overall=compliant
Spec: FreeBSD's trap-return and context-switch code must gate MDT/SDT clearing on Smdbltrp/Ssdbltrp presence, otherwise stale double-trap state leaks across context switches when extensions are absent
Violation: FreeBSD kernel trap-return path or context-switch code assumes that SRET unconditionally clears mstatus.MDT or sstatus.SDT without verifying Smdbltrp/Ssdbltrp extension presence. Specifically: (1) the S-mode trap handler saves sstatus on exception entry, relies on SRET to clear SDT on return to U-mode, but the hardware lacks Ssdbltrp — in this case the SDT bit position is reserved/WARL and SRET is a no-op on that field, leaving stale SDT state in the in-memory saved sstatus that diverges from hardware CSR state; or (2) bhyve's VS-mode SRET emulation unconditionally clears vsstatus.SDT/VS-stage sstatus.SDT without gating on Ssdbltrp extension presence in the guest ISA string, creating a behavioral mismatch between emulated SRET and native hardware SRET.
Consequence: info_leak
Pattern: sstatus.*SDT|mstatus.*MDT|sret|mret.*dbltrp|switch_to.*sstatus|sstatus.*save|sstatus.*restore|dbltrp|double.trap
