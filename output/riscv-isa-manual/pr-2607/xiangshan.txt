PR #2607  target=xiangshan  overall=compliant
Spec: XiangShan PMP checker unconditionally exempts M-mode from PMP enforcement (passThrough=mode>1.U) and mseccfg Smepmp fields MML/MMWP/RLB are hardwired read-only zero, meaning M-mode privilege restrictions via PMP are silently ignored in hardware
Violation: In XiangShan RTL, PMPChecker.pmp_match_res unconditionally sets passThrough=true for M-mode (mode > 1.U), allowing all M-mode accesses to bypass non-locked PMP entries via the ignore=(passThrough && !pmp.cfg.l) logic. The mseccfg CSR module at MachineLevel.scala:324-326 declares MML, MMWP, and RLB as RO(0) — hardwired read-only zero — meaning these fields are never forwarded to the PMP checker decision logic. Consequently, when software writes mseccfg.MMWP=1 (intending to change default M-mode PMP policy from 'ignored' to 'denied'), the write is silently discarded, and M-mode continues to bypass PMP checks. Similarly, mseccfg.MML=1 writes are discarded, so pmpcfg.L never takes on the Smepmp M-mode-only/S-U-mode-only/Shared-Region semantics. The PMP checker's pmp_match_res contains no reference to mseccfg state at all.
Consequence: privilege_escape
Pattern: passThrough.*mode.*>.*1|MML.*RO\(0\)|MMWP.*RO\(0\)|RLB.*RO\(0\)|mseccfg.*ignore|pmp_match_res.*passThrough
