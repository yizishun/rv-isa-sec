PR #1434  target=xiangshan  overall=potential_risk
Spec: PR 1434 requires per-memory-operation PMP checking: misaligned/cross-boundary accesses and CMO instructions must decompose into independent memory operations each checked against PMP—a single-range PMP check in XiangShan would be a privilege-escape bug allowing writes into protected PMP regions at sub-access granularity
Violation:
  When XiangShan's PMP checker evaluates the entire instruction-level memory
  access as one atomic range (single base-address to base+size check) rather
  than decomposing misaligned/cross-PMP-boundary accesses into independent
  memory operations, each checked separately. Specifically: (1) a misaligned
  store spanning two PMP regions is checked with a single PMP lookup on the
  full byte range, allowing the highest-priority matching entry to govern all
  bytes; (2) CMO instructions (cbo.zero, cbo.clean, cbo.flush, cbo.inval) that
  cross PMP region boundaries are checked once for the entire cache-block-
  sized access rather than per-decomposed-memory-operation; (3) stores wider
  than XLEN (e.g., FSD in RV32D) crossing PMP boundaries are checked
  atomically.
Consequence: privilege_escape
Pattern:
  PMP address matching logic that computes a single (start_addr, size) pair
  per instruction and passes it to the PMP checker, with no mechanism to split
  the check across PMP region boundaries or to re-check after LSU decomposes
  the access into sub-operations. Search for PMP check functions that take a
  single address range, or PMP hit logic that exits after the first matching
  entry without per-byte/per-sub-operation iteration.
