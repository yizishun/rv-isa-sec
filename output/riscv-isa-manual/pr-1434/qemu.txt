PR #1434  target=qemu  overall=bug_confirmed
Spec: Memory-operation-granularity PMP: QEMU must decompose CMO cache-block accesses and misaligned/wide memory accesses into individual memory operations, applying independent PMP checks per operation with partial-store-visibility semantics, not a single monolithic check at instruction-access granularity
Violation:
  QEMU performs a single monolithic PMP check at the granularity of the
  architectural instruction access (e.g., cache-block size for CMOs, or full
  operand width for misaligned loads/stores) rather than independently
  checking PMP for each decomposed memory operation. For CMO instructions
  (cbo.zero, cbo.clean, cbo.flush), QEMU must decompose the cache-block access
  into potentially smaller memory operations and apply PMP checks per-
  operation, allowing partial success/failure where an operation spanning two
  PMP regions may succeed if both regions grant identical permissions at the
  memory-operation granularity. For misaligned loads/stores and wide stores
  (e.g., FSD on RV32D), QEMU must apply PMP checks to each naturally-aligned
  sub-operation independently, and must allow partial store visibility—bytes
  that pass PMP becoming architecturally visible—even when a subsequent sub-
  operation faults.
Consequence: privilege_escape
Pattern:
  pmp_check.*size|pmp_hart_has_privs|pmp_is_range_in_range|pmp_get_tlb_size|pm
  p_access_size|cache_block_size.*pmp|cbo.*pmp|target_ulong.*pmp.*check|pmp.*a
  ccess.*len|pmp.*addr.*size

  granularity via probe_write(env, address, cbozlen, ...) at line 181. The PMP
  check function pmp_hart_has_privs() receives the full cbozlen (e.g. 64
  bytes) and rejects any access that is 'partially inside' a PMP region
  (pmp.c:412-418). This means a cbo.zero targeting a cache block that spans
  two PMP regions will always fault, even if both regions grant identical

  memory operations.' The I/O fallback path (lines 197-199) correctly checks

[potential_risk] target/riscv/op_helper.c:211-250  check_zicbom_access
  check_zicbom_access() first tries probe_access_flags() with MMU_DATA_LOAD,
  then falls back to probe_write() with MMU_DATA_STORE. This implements the
  spec requirement (cmo.adoc:352-361) that cbo.clean/cbo.flush/cbo.inval need
  either load OR store permission. However, the spec also states that 'if
  neither a load instruction nor store instruction is permitted... but an
  instruction fetch is permitted... whether a cache-block management
  instruction is permitted to access the cache block is UNSPECIFIED.' QEMU
  does not check execute permission as a third fallback, which is consistent
  with the UNSPECIFIED designation, but means instruction-fetch-only regions
  will incorrectly fault on CBO instructions if this unspecified behavior is
  later defined to permit access.
