PR #1434  target=qemu  overall=compliant
Spec: CMO helpers check PMP atomically with full cache-block size instead of allowing per-region decomposition when CMO range spans PMP boundaries with identical permissions
Violation: QEMU performs PMP checks on CMO instructions (cbo.zero, cbo.clean, cbo.flush, cbo.inval) as a single monolithic operation via probe_write()/probe_access_flags() with the full cache-block size (cbozlen/cbomlen). In pmp_hart_has_privs() at pmp.c:413, when a CMO address range spans two PMP regions, (s+e)==1 triggers 'access is partially inside' and denies the entire CMO. The updated spec mandates PMP checks be applied to each decomposed memory operation independently, so a 64-byte cbo.zero spanning two same-permission 32-byte PMP regions must succeed—QEMU incorrectly faults. Conversely, the QEMU softmmu's cross-page store decomposition (cputlb.c do_st_mmio_idx) may write bytes from the first sub-operation before PMP-failing the second, matching the spec's 'partial-write-before-fault' allowance, but this behavior is accidental rather than intentional.
Consequence: function_loss
Pattern: probe_(write|access_flags)\(env,\s*addr(ess)?,\s*(cbozlen|cbomlen|cpu->cfg\.(cboz_blocksize|cbom_blocksize)|\w+len),\s*mmu_idx
