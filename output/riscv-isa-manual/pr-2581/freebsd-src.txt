PR #2581  target=freebsd-src  overall=compliant
Spec: FreeBSD has no misaligned AMO emulation path: kernel-side unaligned Zabha access triggers panic via do_trap_supervisor, userspace unaligned Zabha kills process with SIGBUS, and the sign-extension semantics of hardware Zabha diverge from the current _atomic_subword.h zero-extended software emulation
Violation: In the FreeBSD kernel, if a Zabha byte/halfword AMO instruction is executed in supervisor mode with an unaligned effective address in rs1 (e.g., amoswap.b to an odd address), the hardware raises SCAUSE_STORE_MISALIGNED or SCAUSE_LOAD_MISALIGNED. The FreeBSD trap handler do_trap_supervisor() in sys/riscv/riscv/trap.c:341-347 unconditionally panics on any misaligned exception in kernel mode. There is no emulation or fixup path for misaligned AMOs. For userspace, do_trap_user() in trap.c:418-424 delivers SIGBUS(BUS_ADRALN) with no emulation attempt, killing the process. Additionally, FreeBSD's existing _atomic_subword.h software emulation (sys/sys/_atomic_subword.h) returns zero-extended subword values, whereas hardware Zabha AMOs sign-extend the value placed in rd per the Zabha_rd_sign_extension normative rule — a semantic mismatch that could cause silent data corruption if the kernel transitions from the software emulation to hardware Zabha without masking adjustments.
Consequence: denial_of_service
Pattern: atomic_(add|clear|set|cmpset|fcmpset|swap)_(8|16|char|short)\(.*\).*on pointer that may not be naturally aligned to operand size; or any __asm __volatile.*amo(add|swap|and|or|xor|min|max|cas)\.[bh] without a preceding alignment check; or lr\.[bh]/sc\.[bh] instruction pair usage without natural-alignment guard
