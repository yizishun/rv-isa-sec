PR #2637  target=qemu  overall=bug_confirmed
Spec: QEMU incorrectly gates JVT CSR and cm.jalt/cm.jt under smstateen bit 2 — spec PR #2637 removed this spurious dependency, so QEMU must drop SMSTATEEN0_JVT checks from the zcmt() predicate and cm_jalt helper
Violation: When the Smstateen extension is implemented and bit 2 of mstateen0/sstateen0/hstateen0 is 0, QEMU incorrectly raises an illegal-instruction trap on JVT CSR access (read/write) and on cm.jalt/cm.jt instruction execution, because the zcmt() CSR predicate and the cm_jalt helper both call smstateen_acc_ok(env, 0, SMSTATEEN0_JVT). Per the corrected spec, bit 2 of stateen0 CSRs should NOT gate JVT or Zcmt instruction access — the prior spec text tying JVT to stateen bit 2 was spurious and has been removed.
Consequence: function_loss
Pattern: SMSTATEEN0_JVT|smstateen_acc_ok.*JVT|stateen0.*bit.2.*jvt
------------------------------------------------------------
[bug_confirmed] target/riscv/csr.c:173-187  zcmt
  The zcmt() CSR predicate function gates JVT CSR access (read/write) on SMSTATEEN0_JVT (bit 2 of stateen0). According to the corrected Smstateen spec, bit 2 of stateen0 should NOT gate JVT access — the prior spec text tying JVT to stateen bit 2 was spurious and has been removed. When bit 2 of mstateen0/sstateen0/hstateen0 is 0 (e.g., because firmware configured stateen0 to disable some unrelated extension), QEMU incorrectly raises RISCV_EXCP_ILLEGAL_INST on JVT CSR reads/writes, causing function loss for Zcmt guest software.

[bug_confirmed] target/riscv/zce_helper.c:24-34  HELPER(cm_jalt)
  The cm_jalt TCG helper gates both cm.jalt and cm.jt instruction execution on SMSTATEEN0_JVT (bit 2 of stateen0). The trans_cm_jalt() translator dispatches both cm.jt and cm.jalt to this same helper (distinguished by index >= 32). Per the corrected spec, bit 2 of stateen0 should NOT gate Zcmt instruction access. When bit 2 of any stateen0 CSR is 0, QEMU incorrectly raises an illegal-instruction exception on both cm.jt and cm.jalt, causing function loss.

[bug_confirmed] target/riscv/cpu_bits.h:357-357  (none — macro definition)
  SMSTATEEN0_JVT is defined as (1ULL << 2), encoding the spurious bit-2 gating that the corrected spec has removed. While the define itself is just a constant, it is the root of why the two consumers above incorrectly gate JVT/Zcmt on stateen0 bit 2. After removing the smstateen_acc_ok calls in csr.c:180 and zce_helper.c:30, this macro becomes dead code and should be removed.
