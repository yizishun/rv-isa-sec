PR #2818  target=qemu  overall=bug_confirmed
Spec: Vector extension dependency validation must accept Zfinx/Zdinx/Zhinxmin as alternatives to F/D/Zfhmin, and TCG must route vector FP scalar moves through x registers (not f registers) when Zfinx is active — stale f-register reads constitute guest info leak.
Violation: QEMU validates the V/Zve32f/Zve64f/Zve64d extension dependency strictly against misa.F/misa.D flags without accepting Zfinx/Zdinx/Zhinxmin as valid alternatives, causing either (a) incorrect rejection of valid V+Zfinx guest configurations, or (b) silent emulation of vector floating-point scalar move instructions (vfmv.s.f, vfmv.f.s, vfmv.s.h, etc.) using non-existent f registers when Zfinx is active, because the TCG translator reads/writes f-register state that does not exist under Zfinx — guest x-register state is used instead at the architectural level.
Consequence: info_leak
Pattern: misa_ext_mask.*V.*F|misa.*D.*V.*dep|has_ext.*F.*V|vext_check_dependencies.*F|(vfmv\.s\.f|vfmv\.f\.s).*freg|Zve32f.*dep.*F[^Z]|!has_ext.*Zfinx.*V
