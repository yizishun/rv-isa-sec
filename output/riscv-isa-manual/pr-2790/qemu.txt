PR #2790  target=qemu  overall=potential_risk
Spec: mie CSR write path accepts writes to all local interrupt bits (13-63) via overly-broad all_ints mask, allowing guest to set and read back non-existent interrupt bits — WARL contract violation causing guest kernel to misidentify available interrupt sources
Violation: QEMU's rmw_mie64 write handler masks incoming writes with `all_ints` which includes `LOCAL_INTERRUPTS` (~0x1FFFULL, i.e. all bits 13-63). This accepts writes to every local interrupt bit regardless of whether the corresponding interrupt source is actually implemented. A guest can write 1 to a non-existent interrupt bit, and subsequent CSR reads return the written value unchanged — violating the WARL requirement that unimplemented bits must read back as legal (zero) values.
Consequence: info_leak
Pattern: rmw_mie64.*all_ints|LOCAL_INTERRUPTS.*mask|env->mie.*all_ints
------------------------------------------------------------

[potential_risk] target/riscv/csr.c:1783-1847  LOCAL_INTERRUPTS (macro, used in sip/sie/vsip/vsie/hvip writable masks)
  LOCAL_INTERRUPTS = ~0x1FFFULL treats ALL bits 13:63 as writable across sip_writable_mask (line 1841), vsip_writable_mask (line 1847), hvip_writable_mask (line 1843-1844), hvien_writable_mask (line 1845), mvip_writable_mask (line 1836-1837), mvien_writable_mask (line 1838-1839), and the dynamic masks in rmw_sie64/rmw_vsie64. Bits 14:63 in LOCAL_INTERRUPTS are treated as 'virtual only' per the comment, but the writable mask never constrains them to zero on hardware without virtual interrupt support. The spec is ambiguous about bits 13:63 WARL behavior, making this a portability concern rather than a spec violation.
