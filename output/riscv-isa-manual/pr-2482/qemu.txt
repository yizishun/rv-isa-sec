PR #2482  target=qemu  overall=potential_risk
Spec: CBO instructions must replicate exact load/store permission semantics including correct fault classes, and cbo.zero must re-validate write permission atomically with the memset to prevent MTTCG TOCTOU privilege-escape windows
Violation: In QEMU TCG, cbo.clean/cbo.flush/cbo.inval dispatch through check_zicbom_access(), which probes MMU_DATA_LOAD with nonfault=true then falls back to probe_write(MMU_DATA_STORE). When a cache block lacks both read and write permission, the fallback raises a store access-fault (PMP) or store page-fault (PTE), but the spec mandates a load access-fault or load page-fault respectively — guest exception handlers expecting load-fault semantics will misroute the trap. More severely, if cbo.zero's probe_write validation passes but the subsequent memset() or cpu_stb_mmuidx_ra() byte-loop operates under a TLB entry that becomes stale before the actual write (MTTCG re-map or PMP reconfig by another hart), the guest zeroes memory it no longer owns. Any TCG fast-path that treats a CBO as a no-op without probing the address first (e.g., skipping probe_access on cbo.clean when D-Cache is not modeled) silently grants unpermitted cache-block access.
Consequence: privilege_escape
Pattern: check_zicbom_access|probe_write.*cbo|helper_cbo_zero.*memset|cbo.*nonfault|gen_helper_cbo_(clean_flush|inval|zero)|ZICBOM.*probe_access|ZICBOZ.*memset|cpu_stb_mmuidx_ra.*cbo

  cbo.zero uses probe_write() to validate store permission and obtain a host pointer, then writes zeros via memset(mem, 0, cbozlen) using the raw host pointer. This bypasses TCG softmmu TLB permission re-validation during the actual write. In an MTTCG scenario where another hart modifies PMP registers or page tables between probe_write() and memset(), the stale host pointer could point to memory the guest no longer owns.
