PR #2482  target=xiangshan  overall=compliant
Spec: XiangShan currently implements CBO permission checks correctly via implicit TlbCmd routing (read for cbo.clean/flush/inval, write for cbo.zero) in NewStoreUnit dispatch, with TLB/PMP both deriving access type from TlbCmd; violation would occur if TlbCmd assignment is corrupted, silently granting unprivileged access to cache-block operations across PMP/page-table boundaries
Violation: If the TlbCmd multiplexer at NewStoreUnit.scala:225 incorrectly assigns TlbCmd (e.g., cbo.clean/cbo.flush/cbo.inval receive TlbCmd.write instead of TlbCmd.read due to inverted isCboNoZero gate, or cbo.zero receives TlbCmd.read), the TLB permission check at TLB.scala:421-427 will verify the wrong access type (w instead of r or vice versa), and the PMP checker at PMP.scala:405-406 will apply the wrong permission bit (cfg.w instead of cfg.r). The hardware would grant access through PMP/TLB with insufficient or incorrect privilege verification.
Consequence: privilege_escape
Pattern: Mux\(isCbo.*TlbCmd\.(read|write)|LSUOpType\.isCbo.*cmd|pmp_check.*cfg\.(r|w).*cbo|TlbCmd\.is(Read|Write).*cbo
