PR #2482  target=linux  overall=compliant
Spec: CBO management instructions (clean/flush/inval) now explicitly require read permission and cbo.zero requires write permission on the accessed page; kernel S-mode use of these instructions on untrusted user addresses without prior access_ok() or equivalent permission validation can bypass the page-table-enforced security boundary, enabling cache-based side-channel probing via cbo.inval or unauthorized memory zeroing via cbo.zero.
Violation: Kernel S-mode code executes CBO management instructions (cbo.clean, cbo.flush, cbo.inval) on a user virtual address without first verifying that the owning user task holds read permission for that page, or executes cbo.zero on a user virtual address without verifying the user holds write permission — relying on the implicit assumption that CBO permission semantics mirror explicit load/store rather than on explicit page-table / PMP checks performed by hardware at the privilege level of execution.
Consequence: function_loss
Pattern: cbo\.(clean|flush|inval|zero)\b.*(user_addr|uaddr|__user|copy_to|copy_from|get_user|put_user|access_ok)
