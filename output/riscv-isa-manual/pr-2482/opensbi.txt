PR #2482  target=opensbi  overall=bug_confirmed
Spec: CBO invalidation from S-mode on PMP_R shared regions can evict M-mode cached data, breaking firmware invariant that read-only S-mode access cannot perturb M-mode cache state
Violation: OpenSBI configures a PMP entry with read permission (PMP_R) granting an S-mode domain shared read access to a memory region also accessed by M-mode firmware. The S-mode domain issues cbo.inval or cbo.flush on addresses within this region, evicting M-mode's cached entries (including potentially dirty cache lines of lock variables, IPC metadata, or domain state). M-mode subsequently reads stale memory or loses pending writes, violating the invariant that S-mode read-only access cannot perturb M-mode's view of shared memory.
Consequence: data_corruption
Pattern: SBI_DOMAIN_MEMREGION_IS_SUR_MRW|SBI_DOMAIN_MEMREGION_IS_SUR_MR|cbo\.inval|cbo\.flush
------------------------------------------------------------
[bug_confirmed] lib/sbi/sbi_hart.c:152-155  mstatus_init
  Unconditionally delegates cbo.inval and cbo.flush to S-mode hardware with ENVCFG_CBIE_INV (the most aggressive setting: invalidate without flush). With CBIE=INV, cbo.inval silently evicts cache lines without first writing back dirty data, even on read-only memory. M-mode's dirty cache lines in shared SUR_MRW/SUR_MR regions are vulnerable to silent eviction by a malicious S-mode domain.

  | __set_menvcfg_ext(SBI_HART_EXT_ZICBOM,
  |                   ENVCFG_CBIE_INV << ENVCFG_CBIE_SHIFT)

[bug_confirmed] lib/sbi/sbi_domain.c:220-271  sbi_domain_check_addr
  Domain memory access check has no concept of CBO operations. The access_flags only recognizes SBI_DOMAIN_READ, WRITE, EXECUTE, MMIO. A cbo.inval issued by S-mode on a SUR_MRW/SUR_MR region passes the check as a 'read', even though cbo.inval is a destructive cache eviction, not a data load. No SBI_DOMAIN_CBO_INVAL or SBI_DOMAIN_CBO_FLUSH access type exists to distinguish cache operations from true reads.

[bug_confirmed] lib/sbi/sbi_domain.c:179-181  sbi_domain_get_smepmp_flags
  SUR_MRW regions (SU read-only, M read/write) are encoded as PMP_W under Smepmp. This PMP encoding grants S-mode read access but cannot distinguish between a data load and a cache eviction (cbo.inval). The PMP hardware has no mechanism to block cache-block operations independently of reads. For SUR_MR regions, the encoding is PMP_L|PMP_R|PMP_W|PMP_X (line 164), which similarly grants read access allowing cbo.inval.
