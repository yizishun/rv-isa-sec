PR #2503  target=xiangshan  overall=compliant
Spec: mseccfg.SSEED and USEED are hardwired Read-Only zero with seed CSR unimplemented, violating the spec's access-control model that requires writable fields to gate S/U-mode entropy source access via Zkr extension
Violation:
  In XiangShan RTL, SSEED (bit 9) and USEED (bit 8) of mseccfg are declared as
  RO (Read-Only) fields with implicit reset value 0 and no writable path. This
  hardwires both fields to zero permanently. The seed CSR (address 0x015) is
  listed in the CSR address table but has no CSRModule implementation
  registered in csrRwMap, so any access to seed triggers the noCSRIllegal path
  regardless of privilege mode. Together, these mean (a) the access control
  mechanism mandated by the spec (USEED/SSEED gating U/S-mode seed access) can
  never be enabled, and (b) the seed CSR itself is entirely absent, making the
  Zkr entropy source extension non-functional at the hardware level. If seed
  CSR were later added without changing SSEED/USEED from RO to RW/WARL, S/HS-
  mode and U-mode seed accesses would always raise illegal-instruction
  regardless of the spec-intended access control bit values.
Consequence: function_loss
Pattern:
  RO\((9|8)\).*(SSEED|USEED)|SSEED.*RO\(9\)|USEED.*RO\(8\)|seed.*0x15.*noCSRIl
  legal|csrRwMap.*seed|Mseccfg.*CSRBundle
