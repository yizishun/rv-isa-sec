PR #1541  target=xiangshan  overall=compliant
Spec: XiangShan CLINT RegField(ipiWidth-1)=RegField(31) reserved bits correctly read-as-zero; violation risk exists if reserved RegField exposes adjacent hart MSIP or internal device state through bits 31:1 of the 32-bit memory-mapped msip register
Violation: In XiangShan RTL, the CLINT implements MSIP as a 1-bit register (ipi(i): Reg(UInt(1.W))) exposed through RegMapper as RegField(1, r) :: RegField(31), which correctly maps bit 0 to the 1-bit MSIP register and reserves bits 31:1 as read-zero/write-ignored. No actual spec violation exists in the current XiangShan CLINT implementation. However, the vulnerability condition would manifest if: (1) the CLINT regmap failed to mask bits 31:1 to read as zero — e.g., if RegField(ipiWidth-1) were replaced with actual register-backed fields that expose adjacent hart MSIP state or internal device state to bits 31:1, causing cross-hart info_leak through the memory-mapped register read; or (2) writes to bits 31:1 were not silently ignored and instead affected adjacent hardware state (e.g., corrupting the next hart's MSIP bit or mtimecmp registers through aliased byte-enable logic), enabling privilege_escape via unauthorized IPI injection. Additionally, the propagation pipeline (CLINT ShiftRegister with intStages=0 → IntNexusNode → MemBlock RegNext → CSR platformIRP.MSIP → mip.MSIP) introduces a bounded 1-cycle delay, which satisfies the spec's 'eventually but not necessarily immediately' clause but means software polling mip.MSIP in the same cycle as the memory-mapped write may observe stale state.
Consequence: info_leak
Pattern: RegField\(ipiWidth\s*-\s*1\)|RegField\(31\)|RegField\(.*\bipi\b
