PR #2729  target=freebsd-src  overall=compliant
Spec: New vtype CSR fields (lambda[2:0], altfmt_A, altfmt_B, bs) introduced by Zvvm matrix extensions must be preserved across context switches; FreeBSD's vector context save/restore path must not mask these bits or they will leak between processes
Violation:
  FreeBSD kernel context-switch code saves/restores vtype CSR but masks out or
  fails to preserve the newly-defined Zvvm bits (lambda[2:0] at
  vtype[XLEN-2:XLEN-4], altfmt_A at vtype[9], altfmt_B at vtype[10], bs at
  vtype[11]). When process A configures these bits for matrix tile operations
  and is preempted, process B either inherits A's tile geometry (info leak of
  computational structure) or has its own tile configuration silently
  corrupted on restore if the kernel zeroes unknown bits on vtype write.
Consequence: info_leak
Pattern:
  vtype.*&=|vtype.*mask|vtype.*write|save.*vtype|restore.*vtype|vsetvli|vsetvl
