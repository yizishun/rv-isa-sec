PR #2729  target=linux  overall=potential_risk
Spec: New vtype CSR fields (lambda, altfmt_A, altfmt_B, bs) added by Zvvm IME must be context-switched by the kernel; failure to save/restore these WARL fields leaks IME tile geometry and format state across processes
Violation:
  When the Linux kernel context-switches vector state without saving/restoring
  the full vtype CSR including the new lambda[2:0] (vtype[XLEN-2:XLEN-4]),
  altfmt_A (vtype[9]), altfmt_B (vtype[10]), and bs (vtype[11]) fields
  introduced by the Zvvm IME extension, a user process may observe or
  manipulate another process's IME tile configuration
Consequence: info_leak
Pattern:
  __riscv_v_state_save|__riscv_v_state_restore|vstate_save|vstate_restore|vtyp
  e_save|vtype_restore
------------------------------------------------------------

[potential_risk] arch/riscv/include/asm/vector.h:167-194  __vstate_csr_restore
  Uses vsetvl to restore vtype, but vsetvl architecturally zeroes bits
  XLEN-2:8 (standard reserved region). On Zvvm hardware, this would silently
  clobber lambda[2:0] (vtype[XLEN-2:XLEN-4]), altfmt_A (vtype[9]), altfmt_B
  (vtype[10]), and bs (vtype[11]). The vsetvl instruction is not extensible to
  preserve non-standard vtype fields, creating a latent architectural gap for
  any extension that defines those fields.
  | asm volatile (
  |   ".option push\n\t"
  |   ".option arch, +zve32x\n\t"
  |   "vsetvl  x0, %2, %1\n\t"

  |   "csrw " __stringify(CSR_VSTART) ", %0\n\t"
  |   : : "r" (src->vstart), "r" (src->vtype), "r" (src->vl));
