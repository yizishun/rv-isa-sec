PR #2974  target=qemu  overall=compliant
Spec: rmw_mie64() fails to enforce WARL read-only-zero for mie bits corresponding to unimplemented interrupt sources, allowing guest writes to non-existent interrupt-enable bits to persist and be read back, violating spec WARL semantics required for correct guest interrupt controller discovery
Violation:
  QEMU's rmw_mie64() at target/riscv/csr.c:2267 applies the writable mask as
  wr_mask & all_ints, where all_ints includes all platform-specific interrupt
  bits (LOCAL_INTERRUPTS = ~0x1FFFULL, i.e., bits 16 and above). The spec now
  explicitly requires that bits of mie that are not writable (i.e., correspond
  to unimplemented interrupt sources) must be read-only zero. QEMU does not
  force unimplemented platform interrupt bits to read-only zero — a guest CSR
  write to unimplemented mie bits persists and is observable on read-back,
  violating WARL read-only-zero semantics.
Consequence: denial_of_service
Pattern:
  mie CSR write handler lacks WARL masking to force read-only-zero for
  unimplemented interrupt source bits; all_ints mask is overly permissive,
  treating all platform-specific bits as writable unconditionally
