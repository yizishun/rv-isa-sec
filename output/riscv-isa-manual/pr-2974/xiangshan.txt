PR #2974  target=xiangshan  overall=compliant
Spec: mie local interrupt enable bits 14-47,49-63 are hardwired to read-zero via regOut override, preventing any corresponding wired interrupt source from ever being enabled even if the internal reg state is non-zero, violating spec requirement that mie bits must be writable if the interrupt can become pending
Violation:
  In XiangShan RTL, the mie CSR module (MachineLevel.scala:114-115)
  unconditionally forces regOut for local interrupt enable bits 14-63
  (excluding bit 13 LCOFIE) to read-only zero via
  `regOut.getLocal.filterNot(_.lsb == InterruptNO.COI).foreach(_ := 0.U)`,
  while the internal register for those same bits can be updated non-zero from
  fromSie/fromVSie signals (lines 105-112). The interrupt filter
  (InterruptFilter.scala:53) computes pending interrupts as `mip & mie &
  (~mideleg).asUInt` using `mie.regOut`, so any local interrupt source wired
  to bits 14-47 or 49-63 with a valid pending signal will never be taken
  because the corresponding mie enable bit is hardwired to zero at the read
  path. The spec mandates that 'a bit in mie must be writable if the
  corresponding interrupt can ever become pending'; if any of these local
  interrupts has a hardware pending source, the RTL violates this by
  preventing software from ever enabling the interrupt.
Consequence: denial_of_service
Pattern:
  regOut.getLocal.filterNot.*foreach.*:= 0\.U.*mie|InterruptEnableBundle.*regO
  ut.*local.*zero|mie.*local.*enable.*hardwired.*read.only.zero|CSRModule.*Mie
  .*regOut\.getLocal
