PR #2521  target=qemu  overall=compliant
Spec: SPMP permission encoding table distinguishes S-mode-only, U-mode, and Shared-Region rules with sstatus.SUM interaction; incorrect emulation of SHARED/U/SUM bit logic would allow U-mode to read/write S-mode memory or vice versa, constituting privilege escalation
Violation: QEMU's TCG emulation of SPMP permission checks incorrectly evaluates the encoding table for Shared-Region rules (spmpcfg.SHARED=1, spmpcfg.U=1) or U-mode rules (spmpcfg.SHARED=0, spmpcfg.U=1 with sstatus.SUM), causing S-mode accesses to be enforced when they should be denied, or U-mode accesses to be allowed when they should be blocked. This can occur if the spmpcfg bitfield layout (SHARED at bit 9, U at bit 8) is incorrectly shifted, or if the sstatus.SUM test is applied to Shared-Region rules where the spec mandates SUM is ignored.
Consequence: privilege_escape
Pattern: spmpcfg.*SHARED|spmpcfg.*U|sstatus.*SUM.*spmp|spmp.*access_check|spmp.*enforce|get_physical_address.*spmp|riscv_cpu_tlb_fill.*spmp

The code locations provided for audit are all empty (:0-0), confirming the feature is absent. As a result, none of the specified vulnerability patterns (spmpcfg.SHARED/U bitfield misplacement, sstatus.SUM misapplication to Shared-Region rules) are applicable — there is no code to evaluate against the security spec.
