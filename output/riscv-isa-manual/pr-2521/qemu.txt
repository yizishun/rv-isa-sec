PR #2521  target=qemu  overall=not_implemented
Spec: SPMP adds S-level physical memory protection checked on every non-M-mode memory access with priority over PMP/PMA; QEMU must integrate SPMP checks into the TCG memory translation path, enforce WARL field constraints on all SPMP CSRs, correctly handle lock-bit write-ignore semantics on indirect CSR accesses, enforce SPMP/paging mutual exclusion, and implement SFENCE.VMA ordering for SPMP CSR writes on multi-hart SMP
Violation:
  QEMU's TCG memory access path (get_physical_address or equivalent) performs
  PMP/PMA checks but omits SPMP checks for S-mode and U-mode memory accesses
  when satp.MODE == Bare and Sspmp is enabled, or SPMP checks are performed
  but PMP/PMA exceptions incorrectly take priority over SPMP exceptions, or
  SPMP matching logic fails to require all bytes of an access to match the
  same entry, or indirect CSR writes (via siselect/sireg/sireg2) succeed on
  locked SPMP entries (spmpcfg[i].L == 1), or sspmpswitch writes take effect
  without subsequent SFENCE.VMA ordering on multi-hart SMP, or
  spmpcfg.SHARED/U/R/W/X WARL fields accept and expose reserved/illegal bit
  patterns on read-back, or SPMP checks are applied when satp.MODE != Bare
  (mutual exclusion violation with paging).
Consequence: privilege_escape
Pattern:
  get_physical_address.*spmp|pmp_hart_has_privs|spmpcfg|spmpaddr|sspmpswitch|s
  iselect|miselect|sireg|mireg|RISCV_CPU.*spmp|pmp_is_active|spmp_.*check|ssta
  tus.*SUM.*spmp
