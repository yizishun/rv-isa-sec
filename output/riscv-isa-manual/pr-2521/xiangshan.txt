PR #2521  target=xiangshan  overall=compliant
Spec: SPMP/paging mutual exclusivity enforcement: failure to atomically synchronize satp.MODE-based SPMP gating with the pipeline creates a window where memory accesses are checked by neither SPMP nor paging, allowing U-mode to access arbitrary physical memory
Violation: In XiangShan RTL, the SPMP check enable signal is derived from satp.MODE==Bare decoded in the TLB/MMU module. If the satp CSR write takes effect immediately in the CSR register file but the corresponding SPMP disable/enable transition is not synchronized with pipeline flushes, in-flight memory instructions in the load/store queue or instruction prefetch buffer may be checked against the wrong isolation mechanism — either SPMP rules when paging is newly enabled (causing spurious page faults), or paging page-table walks when Bare+SPMP is newly selected (bypassing SPMP protection entirely). Additionally, when V=1 and hgatp.MODE goes from non-Bare to Bare, stale VS/VU accesses in the pipeline could bypass SPMP enforcement if the SPMP activation signal is a multicycle path that lags behind hgatp.MODE updates. The spec mandates strict mutual exclusivity: satp.MODE!=Bare means paged virtual memory only, satp.MODE==Bare with Sspmp means SPMP only, and at no point may both or neither apply to S/U-mode accesses.
Consequence: privilege_escape
Pattern: Mux(condition = satp.mode === Bare) selecting between TLB page-table-walk result and SPMP match result; OR wire spmp_active = (satp_mode === Bare) & sspmp_implemented used as enable without pipeline synchronization; OR any combinational path where hgatp.MODE change doesn't immediately gate spmp_check_en in the load/store unit
