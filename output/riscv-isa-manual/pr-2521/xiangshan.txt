PR #2521  target=xiangshan  overall=not_implemented
Spec: SPMP permission decoder must bit-exactly match the 6-row×4-column encoding table in the spec; any Chisel Mux/switch mis-encoding in the {SHARED, U, RWX, SUM}→{Deny,Enforce,EnforceNoX} logic creates a hardware privilege escape where S/U-mode accesses bypass physical memory restrictions
Violation:
  When the XiangShan SPMP checker's permission-decision hardware (a
  combinational decoder mapping {spmpcfg[i].SHARED, spmpcfg[i].U,
  spmpcfg[i].RWX, sstatus.SUM, effective_priv_mode, access_type} to {Deny,
  Enforce, EnforceNoX, Reserved}) incorrectly encodes any row of the SPMP
  Encoding Table, e.g., treating a Reserved encoding (RWX=010 or RWX=011, or
  SHARED=1 with U=0) as Enforce instead of raising a fault, or incorrectly
  evaluating the sstatus.SUM-dependent S-mode access path such that an S-mode
  access to a U-mode rule with SUM=0 is Enforced instead of Denied. This is a
  pure combinational-logic correctness hazard: the decoder is a new hardware
  block with 4 input variables (SHARED, U, RWX[2:0], SUM) producing per-
  access-type decisions; a single bit error in the Chisel `switch`/`Mux` tree
  or an incorrect default case silently inverts the access-control outcome.
Consequence: privilege_escape
Pattern:
  MuxLookup|switch|is.|=== .U|===
  .SHARED|VecInit|MuxCase.*spmpcfg|Mux.*sstatus.*SUM.*spmp
