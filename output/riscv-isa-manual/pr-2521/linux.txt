PR #2521  target=linux  overall=compliant
Spec: SPMP indirect CSR writes (via siselect/sireg/sireg2) are explicitly unordered with respect to subsequent memory accesses; kernel context switch must issue SFENCE.VMA between the final SPMP CSR write and the first user-mode memory access of the incoming task, or stale SPMP state allows one process to access another's physical memory regions.
Violation: In a NOMMU Linux kernel (CONFIG_MMU=n, satp.MODE=Bare) with Sspmp, when the kernel writes spmpaddr or spmpcfg via siselect/sireg/sireg2 indirect CSR access during context switch and immediately resumes the next task's memory accesses without first executing SFENCE.VMA (rs1=x0, rs2=x0), the new task's memory accesses may be checked against stale SPMP entries from the previous task, violating inter-process memory isolation.
Consequence: privilege_escape
Pattern: sireg|sireg2|siselect.*spmp|__switch_to.*spmp|switch_mm.*spmp|flush_tlb.*spmp|SFENCE_VMA.*spmp|NOMMU.*context_switch|satp.*Bare.*spmp
