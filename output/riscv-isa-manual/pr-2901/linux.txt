PR #2901  target=linux  overall=compliant
Spec: Zisb introduces TEB (control-flow), MDB (memory-disambiguation), and DPB (data-value) as strict-contract speculation barriers — not optional hints — encoded via Zimop to close in-domain Spectre leaks; the kernel must emit them at bounds-check sites and store-to-load forwarding boundaries or hardware speculation will violate software security invariants observable through cache side channels.
Violation:
  When a Zisb-capable hart executes a conditional branch that guards a
  dependent load touching security-critical data (e.g., uaccess bounds check
  indexed memory access, user-register-gated indirect function pointer load,
  stack-stored function pointer followed by load that may bypass that store
  via memory disambiguation), and no TEB/MDB/DPB barrier is placed between the
  guard and the dependent load, speculative execution may transiently bypass
  the software security boundary and leak the accessed secret through cache
  timing.
Consequence: info_leak
Pattern:
  conditional branch (bgeu|bltu|beq|bne|beqz|bnez) guarding a security
  boundary, followed within basic-block reach by a load whose address depends
  on the guarded value, with zero intervening teb/mdb/dpb barrier instructions
