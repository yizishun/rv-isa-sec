PR #2901  target=freebsd-src  overall=potential_risk
Spec: Zisb barrier instructions encoded via Zimop silently no-op on non-Zisb hardware, defeating Spectre mitigations FreeBSD places around bounds checks, context switches, and VM boundaries
Violation: FreeBSD kernel executes Zisb speculation barrier instructions (TEB/MDB/DPB) on hardware that either lacks Zisb—treating them as Zimop no-ops—or incorrectly implements the barrier semantics, so transient speculation leaks kernel data through cache-based side channels across context-switch (swtch.S savectx), copyin/copyout bounds checks (copyinout.S), signal-delivery (exec_machdep.c), or bhyve VM-entry/exit (vmm_riscv.c henvcfg paths) boundaries.
Consequence: info_leak
Pattern: isb|fence|teb|mdb|dpb|SPECULATION|spectre|cache.side.channel|transient.execution|Zimop|Zisb
------------------------------------------------------------
[potential_risk] sys/riscv/riscv/swtch.S:258-357  cpu_switch
  Context-switch path (cpu_switch/savectx) performs no speculation barrier between saving old thread state and restoring new thread state. On hardware susceptible to transient-execution attacks, predictor state from the old thread could leak into the new thread's execution without a Zisb TEB/MDB/DPB barrier. Currently the kernel emits no Zisb instructions at all, so the specific violation condition (executing Zisb on non-Zisb HW) is not triggered; however the absence of any speculation barrier is a gap.
