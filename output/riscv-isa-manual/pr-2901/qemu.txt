PR #2901  target=qemu  overall=compliant
Spec: Zisb barrier instructions (TEB/MDB/DPB) encoded via Zimop code points must not be treated as optional NOPs — they impose a strict hardware contract; QEMU TCG must emit barrier ops to pin memory ordering across them, or guest security barriers against Spectre-class transient-execution data leaks are silently defeated under emulation
Violation:
  QEMU TCG decodes Zisb barrier instructions (TEB, MDB, DPB) as NOPs without
  emitting TCG barrier/memory-ordering ops, allowing the TCG optimizer to
  reorder guest loads/stores across the barrier position. Additionally, if
  QEMU recognizes these as plain Zimop MOP NOPs, guest software executing Zisb
  barriers on real hardware that needs them for speculation control will have
  its security assumptions silently nullified under emulation.
Consequence: info_leak
Pattern:
  Zimop MOP decode path that treats all MOP encodings as NOPs without
  distinguishing Zisb barrier opcodes; TCG translator that emits no barrier IR
  (e.g., no gen_mb, no tcg_gen_mb, no fence) for Zisb instructions; missing
  isa_ext_zisb in RISCVCPUConfig or misa_ext mask; translator functions for
  MOP-RR/FUNCT7 encodings that decode-and-discard without calling gen_barrier
  or equivalent
