PR #2901  target=qemu  overall=bug_confirmed
Spec: Zisb barriers (TEB/MDB/DPB) use Zimop MOP encodings; QEMU TCG inherently satisfies barrier semantics since it performs no speculative execution, but failure to decode these instructions as valid NOPs causes guest DoS via spurious illegal instruction traps; on KVM, failure to expose the extension to guests deprives them of speculation barriers needed for in-domain Spectre-variant mitigations on real hardware
Violation: QEMU TCG does not decode Zisb instructions (TEB/MDB/DPB) as valid, causing illegal instruction traps for guest software that relies on them; OR QEMU KVM fails to advertise the Zisb extension to the guest when host hardware supports it, preventing guest kernels from placing speculation barriers at software-defined security boundaries
Consequence: denial_of_service
Pattern: trans_isb|decode_zisb|TEB|MDB|DPB|ZIMOP.*barrier|MOPS.*speculation|illegal_instruction.*zisb|riscv_has_ext.*Zisb
------------------------------------------------------------

[bug_confirmed] target/riscv/insn32.decode:1037-1054  (MOP decode definitions, lines 1037-1054)
  The MOP decode space defines only NOP-like encodings (mop_r_n, mop_rr_n) that write zero to rd. No Zisb barrier instructions (TEB: MOP.R 0/1, MDB: MOP.R 2, DPB: MOP.R 3) are decoded. The mop_r_n pattern (1.00..0111..) may also mis-decode Zisb-occupied encodings as generic MOP NOPs rather than recognizing them as speculation barriers with distinct semantics.
  | mop_r_n    1 . 00 .. 0111 .. ..... 100 ..... 1110011 @mop5
  | mop_rr_n   1 . 00 .. 1 ..... ..... 100 ..... 1110011 @mop3
  | /* No TEB/MDB/DPB decode entries exist */

[potential_risk] target/riscv/insn_trans/trans_rvzimop.c.inc:25-37  trans_mop_r_n, trans_mop_rr_n
  MOP NOP translation treats all matched MOP encodings as register-zeroing NOPs. If Zisb barrier encodings happen to match the mop_r_n/mop_rr_n wildcard patterns, they would be silently executed as NOPs rather than triggering speculation barriers. This means guest software relying on TEB/MDB/DPB for Spectre mitigation would have ineffective barriers (silent failure, not illegal instruction).
