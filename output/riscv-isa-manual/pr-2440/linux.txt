PR #2440  target=linux  overall=compliant
Spec: stval holds raw instruction addresses on EXC_INST_PAGE_FAULT but pointer-masked data addresses on EXC_LOAD/STORE_PAGE_FAULT; kernel page-fault code must not uniformly untag or transform stval without checking regs->cause
Violation:
  In arch/riscv/kernel/entry.S and arch/riscv/mm/fault.c, the kernel reads
  CSR_TVAL into pt_regs->badaddr on every exception entry and uses it directly
  in handle_page_fault() for VMA lookup and signal delivery. If pointer
  masking (Zpm/Ssnpm) is enabled for a privilege mode, the hardware writes the
  *transformed* (masked) data-access address to stval for load/store page
  faults, but writes the *raw untransformed* instruction address for
  instruction page faults. The kernel violates the spec if it applies any
  additional pointer-unmasking or sign-extension transformation to stval
  values without first checking regs->cause to distinguish EXC_INST_PAGE_FAULT
  from EXC_LOAD_PAGE_FAULT/EXC_STORE_PAGE_FAULT, because the instruction-fault
  address is already the raw PC and would be corrupted by unmasking.
Consequence: data_corruption
Pattern:
  regs-
  >badaddr.*PMLEN|CSR_TVAL.*sign.extend|CSR_TVAL.*pointer.mask|badaddr.*untag|
  handle_page_fault.*transform.*addr
