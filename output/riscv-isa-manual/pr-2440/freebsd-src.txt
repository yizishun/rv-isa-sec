PR #2440  target=freebsd-src  overall=compliant
Spec: FreeBSD trap handler treats stval as raw unmasked virtual address unconditionally; enabling pointer masking causes page faults on tagged user addresses to fail VIRT_IS_VALID() and pmap resolution, yielding spurious SIGSEGV or fatal kernel panic
Violation: When Ssnpm/Smnpm pointer masking is enabled via senvcfg, the hardware writes the pointer-masked (transformed) virtual address into stval for page/access/misaligned faults on masked memory accesses. FreeBSD's page_fault_handler() at sys/riscv/riscv/trap.c:231-276 uses frame->tf_stval directly as an untransformed virtual address — passing it through VIRT_IS_VALID(), trunc_page(), pmap_fault(), vm_fault_trap(), and call_trapsignal(si_addr) — without any awareness, tracking, or reversal of the hardware pointer-mask transformation. Concurrently, stval written for non-memory-access exceptions (e.g., illegal instruction) is NOT masked per the clarified spec, but FreeBSD's single code path treats all stval values identically, with no exception-type dispatch to distinguish address values from non-address values before address validation.
Consequence: denial_of_service
Pattern: frame->tf_stval (used|passed|checked) without (senvcfg|pm_en|pointer.mask|pm_current|Zpm|ssnpm|smnpm)
