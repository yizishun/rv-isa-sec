PR #2440  target=xiangshan  overall=compliant
Spec: If hardware unconditionally applies pointer masking to all addresses written to *tval CSRs on trap entry — rather than only to addresses from pointer-masked explicit memory accesses — instruction-fetch fault addresses written to stval will be corrupted, causing the supervisor trap handler to receive a mangled instruction address and potentially misidentify or fail to handle the fault.
Violation:
  In XiangShan RTL, when the trap delivery logic in the CSR module writes an
  instruction-fetch fault address (e.g., instruction page fault, instruction
  access fault, instruction guest-page fault) to stval/mtval, the hardware
  incorrectly applies pointer-masking (the 'ignore' transformation) to the
  instruction address before writing it to the *tval CSR. This violates the
  spec because instruction fetches are explicitly NOT subject to pointer
  masking — only data access addresses generated by explicit memory
  instructions are. The hardware must distinguish between instruction-fetch
  fault addresses (no PM applied) and data-access fault addresses (PM applied
  as part of the original memory access).
Consequence: data_corruption
Pattern:
  tval.*pm|pointer_mask.*tval|stval.*mask|mtval.*mask|trap.*addr.*pm|exception
  .*addr.*mask|inst_page_fault.*mask|ifetch.*pm|ignore_transform.*stval|PMLEN.
  *tval
