PR #2440  target=xiangshan  overall=compliant
Spec: Applying Zpm pointer masking to instruction-fetch fault addresses written to *tval corrupts the trap handler's ability to identify the faulting instruction, violating the spec clarification that only pointer-masked (data) addresses—not instruction addresses—undergo PM transformation in *tval.
Violation: When an instruction-fetch exception (e.g., instruction page fault, instruction access fault, instruction guest-page fault) occurs while Zpm pointer masking is enabled (pm bits in senvcfg/menvcfg configured with non-zero mask), if the XiangShan hardware writes the faulting instruction address to stval/mtval/htval and incorrectly applies pointer masking (i.e., clears/sets upper bits according to the active PM mask), the instruction address stored in *tval is corrupted.
Consequence: function_loss
Pattern: (tval_write|stval_write|mtval_write|htval_write|ExceptionToTval|GPADdrToTval).*(pm_enabled|pm_mask|ptr_mask|applyPM|pointerMask)
