PR #2440  target=qemu  overall=compliant
Spec: QEMU must not apply pointer masking to instruction addresses stored in stval on trap delivery; uniform masking leaks untagged instruction addresses to supervisor mode, breaking guest kernel pointer-masking security invariants.
Violation: QEMU applies pointer masking uniformly to all addresses written to stval during exception delivery, without distinguishing instruction-fetch addresses (which must NOT be pointer-masked per this clarification) from data-access addresses (which must be pointer-masked). Specifically, when QEMU sets stval for exceptions like instruction page faults, fetch access faults, or illegal instruction traps where stval holds the guest PC, the emulator must not apply pmask to the stored value.
Consequence: info_leak
Pattern: riscv_cpu_do_interrupt.*stval|env->xtval.*pmask|set_tval.*pm|xtval\s*=.*get_physical|trigger.*stval.*mask
