PR #2601  target=qemu  overall=bug_confirmed
Spec: mseccfg.MML redefines PMP rule semantics (M-mode-only, S/U-only, Shared-Region) with sticky lockdown; QEMU failing to gate PMP checks on MML state would break guest Smepmp M-mode isolation, letting S/U-mode access M-mode-only regions or M-mode execute from unapproved memory
Violation: QEMU's PMP check logic (likely in target/riscv/pmp.c) does not re-evaluate PMP rule classification when mseccfg.MML is set, causing M-mode-only rules (pmpcfg.L=1 under MML) to still be enforced in S/U-mode, or S/U-mode-only rules (pmpcfg.L=0 under MML) to incorrectly grant M-mode access, or Shared-Region encodings (pmpcfg.RW=01, pmpcfg.LRWX=1111) to be treated as reserved/ignored instead of enforced with correct access semantics. Additionally, M-mode instruction fetch restrictions under MML=1 (only M-mode-only or locked Shared-Region with X) may not be enforced in TCG-translated code, allowing M-mode to execute from unapproved memory regions.
Consequence: privilege_escape
Pattern: pmpcfg_L.*mseccfg|mseccfg.*MML|pmp_is_.*|pmp_hart_has_privs|mseccfg_mml|Smepmp|pmpcfg.*locked|shared.region|M-mode.only

  Smepmp operation encoding is correct.
