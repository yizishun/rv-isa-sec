PR #2922  target=xiangshan  overall=bug_confirmed
Spec: Ziccrse extension norm requires RsrvEventual (guaranteed forward progress) for LR/SC on coherent cacheable main memory — PMA checker must enforce or deny CSRSC operations to non-RsrvEventual regions, and the LR/SC reservation hardware must provide the eventual success guarantee to avoid infinite livelock in synchronization primitives
Violation:
  When the Ziccrse extension is implemented in XiangShan but the PMA checker
  hardwires or is configured to report RsrvNone or RsrvNonEventual for any
  coherent cacheable main memory region, or when the LR/SC reservation
  hardware (LSU reservation station / reservation monitor) does not guarantee
  RsrvEventual forward progress semantics on those regions despite reporting
  PMA support for it.
Consequence: denial_of_service
Pattern:
  RsrvEventual|RsrvNonEventual|RsrvNone|reservation.*eventual|lr_sc.*pma|ziccr
  se.*pma|pma_checker.*rsrv|reservability.*PMA|LrScForwardProgress

[bug_confirmed] /home/yzs/riscv/XiangShan/src/main/scala/xiangshan/cache/dcache/DCacheWrapper.scala:1566-1570  reservation invalidation path
  The reservation set invalidation (invalid_resv_set) is wired ONLY to the
  writeback/eviction path — it triggers when a cache block is evicted and the
  address matches lrsc_locked_block. There is NO reservation invalidation on
  incoming coherent probes (TileLink Probe messages) from other harts' stores.
  Instead, probes to the reserved block are simply blocked (Probe.scala:87-91)
  during the reservation window. This means: (a) if the probe arrives after
  reservation expiry, the reservation sees stale data; (b) there is no
  mechanism to forward progress guarantee when coherence is maintained by a
  shared L2. The probe-blocking approach conflicts with RsrvEventual's
  requirement for reservations that are aware of coherent external stores.
  | mainPipe.io.invalid_resv_set := RegNext(
  |     wb.io.req.fire &&
