PR #2922  target=linux  overall=potential_risk
Spec: Ziccrse now formally requires RsrvEventual on coherent cacheable main memory; kernel qspinlocks implicitly depend on this guarantee but do not verify per-PMA-region reservability at runtime, so a firmware/hardware PMA misconfiguration could cause silent hart-level livelock.
Violation: When the kernel enables qspinlocks based on Ziccrse detection (RISCV_QUEUED_SPINLOCKS or RISCV_COMBO_SPINLOCKS with ziccrse available) and schedules a spinlock holder onto a hart whose coherent cacheable main memory PMA region lacks RsrvEventual support, the LR/SC in cmpxchg may never make forward progress, causing the unlock path to livelock indefinitely.
Consequence: denial_of_service
Pattern: riscv_isa_extension_available(NULL, ZICCRSE) && (IS_ENABLED(CONFIG_RISCV_QUEUED_SPINLOCKS) || static_branch_likely(&qspinlock_key))
------------------------------------------------------------
[potential_risk] arch/riscv/kernel/setup.c:282-312  riscv_spinlock_init
  The kernel enables queued spinlocks solely based on ZICCRSE ISA string presence (line 297), without verifying the RsrvEventual PMA property that Ziccrse requires for its forward-progress guarantee. On a platform where M-mode firmware configures main memory without RsrvEventual, the LR/SC-based cmpxchg in qspinlock fast/slow paths can livelock indefinitely because lr.w reservation may never succeed. The kernel has no SBI mechanism to query PMA properties, so this gap is architectural — but it means the Ziccrse check alone is insufficient to guarantee correctness.

[potential_risk] arch/riscv/include/asm/cmpxchg.h:196-211  __arch_cmpxchg
  When Zacas is unavailable (no amocas), cmpxchg on RISC-V falls back to a plain lr.w/sc.w retry loop (lines 199-207). On a hart whose PMA region lacks RsrvEventual, this loop may spin forever. When qspinlocks are enabled based on Ziccrse detection, the fast-path lock acquisition (queued_spin_lock → atomic_try_cmpxchg_acquire → arch_cmpxchg_acquire) and slow-path queue transitions (atomic_try_cmpxchg_relaxed in xchg_tail when _Q_PENDING_BITS != 8) both execute this same LR/SC retry loop. With Ziccrse but no RsrvEventual, Ziccrse's forward-progress guarantee is voided.

[potential_risk] arch/riscv/include/asm/spinlock.h:23-29  SPINLOCK_BASE_DECLARE
  The combo-spinlock dispatch (arch_spin_lock/unlock at line 26) resolves at runtime via static_branch_unlikely(&qspinlock_key). There is no per-hart check: if qspinlock_key is enabled because CPU0 detected Ziccrse, all harts use qspinlocks even if a hotplugged CPU's PMA regions lack RsrvEventual. The queued_spin_unlock path (include/asm-generic/qspinlock.h:128) uses smp_store_release on lock->locked — a plain store, no LR/SC — so unlock itself won't livelock. But the holder of a lock queued behind a stuck LR/SC on another hart may never get the lock.
