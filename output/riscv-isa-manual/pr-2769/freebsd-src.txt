PR #2769  target=freebsd-src  overall=bug_confirmed
Spec: FreeBSD never defines or validates sstatus.UXL (bits 33:32); the kernel blindly propagates whatever UXL M-mode firmware set through context switches, trapframe copies, and bhyve vCPU state, risking illegal UXL values causing mis-speculated instruction-width interpretation for user-mode execution
Violation: FreeBSD kernel code writes the full sstatus register (or vsstatus in bhyve) via csrw without masking the UXL field (bits [33:32]) to architecturally legal values, or blindly propagates a corrupt UXL value set by M-mode firmware (OpenSBI) through context-switch save/restore and signal-delivery trapframe copies — and no FreeBSD code path currently validates that sstatus.UXL is an architecturally legal value because SSTATUS_UXL is not even defined in riscvreg.h.
Consequence: data_corruption
Pattern: csrw\s+sstatus|csrw\s+vsstatus|tf_sstatus\s*=|gp_sstatus\s*=|hyp_sstatus\s*=
------------------------------------------------------------
[bug_confirmed] sys/riscv/include/riscvreg.h:60-80  N/A (header definitions)
  SSTATUS_UXL is not defined. Bits [33:32] (UXL field) of sstatus have no corresponding mask/constant in riscvreg.h, making it structurally impossible to validate or sanitize the UXL field anywhere in the kernel. Every SSTATUS_ definition (UIE, SIE, UPIE, SPIE, SPP, FS, XS, SUM, SD) covers only bits 0-18 and 63/31, leaving the UXL field unaddressable by any kernel code.
  | #define SSTATUS_UIE    (1 << 0)
  | #define SSTATUS_SIE    (1 << 1)
  | #define SSTATUS_SUM    (1 << 18)
  | /* NO SSTATUS_UXL definition — bits [33:32] invisible to kernel */
  | #define SSTATUS_SD     (1ul << 63)

[potential_risk] sys/riscv/riscv/exception.S:101-104  save_registers (macro)
  csrr t0, sstatus reads the full sstatus register (including UXL) and stores it to tf_sstatus on the trapframe. This is the entry point: any corrupt UXL from hardware is faithfully captured into the trapframe and will be re-asserted on return via load_registers. This is the correct thing to do for save/restore fidelity, but combined with the lack of any UXL validation elsewhere, it means a corrupt UXL is preserved indefinitely across all context switches.
