PR #2493  target=freebsd-src  overall=potential_risk
Spec: FreeBSD S-mode kernel relies on M-mode firmware (OpenSBI) for PMP configuration; under Smepmp with MML+MMWP enabled, SBI ecalls passing physical addresses to M-mode will fault if firmware omits Shared-Region rules for SBI communication buffers, causing system-wide denial of service on first SBI timer/IPI call after boot
Violation: In the FreeBSD kernel, if M-mode firmware (OpenSBI) sets mseccfg.MML and mseccfg.MMWP before handing off to S-mode, but fails to configure M-mode-only or Shared-Region PMP rules covering the physical memory regions used as SBI call arguments (e.g., the SBI scratch buffer, IPI fences, timer memory-mapped registers), then any S-mode ecall into M-mode that passes pointers to non-shared S/U-mode-only memory will cause M-mode to take an access fault, because MMWP changes M-mode's default policy from 'ignored' to 'denied' for regions without a matching PMP rule.
Consequence: denial_of_service
Pattern: grep -n 'mseccfg\|MML\|MMWP\|RLB\|Smepmp\|smepmp\|pmpcfg.*L.*set\|PMP.*lock' sys/riscv/
