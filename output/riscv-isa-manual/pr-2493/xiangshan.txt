PR #2493  target=xiangshan  overall=bug_confirmed
Spec: RLB write-enable interlock with pmpcfg.L requires cross-CSR state inspection and permanent write-ignore latch until PMP reset; missing this creates a privilege-escalation path where locked PMP rules can be bypassed by toggling RLB
Violation: In XiangShan RTL, if the PMP CSR write logic does not inspect all pmpcfg.L bits and suppress mseccfg.RLB writes when RLB=0 and any pmpcfg.L=1 (including disabled entries), the RLB bit can be set despite existing locked PMP rules. Additionally, the write-ignore must be permanent until a PMP reset — a naive implementation that only checks on-write but allows RLB to become writable after a transient pmpcfg change would violate the sticky lock-out semantics. The PMP checker must also treat RLB=1 as a temporary override of locked-rule write-protection for pmpcfg/pmpaddr registers, but must NOT allow RLB=1 to override the MML-mediated execution-prevention rules (rule addition with execute privilege after MML=1 is still denied unless RLB=1 is explicitly set before the rule write).
Consequence: privilege_escape

[bug_confirmed] src/main/scala/xiangshan/backend/fu/NewCSR/MachineLevel.scala:319-327  MachineLevel.mseccfg
  mseccfg Smepmp control fields (RLB bit 2, MMWP bit 1, MML bit 0) are declared as RO (Read-Only) with no write function logic. Per the Smepmp spec (Priv 1.13, Sec 3.7.2), these fields must be WARL with specific write-constraint behavior: RLB writes are conditionally ignored when RLB=0 and any pmpcfg.L=1 (including disabled entries), and the ignore must be sticky until PMP reset. MML and MMWP must also be WARL. By making them RO, the entire Smepmp extension is non-functional — software that relies on Smepmp for M-mode isolation, whitelist policy, or rule-locking bypass will silently get no protection. The CSR address (0x747) and bit positions are correct per spec, but the fields are hardwired to their reset values (all 0) with no write path. This creates a false sense of security: the CSR exists at the right address with the right field layout, suggesting Smepmp is implemented, but the control bits can never be modified.

  |     val USEED = RO( 8)
  |     val RLB   = RO( 2).withDescription("Rule-locking bypass control from the Smepmp extension.")
  |     val MMWP  = RO( 1).withDescription("Machine-mode whitelist policy control from the Smepmp extension.")
  |     val MML   = RO( 0).withDescription("Machine-mode lock-down control from the Smepmp extension.")
