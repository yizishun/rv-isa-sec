PR #2493  target=linux  overall=compliant
Spec: Smepmp MML=1 enforces M-mode/S-mode memory isolation in hardware: S/U-mode-only PMP regions deny all M-mode access, breaking the kernel's implicit assumption that M-mode firmware (OpenSBI) can always dereference kernel-passed pointers during SBI calls
Violation:
  In the Linux kernel (S-mode), any SBI ecall that passes a kernel virtual
  address pointer to M-mode firmware, expecting M-mode to read/write that
  memory, when Smepmp is active (mseccfg.MML=1) and the target physical page
  is covered by an S/U-mode-only PMP rule (pmpcfg.L=0) rather than a Shared-
  Region rule — M-mode will take an access fault instead of fulfilling the
  request, potentially causing silent SBI call failure, M-mode trap loop, or
  system hang.
Consequence: denial_of_service
Pattern:
  sbi_ecall\(|SBI_EXT_|riscv_sbi_|__sbi_|sbi_call\(|ecall\(.*SBI
