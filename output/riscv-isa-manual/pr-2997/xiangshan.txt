PR #2997  target=xiangshan  overall=compliant
Spec: mstatus.MS dirty tracking must be atomic with tile state modification; decoupled CSR update and tile SRAM write in pipeline creates context-switch info-leak window
Violation: When the hardware executes a matrix tile-modifying instruction (vtfmm.tvv, vtmmu.tvv, vtmv.t.v, vtzero, vtle*, vtse*), the mstatus.MS[30:29] field must transition to Dirty (2'b11) in the same commit cycle as the tile SRAM write. If the RTL CSR update path is decoupled from the tile write commit (e.g., MS update in WB stage but tile SRAM write in a later commit stage), an exception or pipeline flush occurring between them leaves mstatus.MS=Clean while tile state is modified. The OS context-switch handler then skips saving tile state, leaking the previous hart's matrix computation data to the next process.
Consequence: info_leak
Pattern: mstatus\.MS.*Dirty|tile.*state.*commit|MS_.*update.*pipeline|csr_write.*MS_tile
