PR #2997  target=linux  overall=compliant
Spec: Matrix tile tail-agnostic policy means kernel cannot rely on tail elements surviving across context switches; must save/restore full tile dimensions (ETE×ETE per tile) unconditionally
Violation: Linux kernel context-switches matrix tile state without saving/restoring all elements of all tiles, relying on tail-agnostic policy to implicitly preserve tail elements (indices ≥ min(vl,ETE) or cols ≥ tm, rows ≥ tn). The spec explicitly makes tail-agnostic policy non-guaranteed, meaning an implementation may clobber tail elements on any matrix instruction, corrupting the tile state of the previously running task.
Consequence: data_corruption
Pattern: mstatus[30:29].*MS|mtype.*context|tile.*save|tile.*restore|__sched.*MS|switch_to.*matrix|fpsimd_save|fpsimd_restore|vtdiscard

[compliant] arch/riscv/include/asm/vector.h:233-268  __riscv_v_vstate_restore
  The existing vector vstate save/restore uses tail-agnostic policy ('ta, ma' in vsetvli at lines 219, 255) for the V register file (v0-v31). This is safe for vector registers because the full VLENB-sized register file is explicitly saved/restored — VLENB determines the vector element width for e8,m8 configuration, so all 32 registers are fully covered by four vse8.v/vle8.v blocks for v0-v7, v8-v15, v16-v23, v24-v31. The tail-agnostic flag only matters for elements within a single register group beyond the current vl setting, which are irrelevant since vl is set to VLMAX (x0). This pattern would become unsafe for matrix tiles if tiles use a different sizing mechanism and the code fails to cover all elements explicitly.
  | vsetvli %0, x0, e8, m8, ta, ma   /* VLMAX, tail-agnostic */
  | vle8.v  v0, (%1)                    /* Full register group, all elements */
  | vle8.v  v8, (%1)
  | vle8.v  v16, (%1)
  | vle8.v  v24, (%1)
