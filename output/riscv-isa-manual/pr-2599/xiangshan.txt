PR #2599  target=xiangshan  overall=compliant
Spec: G-stage (guest-stage) page table walker must recognize and correctly decode Svnapot N bit in hypervisor-managed page tables: PPN must merge vpn[3:0] into ppn[3:0] when N=1, tag matching must truncate to pteNapotBits boundary, and all G-stage PTE entry containers (HptwResp, PtwMergeResp) must carry hasNapot=true, or else guest physical addresses will be silently miscomputed, causing cross-VM data corruption.
Violation: In XiangShan RTL, if any G-stage-only PTW path (e.g., s2xlate === onlyStage2 or allStage G-stage walk) processes a G-stage PTE with the N bit set without treating it as an Svnapot 64KB page — specifically, failing to merge vpn[pteNapotBits-1:0] into the PPN lower bits — or if a PtwEntry/PtwSectorEntry instantiated for G-stage contexts omits hasNapot=true, or if the G-stage PTE tag comparison does not use the truncated tag match (pteNapotBits-based) when n=1, the hardware produces an incorrect guest physical address, violating the spec requirement that Svnapot is supported in G-stage translation.
Consequence: data_corruption
