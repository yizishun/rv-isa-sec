PR #2576  target=qemu  overall=not_implemented
Spec: Undefined-behavior for reserved SEW values in Zvdot4a8i dot-product instructions risks data corruption via incorrect sub-element extraction from vector registers when SEW!=32
Violation:
  QEMU TCG translates vdot4a/vdot4au/vdot4asu/vdot4aus instructions without
  checking that SEW==32, allowing execution with reserved SEW values (e.g.,
  SEW=8, 16, or 64) which the spec explicitly reserves. The instruction
  operates on 4-element groups packed within a SEW-bit bundle; when SEW!=32,
  the element group boundaries and sub-element extraction logic would be
  undefined, potentially accessing misaligned vector register state or
  reading/writing beyond intended element boundaries.
Consequence: data_corruption
Pattern:
  trans_vdot4a.*\(|gen_helper_vdot4a|OPMVV.*0b101[01]|vd*vdot|vext_vdot|s-
  >sew.*!=.*32|require.*zvdot
------------------------------------------------------------
[not_implemented] target/riscv/:0-0  
  Zvdot4a8i extension instructions (vdot4a, vdot4au, vdot4asu, vdot4aus) are
  not yet implemented in this QEMU tree. No translation functions, helper
  functions, opcode decode entries, or CSR definitions for these instructions
  exist in target/riscv/. The PR adding this extension is still in the review
  stage and has not been merged.
  | No relevant code exists in target/riscv/ for these instructions.
