PR #2604  target=linux  overall=potential_risk
Spec: Kernel executes WRS.NTO in S-mode via __cmpwait()/smp_cond_load_relaxed() without managing mstatus.TW; firmware-set TW=1 causes unexpected illegal-instruction exception and kernel panic
Violation: The Linux kernel executes WRS.NTO in S-mode via __cmpwait() (arch/riscv/include/asm/cmpxchg.h) and smp_cond_load_relaxed() (arch/riscv/include/asm/barrier.h) without configuring or reading mstatus.TW. If firmware (M-mode) sets mstatus.TW=1, a WRS.NTO that exceeds the implementation-specific bounded time limit raises an illegal-instruction exception (scause=2). The kernel's do_trap_insn_illegal() handler in arch/riscv/kernel/traps.c unconditionally panics on illegal instructions in kernel mode, resulting in immediate system halt.
Consequence: denial_of_service
Pattern: WRS\.NTO executed in S-mode without mstatus\.TW check or save/restore; illegal-instruction handler unconditionally panics in kernel context
------------------------------------------------------------
[potential_risk] arch/riscv/include/asm/cmpxchg.h:367-441  __cmpwait
  WRS.NTO is emitted via ZAWRS_WRS_NTO (0x00d00073) in inline asm at lines 393, 410, 421, 432 without any exception-table (_ASM_EXTABLE) entry and without checking mstatus.TW. If firmware (M-mode) sets mstatus.TW=1, a WRS.NTO exceeding the implementation's bounded time limit raises scause=2 (illegal instruction), which fixup_exception() cannot recover because there is no extable entry. The code's own comment at line 364-365 acknowledges this: 'because it has been configured to raise an illegal instruction exception.' Only extension presence (riscv_has_extension_likely()) is checked, not the mstatus.TW trap-enable bit.

[potential_risk] arch/riscv/include/asm/barrier.h:70-80  smp_cond_load_relaxed
  smp_cond_load_relaxed() unconditionally calls __cmpwait_relaxed() -> __cmpwait() which emits WRS.NTO. Used in hot spinlock paths: qspinlock slowpath (kernel/locking/qspinlock.c:368), osq_lock (kernel/locking/osq_lock.c:146), and BPF rqspinlock (kernel/bpf/rqspinlock.c:576,608,647). A WRS.NTO trap in any of these paths — especially in interrupt context where die() unconditionally panics — would either halt the system or kill the lock-holder via make_task_dead(), leaving the lock permanently held.
  | #define smp_cond_load_relaxed(ptr, cond_expr) ({                                 \
  | 	typeof(ptr) __PTR = (ptr);                                          \
  | 	__unqual_scalar_typeof(*ptr) VAL;                                   \
  | 	for (;;) {                                                          \
  | 		VAL = READ_ONCE(*__PTR);                                \
  | 		if (cond_expr)                                          \
  | 			break;                                          \
  | 		__cmpwait_relaxed(ptr, VAL);                            \
  | 	}

[potential_risk] arch/riscv/kernel/traps.c:132-143  do_trap_error
  Kernel-mode exception handling unconditionally calls die() if fixup_exception() returns false. There is no intermediate recovery path for WRS.NTO traps: no attempt to read mstatus.TW, no fallback to a pause-based polling loop, and no handling of the case where the trapping WRS.NTO was in a spinlock-acquisition path. fixup_exception() searches exception tables by epc, and since the WRS.NTO inline asm has no extable entry, it always returns false.
  | static void do_trap_error(struct pt_regs *regs, int signo, int code,
  | 	unsigned long addr, const char *str)
  | {
  | 	if (user_mode(regs)) {
  | 		do_trap(regs, signo, code, addr);
  | 	} else {
  | 		if (!fixup_exception(regs))
  | 			die(regs, str);
  | 	}
  | }

[potential_risk] arch/riscv/kernel/traps.c:76-112  die
  die() has two unconditional panic() paths: (1) in_interrupt() leads to 'panic("Fatal exception in interrupt")' — and WRS.NTO is called from qspinlock/osq_lock paths that may run in IRQ context; (2) panic_on_oops leads to 'panic("Fatal exception")'. Even the non-panic path calls make_task_dead(SIGSEGV), which kills the current task. If that task held a spinlock (the very scenario when WRS.NTO is executing), the lock is never released.
  | void die(struct pt_regs *regs, const char *str)

  | 	if (panic_on_oops)
