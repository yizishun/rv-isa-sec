PR #2604  target=xiangshan  overall=compliant
Spec: WRS.NTO stall timeout enforcement via mstatus.TW/hstatus.VTW is a privilege-boundary security mechanism; a stuck timeout counter or incorrect privilege check in the commit stage allows unprivileged code to stall the hart indefinitely, causing hardware-level denial of service
Violation: In XiangShan RTL, when WRS.NTO executes in S-mode or U-mode with mstatus.TW=1 (or in VS/VU-mode with hstatus.VTW=1 and mstatus.TW=0), the commit stage must track stall duration via an implementation-specific counter and raise illegal-instruction or virtual-instruction exception if the stall exceeds the bounded time limit. A hardware violation occurs if: (a) the stall duration counter is never incremented or is stuck, causing the hart to hang indefinitely in a low-privilege mode with no timeout escape; (b) the privilege-mode check in the commit logic incorrectly masks the TW/VTW condition, allowing lower-privilege code to bypass the timeout and stall the hart forever; (c) the exception is raised but the exception delivery logic corrupts mtval/stval (which should capture the WRS.NTO opcode), causing an unrecoverable fault; or (d) pipeline flush on exception delivery fails to clear younger speculative instructions that already observed the stalled state, leaking microarchitectural side effects.
Consequence: denial_of_service
Pattern: WRS\.NTO.*stall.*counter|mstatus\.TW.*WRS|hstatus\.VTW.*WRS|wrs_nto.*timeout|Zawrs.*exception|stall_duration.*counter|WRS.*commit.*privilege
