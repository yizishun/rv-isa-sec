PR #79  target=xiangshan  overall=compliant
Spec: Hardware tag-check decision logic must condition on both PTE.MTAG AND PTE.X to classify pages as tagged-data (MTAG=1,X=0) vs tagcheck-exempt (MTAG=1,X=1); evaluating MTAG alone violates the new two-tier page classification and enables privilege escalation via unchecked access to tagged memory from code incorrectly treated as exempt
Violation:
  In XiangShan RTL, when the PTW/TLB page-walk result or the load/store unit
  evaluates tag-check applicability using only the PTE.MTAG bit without also
  evaluating the PTE.X (execute) permission bit, the hardware fails to
  distinguish between 'tagged-data pages' (MTAG=1, X=0) and 'tagcheck-exempt
  code pages' (MTAG=1, X=1). This causes loads/stores fetched from a tagcheck-
  exempt code page to incorrectly undergo tag checks (precedence rule 3
  violated), or loads/stores targeting a non-executable page with MTAG=1 to
  incorrectly skip tag checks (rule 2 misapplied). Additionally, if the
  hardware's misaligned-access handling in the LSU does not detect a page-
  boundary straddle between a tagged-data page and a normal page and fails to
  apply the 'both halves treated as tagged-data' rule, one half of the access
  escapes tag checking.
Consequence: privilege_escape
Pattern:
  PTE.MTAG evaluated in isolation from PTE.X in tag-check-decision logic;
  absence of (pte.mtag && !pte.x) gating for tagged-data-page classification;
  missing page-crossing straddle detection in LSU tag-check FSM for misaligned
  loads/stores
