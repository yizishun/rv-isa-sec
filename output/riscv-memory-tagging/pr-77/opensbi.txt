PR #77  target=opensbi  overall=compliant
Spec: Trap-deposited mstatus.MTAG_I can silently disable tag checks on subsequent OpenSBI MPRV memory accesses, leaking tagged S-mode data through M-mode firmware read paths.
Violation:
  In OpenSBI, when a trap to M-mode sets mstatus.MTAG_I (via the new trap-
  deposition rule: MTAG bit of the trapping instruction's code page is
  deposited into mstatus.MTAG_I when mtval is written nonzero during trap
  entry), and OpenSBI subsequently uses MPRV-based loads or stores (e.g., in
  SBI handler memory copy routines, domain context save/restore, or
  sbi_load/store helpers) without first clearing mstatus.MTAG_I, the MPRV
  loads/stores become unchecked — silently bypassing tag checks that S-mode or
  VS-mode expects to be enforced on those memory locations.
Consequence: info_leak
Pattern:
  MPRV load/store after M-mode trap entry without explicit mstatus.MTAG_I
  clear; CSR read-modify-write of mstatus that preserves MTAG_I across MRET;
  HSM suspend context save/restore that blindly preserves mstatus.MTAG_I
  without sanitization.
