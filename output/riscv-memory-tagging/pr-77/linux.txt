PR #77  target=linux  overall=compliant
Spec: HLV/HSV in KVM emulation breaks on guest tagged-data pages: kernel uses untagged pointers and no tag storage, so new spec-mandated tag checks trigger unhandled software-check exceptions, letting a malicious guest crash hypervisor instruction emulation
Violation:
  In the Linux kernel, KVM's emulation path (kvm_riscv_vcpu_unpriv_read at
  arch/riscv/kvm/vcpu_exit.c:63) uses HLV/HSV instructions to access guest
  memory for instruction emulation, MMIO decode, and SBI handling. When the
  VS-stage PTE for the accessed data page has MTAG=1 (tagged-data page) and
  the guest has memory tagging enabled, HLV/HSV now perform tag checks. The
  kernel's HLV/HSV accesses use untagged host pointers and have no tag storage
  provisioned, so any tag check will mismatch and raise a software-check
  exception (tval=4, hstatus.GVA=1) that __kvm_riscv_unpriv_trap does not
  handle—it only handles load/store page faults.
Consequence: denial_of_service
Pattern:
  HLV_D|HLV_W|kvm_riscv_vcpu_unpriv_read|kvm_riscv_vcpu_unpriv_write|__kvm_ris
  cv_unpriv_trap|csr_swap\(CSR_HSTATUS
