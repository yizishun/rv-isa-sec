PR #77  target=linux  overall=compliant
Spec: hstatus.MTAG_I and mstatus.MTAG_I are new Zimt CSR bits deposited by hardware on trap entry (HS-mode and M-mode respectively); if the kernel's context-switch or register-save paths omit these bits, a guest VM or process can inherit stale MTAG_I state from a prior context, suppressing tag checks on HLV/HSV emulated accesses and defeating the memory-tagging security boundary
Violation: KVM context-switches hstatus between VCPUs without saving/restoring hstatus.MTAG_I, or the kernel writes a synthesized sstatus/mstatus value (e.g., during signal frame setup, ptrace register set, or user_regs recovery) that corrupts MTAG_I, causing one execution context to inherit another context's code-page tag state
Consequence: privilege_escape
Pattern: save/restore of sstatus/mstatus/hstatus without MTAG_I mask; __fswrite sstatus CSR without MTAG_I preservation; KVM vcpu switch omitting hstatus.MTAG_I in the save/restore sequence
