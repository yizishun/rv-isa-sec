PR #82  target=opensbi  overall=compliant
Spec: mstatus.MTAG_I controls whether MPRV=1 loads/stores in M-mode bypass tag checks; if OpenSBI fails to sanitize this hardware-deposited bit before performing MPRV memory accesses, S-mode memory tagging enforcement is silently defeated on the firmware code path
Violation: OpenSBI's M-mode code sets MPRV=1 to access S-mode memory (e.g., during SBI handler emulation or domain context switching) without explicitly saving and clearing mstatus.MTAG_I first. Hardware may have deposited the trapping instruction's code-page MTAG into mstatus.MTAG_I on trap entry; if OpenSBI does not sanitize this bit before MPRV loads/stores, tag checks may be incorrectly bypassed (MTAG_I=1) or incorrectly enforced (MTAG_I=0), breaking memory-tagging invariants that S-mode relies on.
Consequence: privilege_escape
Pattern: MPRV=1 set without preceding save/clear of mstatus.MTAG_I; csrw/csrs mstatus with MPRV|MTAG_I bitmask not sanitized; trap handler entry path that reuses mstatus without masking MTAG_I before MPRV memory access; HSM suspend/resume mstatus save/restore missing MTAG_I bit
