PR #91  target=qemu  overall=compliant
Spec: Inverted 'is/is not' logic: tag-check exemption for code on MTAG+X pages is negated, causing trusted compiler-generated code to be checked and untrusted code to bypass checks, breaking the Zimt memory tagging security model
Violation:
  QEMU TCG implements the tag-check eligibility logic per the old (buggy) spec
  text, where a regular load/store is subject to tag checks when the
  instruction resides on a tagcheck-exempt code page (MTAG=1, X=1 in first-
  stage PTE) rather than the inverse. This inverts the exemption rule: code
  pages marked as trusted/tagcheck-exempt get checked, while code on non-
  exempt pages bypasses checks.
Consequence: function_loss
Pattern:
  checking PTE.MTAG bit and execute permission of the instruction-fetch page
  to decide tag-check eligibility for load/store—specifically, branching on
  (pte_mtag && pte_x) to enable checks instead of disable them
