PR #91  target=opensbi  overall=potential_risk
Spec: OpenSBI must correctly preserve the tagcheck-exempt PTE bit when configuring page tables, or else code on non-exempt pages accessing tagged-data pages will be subject to tag checks — the inverse of the intended exemption semantic — enabling privilege-boundary bypasses through misconfigured memory tagging
Violation: OpenSBI incorrectly sets or clears the tagcheck-exempt PTE attribute on a code page (e.g., during page table setup via sbi_domain, HSM context save/restore, or Svpbmt/Svadu PTE configuration), causing tag checks to be either unexpectedly enforced or silently bypassed when M-mode, S-mode, or U-mode code on that page accesses tagged-data pages
Consequence: privilege_escape
Pattern: PTE bit manipulation without preserving memory-tagging-related reserved/attribute bits; CSR save/restore of menvcfg/senvcfg without masking MTE field; page table walk or PTE update that clobbers tagcheck-exempt bit

  When transitioning to S-mode, SATP and VSATP are explicitly zeroed (lines 815, 820).
