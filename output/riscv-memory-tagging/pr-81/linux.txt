PR #81  target=linux  overall=compliant
Spec: Removing Zitagelide eliminates a CSR bit-24 conflict: SPTTCD collided with SPELP in mstatus/sstatus; kernel context-switch and trap-entry code managing SPELP would have silently clobbered or misinterpreted tag-check-elide state.
Violation:
  If hardware had implemented Zitagelide with SPTTCD at mstatus/sstatus bit
  24, the kernel's existing SPELP management (sr->status & SR_SPELP
  save/restore at context-switch and csrrc clearing of SR_ELP on trap entry in
  entry.S:178-183) would silently alias TTCD state, causing: (a) kernel
  clobbering tag-check-elide state across context switches when
  saving/restoring SPELP, and (b) hardware interpreting SPELP writes as TTCD
  transitions, potentially eliding tag checks on kernel-originated memory
  accesses when landing-pad state changes.
Consequence: privilege_escape
Pattern:
  csrrc.*CSR_STATUS.*SR_SPELP|csrw.*CSR_STATUS.*SR_SPELP|csrs.*CSR_STATUS.*SR_
  SPELP|SR_SPELP_AC\(0x00800000
------------------------------------------------------------
[compliant] arch/riscv/kernel/entry.S:176-190  handle_exception (trap entry)
  Kernel correctly implements SPELP management per Zicfilp spec: csrrc reads-
  and-clears SR_ELP on trap entry (line 183), saves pre-clear sstatus (with
  SPELP preserved) to pt_regs->status (line 190), and restores via csrw
  CSR_STATUS on sret return (line 301). Bit 24 is formally assigned to SPELP
  by the ratified Zicfilp extension. No aliasing conflict exists because
  Zitagelide is not a defined RISC-V extension and is not implemented in this
  kernel.

[not_implemented] arch/riscv/kernel/entry.S:1-1  Zitagelide / SPTTCD
  Zitagelide is not a defined RISC-V extension in any specification document
  under spec_ref/. No Zitagelide or SPTTCD code exists in the Linux kernel
  (confirmed by exhaustive grep). The hypothetical aliasing conflict described
  in the security spec—where SPELP and SPTTCD both use bit 24—is a spec-level
  bit-allocation concern that would need to be resolved at the ISA design
  level before any kernel implementation could exist. The kernel correctly
  uses bit 24 exclusively for SPELP per the ratified Zicfilp extension.
  | (no Zitagelide/SPTTCD code exists in kernel)
