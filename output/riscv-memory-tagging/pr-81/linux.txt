PR #81  target=linux  overall=compliant
Spec: Zitagelide removal reclaims mstatus[42] and sstatus[24] as WPRI; kernel must not touch these bits — any stale save/restore of the now-nonexistent TTCD state would corrupt CSR fields across context switches or VM exits.
Violation: Kernel context-switch or trap handler writes to the now-WPRI bits 24 (SPTTCD) or 42 (MPTTCD) in mstatus/sstatus, or kernel relies on mret/sret to restore a TTCD state that no longer exists — causing silent corruption of adjacent fields if hardware repurposes these bits.
Consequence: info_leak
Pattern: mstatus.*0x[0-9a-fA-F].*24|sstatus.*BIT\(24\)|MPTTCD|SPTTCD|TTCD|nietc|TAG_CHECK_ELIDE

[potential_risk] arch/riscv/include/asm/csr.h:42-46  SR_VS_CLEAN_THEAD / SR_VS_DIRTY_THEAD overlap with bit 24
  XTheadVector uses bits 23-24 of sstatus for VS status (SR_VS_CLEAN_THEAD=0x01000000, SR_VS_DIRTY_THEAD=0x01800000). Bit 24 (0x01000000) is the former SPTTCD position. On hardware that supports XTheadVector, bit 24 will be actively toggled by context-switch. This is NOT a TTCD violation — XTheadVector is a vendor extension with known semantics — but if future spec revisions repurpose bit 24 for a different mandatory feature, the XTheadVector usage at this bit position could conflict. Currently low risk since XTheadVector and zitagelide cannot coexist on the same hart.
