PR #80  target=xiangshan  overall=compliant
Spec: Stale MT_ASYNC CSR bit left in hardware after spec removal: writes to now-WPRI bit can enable undocumented asynchronous exception deferral, breaking synchronous trap-delivery guarantees and opening a window where tag-mismatched stores retire without immediate exception
Violation: XiangShan RTL retains the MT_ASYNC bit (bit 36 in xenvcfg; former bit adjacent to MT_MODE in mseccfg) as a writable control register field after the spec removes it, causing writes to a now-WPRI bit to configure non-existent asynchronous tag-check behavior, or the store tag-check FSM still conditionally defers software check exceptions based on this stale control bit instead of always reporting synchronously
Consequence: privilege_escape
Pattern: MT_ASYNC|mt_async|MteAsync|async_tag_check|deferred_tag_exception|tag_mismatch_async
