PR #80  target=linux  overall=compliant
Spec: Removal of MT_ASYNC bit reclassifies those CSR bit positions as WPRI: kernel context-switch and KVM code that explicitly clears or rewrites these bits (rather than preserving read-back values) corrupts implementation-defined state, risking undefined hardware behavior on implementations that repurpose the reclaimed bits.
Violation: Kernel explicitly clears or modifies bit 36 (former MT_ASYNC) in senvcfg/henvcfg/menvcfg, or the corresponding bit in mseccfg, during context-switch save/restore or KVM vcpu load/put, instead of preserving the value read from hardware. Since these bits are now WPRI, writes must preserve original values; writing a hardcoded 0 (or any value different from what was read) violates the spec.
Consequence: data_corruption
Pattern: envcfg.*MT_ASYNC|MT_ASYNC.*envcfg|BIT.*36.*envcfg|sencfg.*36|hencfg.*36|__enable_mte|__disable_mte|csr_write.*senvcfg.*mask|csr_write.*henvcfg.*mask
