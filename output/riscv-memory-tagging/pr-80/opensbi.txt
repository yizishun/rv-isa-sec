PR #80  target=opensbi  overall=compliant
Spec: menvcfg bit 36 (was MT_ASYNC) becomes WPRI — OpenSBI HSM save/restore and menvcfg write paths must mask this bit to avoid UNSPECIFIED behavior
Violation: OpenSBI reads menvcfg CSR, then writes it back verbatim (e.g., HSM save/restore or menvcfg modification in sbi_hart.c) without masking bit 36 — now WPRI after MT_ASYNC removal. Writing WPRI bits causes UNSPECIFIED behavior on hardware that hardwires or repurposes this bit.
Consequence: denial_of_service
Pattern: csr_read(CSR_MENVCFG) followed by csr_write(CSR_MENVCFG, val) where val is the raw read value without masking WPRI bits; also menvcfg read-modify-write sequences that preserve undefined bits
