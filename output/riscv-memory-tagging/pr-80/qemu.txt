PR #80  target=qemu  overall=compliant
Spec: Removal of MT_ASYNC from *envcfg bit 36 and mseccfg: if QEMU fails to convert the bit to WPRI (writes ignored, reads return 0), previously-written values leak across VM reset/context-switch boundaries, and stale asynchronous tag-check paths may create a covert side-channel observable by the guest kernel.
Violation: QEMU still emulates the MT_ASYNC bit (bit 36 in menvcfg/senvcfg/henvcfg; or the removed MT_ASYNC field in mseccfg) as a readable/writable field after the spec removed it. If QEMU's CSR emulation allows the guest to set bit 36 of *envcfg to 1, or reads back a previously-written value instead of returning 0 (WPRI), the emulation violates the updated spec. Additionally, if QEMU previously implemented deferred/asynchronous tag-check reporting for stores and that code path still exists, a guest setting the now-WPRI bit could trigger stale asynchronous behavior that the spec no longer permits.
Consequence: info_leak
Pattern: menvcfg.*MT_ASYNC|senvcfg.*MT_ASYNC|henvcfg.*MT_ASYNC|mseccfg.*MT_ASYNC|envcfg.*bit.*36|WPRI.*36|MTE_ASYNC|mt_async|tag_check.*async
