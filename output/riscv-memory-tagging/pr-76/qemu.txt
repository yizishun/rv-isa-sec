PR #76  target=qemu  overall=compliant
Spec: Deferred async MTE tag mismatch state in TCG risks cross-CPU info leak via stval2/htval2/mtval3 if pending buffer is not per-hart and not sanitized on mode transitions
Violation: In QEMU TCG, when menvcfg.MT_ASYNC is set and a tag-mismatching regular store executes, the software check exception must be deferred to the next trap. If QEMU stores the pending mismatch flag and the faulting virtual address (destined for stval2/htval2/mtval3) in a non-per-CPU location, or fails to clear them on writes to menvcfg/mseccfg that disable tagging, or fails to flush them on privilege-mode transitions, then (a) one hart's trap handler can observe another hart's faulting virtual address in these CSRs, or (b) a guest can read stale virtual addresses from a prior security context after toggling MT_ASYNC off and back on.
Consequence: info_leak
Pattern: pending.*tag|tag.*pending|mte_defer|mte_async|async.*mismatch|MT_ASYNC|stval2|htval2|mtval3|riscv_cpu_do_interrupt.*mte
